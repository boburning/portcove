---
name: portcove-port-qualification
description: Investigate, add, or requalify a Portcove port with exact upstream, source and artifact evidence. Use for catalog admission and lifecycle qualification, not ordinary UI changes.
---

Resolve the current checkout root before using paths below. Read [catalog contracts](../../../docs/CATALOG.md) and the port's canonical issue and live Project fields. For new intake, use the existing roadmap capture/normalization commands in [governance](../../../docs/PROJECT-GOVERNANCE.md); search for the canonical issue before creating anything.

Establish direct upstream identity, exact runnable asset/platform, independent checksum authority, required source variant/representation, persistence paths, and fit with existing generic adapters. A local hash records bytes; it does not independently authenticate an upstream download. Missing optional gameplay evidence alone does not block unrelated promised operations.

Use an explicitly isolated library and authorized source files. Exercise the operations promised by the issue through core/CLI: source validation, install, launch preflight, update, rollback and persistence where applicable. Never implement title-specific Rust behavior when catalog data can express it.

Capture an initialized library with `node scripts/qualification-report.mjs --cli <absolute-executable> --library <absolute-library> --output <new-directory>`. Inspect the script's current arguments before composing a larger session. For Windows session orchestration, read [windows-qualification-session.ps1](../../../scripts/windows-qualification-session.ps1).

Report exact artifact, platform, source contract/variant/representation, check version, operation, outcome and evidence location. Preserve failed, not-run and unknown results. The report collects snapshots; it does not grant qualification. Record catalog evidence only for the exact scope established. Keep isolated fixtures, packaged execution, physical-device results and human gameplay distinct.

Finish with the linked issue's acceptance observations and unresolved resume conditions. Use existing quality/release checks appropriate to the change; do not substitute a successful download for lifecycle evidence.
