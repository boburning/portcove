Setup

  1. Set up the managed copy on first Play

    Choose Load ROM and select your own supported Japanese or English Sin and Punishment ROM (see Check the required game files). The player keeps a copy in its snprecomp profile, with separate saves for Japanese and English. Back up that profile separately before changing versions.

  2. Check the required game files

    Use your own Japanese ROM with SHA-1 581297b9d5c3a4c33169ae0aae218c742cd9cbcf, or an English variant with SHA-1 5945ff3935d9d9531bbb5cfcabed7c198e2b2f41 or e3906c919236dac6eba020b4b8c1df91fd725c5d. This guide has not confirmed other translations; check the project’s requirements before using one.

  3. Follow upstream setup

    Extract the complete package to a writable folder. On Windows run SnPRecompiled.exe. On Linux run SnPRecompiled.sh from the extracted folder. Choose Load ROM and select your own supported copy, then start the game. To register a Linux copy, select the SnPRecompiled program, not SnPRecompiled.sh.

  4. Select the prepared player

    Select SnPRecompiled.exe and use its containing folder as the working directory. Leave arguments empty. Keep the complete independently permitted runtime and finish the title-specific preparation before Play.

Setup notes
Set up the separate Android ARM64 app
Use SnPRecompiled-0.2.11-android.apk from the upstream release on Android 9 or newer. It needs a Vulkan driver with descriptor indexing. Open the app and choose Load ROM to select your original with the system picker. The app copies it into its own storage.
Registration ownership and removal
Portcove records the selected executable, working folder and literal arguments after review. Play is separate and only the selected process is supervised. You and upstream own replacement and updates; relink changed executable bytes after reviewing them. Removing this registration preserves every external file. Managed installation, backup, rollback, migration and deletion are not offered for this external copy.
Player-data ownership
You and upstream own the external copy's data: the existing snprecomp profile or the application folder when portable.txt is present. Back up these locations separately; registration does not migrate or certify their compatibility.
Managed runtime ownership
Portcove installs and replaces its separate official runtime using the declared release rules. Existing external registrations retain their files and user/upstream ownership. Runtime rollback carries current declared data; it does not rewind saves or establish older-runtime compatibility. Gameplay and populated-save compatibility remain separate qualification. The managed copy has no declared local player data to back up. Back up the external profile separately.

Limitations and evidence

  • Upstream marks the Linux and Steam Deck routes untested. Portcove has not observed native setup or gameplay.
  • The Android app disables Android backup. Clearing its data or uninstalling can remove its imported ROM and separate Japanese and English saves. Keep your external original and update io.github.wootbeer.snprecomp with the same package identity and signer.
  • The profile is %LOCALAPPDATA%\snprecomp on Windows and ~/.config/snprecomp on Linux; a separately prepared copy without portable.txt shares it. Use a separate upstream copy for portable.txt mode. Do not use Add to Steam from the managed copy: the shortcut points at one version folder, starts the game outside Portcove and stays in Steam after removal. The Linux x86-64 player needs glibc 2.38 or later and system SDL2, Vulkan, X11, FreeType and D-Bus libraries; Load ROM uses the desktop file-chooser portal.
