Setup

  1. Use a completed Windows copy

    Use an independently permitted completed Windows copy. The inspected 1.7 ZIP (SHA-256 21e13616bbc0d62dcf1341be10d392694b1f6033965dc4c9ab15f13a8f028ac6) contains bigodao_1.7_win/bigodao_1.7_win.exe and tools/wl_sm3_dx_v12_patch.json beneath that folder. Keep both together in a writable folder. A separately completed source build instead uses wario_land_port.exe; this route does not supply missing generated game code or establish source-to-binary reproducibility.

  2. Keep exact original and patch inputs

    For upstream first-run preparation, supply your legally obtained Wario Land - Super Mario Land 3 (World) ROM (SHA-256 ac1682f17abcf590311a233289ee325214c2d71ab3a5aa175004002d85075e56) and independently permitted korxo DX v1.2 IPS patch (SHA-256 599d9f59090df3e1e77c1678e069290a2cd9ce59c71cf58d66c4dc3db8b7facd). Owning the game or the project code license does not grant acquisition or redistribution of the patch or optional music/art packs.

  3. Back up old and new storage before startup

    Before first startup or an update, close Bigodão and separately back up the complete old and new folders, saves/, legacy loose .sav/.rtc/.state files, wario.o2r and any .tmp recovery file, mods/, and the SDL preference directory for gbrecompiled/runtime (normally %APPDATA%/gbrecompiled/runtime/runtime_prefs.ini; local runtime_prefs.ini is a fallback). Startup copies eligible legacy loose saves into missing saves/ destinations and retains the old files; failure to create saves/ falls back to beside-executable storage.

  4. Let upstream prepare its private data package

    Complete the upstream ROM/IPS picker before registration. It patches a copy in memory and creates wario.o2r beside the executable, with a current-directory fallback for an existing package. An older texture recipe can request re-preparation; creation verifies a temporary package, then removes the prior package before renaming the replacement. Keep the separate pre-start backup and original inputs; cancelling that update can continue with the previously loaded old ROM.

  5. Link the ordinary native executable

    For the inspected 1.7 Windows package, add bigodao_1.7_win.exe through the existing-copy route, use the bigodao_1.7_win folder containing it as the working directory, and leave arguments empty. For a separately completed source build, select its wario_land_port.exe with that executable's parent folder and no arguments. The source runs its picker and normal game loop in one process; Portcove has not tested launch with this package. Do not select Android files, packaging tools, or a compiler helper.

  6. Keep replacement ownership upstream

    Quit the game completely before maintenance, relinking or removal. Upstream and the user own preparation, runtime replacement and updates; Portcove only links the selected executable and does not install, update, roll back, move or delete this external copy or its player data.
