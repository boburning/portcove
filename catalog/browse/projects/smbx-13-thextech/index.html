Setup

  1. Choose the Super Mario Bros. X game pack

    Use a permitted, already unpacked Super Mario Bros. X 1.3-compatible game/episode copy prepared with TheXTech. The official v1.7.4.1 release identifies a specific super-mario-bros-x-thextech-v1.7.4.1-win64.7z game package and a separate smbx13 asset pack; a bare TheXTech engine is not this game. Adventures of Demo is a separate excluded game, and SMBX2/LunaLua content is incompatible. Retain the actual gameinfo.ini, episode/worlds and complete asset pack. Package availability does not grant rights to original art, music or episodes.

  2. Select the prepared SMBX player

    Keep the full upstream-unpacked package and select its actual native Windows SMBX player, with its established asset/game working directory, rather than an editor, installer or bare engine without game data. The selected Windows packaging source names the SMBX x64 player smbx-win64.exe (32-bit smbx.exe), separately from advdemo and bare thextech. Released 7z contents have not been inspected here; select the actual executable in your permitted prepared copy. Finish any conversion and asset placement upstream before attaching it.

  3. Retain the effective asset and user roots

    Preserve the creating runtime, complete game/episode assets and actual writable user directory. --asset-pack (-c), --user-directory (-u) and --game-dirname can select different locations; retain established literal arguments and use absolute paths when already configured. Windows normally uses roaming AppData/TheXTech, with a legacy .PGE_Project/thextech fallback and other configured directory names. A [Main] force-portable=true thextech.ini beside the runtime selects portable paths. Keep thextech.ini and controls.ini in the effective settings location, gamesaves, screenshots, logs, worlds, battle content, mods/custom and unknown files across every effective root; a second executable does not isolate shared profiles.

  4. Check the prepared copy before registration

    Finish setup with the project’s tools, then start and quit the copy you intend to add. Keep its game executable, working folder and supported launch arguments. Review those details in Portcove and agree to launch them, then choose Play separately. Adding a copy does not confirm its original game files, gameplay or save compatibility.

  5. Keep updates and removal under the existing owner

    Close every running copy of the game before changing files. Keep the working game version and every data and profile folder recoverable. Update it with the project’s tools, then review and select the changed executable in Portcove before choosing Play. You manage setup, updates, file changes, data migration and recovery. Portcove monitors the process you selected; it does not prevent other copies from running or restrict the game’s file access. Removing the registration leaves external files in place. This route does not offer Portcove downloads, setup, updates, backups, rollback, data migration or external-file deletion.

Limitations and evidence

  • Use only a copy and content you are already permitted to use. Engine licensing does not grant rights to original game assets, music, mods or bundled components.
  • Before updating the game, keep a copy of its working files and every location containing saved data. Choosing a different executable does not give it a separate profile.
