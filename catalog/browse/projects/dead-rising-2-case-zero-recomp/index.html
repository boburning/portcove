Setup

  1. Use a completed copy you already have

    Continue with a complete player you already have. Portcove downloads are paused because the package includes shader pre-warm data recorded from the game and recipes for patching the game’s own shaders. The reviewed v1.1.3 package also includes compiled-in libxlive, whose licence it defers to XenonLive; offline use does not remove it. The preparation and data-preservation guidance below applies to that copy.

  2. Prepare the own-game offline Windows copy upstream

    Use your legally obtained Xbox Live Arcade Dead Rising 2: Case Zero package, Title ID 58410A8D: the approximately 825 MB extensionless package under Content/0000000000000000/58410A8D/000D0000, not the full Dead Rising 2 game. Follow the standalone package’s first-run instructions outside Portcove. Its native runtime performs STFS extraction, shader preparation and game-data overlays; no external compiler or setup helper is run by this guide. The project’s PolyForm Noncommercial grant covers its own work, not the original game or separately licensed components.

  3. Select the actual offline native runtime

    The reviewed v1.1.3 Windows x86-64 ZIP contains CaseZeroRecomp/cz_runtime.exe, its DLLs and the initial assets/package marker. Attach the completed cz_runtime.exe with its executable directory as the established working directory. An online XenonLive launcher is not required for this offline entry; do not enroll one copy under competing runtime updaters. The package’s independent published SHA-256 is recorded in the source dossier, but attachment is explicit user-selected trust, not curated tree certification.

  4. Attach the completed native player and choose Play separately

    Finish setup with the project’s tools, then select the Windows game executable, working folder and supported launch arguments in Portcove. Review and agree to those details, then choose Play separately. Keep the complete package together and close the game and companion programs before changing files. You manage this external copy; Portcove does not replace it or back up, convert, migrate or delete its data. Removing its registration leaves those files in place. Source review and automated registration checks do not confirm an installed game session, successful forced exit, gameplay or save compatibility.

Limitations and evidence

  • Before changing versions, keep a copy of the working game and all original files, profiles, mods, generated caches and custom data locations. Another executable may use the same saved data.
  • A present CZ_SAVE_DIR overrides both roots and prevents profile switching; preserve its actual configured location. Startup can copy legacy assets/save container directories into a root with no existing container directories and copy settings only if absent, retaining old copies and leaving loose legacy files. Keep all old/new and unfinished roots: this is upstream behavior, not a Core migration or compatibility promise.
  • The bundled SDK’s complete effective user/account/capture paths are not established by the public source: preserve the actual roots belonging to that copy, including custom SDK locations. Do not infer backup or cleanup permission. Reports can contain private paths or saves; this route does not enable collection/upload, online login, private SDK access or credential use.
