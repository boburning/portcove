Setup

  1. Keep the complete Windows player and its terms

    Use MarioTennisVirtualBoyRecomp-windows-x64.zip v0.2.3 with MarioTennisVirtualBoyRecomp.exe, SDL2.dll, assets, licenses and existing optional mods retained together. Root MIT licensing covers build glue and documentation; original Nintendo game code/data/artwork and the separately pinned framework/UI keep their own terms. No permission to redistribute a ROM, generated cartridge code or third-party artwork is inferred. Upstream full-match and comparison claims are not Portcove native/gameplay observations.

  2. Use your own matching Mario’s Tennis cartridge dump

    The supported Virtual Boy ROM is 524,288 bytes, CRC32 7CE7460D and SHA-256 5dc5e6b5d5f538f56b3b9727db1c7931d9dfe1bbd0743f698897e0fd90e70101. Use your own matching dump through the upstream picker and keep it at its current location. The runtime checks the supported ROM and refuses a mismatch. Another Virtual Boy title, archive wrapper or changed original is not a substitute. Optional color mods are separate and disabled by default; registration does not enable them or modify the ROM.

  3. Add the ordinary native frontend

    Select MarioTennisVirtualBoyRecomp.exe, use its complete containing release directory as working directory and leave arguments empty. Review the selected program, folder and arguments, then choose Play when ready and use its native ROM picker. Preserve an existing remembered original/configuration rather than resetting it. Headless, trace and TCP-debug commands are developer routes, not the game entry offered here; release packaging disables debug tools.

  4. Preserve configuration and cartridge progress

    Keep vbrecomp.cfg, keybinds.ini, mods and the entire saves folder beside the player, including the title’s existing cartridge-save file. Preserve the original ROM’s separate path and any existing --config, --save or --mods-dir choices if using a previously customized upstream route. Do not transplant another Virtual Boy title’s save or enable a mod to register the game. No source rewrite, save migration, conversion, backup or cross-build compatibility promise is supplied.

  5. Keep updates and qualification upstream

    Close the actual game and helpers before upstream replacement or file recovery, retain the old complete runtime/data, and review/select the executable after changes. Portcove observes only the selected program and removing the reference leaves all external files intact. Upstream owns runtime replacement, optional mods and save compatibility. Managed acquisition/install/update/backup/rollback, full-session tracking and Supported qualification are not offered; controller, complete-game and real-save acceptance remain separately observed outcomes.
