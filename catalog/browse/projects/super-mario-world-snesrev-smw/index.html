Setup

  1. Keep the matching original

    Use your own unchanged USA Super Mario World original. The selected upstream runtime requires a 524288-byte unheadered smw.sfc for its matching packaged smw_assets.bps; BPS validation can reject a different original. Preserve the original unchanged outside the player folder. Super Mario All-Stars, translations, patched files and other editions are different inputs.

  2. Finish upstream setup and select the real player

    Use the upstream v0.1 Windows package in a separate writable folder with its matching smw_assets.bps, smw.ini and SDL2.dll; place only your matching original copy named smw.sfc beside smw.exe. Alternatively finish the upstream-supported source build and matching smw_assets.dat extraction. Finish normal upstream setup successfully before registration; do not select extract_assets.bat, run_with_tcc.bat or another compiler/helper as the player. Use the selected player’s containing folder as working directory and keep the already working literal arguments; do not invent shell commands.

  3. Register the existing player and use explicit Play

    You manage this external game and all its original files and saved data. Portcove saves the executable, working folder and launch arguments you select; it does not authenticate the complete package or original game files. Choose Play explicitly when you are ready. Removing the registration leaves external files in place. Portcove does not offer updates, backups, rollback, data migration or external-file deletion for this copy. Finish setup with the project’s tools and add only a working game. These instructions do not confirm successful setup, gameplay or save-state compatibility.
