Setup

  1. Prepare a supported original revision

    Use a complete player/components you are independently permitted to use and your own GameCube Mario Party 4 disc. The inspected v0.21.0 package manifest offers GMPE01_00, GMPE01_01 and GMPP01_02: USA revisions 0/1 and Europe revision 2. A recognized Japanese or other European revision is not thereby supplied with a compatible package module. Finish upstream disc verification/import first. ISO/RVZ/WIA/GCZ input verification hashes the decoded disc stream through Nod, not arbitrary compressed-container bytes. No disc, converter, helper or game is executed here.

  2. Keep the complete selected player

    The actual official v0.21.0 Windows ZIP contains AMD64 partyboard.exe, PartyBoardOnline.exe, regional game modules and runtime resources. Its manifest binds source 2fedc7553c1aab52cef671080e04ee44da9832aa. Older README version labels and the initial release’s missing Windows/macOS packages do not describe this selected artifact. Keep the complete extracted unit; a regional module or the optional online companion is not the ordinary player.

  3. Add the normal native game

    Select partyboard.exe, use its full package directory as working directory and leave arguments empty after upstream disc setup. Review the exact intent and request Play separately. Native main enters the normal port/UI in process. Lancer PartyBoard.cmd uses start and detaches, so do not select that script. Finish setup and original selection upstream, then return to the ordinary player; do not use test-profile, headless or online-test options as normal Play.

  4. Preserve the active SDL data root

    Windows resolves the normal configuration root with SDL_GetPrefPath("MarioPartyRD", "Party Board"), normally the roaming AppData MarioPartyRD/Party Board directory. Preserve the actual returned root, preferences, memory cards, achievements, pipeline cache, imported/original disc paths and existing recovery copies. Test-profile environment overrides are test isolation, not a portable-data recommendation. Keep regional cards and online/offline preferences distinct; no save conversion, backup, restore or folder removal is performed.

  5. Check online support, permissions and update limits

    Retain project, Aurora, libco, MusyX, Dolphin AX reference and other component notices; no blanket license for Nintendo originals is inferred. Online/RetroAchievements login, credentials and external installer operations remain upstream and are not performed here. Online matching has revision-specific requirements, including USA revision 1 rather than revision 0; package availability does not prove multiplayer compatibility. Quit normally before upstream replacement, preserve data/recovery and review/relink changed bytes. No native/physical, real-save, online, Supported or managed lifecycle observation is asserted.
