Setup

  1. Choose the Windows ZIP for your processor

    Use the standard x64 ZIP for a 64-bit Intel or AMD PC. The publisher offers separate ARM64 and 32-bit x86 builds. The x64 AVX2 build requires an AVX2-capable processor. Extract the complete ZIP and keep its PAKs, locale files and maps with dunelegacy.exe.

  2. Supply your original Dune II data

    Copy the original PAK files listed by the project to %APPDATA%/dunelegacy/data, or beside the Windows executable. Keep your original copy. The ZIP supplies LEGACY.PAK, OPENSD2.PAK and GFXHD.PAK for the fork. You still need the matching original files.

  3. Find the Linux and Mac source routes

    The pinned release publishes Windows packages. Linux source is available with local build fixes required. The pinned zlib URL failed. The checked Linux build used CMake 3.31.8, the official zlib fossil archive matching the pinned SHA-512, and `-include vector` with GCC 15. Use $XDG_CONFIG_HOME/dunelegacy/data or the default ~/.config/dunelegacy/data for original PAKs. The tag has macOS source, with no Intel or Apple Silicon package from this release.

Setup notes
Preserve the player profile
Windows normally uses %APPDATA%/dunelegacy. The Linux source uses $XDG_CONFIG_HOME/dunelegacy, normally ~/.config/dunelegacy. Keep the actual profile with settings, save, mpsave, replay and any custom maps.

Limitations and evidence

  • The upstream package or your external build owns runtime replacement. Keep its profile, originals and custom maps before replacing the player.
