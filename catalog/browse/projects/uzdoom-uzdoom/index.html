Setup

  1. Use the upstream-owned player

    On Windows, extract the complete official x64 archive into a separate folder. Choose uzdoom.exe with that folder as its working directory and save launch details, then choose Play deliberately. updater.exe is the upstream runtime replacement helper, not the player to register.

  2. Choose your game data

    Use the launcher to select your own supported IWAD or compatible free game data. Keep mods and game data under the upstream documented setup. Adding launch details does not start a game; choose Play separately.

  3. Register your prepared Windows player

    Complete the upstream setup in your permitted working copy first. Select the actual uzdoom.exe and its containing folder as the working directory; keep all companions. Normally leave arguments empty. Enter separate literal arguments only when deliberately following documented options. Confirm the selected player, folder and arguments; registration does not start a game. Choose Play separately when ready.

  4. Register your Linux x86-64 AppImage

    Keep the full official AppImage in a folder outside your Portcove library. Make it executable and open it with AppImage support to finish upstream setup. The player needs glibc 2.34 or newer. Select the AppImage itself and its containing folder. Leave arguments empty for the IWAD chooser, or supply documented options as separate arguments. Confirm the selection and choose Play separately.

Setup notes
Update through upstream
UZDoom’s launcher checks for updates and can use updater.exe to replace package files. Keep that runtime ownership with upstream. Portcove leaves these external files untouched and offers no managed Update, Backup or Rollback promise for them. Before changing versions, close the game and back up your actual IWADs, mods and configured save paths. Windows normally stores uzdoom.ini under Documents/My Games/UZDoom and saves under the Windows Saved Games/UZDoom folder. Portable mode uses uzdoom_portable.ini and the local Save and Screenshots folders. Custom config/save overrides and relocated Windows user folders need their own backup. Keep the working copy recoverable; upstream update_backup is not a Portcove-verified player-data backup.
Keep your Linux or Mac files
On Linux, keep configuration in $XDG_CONFIG_HOME/uzdoom (default ~/.config/uzdoom) and saves under $XDG_DATA_HOME/games/uzdoom/savegames (default ~/.local/share/games/uzdoom/savegames). Screenshots have a separate Pictures location. On Apple Silicon with macOS 12 or newer, copy the complete UZDoom.app from the official ARM64 DMG to Applications and open it through macOS. Preserve ~/Library/Preferences/uzdoom.ini and ~/Documents/UZDoom.

Limitations and evidence

  • Portcove tracks the player you selected. On Windows, if UZDoom’s error window restarts it, the new player can keep running after Portcove reports the original process finished. Close any remaining UZDoom players before choosing Play again or updating files. Removing the registration does not confirm that restarted players have stopped and leaves every external file untouched.
  • Keep that runtime ownership with upstream. Portcove leaves these external files untouched and offers no managed Update, Backup or Rollback promise for them. Before changing versions, close the game and back up your actual IWADs, mods and configured save paths.
  • Custom config/save overrides and relocated Windows user folders need their own backup. Keep the working copy recoverable; upstream update_backup is not a Portcove-verified player-data backup.
  • Close all actual players and preserve the working copy and every actual data location before upstream changes.
  • Managed Install, Update, Backup, Rollback, migration, original authentication and external deletion are unavailable for this route.
