Setup

  1. Prepare the exact Japan PlayStation disc

    Use a complete player/components you are independently permitted to use, with your own Puyo Puyo Box Japan SLPS-03114 CUE and all referenced BIN tracks. The selected profile pins data Track 01 to 141,853,824 bytes and SHA1 ca01a98ccc5ca796df082782a6dd1adee856c064, boot executable SLPS_031.14. This is a track fingerprint, not a signature for any renamed image or another release. Replace the upstream author’s example absolute path with your own actual source in its setup UI; this guide accesses no such example path. Keep independent originals.

  2. Complete the standalone setup flow upstream

    The inspected official v.0.1.1 Windows ZIP contains AMD64 PuyoPuyoBox_Recomp.exe as the preparation host with SDK/project resources and OpenBIOS. It is not proof of a finished gameplay executable. Complete the built-in Generate & Build flow first. The selected codegen_setup.c names build-release/ and completed PuyoPuyoBox_Recompiled as its product, with generation marker SLPS_031.14_dispatch.c; setup/rebuild can quit and relaunch through a helper. Bundled OpenBIOS is the supported no-Sony-BIOS route; an independently permitted personal SCPH BIOS is separate. No disc, BIOS, helper, toolchain, compiler or game is obtained or executed here.

  3. Add the completed native game

    After upstream reports the build complete, select the actual build-release/PuyoPuyoBox_Recompiled.exe in the completed upstream product, use that complete build-release directory with its staged resources as working directory and set the runtime’s documented --no-launcher argument. Review the exact intent and request Play separately. The actual generated runtime main handles the integrated launcher and game in process. Do not attach the first-run setup host or RetComM hub and assume it represents the finished player. If the named native product is absent or generation/rebuild is still needed, finish upstream preparation before attachment; do not substitute a guessed executable.

  4. Keep your setup, game and memory-card paths

    Retain the complete upstream setup/project tree and build-release product, generated source/build metadata, staged game.toml/game_options.toml, settings.toml, bios/, disc files, mods/ and actual saves/memory-card paths. Source/runtime defaults use saves/, but existing per-slot/external card settings remain authoritative. Keep every previous product root and original CUE/BIN; rebuilds can replace the native program and restage support data. Cards, save states, netplay track/TOC identity and four-player settings have separate compatibility scope. This guide performs no import, conversion, backup, restore, migration or deletion.
