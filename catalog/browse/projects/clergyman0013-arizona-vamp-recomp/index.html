Setup

  1. Complete this implementation’s owned-input preparation upstream

    Use an independently permitted complete Arizona Vamp Recomp Windows copy and your own original-Xbox Darkwatch USA-release disc image or extracted default.xbe with matching files. This is the Clergyman0013 implementation, not Darker Edition or the older reference port. The selected game config identifies title0x43430016 and XDK5849; the Windows preparation document specifies the USA release, but an exact accepted disc revision/default.xbe digest is not established here. The host compares the XBE with its creating build’s expectedSHA1, but that generated value is not supplied by another title or this guide. Finish upstream input selection and first-start generation/compilation before attachment; no game, BIOS, extractor, compiler or helper is acquired or run by Portcove.

  2. Select the completed native player and all companions

    Select Darkwatch.exe, its complete creating writable output/package directory and no arguments for normal Play. Keep the matching generated Darkwatch.dll, assets, compiler resources, GPU/runtime dependencies and notices together. The documented source-build output is darkwatch-hle/out/build/release/Darkwatch.exe, but choose the actual completed location. Windows10/11 x64 and Direct3D12 are upstream prerequisites; Proton/macOS/Android are not qualified by this Windows route. Review the exact executable/CWD/arguments and consent, then request Play separately.

  3. Preserve upstream preparation and lifetime boundaries

    The selected pinned SDK plus title patch adds PrepareGameCode before the ordinary native window/game loop: it checks stale DLL targets, can launch/wait for compiler children with a progress window, then loads the generated DLL into the native program. Complete those setup/rebuild paths outside this attachment and retain a separate known-working copy before first prepared startup; if inputs/compiler/configuration change, startup may rebuild again. Ordinary ready-player execution stays in the native process. The SDK also supports Xbox quick-reboot handoff to another executable; actual title use is unqualified and successors are outside this attached-session promise. Close all actual players/compiler/helpers/successors before maintenance.

  4. Use permitted files and update through the project

    Project/SDK and compiler/third-party licenses apply to their own code and do not grant the original game/assets or arbitrary mods. Use only a completed copy, sources and components you are independently permitted to use. Upstream/user owns generation, preparation, updates, runtime replacement and recovery. Keep previous complete runtime/data separately, maintain it upstream, then review/relink changed selected bytes. Removing registration preserves every external file; no Core builder, external update/backup/rollback/migration, save conversion or deletion is offered.
