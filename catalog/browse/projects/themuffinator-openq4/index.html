Setup

  1. Use your own PC Quake 4 installation

    Use the official v0.13.2 Windows x64 package and a legitimate supported PC Quake 4 installation, such as Steam or GOG. This is the PC engine route, not the Xbox 360 recompilation or a standalone replacement for original assets. Keep all selected package/components you are independently permitted to use and the original installation.

  2. Keep the complete client and game modules

    Retain openQ4-client_x64.exe, OpenAL/renderer libraries, baseoq4/ with its SP/MP game modules and runtime packages, docs and notices together. The separate openQ4-ded_x64.exe is a server, not normal Play. Retail game assets remain under the original installation’s q4base/; do not copy them into baseoq4/. The selected player route uses OpenGL by default; experimental Vulkan, Windows ARM64, Linux/Deck and macOS claims remain separate, unobserved qualifications.

  3. Attach the native client with its retail root

    Select openQ4-client_x64.exe, use its complete extracted package root as working directory, and set +set fs_basepath "the actual PC Quake 4 root containing q4base". Review the exact path and intent and choose Play when ready. Point at the root, not q4base/ or baseoq4/. Retain any already chosen supported fs_savepath or mod configuration rather than selecting a new profile. Quit the client normally before ending the session; developer, replay and dedicated-server modes do not replace ordinary Play.

  4. Preserve the actual openQ4 save root and compatibility

    The selected Windows source normally resolves Known LocalAppData/openQ4, with environment/Saved Games fallbacks; +set fs_savepath can select an existing explicit root. Keep the actual resolved root, configs, saves/screenshots, logs, mods, cache and recovery, plus legacy/stock Quake 4 saves separately. The current policy writes v3 and gates an exact wire ABI, verified build floor and integrity; it rejects v2, newer payloads and unsupported ABI tuples. Format eligibility is not runtime certification, and stock/old/cross-platform saves are not automatically compatible. No save conversion, restore, merge or deletion is performed.

  5. Keep distinct licenses and upstream replacement

    Engine code is GPLv3 with retained Doom 3/Doom 3 BFG notices and accompanying Additional Terms. The openQ4-game libraries are Quake 4 SDK-derived and retain the SDK EULA; original Quake 4 assets have separate ownership. Retain all accompanying terms; the provenance inventory is an engineering record, not a blanket permission or compatibility conclusion. Upstream/player owns runtime replacement and recovery: finish updates outside a session, preserve data and review/relink changed bytes. No campaign, physical controller, multiplayer, installed/native, Supported or managed install/update/rollback/backup/deletion acceptance is asserted.

Limitations and evidence

  • Select the native x64 client and point fs_basepath at the PC Quake 4 root. Keep q4base and baseoq4 separate; preserve the actual save root and do not infer stock, legacy or cross-platform save compatibility.
