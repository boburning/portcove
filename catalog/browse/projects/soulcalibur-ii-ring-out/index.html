Setup

  1. Finish upstream preparation first

    Use your own permitted Soulcalibur II USA GRSEAF revision 0 disc and complete the supported Ring Out preparation outside Portcove. Establish a working prepared copy first. Keep the original, extracted game and generated module private; Portcove does not extract, compile or authenticate them.

  2. Choose the direct runtime

    Select bin/moderngekko-run.exe inside the prepared Ring Out folder, with the complete package root as the working directory. Do not select RingOut.exe, RingOut.ps1, setup.ps1, a compiler or tool mode. RingOut.exe can invoke preparation when game/module files are missing.

  3. Bind your exact data and module paths

    Use six separate literal argument tokens: --user-dir, the absolute path to this copy's userdata directory, --game, its absolute game directory, --module, and its absolute bin/gGRSEAF_recomp.dll path. Preserve spaces within each path token. Replace paths with your actual prepared locations; do not enter placeholders or --extract. The generated DLL is executable code and must be part of your permitted trusted prepared copy.

  4. Add the game, then choose Play

    Review the program, start folder and all six launch arguments. Add it to Portcove, then choose Play. If you move this copy, review every changed path before playing again.

Setup notes
Preserve the complete copy and keep one update owner
Keep game, bin including the generated module, art, module-src, work, userdata and every actual custom location together. Preserve settings, memory cards, states, screenshots, logs, replays, shaders, textures, mods and unknown files. Upstream and the player own preparation, repair and replacement.

Limitations and evidence

  • Use a prepared copy you have permission to use. The engine’s license does not give you rights to original game files or generated code. Portcove checks the selected launch details. Check the origin of your disc, package and generated DLL yourself.
  • Explicit --user-dir avoids an unintended shared default profile; without it the runtime can use LOCALAPPDATA/moderngekko, an XDG/HOME profile or a working-directory fallback depending on its build. Explicit --game and --module avoid default-game.txt and module discovery. Keep your actual prior profiles and custom data paths; changing coordinates does not migrate them or prove state compatibility.
  • Player startup creates and writes profile directories and settings; diagnostic, replay, texture/mod and configured external paths remain player-owned. Registration provides no sandbox or guarantee that upstream retains every file. Managed acquisition, Install, Update, Backup, Rollback, migration and external deletion are unoffered. Gameplay, save/load, netplay and other platforms remain unqualified.
  • The reviewed v1.7 publication is distinct from historical v1.6.1 assets whose bytes changed under one name. It does not repair that old integrity gap. Old package CREDITS/README version and source-bundle instructions are stale; preserve notices and follow the matching upstream source. No binary/source attestation or new distribution right is inferred.
  • Close all actual players and preserve originals/data before upstream changes. Removing the registration removes only Portcove metadata and preserves external files.
