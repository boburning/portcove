Setup

  1. Copy your own classic Quake data beside the managed player

    Open the managed runtime folder and copy the id1 folder containing pak0.pak and pak1.pak from your own classic Quake installation beside ironwail.exe before Play. Keep the original copy in its existing location. Portcove starts this copy from that local base folder and disables the online add-on server.

  2. Prepare the existing Ironwail copy

    Use a complete permitted Windows copy with its matching libraries. Finish classic or rerelease setup with your own compatible Quake data, then start and quit it. The ordinary prepared launch uses no arguments. Keep the actual working folder and any literal arguments your prepared copy already needs for store, expansion, mod or custom base-directory choices.

  3. Preserve old and new migration roots before changes

    Standalone copies may use their base/game folders; Windows store-selected copies can use actual Saved Games/Ironwail/original or Saved Games/Ironwail/rerelease. Keep the actual known-folder location, old Nightdive Studios/Quake tree, standalone/store/custom roots, ironwail.cfg and all saves/autosaves/screenshots/demos/mod/addon files and unknowns. Startup migration can rename episode directories and move recognized files, writing a new config and removing its old copy; it is not a read-only import. Finish any chosen upstream migration first and keep the full pre-migration tree recoverable. No cross-version mod/save/replay roundtrip is certified.

  4. Run the upstream Linux build

    For a separately prepared Linux copy, unpack the official x64 tarball and keep ironwail and ironwail.pak together. Use glibc 2.29 or newer, OpenGL 4.3, SDL2, libcurl, libvorbisfile and libmpg123. Back up id1 beside the player and any separate .ironwail profile your copy uses. Keep your original Quake files separately. Store-selected profiles and migration files stay with your separately prepared copy.

  5. Select the prepared player

    Select ironwail.exe and use its containing folder as the working directory. Leave arguments empty. Keep the complete independently permitted runtime and finish the title-specific preparation before Play.

Setup notes
Registration ownership and removal
Portcove records the selected executable, working folder and literal arguments after review. Play is separate and only the selected process is supervised. You and upstream own replacement and updates; relink changed executable bytes after reviewing them. Removing this registration preserves every external file. Managed installation, backup, rollback, migration and deletion are not offered for this external copy.
Player-data ownership
You and upstream own the external copy's data: the actual prepared Quake directory and any store, rerelease, add-on or custom profile directories. Back up these locations separately; registration does not migrate or certify their compatibility.
Managed runtime ownership
Portcove installs and replaces its separate official runtime using the declared release rules. Existing external registrations retain their files and user/upstream ownership. Runtime rollback carries current declared data; it does not rewind saves or establish older-runtime compatibility. Gameplay and populated-save compatibility remain separate qualification. Portcove preserves only these declared local inputs during replacement and backup: id1, history.txt. Its backup does not include external profiles.

Limitations and evidence

  • Use only a copy and content you are already permitted to use. These instructions do not establish permission for the original game or other components, or confirm the resulting game files.
  • These instructions do not confirm gameplay, saving, mods, network play, physical controls or behavior on other platforms.
  • Before updating the game, keep a recoverable copy of its working files and every location containing saved data. Another game folder may use the same profile.
  • For store discovery, rerelease migration, expansions, mods or custom base directories, use a separately prepared copy. The managed route preserves id1 and console history only. Gameplay and real save compatibility across versions remain unverified.
