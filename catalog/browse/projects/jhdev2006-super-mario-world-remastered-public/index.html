Setup

  1. Keep this archived parent distinct

    Use an independently permitted, already completed Windows Godot game export of JHDev2006 Super Mario World Remastered, keeping its native game executable and any companion .pck/data together. The upstream project is archived and abandoned. This is the parent project, not BTFighter Remastered Plus, snesrev/smw, or another similarly named implementation; their binaries and qualification are not interchangeable.

  2. Keep artwork and original-file permissions separate

    Fresh package acquisition remains conditional on permission for its bundled original sprites and music. The root ISC code license and owning a Super Mario World ROM do not establish that component grant. This guide only links a completed copy you are independently permitted to use; it does not obtain the game, rebuild or extract Nintendo assets, or bypass that condition.

  3. Use the exact upstream ROM gate

    Place your own recognized SNES ROM at baserom.sfc in the SuperMarioWorldRemastered user-data folder shown by the ROM screen. The selected checker accepts seven full-file hashes; the explicitly labelled USA1.0 image has SHA-256 0838e531fe22c077528febe14cb3ff7c492f1f5fa8de354192bdff7137c27f5b. Other exact Japanese, European and headered variants are listed upstream, while one accepted hash has no established edition label. The gate checks the file hash; it does not extract or license the already bundled artwork/music.

  4. Back up the actual shared profile before startup

    With this game and Remastered Plus closed, separately back up the complete old and new runtime folders and the actual SuperMarioWorldRemastered Godot profile, normally %APPDATA%/SuperMarioWorldRemastered on Windows. Preserve baserom.sfc, settings.cfg, Saves/ with campaign subfolders, modlist.json and every referenced external resource pack. Startup creates settings when missing and verifies/rewrites existing settings; save creation/replacement and the in-game delete action can overwrite or remove a campaign slot. Keep recovery copies outside the active profile.

  5. Keep parent and fork data recoverable

    The independently checked parent configuration and the existing Remastered Plus record select the same SuperMarioWorldRemastered custom user directory. Do not run or switch them against an unbacked-up shared profile. No save, mod, campaign or settings compatibility between forks or versions, and no automatic profile migration, is qualified.

  6. Link the completed game export

    Choose the native game .exe in your completed Windows export, use its containing game folder as the working directory, and leave arguments empty. The exact packaged filename and release-ZIP layout have not been established here; do not select a Godot editor, console/helper wrapper or installer. The selected project starts the ROM-check scene and transitions within its Godot process; its title-screen Quit ends that process.

  7. Keep updates and external data upstream

    Close the game completely before replacing, relinking or removing an external copy. Upstream and the user own the runtime, companion files, custom packs and all player data. Portcove only links the selected existing executable and does not install, update, roll back, move or delete it. An archived release is not a promise of future maintenance or live online-service availability.
