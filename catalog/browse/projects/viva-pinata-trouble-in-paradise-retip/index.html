Setup

  1. Complete the own-retail-disc ReTiP setup upstream

    Use your legally obtained retail Viva Piñata: Trouble in Paradise Xbox 360 disc ISO, retaining the canonical world-region source contract. Follow upstream’s normal ISO-selection/extraction flow outside Portcove. The public release documentation does not establish that every disc revision or another game is compatible. Core does not extract, build or authenticate original data. The standalone GitHub build is documented as the same game build without GameJolt integration; select the already prepared copy you intend to keep.

  2. Select the native standalone player and keep the whole package

    The reviewed 1.14.0 Windows AMD64 package contains retip.exe, retip.toml, the retip directory, retip_pipelines.bin, rex runtime/DXC DLLs and crash reporter companions. Attach the completed retip.exe with its established package working directory. Public title code uses an in-process ReXApp/windowed-app entry and opens the prepared game through its launch menu; the customized backend/native renderer is not public, so this is not a full backend or companion-process certification. No private backend access, build, GameJolt login or compiler execution is requested.

  3. Add the completed native player, then choose Play

    Finish setup with the project’s tools, then select the Windows game executable, working folder and supported launch arguments in Portcove. Review and agree to those details, then choose Play separately. Keep the complete package together and close the game and companion programs before changing files. You manage this external copy; Portcove does not replace it or back up, convert, migrate or delete its data. Removing its registration leaves those files in place. Source review and automated registration checks do not confirm an installed game session, successful forced exit, gameplay or save compatibility.

  4. Preserve the complete upstream-owned copy and actual data roots

    Keep the whole creating package, retail ISO, extracted game_data_root, default.xex, retip.toml, mods, textures, caches, logs, captures, saves/settings and every actual SDK/account/custom root belonging to that copy. The packaged TOML allows game-relative writes and records enabled mods; it does not establish the closed backend’s default save/profile directory. Do not infer a default path or Core backup/delete rights from another public ReXGlue version. Locate and retain the effective roots configured by your already prepared copy before changes. Upstream owns compatible replacement, data preparation and any mod/update integration; avoid competing updaters for one copy, preserve old runtime/data and review/relink a changed selected executable. Optional networking, mod downloads, credential use and crash uploads are not enabled or qualified by attachment.
