Setup

  1. Get the upstream setup for your platform

    Open the v0.1.7-alpha release linked below and pick the Windows x64 setup EXE or Linux x86-64 AppImage. Check the file against its SHA-256 sidecar before opening it. Both paths need a clean big-endian USA .z64 from your own game. Setup checks SHA-256 057232ef7618e25f5645df50d3cd45f08cb5a2cccb3e2fdf48faa8755c4ddb1a. Keep that original available for later launches.

  2. Build the playable copy once

    On Windows, open the upstream setup, select the matching ROM and choose a folder for the generated player. On Linux, install the development dependencies from the build guide, then open the upstream self-building AppImage, select the ROM and choose where to save the playable AppImage. First setup needs Internet access and builds locally. On later Windows launches open 40-Winks-PC-Port.exe from the output folder. On Linux reopen the original AppImage to start the locally built player.

Setup notes
Keep Windows settings and Controller Pak saves
Preserve %LOCALAPPDATA%\40-winks-pc-port when changing the player. The separate %LOCALAPPDATA%\40WinksBuild stores build tools and generated files.
Linux build requirements and launcher paths
Follow the tagged build guide for Git, Python, CMake, a C++20 compiler, SDL2 development files, Vulkan and the runtime dependencies. The builder tracks the selected ROM and playable AppImage under the 40-winks-pc-port directory in XDG_CONFIG_HOME. The first-run launcher suggests ~/Applications/40-Winks-Recompiled-x86_64.AppImage for the playable copy. Its build cache is under XDG_CACHE_HOME. Preserve the game data under XDG_DATA_HOME/40-winks-pc-port (normally ~/.local/share/40-winks-pc-port), or the data directory you explicitly chose.

Limitations and evidence

  • The Windows setup is unsigned. Follow your usual executable trust settings.
  • Keep the original outside the build and player folders. Replacement builds and player data are managed through upstream.
