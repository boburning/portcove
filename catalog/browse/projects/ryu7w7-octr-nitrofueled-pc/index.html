Crash Team Racing Nitro-Fueled (OCTR: Online CTR Nitro-Fueled PC)

An online Crash Team Racing Nitro-Fueled fork derived from GetLostIn’s Windows fork of SacredFire. The project reports menus, races, audio, controllers, saves and community online; complete campaign, online and GPU coverage remain unconfirmed. Its inherited and maintained online changes do not automatically establish a separate canonical implementation. Windows 10/11 ZIP and Linux AppImage routes use a PS4 compatibility layer with direct x86-64 execution. Supply your own PS4 CUSA13795 v1.21 dump. Exact accepted hashes and BIOS/firmware needs are unconfirmed. You and the project manage setup and updates; Portcove has not qualified a release package or confirmed gameplay.

Setup

  1. Finish preparation with your own exact PS4 edition

    Use your own already decrypted Crash Team Racing: Nitro-Fueled PS4 USA CUSA13795 base game and v1.21 update folders. Complete upstream Prepare game, or select an already prepared CUSA13795-1.21 folder. The supported extracted layouts include ordinary eboot.bin/sce_module/sce_sys and the documented Image0/Sc0 representation. A raw encrypted PKG, other region such as CUSA14876, another version or an undecrypted executable is not equivalent. This guide supplies no game, account, decryption, key or dump tooling.

  2. Keep the complete selected Windows portable package

    Use CTR-NitroFueled-PC-portable-v0.7.5-windows.zip with the whole CTR-NitroFueled-PC-portable folder retained: its native launcher, bin/sacredfire.exe, Python, run.py, scripts, resources, libraries and notices. Windows 10 1903+ or Windows 11 x64, Direct3D 11 for the launcher and Vulkan 1.3-capable graphics/drivers for the game are documented. This runs original x86-64 PS4 code with replacement system/GPU services; the description is not proof of an entirely native reimplementation. Preserve GPL-2.0-or-later, separate components/fonts/graphics-library and original-game rights.

  3. Add the normal native Windows launcher

    Select the package’s Crash™ Team Racing Nitro-Fueled.exe, use its complete containing portable root as working directory and leave arguments empty. Review the selected program, folder and arguments, then choose Play when ready and use its ordinary Play control. The launcher supplies the game directory, settings and environment to bundled Python/run.py, which starts the actual runtime. Do not select python.exe, a BAT file, a diagnostic utility or context-free bin/sacredfire.exe as an equivalent route. Preserve existing settings rather than enabling new patches, DLC or online features during registration.

  4. Preserve all active game and user-data roots

    Keep the full portable root, especially user/ with saves, trophies and shader caches, bbport.ini, launcher.ini, backups/, optional dlc/, mods/patches and logs as present. Retain the separate original base/update folders and prepared merged-game folder; upstream preparation can use hard links, so do not treat the merged folder as an independent backup. Preserve existing BB_GAME_DIR, BB_USER_DIR, BB_DATA_DIR, BB_CONFIG and other path overrides. Portcove does not merge updates, import PS4 saves, move roots, supply trophy keys or convert data.

  5. Leave services, updates and recovery upstream

    The native launcher supervises its own helpers, but Portcove observes only the selected program; its activity is not evidence that all games/helpers stopped. Quit actual processes before upstream replacement, rebuild, save restore or recovery, preserve complete previous application/data and review/select the current launcher after changes. Online accounts/servers, mods, experimental renderers, DLC and native/gameplay/controller/save acceptance remain upstream or separately observed outcomes. Reference removal preserves external files; managed installation/update/backup/rollback, full-session tracking and Supported qualification are unavailable.
