Setup

  1. Prepare your own Gold Edition data upstream

    Use your legally obtained Naughty Bear: Gold Edition Xbox 360 data. The inspected release_v1.5.1 Windows package’s own README supports a standalone setup: extract the complete disc contents directly into assets beside restuff.exe so assets/Default.xex exists. Keep the files together rather than inside an extra nested folder. Core does not acquire, extract or authenticate the game. The older repository README also describes Goopie extraction/installation; a completed standalone copy need not run through that general launcher.

  2. Use the actual standalone Windows player

    Keep restuff.exe, restuff.toml, all SDK/GPU/shader DLLs and packaged data together. Use restuff.exe with its established executable-directory working coordinates. prewarm_shaders.bat is an optional GPU-cache helper, not the normal game entry; do not attach or run it through this guide. Normal first launch performs its own shader/pipeline warming, so prior helper execution is not an added requirement.

  3. Review launch details, then choose Play

    Select the intended completed native Windows player, its established working directory and supported literal arguments. Review the launch details, add the game, then choose Play. Keep the whole creating runtime and data usable. This is non-owning attachment: upstream/player owns source preparation, engine replacement and recovery. Core provides no external update, backup, rollback, conversion, migration or deletion. Removing the registration preserves every external file.

  4. Preserve all source, profile, cache and customization roots

    Retain the complete creating runtime, own extracted assets/Default.xex tree, restuff.toml, texture_mods, optional texture_dump/glsl_dump, shader_spv.bin, pipeline_cache.bin, pipeline_prewarm.bin and their temporary/build-ID companions. The selected public SDK source defaults Windows user data to the redirected Documents/restuff folder and cache beneath it; user_data_root, cache_root, update_data_root and metadata_root can select other effective roots. If Windows known-folder resolution fails, preserve any actual relative fallback location too. Keep existing original, game_data_root and all custom/environment paths. Normal SDK config is executable-local restuff.toml; diagnostic paths include its configured restuff_dbg.log and the source’s /tmp/restuff_drive location or CWD restuff_mergelog fallback, with optional per-process names. Data/paths from another SDK version are not imputed to your copy. Preserve every effective root and old runtime before deliberate compatible upstream replacement; review package defaults instead of assuming extraction over old settings is lossless. Core does not migrate saves or claim that a previous version can read newer profiles. GPU cache/source observations do not qualify native rendering, driver behavior or actual progress.

Setup notes
Download the standalone Windows player
Extract the v1.5.1 Windows ZIP and keep its DLLs and configuration beside restuff.exe. Prepare your owned Gold Edition disc files once in assets as described above. Run restuff.exe again from the same folder to reuse that copy. Keep the actual profile and cache roots described above when replacing it.
Download the standalone Linux player
Extract the v1.5.1 Linux x64 tarball. Keep restuff, restuff.toml and its packaged libraries together. Place your owned Naughty Bear: Gold Edition disc files in the package’s assets folder and start ./restuff from the extracted folder. The Windows registration and profile instructions above apply to Windows.

Limitations and evidence
