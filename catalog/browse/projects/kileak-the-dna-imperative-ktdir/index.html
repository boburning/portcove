Setup

  1. Complete the owned-input KTDIR setup upstream

    Use your own USA Kileak: The DNA Imperative PlayStation disc, SCUS-94102, as its Redump-style CUE and every referenced BIN. The official Windows setup ZIP is an owned-input build kit: it does not ship a ready game, original disc, extracted game executable or generated game code. Upstream’s own wizard selects the matching CUE and uses OpenBIOS by default, then generates/rebuilds locally with its supported Python/toolchain. Complete that process outside Portcove. This guide runs no compiler/helper, imports no original and grants no retail BIOS rights.

  2. Keep the kit and matching configuration together

    Keep the complete KTDIR-setup-0.1.1-windows-x64.zip setup kit with your completed build and original inputs. The published kit has updated digital controller settings under the same version label; the older tag-source archive has different settings. Preserve the working configuration instead of replacing it from that older archive.

  3. Attach the completed product rather than the setup host

    After the upstream build, use the supported completed product under build-release/Kileak__The_DNA_Imperative_Recompiled.exe, with the established kit/project root as working directory and supported --launcher literal argument, preserving any actual source selections. Upstream’s root setup executable forwards there and exits on Windows; attaching that setup host is not equivalent to tracking the completed player. Keep Generate/Rebuild and SDK/toolchain changes as deliberate upstream maintenance outside the active attached session; stop the actual player/companions first, preserve data and review/relink changed selected bytes.

  4. Review launch details, then choose Play

    Select the intended completed native Windows player, its established working directory and supported literal arguments. Review and consent to those launch details, then choose Play separately. Keep the whole creating runtime and data usable. This is non-owning attachment: upstream/player owns source preparation, engine replacement and recovery. Core provides no external update, backup, rollback, conversion, migration or deletion. Removing the registration preserves every external file.

  5. Preserve the whole kit, built runtime and effective player data

    Keep both the complete source/setup kit and build-release product, including disc, generated source, framework/UI/BIOS/toolchain resources, mods, configs and every external/custom path. Upstream tools generate the game locally; Portcove does not build it or manage generated-code caches. The packaged default is memcard_dir=saves; settings or explicit card paths can override it. Preserve actual memory cards, states, settings.toml, game.toml/game_options.toml, input.ini/keybinds.ini, diagnostics/caches, and every creating layout. Relative or generated paths can depend on the established executable/project coordinates; Core does not relocate or rewrite them. Retain the old runtime before updates, rollback or moving a copy; no cross-version save/state compatibility, controller/device observation or title gameplay result is supplied.
