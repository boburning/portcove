Setup

  1. Prepare the Xbox USA game upstream

    Use a complete copy and components you are independently permitted to use. Finish upstream preparation outside Portcove, keep independent originals and recovery copies. No original, helper, compiler or game is obtained or executed by this guide. Use your own The Lord of the Rings: The Two Towers original Xbox USA data. Finish upstream disc/folder preparation and settings, keep default.xbe with the complete matching data in game_files/ or the already configured game directory, and retain independent originals. Other regions, console editions and Athelas embedded Two Towers are not interchangeable by title.

  2. Keep the complete native package

    The inspected official 1.9.9 Windows ZIP contains AMD64 twotowers_recomp.exe, the separate The Two Towers Recompiled.exe UI and matching runtime/resources. Keep the complete package. The native player already contains the translated program; the source-build route still translates/compiles from an owner’s original separately. Do not select the setup UI, texture compiler, script or original Xbox executable as the attached game.

  3. Attach direct native play

    Select twotowers_recomp.exe, set the complete extracted package folder as working directory and leave arguments empty. Review and consent to the selected launch details, then choose Play separately. Its native entry reads the existing paths/settings and runs the game in process. The source uses [Paths] game_dir in twotowers_recomp.ini or the package-local game_files default; an already established game-dir environment override wins. Preserve it rather than silently pointing at another copy. Finish missing setup outside the attached attempt.

  4. Preserve player data and old settings

    Keep saves/ beside the native player, twotowers_recomp.ini, its .ini.old retained by upstream’s legacy settings rewrite, game_files/, screenshots, logs, achievements, mods, texture caches and all configured external game/data paths. Upstream can rewrite an older configuration while carrying selected fields forward; keep independent originals and both versions. This guide performs no migration, restore, backup or deletion and claims no cross-build save compatibility.

  5. Separate ancestry, optional packs and notices

    The selected Gumpolas 1.9.9 route uses sp00nz/xboxrecomp and separately licensed The128ReBits contributions; the compared Athelas 1.8.0 Two Towers component credits Shagg and TGP482/XboxXBE-Recomp. They are independently maintained packages and launch/data contracts for the same Xbox title, not interchangeable binaries or profiles. Gumpolas uses direct twotowers_recomp.exe with twotowers_recomp.ini, game_files and saves; Athelas selects TT-Xbox/TwoTowers.exe through its own launcher and supplied config/save paths. Shared game/toolkit ancestry does not establish source independence, compatible saves or transferred qualification. Keep the project license, CONTRIBUTION_NOTICES, The128ReBits notice, XboxRecomp/MCPX and all font/component notices. Source credits and independently maintained package identity do not establish another port’s qualification. Grants for port/runtime code do not license original game material, optional GameCube HD packs, music or mods. Use only components you are independently permitted to use. Texture generation, optional Ultra content and co-op/mod changes remain upstream work; no separate pack is downloaded or executed here.

  6. Maintain the external player

    Quit the actual game normally before upstream replacement or data operations; forced termination is not a save-flush guarantee. Review/relink changed executable bytes. Source, package and upstream playability reports do not establish native gameplay, complete-game, save/reload, installed-app or Supported acceptance. Removing registration preserves external files; managed install/update/rollback/backup/removal remain unavailable. Upstream unlocked-frame-rate, versus and alpha co-op reports are not Portcove observations; preserve the documented compatibility limits instead of treating a package as complete-game acceptance.
