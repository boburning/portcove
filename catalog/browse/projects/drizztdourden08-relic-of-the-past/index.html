Setup

  1. Use the complete Windows desktop distribution

    Keep the full rotp-windows-directory.zip v0.21.2 layout. The ordinary entry is the root Relic of the Past.exe alongside Update.exe and current/. The current directory contains replaceable application files; do not select Update.exe as the game or move a single executable away from its companions. This is an Electron desktop frontend with a WebAssembly zelda3 core, not a wholly native recompiled game. Project MIT, zelda3 and other component/font/MSU terms remain separate from original-game rights.

  2. Import your own supported game data upstream

    In the application use the title-bar Data → ROMs → Import ROM route with your own US NTSC A Link to the Past SNES .sfc/.smc, then create a profile and select its ROM/language. EU and Japanese originals are separate language-import sources, not the gameplay base. Upstream copies imported originals and extracts zelda3_assets.dat into its data directory. The selected base-ROM specification accepts unknown hashes, so import acceptance alone is not proof of an exact original-file fingerprint. Portcove supplies no ROM, external ROM URL, asset extraction or source validation.

  3. Add the ordinary application entry

    Select the root Relic of the Past.exe, set the complete extracted distribution root as working directory and leave arguments empty. Review the selected program, folder and arguments, then choose Play when ready and use the existing upstream profile. Keep the root launcher and current application together. It can hand off to another process: Portcove observes the selected program only, so a finished activity does not prove the game or Electron helpers have closed.

  4. Preserve the actual data root and every profile

    The normal Windows data folder is %APPDATA%/relic-of-the-past. Existing portable mode uses data/ beside Update.exe, outside current/; preserve that existing choice and all its contents. Keep profiles/<profile>/saves with all save kinds, settings/controls, imported ROMs, extracted assets, languages, MSU packs and related user files. Do not create an empty data folder just to register the player: that changes the active data root and can hide existing profiles. Do not place user data in current/, which upstream replaces during updates, or assume switching portable mode migrates anything.

  5. Leave updates, profile changes and recovery upstream

    Quit the actual game and all helpers before upstream update, replacement or recovery, even after Portcove’s activity ends. Use upstream’s own profile and data tools deliberately; profile deletion is destructive and is not part of adding or removing the library reference. Keep prior complete application/data copies and review the selected entry after changes. Portcove removes only its reference and offers no managed installation/update, ROM or save conversion, backup, rollback, full-session tracking or Supported qualification. No personal gameplay, controller or real-save acceptance is claimed.
