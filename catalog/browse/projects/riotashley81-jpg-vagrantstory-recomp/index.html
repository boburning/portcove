Vagrant Story (Vagrant Story Recompiled)

A hybrid Vagrant Story port: its ROM-free Windows player reads your own USA SLUS-01040 PlayStation disc, then compiles battle, menu and title code in the background with bundled GCC. An interpreter/TinyCC handles remaining code, so full-game native coverage is unconfirmed. The separate MSVC source build is a development route. The project manages generated code and caches. Other player platforms, exact accepted revision/hashes and BIOS/firmware requirements are unconfirmed. Portcove has not confirmed setup or gameplay.

Setup

  1. Use the exact USA PlayStation original

    Use your own Vagrant Story USA SLUS-01040 CUE/BIN disc. The selected game.toml identifies data Track 01 by size 750643152 bytes and SHA1 38c63db6c49a06b91d87cd5a4e31b1ec68fe212c, boot SLUS_010.40; this is not a whole-CUE or all-region fingerprint. Finish original selection and settings in the upstream integrated launcher first.

  2. Keep the complete hybrid Windows package

    Use the official v0.1.11 Windows x64 package as one complete unit, including VagrantStory_Recompiled.exe, game.toml, bios/, assets/, mods/, licenses/ and overlay_toolchain/. The player reads original code/data from the user’s disc and locally compiles battle/menu/title overlays with bundled gcc in the background, retaining cache/; other code still uses the interpreter and TinyCC. First preparation can take an hour or more and resume later. Do not call this fully static coverage, impose a short first-use gameplay deadline or substitute an interpreter-only demo for a prepared route.

  3. Attach the integrated native player

    Select VagrantStory_Recompiled.exe, use its full player directory as working directory and leave arguments empty to retain the ordinary integrated launcher and settings. Review the selected program, working folder and arguments and choose Play when ready. Its selected native runtime hosts the frontend/game in process. Do not select codegen setup, overlay_toolchain tools, profiling/headless modes or another Vagrant Story implementation. Finish upstream preparation/maintenance and close the actual game normally.

  4. Preserve executable-relative cards and generated cache

    The selected Windows runtime resolves relative settings and data from its actual executable directory. Keep the complete writable root, settings.toml, disc.cfg/bios.cfg where present, game.toml, input/bindings, mods, cache/ and all actual card paths. game.toml configures saves/, normally card1.mcd and card2.mcd, with existing explicit slot/directory overrides retained. Preserve durable cards separately from states and original disc/legacy copies. Do not clear slot paths through a new --memcard-dir argument, merge roots or discard generated overlay work. No migration, card restore or deletion is performed.

  5. Retain exact component and maintenance terms

    The selected psxrecomp revision uses PolyForm Noncommercial 1.0.0; the exact recomp-ui revision is MIT. Keep those distinct terms plus OpenBIOS, bundled GCC/Binutils/mingw-w64, TinyCC, font and other notices; a project or UI license does not replace noncommercial restrictions or license original assets. Only use components you are independently permitted to use. Upstream/player owns updates and locally generated output: quit normally, keep populated cards/cache/recovery and review/relink changed bytes. No full playthrough, physical controller, real-save restore, native/installed, Supported or managed lifecycle acceptance is asserted.
