Setup

  1. Set up OpenTTD’s base graphics

    Start the official OpenTTD player. When it asks for base graphics, choose the download option to install free OpenGFX. If you use your own original Transport Tycoon Deluxe graphics, follow the upstream setup guide. Add the optional OpenSFX sound and OpenMSX music through Online Content. On Windows, select native openttd.exe and keep its package resources. Keep OpenTTD and JGR Patch Pack in separate profiles.

  2. Retain the actual personal or portable directories

    Keep the creating working directory and established literal arguments, including an existing -c config selection. Do not create an executable-side openttd.cfg merely to register. Windows normally searches the current account’s Documents/OpenTTD personal directory as well as package/working locations; an existing portable/config choice changes the selected root. Preserve every actual config and personal directory, openttd.cfg, private.cfg/secrets.cfg, saves, scenarios, heightmaps, orders, NewGRFs, scripts, screenshots, content_download, custom files and unknowns. Keep secrets private. Other OpenTTD variants can share those paths; a separate runtime folder does not isolate them.

  3. Keep compatible versions and content recoverable

    Before changing an engine, close all clients using the actual shared profile, retain its old creating runtime, configuration, saves and exact content sets, and follow upstream’s compatibility guidance. Do not assume JGR/upstream, multiplayer, NewGRF or backward-save compatibility. This route does not freeze an arbitrary CDN version or turn a locally computed download hash into a publisher-approved identity; upstream/player remains the runtime replacement owner.

  4. Check the working copy before registration

    Finish setup with the project’s tools, then start and quit the copy you intend to add. Keep its game executable, working folder and supported launch arguments. Review those details in Portcove and agree to launch them, then choose Play separately. Adding a copy does not confirm its game files or save compatibility.

  5. Keep updates and removal under the existing owner

    Close every running copy of the game before changing files. Keep the working game version and every data and profile folder recoverable. Update it with the project’s tools, then review and select the changed executable in Portcove before choosing Play. You manage setup, updates, file changes, data migration and recovery. Portcove monitors the process you selected; it does not prevent other copies from running or restrict the game’s file access. Removing the registration leaves external files in place. This route does not offer Portcove downloads, setup, updates, backups, rollback, data migration or external-file deletion.

Setup notes
Get the official OpenTTD package for your host
Use the upstream downloads page and its published SHA-256. The stable channel has a Linux x86-64 generic tar.xz, an Intel and Apple Silicon universal Mac DMG or ZIP, and Windows ZIPs or installers for x86-64 and ARM64. The reviewed Linux player needs glibc 2.28 and libstdc++ with GLIBCXX_3.4.22. Use your system archive tool and keep the entire extracted folder or OpenTTD.app. Open the official executable or app directly and complete its base-graphics setup. On Mac, the native program is inside OpenTTD.app at Contents/MacOS/openttd. For CLI registration, run external select-preview with absolute program and --working-directory paths; pass each existing literal argument with --arg=VALUE. Repeat those details with external select and pass the returned preview hash to --expected-preview. Choose Play separately with portcove exec transport-tycoon-deluxe-openttd-upstream. Keep the established config and save locations.
Use the Flatpak on Linux x64 or ARM64
Install org.openttd.OpenTTD from Flathub on x86-64 or ARM64. The Flatpak includes the free OpenGFX graphics, OpenSFX sound and OpenMSX music. Start and update it through Flatpak. Keep the app profile in ~/.var/app/org.openttd.OpenTTD backed up with your saves and content.
Keep the actual OpenTTD config and save roots
The Linux generic build normally uses ~/.config/openttd and ~/.local/share/openttd, or the corresponding XDG locations. An older ~/.openttd profile or an existing -c config choice can change where it writes. On Mac preserve ~/Library/Application Support/OpenTTD and any custom location. Keep openttd.cfg, private.cfg, secrets.cfg and all actual saves and content private and backed up. These upstream copies stay under player ownership.

Limitations and evidence

  • Use only a copy and content you are already permitted to use. Engine licensing does not grant rights to original game assets, music, mods or bundled components.
  • Before updating the game, keep a copy of its working files and every location containing saved data. Choosing a different executable does not give it a separate profile.
