Setup

  1. Put your own European Dune II v1.07 PAKs in the personal data folder before Play

    Follow upstream’s FILELIST.TXT. On Windows, place the original files in Dune Dynasty/data under your Windows roaming app-data folder, normally %APPDATA%. On Linux, place them in dunedynasty/data under your XDG data location, normally ~/.local/share. Settings and saves use the XDG config location, normally ~/.config/dunedynasty. Keep originals and dunedynasty.cfg outside the managed game folder.

  2. Finish setup before registering a prepared copy

    Use a permitted complete Windows Dune Dynasty copy with your own European Dune II 1.07 PAK files, following upstream’s FILELIST.TXT. Keep those data files in the prepared data directory or the actual personal Dune Dynasty/data directory used by the copy. Missing original data makes normal startup fail; attaching the engine alone does not prepare it. Optional music, soundfonts and enhancements have separate requirements and rights. The ordinary launch uses no arguments. Retain any supported arguments your prepared copy already needs and review its actual working directory. For an independent Windows ARM64 or x86 copy, use the matching upstream ZIP. The 32-bit package uses a different personal directory; follow upstream’s Windows instructions before copying the PAKs.

  3. Set up an independent Linux ZIP or Flatpak

    Choose the regular x86-64 or ARM64 ZIP for your host, keep the complete extracted tree, start dunedynasty from its containing folder and use upstream’s Linux library requirements. The regular ZIPs need glibc 2.38 and libstdc++ providing GLIBCXX_3.4.32. Copy your EU v1.07 PAKs into the working copy’s data folder or your personal Dune Dynasty data folder. For the Flatpak, install and start io.github.gameflorist.dunedynasty once to create its folders, then put the PAKs in ~/.var/app/io.github.gameflorist.dunedynasty/data/dunedynasty/data. Keep the sandbox profile and external backup separate from the regular ZIP.

  4. Prepare the Mac app before opening it

    Choose the Intel or Apple Silicon ZIP from upstream. In Finder, use Show Package Contents and copy your EU v1.07 PAKs to Contents/Resources/data. The bundle launcher checks for uppercase DUNE.PAK there before it starts the player. Keep the app intact and follow upstream’s first-open instructions under your Mac’s local policy. Back up the original files and the actual profile, normally ~/Library/Application Support/dunedynasty, before replacing the app. An existing bundle-side dunedynasty.cfg selects portable settings and saves.

  5. Select the prepared Windows player

    Select dunedynasty.exe and use its containing folder as the working directory. Leave arguments empty. Keep the complete independently permitted runtime and finish the title-specific preparation before Play.

Setup notes
Registration ownership and removal
Portcove records the selected executable, working folder and literal arguments after review. Play is separate and only the selected process is supervised. You and upstream own replacement and updates; relink changed executable bytes after reviewing them. Removing this registration preserves every external file. Managed installation, backup, rollback, migration and deletion are not offered for this external copy.
Player-data ownership
You and upstream own the external copy's data: the complete personal Dune Dynasty profile or the actual executable-side data and configuration of your prepared copy. Back up these locations separately; registration does not migrate or certify their compatibility.
Managed runtime ownership
Portcove installs and replaces its separate official runtime using the declared release rules. Existing external registrations retain their files and user/upstream ownership. Runtime rollback carries current declared data; it does not rewind saves or establish older-runtime compatibility. Gameplay and populated-save compatibility remain separate qualification. The managed copy has no declared local player data to back up. Back up the external profile separately.

Limitations and evidence

  • Use only a copy and content you are already permitted to use. Engine licensing does not grant rights to original game assets, music, mods or bundled components.
  • Before updating the game, keep a copy of its working files and every location containing saved data. Choosing a different executable does not give it a separate profile.
  • Do not create an executable-side config merely to register the game. Preserve that whole actual profile, its save directory, configuration, original data, custom campaigns/music and the old creating runtime before replacement. Original-format save reading is not a promise that every newer save works in an older engine.
  • Linux and Mac screenshots and the save directory belong to the profile containing the active dunedynasty.cfg. On a regular Linux build, that is normally ~/.config/dunedynasty unless an executable-side config already selects a portable profile. Back up the actual config, save folder and original-data folder. The Flatpak has a separate sandbox profile.
  • Upstream and the player maintain independent copies and their profiles. Back up the actual data and configuration paths, especially if your environment redirects HOME or the XDG paths.
  • The Linux x86-64 ZIP needs glibc 2.38, libstdc++ with GLIBCXX_3.4.32, and the upstream Allegro, ALSA, ENet, MAD and OpenGL libraries. Keep the packaged libs folder with the player.
  • Back up the actual Dune Dynasty settings, saves and original data separately. Linux uses HOME to resolve relative XDG paths. Use an independent upstream copy for executable-side profiles. Real saves across versions remain unverified.
