Setup

  1. Choose your own NHL ’94 cartridge dump

    On first Play, select your own supported 1 MiB NHL ’94 Genesis US/Europe ROM in the upstream picker. Keep it at a stable location outside the managed runtime.

  2. Prepare the exact original upstream

    Use a complete player and components you are independently permitted to use, with your own 1 MiB retail NHL ’94 Genesis US/Europe ROM. Finish the upstream first-launch ROM picker and saved settings before attachment; retain the independent original. Optional larger ROM hacks and roster imports are separate upstream operations, not another accepted retail revision by title alone. This guide obtains or executes no ROM, converter, helper or game. The inspected official 0.3.6 ZIP contains ninety-four-windows-x86_64/nhl94.exe as an AMD64 native player with matching library and notices. Keep that complete directory. This is the native rewrite using the linked pulseman hardware/audio/frontend facilities; it is not an original Genesis executable or a generic emulator admission. A source build and another platform’s application are separate artifacts. Upstream documents the remembered ROM picker for normal windowed starts; the native entry runs the game in the selected process. Complete a missing-ROM prompt outside the attached attempt. Do not add headless, finite-frame, trace, ROM-extraction or network-server arguments as normal Play.

  3. Preserve the actual Linux and Mac data locations

    Preserve any older working-directory data before choosing a different folder. SRAM and whole-machine states are different objects; the source checks a session state against its roster set, which does not prove observed restore or cross-version compatibility. This guide performs no import, migration, backup or deletion. Quit the actual game normally before upstream replacement, restoring SRAM/states or changing roster sets. Keep independent recovery copies and review/relink changed executable bytes; forced termination is not a save-flush guarantee. Upstream whole-game, 60 FPS, rewind and online reports remain upstream claims. No native/installed-app, gameplay, save/reload or Supported acceptance is asserted. On Linux x86-64, the upstream archive needs glibc 2.34 or newer, SDL2 and the GNU C++ and GCC support runtimes. For an existing copy, keep nhl94 and its full archive together and run it from that folder. On macOS 11 or newer, use the upstream universal application for Intel or Apple Silicon. Finder launches keep settings and saves under ~/Library/Application Support/ninety-four. A shell launch can use the working directory instead. Keep the complete application bundle and back up the data location your copy actually uses. Portcove manages the separate Linux runtime, while the Mac application stays with upstream setup.

  4. Keep original, roster and component terms separate

    Retain the project MIT notice and pulseman/component notices, including Nuked-OPN2 LGPL-2.1, ymfm BSD-3 and the separately credited upscalers. They grant nothing over the original NHL ’94 name or game data. Use only originals, roster art and modified content you are independently permitted to use. Online peers need matching releases and applicable roster/state data; no account, relay/server, real multiplayer or full user-content corpus qualification is provided.

  5. Select the prepared Windows player

    Select nhl94.exe and use its containing folder as the working directory. Leave arguments empty. Keep the complete independently permitted runtime and finish the title-specific preparation before Play.

Setup notes
Registration ownership and removal
Portcove records the selected executable, working folder and literal arguments after review. Play is separate and only the selected process is supervised. You and upstream own replacement and updates; relink changed executable bytes after reviewing them. Removing this registration preserves every external file. Managed installation, backup, rollback, migration and deletion are not offered for this external copy.
Player-data ownership
You and upstream own the external copy's data: settings.ini; out/nhl94.srm cartridge SRAM; states/ including Autosave; rosters, recordings, screenshots, videos and configured external ROM/save paths. Back up these locations separately; registration does not migrate or certify their compatibility.
Managed runtime ownership
Portcove installs and replaces its separate official runtime using the declared release rules. Existing external registrations retain their files and user/upstream ownership. Runtime rollback carries current declared data; it does not rewind saves or establish older-runtime compatibility. Gameplay and populated-save compatibility remain separate qualification. Portcove preserves only these declared local inputs during replacement and backup: out, rosters, screenshots, settings.ini, states, videos. Its backup does not include external profiles.

Limitations and evidence

  • Keep the original retail ROM and actual working-directory data. Cartridge SRAM, states, modified rosters and online session compatibility are separate.
  • Use the default data paths with the managed runtime. Keep an independent copy of your ROM, and use a separately prepared copy for custom data paths. Runtime rollback does not establish save-state compatibility.
  • On Linux x86-64, use glibc 2.34 or newer with SDL2, libstdc++.so.6 and libgcc_s.so.1.
