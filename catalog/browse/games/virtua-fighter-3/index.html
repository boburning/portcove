Setup

  1. Set up the game with your matching ROM

    Use a complete copy and components you are independently permitted to use, with your own vf3.zip (MAME vf3 set, RevisionD). The reviewed 0.1.13-alpha runtime reads and recompiles that input locally when it starts; no ROM is supplied by this guide. Follow upstream first-run selection/checks outside Portcove and retain the original archive before any picker copies it into the active roms folder. Another game’s similarly named set is not interchangeable. No original, game program, helper, reference build or test mode is obtained or executed here.

  2. Keep this complete native Windows package

    The inspected selected Windows ZIP contains AMD64 VirtuaFighter3/VirtuaFighter3.exe with its matching assets/resources and LICENSES.txt. Keep the complete VirtuaFighter3 directory. The actual mechanism is PowerPC603e program translated at launch, with separate Model3 board/Real3D implementation and MAME-derived sound; this is not a static-only pipeline; do not describe the whole arcade hardware as recompiled native code or inherit another title’s qualification. Do not select a headless/reference/lockstep tool, ROM archive or another platform’s launcher as the registered executable.

  3. Select the prepared ordinary player

    Select VirtuaFighter3.exe, use its complete extracted VirtuaFighter3 directory as working directory and leave arguments empty after upstream setup has located the intended ROM. Review the exact selected intent, then request Play separately. The ordinary SDL host runs the game in the selected process. If it asks for setup again, complete that outside the attached attempt before retrying. Source/header inspection establishes coordinates, not native execution, dynamic dependency resolution or gameplay.

  4. Keep the ROM and game-data folders in use

    Keep the complete active data folder, normally %APPDATA%/Virtua Fighter 3 Recomp on Windows, including settings.ini, roms, backup and eeprom, with separate edition/profile subfolders where used, log.txt and screenshots/resources. An existing portable.txt mode or package-local roms/source-tree route can select another root; keep the actual location named by the upstream log. An already configured --roms, VF3_ROMS or settings.ini roms_folder selects a separate ROM folder, and an established VF3_DATA selects another data root. Retain all of them and original archives. This guide adds no override/portable marker, copies no ROM and performs no save migration.

  5. Restart and update this game through the project

    For this title, Team Battle uses a different vf3tb set/profile with its own rankings/settings; edition switching must finish outside attachment. Complete upstream edition changes, arcade/service reset paths, setup and runtime replacement outside an attached session. Close the actual game and any successor, preserve independent recovery copies, then review/relink changed executable bytes. Quit normally so upstream can save NVRAM/settings; forced termination is not a flush or quiescence guarantee. Removing registration leaves all external files intact.

  6. Retain permissions and observed limits

    Preserve the selected upstream/LICENSES.txt and component notices: MIT for its own code, MAME-derived BSD3-Clause parts, SLJIT BSD2-Clause, separate RmlUi/font terms and CC BY4.0 icon attribution to Mr Finster. Own-code grants do not grant SEGA original-game rights; the reference/tool terms do not automatically cover the player. This selected alpha documents experimental online play, resolving the older online-not-yet wording; Windows testing is reported under Wine, not a native physical Windows gameplay pass. Intel Mac remains untried. Those limits remain explicit. No Portcove online, gameplay, save/reload, installed-app or Supported acceptance is claimed. Portcove does not own managed installation, runtime updates, rollback, backup, ROMs or external deletion for this registration.
