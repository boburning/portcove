Setup

  1. Get the complete GemRB player

    On Windows x64 use the official SourceForge Windows ZIP and keep gemrb.exe with its companions. On Linux x86-64 use the official GemRB AppImage and provide the host libjack.so.0 library. On Intel or Apple Silicon Mac use the intact Universal 2 GemRB application from Mac Source Ports.

  2. Prepare your own Enhanced Edition data

    Keep a complete working copy of your installed Baldur’s Gate II: Enhanced Edition. Point GamePath at the folder with chitin.key. Set GameType=bg2ee and configure GameLanguagePath for the language you installed, such as lang/en_US. The upstream player reads the prepared data.

  3. Use separate game data folders

    Set CachePath to an empty folder dedicated to this edition because GemRB clears it. SavePath is the parent that contains save/. Keep saves, settings and mods for the original edition in separate folders.

  4. Register the player and play

    Choose gemrb.exe on Windows, the executable AppImage on Linux, or Contents/MacOS/gemrb inside the intact Mac application. On Windows, choose the complete GemRB installation folder as the working folder. On Linux and Mac, choose the private working folder. Enter -c and the absolute configuration path as separate arguments. If the official Linux AppImage cannot mount, add --appimage-extract-and-run before -c. Review and save the selection, then choose Play.

  5. Keep your working copy and saves

    The player owns the runtime, working data and profile. Back up the actual configuration, saves and mods before replacing the upstream player. Removing the registration preserves your external files.

Setup

  1. Use this original game and edition

    Use a complete installed original Baldur’s Gate II: Shadows of Amn working copy, with Throne of Bhaal only if you own and installed it. Enhanced Edition files and the trivial demo do not supply the original edition. Keep your originals elsewhere unchanged; upstream handles its own data recognition and preparation. A Portcove registration does not authenticate original-game files.

  2. Prepare upstream and select the real player

    For Windows x64, use the official SourceForge archive with its plugins, scripts and configuration. Its v0.9.5 ZIP is named gemrb-win32-v0.9.5.zip and contains a 64-bit player. The player needs the Microsoft Visual C++ x64 runtime. Give this game its own configuration: GamePath points to a separate complete working copy of the installed original; GameType=bg2. Use the configuration supplied with your actual build rather than leaving @...@ development-template placeholders. Register gemrb.exe with the complete GemRB installation as working directory and two literal argument lines, -c then the absolute path to this game’s configuration.

  3. Keep the actual original and player data

    Choose a dedicated empty private CachePath for this game: GemRB clears that directory, so it must never be your originals, saves or profile root. SavePath is the parent containing save/, not save/ itself. Keep a separate SavePath per game.

  4. Choose the upstream Linux build

    Use the official x86-64 GemRB AppImage with the host libjack.so.0 library, or install org.gemrb.gemrb from Flathub on x86-64 or ARM64 Linux. Start the Flatpak normally once to create GemRB.cfg in ~/.var/app/org.gemrb.gemrb/config/gemrb. For that package, copy this title’s complete original working copy to ~/.var/app/org.gemrb.gemrb/data/baldurs-gate-2, and use that absolute GamePath in a separate baldurs-gate-2.cfg. Use a writable SavePath parent and an empty, dedicated CachePath under the same app’s data and cache directories. Start with flatpak run --command=gemrb org.gemrb.gemrb -c followed by the absolute config path in quotes. This passes the path to the player as one argument. Back up the sandbox config and actual saves separately. To register the standalone x86-64 AppImage, allow the downloaded file to run and select the AppImage itself in Portcove. Choose your private working folder. Enter -c and the absolute path to this game’s config on separate argument lines, then review and save the selection. If the official AppImage reports that it cannot mount, add --appimage-extract-and-run as the first separate argument. Keep -c and the config path on their own lines. Play starts the upstream player. For Flatpak, use the command above.

  5. Choose the upstream Mac build

    Use the Mac Source Ports Universal 2 DMG at https://github.com/MacSourcePorts/MSPBuildSystem/releases/tag/GemRB_0.9.5. Its v0.9.5 build uses macOS 10.15 or later on Intel and macOS 11 or later on Apple Silicon. GemRB’s SourceForge release directory also offers separate Intel and Apple Silicon builds. Keep the bundle complete. Use this game’s own configuration and point GamePath to the prepared original game folder. Keep this title’s saves, config and working data together when replacing the bundle. To register the Mac Source Ports bundle, copy the complete gemrb.app from the DMG and open it normally once. Select gemrb.app/Contents/MacOS/gemrb in Portcove. Choose your private working folder, then enter -c and the absolute path to this game’s config on separate argument lines. Review the selection and choose Play.

  6. Add the game and manage your files

    Finish setup with the project’s tools before adding the game. Portcove saves your selected executable, working folder and launch arguments; choose Play separately when you are ready. You manage this game’s files, original files and profile. Removing its registration leaves those files in place. Portcove does not offer updates, backups, rollback, data migration or file deletion for this external copy. Keep a working copy and its data before changing versions.

Setup notes
Preserve working data across updates
GemRB can also write gem-*.ini into GamePath before trying SavePath, so preserve and use a working data copy; SavePath alone does not isolate original installation writes. Preserve that working copy, actual save/config locations and mods with GemRB closed before updates. Do not move saves between different games or editions.

Limitations and evidence

  • GemRB clears its cache directory. Use a dedicated private CachePath, separate from original files, saves and profile roots.
  • GemRB can also write gem-*.ini into GamePath before trying SavePath, so preserve and use a working data copy; SavePath alone does not isolate original installation writes. Preserve that working copy, actual save/config locations and mods with GemRB closed before updates. Do not move saves between different games or editions.
