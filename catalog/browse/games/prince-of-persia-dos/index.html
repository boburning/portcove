Setup

  1. Use only an already permitted working native copy

    Use a complete SDLPoP Windows copy that you are already permitted to use, with its actual working data/libraries/resources. Select the modern native prince.exe, not the same-named DOS original, a download helper or installer. Selected current source enters pop_main in the game process, but does not certify an external binary. Official README links desktop builds externally; no selected GitHub release does not mean there is no distribution.

  2. Check the unresolved asset permissions

    Fresh managed-package admission remains unavailable while exact official distribution contents, accepted original/mod DAT set and applicable original asset permissions are unresolved. README supports original/mod DAT and MIDISND data but does not establish a separate player-owned original EXE or ROM requirement; do not invent one. The engine GPL/disassembly classification does not grant proprietary asset rights. This conditional existing-copy route neither downloads assets nor resolves that open permission/data question.

  3. Keep the working folder and options used by this copy

    Complete upstream preparation and a normal start/quit before registration. Select the actual prepared working directory and established supported literal arguments/mod choices. Keep SDLPoP.ini and actual resource/levelset setup; do not substitute a replay-validator/headless/helper invocation for the normal player. Review exact intent/consent and choose Play separately. No Core environment injection or forced profile migration is supplied.

  4. Preserve all actual save, mod and replay roots

    On Windows normal PRINCE.SAV/QUICKSAVE.SAV/PRINCE.HOF writes can use the actual working directory. Existing SDLPOP_SAVE_PATH redirects save/HOF output, including a levelset subdirectory; without it a custom levelset can use its actual mod_data_path. Preserve all those roots, full runtime/DAT/MIDISND/mod data, SDLPoP.ini, configured replays_folder and recordings, legacy and unknown files. Keep the old creating runtime/data/config tuple before updates; no save/replay/mod compatibility or isolated profile is certified.

  5. Update the game and remove its registration

    Close every running copy before changing external files. You manage setup, game replacement, profile changes, data migration and recovery. Keep the working game version and every data folder, update it with the project’s tools, then review and select the changed executable before choosing Play. Portcove monitors only the process you selected and agreed to launch. It does not prevent other copies from running, restrict file access or take over unrelated helpers or replacement processes. Removing the registration leaves external files in place. This route does not offer Portcove downloads, setup, updates, backups, rollback, data migration or deletion.

Limitations and evidence

  • Use only a copy and content you are already permitted to use. These instructions do not establish permission for the original game or other components, or confirm the resulting game files.
  • These instructions do not confirm gameplay, saving, mods, network play, physical controls or behavior on other platforms.
  • Before updating the game, keep a recoverable copy of its working files and every location containing saved data. Another game folder may use the same profile.
