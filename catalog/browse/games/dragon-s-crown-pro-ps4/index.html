Setup

  1. Prepare an exact permitted PS4 build upstream

    Use a complete copy and components you are independently permitted to use. Version 0.9.1 supports your own decrypted Dragon’s Crown Pro PS4 package: USA CUSA10454 base 1.00 or base plus 1.01; Japan CUSA07001 base 1.00 or base plus 1.02/1.03; Asia/Hong Kong CUSA10209 base 1.00 or base plus 1.02. Updates require the matching base. Follow the pinned upstream table for title, content, version and each build’s eboot.bin SHA256; a title match alone is insufficient. Encrypted console packages and other code versions are refused. Finish upstream import and preparation before adding the game to Portcove. Keep your originals and check the testing limits for your build. Portcove does not obtain or run packages, keys or setup helpers for you.

  2. Keep the complete title-specific Windows runtime

    Keep the complete DragonsCrownProPC-v0.9.1-windows-x64.zip contents together, including dragons_crown_pro.exe, trg-updater.exe, matching DLLs, resources, licences and prepared game/image data. This Windows player runs the game’s x86-64 code using a title-specific PS4 compatibility layer and Vulkan translation. It does not provide general PS4 support. Select dragons_crown_pro.exe; the updater, internal boot image, DLLs and original eboot.bin are not game players.

  3. Select the same-process prepared play mode

    In the game’s settings, turn Allow overlay programs Off and finish preparation. Select dragons_crown_pro.exe, use the complete extracted package folder as the working directory and enter --dcp-skip-launcher as the single argument. Review those launch details and consent, then choose Play separately. With overlays Off, the game continues in the selected process. Enabling overlays starts another process and closes the selected one, which Portcove does not track. Portcove does not lock this setting; confirm it remains Off before playing. This process behavior has not been tested through Portcove.

  4. Preserve all builds and the actual user tree

    Keep the complete game/prepared/<build> and game/image/<build> trees, original PKGs, user/dcp.ini, user/savedata, trophy data, caches and numbered logs. Retain user/keys.json if you previously configured a Trophy Key; this guide neither reads nor obtains it. Existing explicit app0/image, --user, --logs or --log selections can point elsewhere; preserve every effective root without creating overrides here. Selecting another build does not prove save compatibility or migrate data. No import, backup, rollback, credential or deletion operation is performed by this attachment.

  5. Complete online, overlay and update work upstream

    Keep online account/Friend Code, service/usage-data choices and overlay/injection tools under explicit upstream/user control; this guide does not create an account, request credentials or qualify network play. Complete updater/helper, install/reinstall, build switching, overlay handoff and runtime replacement outside an attached session. Close actual players/helpers/successors, preserve independent recovery copies and review/relink changed bytes. Upstream’s reinstall/recovery behavior is not a Portcove rollback promise. Quit normally; forced termination is not a save-flush or successor-quiescence guarantee.

  6. Keep licences and platform limits in view

    Keep the GPL2-or-later licence for original project code, TRG Launcher MIT licence and all component, NVIDIA and font notices. They do not grant original-game, console or package rights. Check the documented untested features for non-USA builds. Linux, AppImage, Steam Deck and upstream online results do not establish Windows compatibility. Portcove has not confirmed gameplay, online play, save/reload or installed behavior. Removing the registration leaves all external files in place; Portcove does not install, update, roll back, back up or delete this external copy.
