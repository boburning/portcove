Setup

  1. Select your own Banjo-Tooie ROM on first Play

    Choose Play, then select your own NTSC-U 1.0 big-endian .z64 Banjo-Tooie ROM when asked. The upstream player requires SHA-256 9ec37fba6890362eba86fb855697a9cff1519275531b172083a1a6a045483583 and stores its own profile copy. The Windows ZIP has no installer. If Windows reports a missing runtime DLL, use the Microsoft Visual C++ x64 Redistributable linked in the packaged README; no helper runs automatically.

Setup notes
Profile location and preserved contents
Saves, settings, copied ROM, logs, cache and RT64 texture packs use %LOCALAPPDATA%/BanjoTooieScurvyDogPort.

Limitations and evidence

  • Keep a separate backup of %LOCALAPPDATA%/BanjoTooieScurvyDogPort; do not share the whole profile because it contains your ROM. On first start only, if this destination does not exist, the game can copy selected Alpha 4/4.1 data from BanjoTooieEncore while leaving the old profile unchanged. Close the old game first; the copies do not synchronize. An existing destination, even empty, wins. A failed copy can leave an unused .migrating-… folder; preserve it and consult the upstream recovery instructions before retrying. Alpha 3 save import asks once if there is no current save; Alpha 3 settings and practice states are not carried over. Texture packs are experimental; code mods and ROM patches are unsupported.
  • This is an upstream alpha: distant geometry, aspect sizing, shadows, animation and lost-focus controller behavior have documented limitations; the upstream has not verified the whole game. Portcove gameplay and populated save restoration remain unqualified.

Setup

  1. Use the documented native source-build route

    Use an authorized completed native source build from the upstream Building from source route, keeping its SDK and third-party notices. This route is distinct from the packaged Banjo-Tooie.exe launcher. Upstream requires CMake 3.25+, Clang 20+, Ninja, and the Windows MSVC/Windows SDK toolchain; its documented x86-64-v3 compiler options require a suitable CPU. The selected tree pins the iron-jay ReXGlue fork as a submodule. Runtime/component licenses remain separate, and the repository does not grant original-game rights. No automated acquisition or rebuild is offered by this guide.

  2. Complete original-data extraction and generation with upstream

    Supply your own legally owned Xbox 360 XBLA Banjo-Tooie package, not an N64 ROM. Deliberately finish upstream extraction outside Portcove, preserving default.xex and the expected extracted files and RAWFiles layout. The source manifest uses ../xbla/files/default.xex and includes overrides.toml. Its generated source and generated/rexglue.cmake are intentionally absent from Git: finish the pinned SDK codegen against that manifest before the documented CMake configure/build target banjotooie. The SDK codegen creates the missing helper after successful generation. Do not point Portcove at an incomplete clone, run a generator through Play, or infer original authenticity from upstream extraction, which does not verify container signatures/hashes.

  3. Add only the completed native game executable

    Select the completed banjotooie.exe build with its containing output folder as the working folder, retaining rexruntime.dll and every companion staged by the build. Set the two launch arguments --game_data_root and the absolute path to your own extracted XBLA game-data directory, preserving the path as one argument. The selected native app owns its Windows message loop and waits for the guest game; it is a different entry from the outer Banjo-Tooie.exe launcher. That packaged launcher starts a child then exits, so do not use it for a tracked Portcove session or select a private PyInstaller extraction path. Saving launch details and Play are separate actions.

  4. Preserve the direct build’s actual player-data roots

    Upstream/player owns runtime replacement and the extracted originals. For this direct native app the default player-data root is Documents/banjotooie and its cache is under that root; the executable-side banjotooie.toml is separate. Explicit --user_data_root, --cache_path or opt-in --update_data_root values select other roots. Retain the exact chosen arguments and preserve all active roots before changing builds. The packaged launcher’s BanjoTooie-Data/saves override is a different layout and is not automatically inherited or migrated by a direct build. Portcove does not promise external-save backup, rollback, compatibility or deletion.

Limitations and evidence

  • This guide follows upstream source instructions. Portcove has not run original-data preparation, generation, compilation or the game, or checked the resulting build, dependency compatibility, files, saves or source correspondence. The packaged Windows launcher starts another process and exits; use the completed native build described above. Source and component downloads require their own applicable permissions.

Setup

  1. Choose your original cartridge dump on first Play

    Choose Play, then Select ROM and supply your own Banjo-Tooie USA 32 MiB cartridge dump. The project recommends an unmodified big-endian .z64; the player also converts byteswapped dumps of the same cartridge. Another region or a modified image is not accepted. The player checks the file and keeps its own copy in its profile, so keep your original separately.

  2. Keep the complete player package

    For a copy you manage yourself, extract the whole package. On Windows, run BanjoTooieRecompiled.exe with assets and the supplied SDL2 and DXC libraries beside it. On Linux, run run.sh, or start BanjoTooieRecompiled with its extracted folder as the working folder.

Setup notes
Keep your actual profile when updating
Preserve the player's profile before replacing a copy you manage yourself: normally %LOCALAPPDATA%\BanjoTooieRecompiled on Windows or ~/.config/BanjoTooieRecompiled on Linux. It holds the copied original bt.n64.us.1.0.z64, saves, settings and mods. For Flatpak, keep the complete ~/.var/app/io.github.Vidanox.BanjoTooieRecompiled folder, and keep any APP_FOLDER_PATH or portable.txt folder you actually used. Keep a working copy before replacing the player.

Limitations and evidence

  • Upstream calls Linux less exercised than Windows. Portcove has not observed native setup, gameplay or saves. On Linux the player needs Vulkan, SDL2, FreeType, D-Bus and a running xdg-desktop-portal service for Select ROM.
  • The package includes the Suplexmentary Comic NC font, which the project license does not cover, and menu art based on Rare's promotional artwork. Portcove downloads the package only from the project’s own releases. You need your own original game files.
