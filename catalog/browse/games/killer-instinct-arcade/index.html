Setup

  1. Prepare this exact arcade set upstream

    Use a complete UltraCombo copy and components you are independently permitted to use, with your own kinst arcade set. Supply ki-l15d.u98 (524,288 bytes, SHA1 607394d4ba1713f38c2cb5159303cace9cde991e), the eight sound ROMs u10-l1 through u13-l1 and u33-l1 through u36-l1, and kinst.chd. The CHD content SHA1 reported by chdman info is 81d833236e994528d1482979261401b198d1ca53; it is not the SHA1 of the compressed container. Keep the full originals independently. Killer Instinct also supports optional L1.4 boot ki-l14.u98, SHA1 07254f20707377f7195e64675eb6458e663c1a9a; its settings and compatibility remain separate.

  2. Finish the upstream native-module preparation

    The inspected official 1.1.0 Windows ZIP contains AMD64 UltraCombo-Windows/UltraCombo.exe, SDL2, tools, shaders and component notices. Place the original set in its documented run/ layout or keep the existing explicitly configured paths. On first use of each game/revision, upstream interprets the original to translate and compile a native module into cache/. It tries bundled Zig, an available C compiler, then TinyCC, and can fall back to an interpreter. Finish that preparation outside Portcove; this guide runs no compiler, converter, ROM, helper or game and does not claim every run uses translated code.

  3. Attach only this prepared game

    Select UltraCombo.exe, use the complete extracted UltraCombo-Windows directory as working directory and set arguments to --game ki1. This documented selector binds this record even if both games are installed. Review and consent to the selected launch details, then choose Play separately. The selected normal game continues in the same player. Change game restarts the program and removes the selector; finish game changes outside the attached attempt instead of assuming successor tracking. Do not use --write-raw, --recomp, headless, tracing or network-host commands as normal Play.

  4. Preserve this game and revision separately

    Keep ki1.ini, saves/<boot-ROM-name>.settings with disk settings/audits/high scores, states/slot1.ki1s through slot9.ki1s, logs, screenshots, cache/ and the originals. The player normally writes beside the executable when writable, otherwise under %APPDATA%/UltraCombo; preserve the actual active root, external paths and any former writable-directory data. CHD/raw originals are now read-only, but an older played-on raw disk can carry settings that upstream copies into the separate settings file. States are accepted only for the same build/game/version and are distinct from cabinet settings sectors. This guide performs no conversion, migration, backup or deletion.

  5. Keep permissions and maintenance explicit

    Retain the own-code MIT, SDL2 zlib, Zig MIT, TinyCC LGPL-2.1, libchdr and shader/component notices. Those terms do not license the original arcade ROMs, translated game code or disk data; do not redistribute generated native modules. Quit normally before upstream replacement or data operations, keep recovery copies and review/relink changed executable bytes. Netplay needs matching game/version/ROM/disk and remains unobserved. No native/installed, gameplay, real-save, whole-game or Supported acceptance is asserted. Removing registration preserves external files; managed lifecycle operations remain unavailable.

Limitations and evidence

  • Keep the kinst originals, active data root and per-version settings/states. First-use compilation, game switching and netplay remain upstream-owned operations.
