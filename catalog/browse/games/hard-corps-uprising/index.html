Setup

  1. Keep the complete package together

    Follow the upstream guide. Keep the complete package, runtime libraries, configuration and notices in a writable folder. Do not select an installer or updater as the game. Before the first upstream startup, make separate backups of any existing Documents/hard_corps_uprising profile and portable user_data/ profile; a successful upstream migration removes the legacy folder.

  2. Install this title and any separately owned DLC

    Deliberately finish upstream setup outside Portcove using your own Hard Corps: Uprising XBLA LIVE package, title 58410A18 and content type 000D0000. Its extracted default.xex must be 12,955,648 bytes with SHA-256 530EDE8ED5271051A2AB19C077A97FB167E4F30B094C292E8F59D37D0D2069DC. Package container hashes can vary. Optional character DLC requires separately owned Marketplace packages for this title, content type 00000002; it is not required for the base game.

  3. Add the prepared native player

    Select hard_corps_uprising.exe (on Linux, the HardCorpsUprisingRecompiled AppImage), its containing package folder as working folder, and no arguments for ordinary Play. The embedded launcher resumes the native game in-process. Complete installation, updates and settings that require Restart outside a tracked session: Restart explicitly starts a successor process and exits this one, and the separate updater is not a game entry. Saving launch details and Play are separate Portcove actions.

  4. Keep upstream ownership and all active data roots

    Upstream/player owns runtime replacement. Preserve game/, logs/, the executable TOML and the complete user_data/ tree: settings.toml, 58410A18 local scores, achievements, cache and 0000000000000000/58410A18 DLC. Before the first upstream startup, back up the legacy Documents/hard_corps_uprising profile and any portable user_data/ profile separately. When upstream migrates legacy data, it moves the legacy folder by rename, or uses a staged verified copy and then removes the legacy folder after activation; successful migration does not leave the old profile in place. A failed migration falls back to the legacy root for that run and retries on the next startup. If only legacy cleanup fails after activation, portable user_data/ stays active and the legacy folder may remain. An unwritable portable root can also fall back to the system root. --user_data_root=<folder> selects that root without migration; --cache_root can select a separate cache. Preserve every active root and the separate backups. Portcove does not manage their backup, rollback, compatibility or deletion.

Limitations and evidence

  • This guidance follows upstream release descriptions and source. Portcove has not inspected the archive or tested gameplay, saving or updates. Upstream calls its native Linux AppImage experimental.
  • The package includes an unlicensed TRG launcher that the project license does not cover. Portcove downloads it only from the project’s own releases. You need your own original game files.
