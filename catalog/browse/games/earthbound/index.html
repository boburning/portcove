Setup

  1. Use your prepared upstream copy

    Prepare your own permitted Windows native copy using upstream's instructions and your own original outside Portcove. The documented build target is EarthBoundRecomp; its Windows executable is EarthBoundRecomp.exe. Keep the complete source/build working copy and matching SDL/framework dependencies together. Portcove does not run the Python generation pipeline, compile the game or repair this prototype. No official binary download is required for registration.

  2. Keep the project working folder and original argument

    Select the completed build/EarthBoundRecomp.exe from your prepared Windows copy and use the project root as working directory, matching upstream's documented invocation. Enter the actual absolute path to your own EarthBound USA .sfc as one argument line, without shell quotes. The documented headerless original is 3,145,728 bytes with SHA-256 a8fe2226728002786d68c27ddddf0b90a894db52e4dfe268fdf72a68cae5f02e. The upstream runtime checks its original input; Portcove records the argument but does not import or authenticate that file.

  3. Review registration and choose Play separately

    Portcove records your selected native executable, working folder and literal arguments after review; Play is separate. Only the selected process is supervised. Removing the registration preserves all external files. Managed installation, generation, updates, backup, rollback, migration and deletion are not offered for this copy. Existing Portcove-built installations retain their original installation, source, backup and recovery contracts.

Setup notes
Preserve the complete creating environment
Keep the original and its location, complete project/build tree, private generated code, saves folder, SRAM/save-state files, config.ini, config.local.ini, rom.cfg and diagnostic output with the creating runtime. Preserve separately configured or original-adjacent files too. The documented host reads configuration and creates saves relative to its working folder, and can automatically load and save slot zero when autosave is enabled. Upstream or you own rebuilds and runtime replacement; older save states, settings and generated code are not guaranteed compatible with another build.

Setup

  1. Use the Companion launcher you are permitted to use

    Select EarthBound Companion.exe with its own folder as the working directory, then choose Play explicitly. Use its guided setup with your own clean USA EarthBound ROM. The launcher builds native game data and optional supported Redux content; Portcove does not run its helpers during discovery. This is a distinct implementation from nickclyde/EarthBoundRecomp and does not change that integration or retained contracts. If your existing launcher uses a custom data root, retain its --data-root argument and chosen directory when registering: enter --data-root and the directory as two separate argument lines. Otherwise it opens the default profile instead.

Setup

  1. Keep the complete Windows development release

    Use the full Phase-Distorter-0.5-windows-x86_64.zip folder with Phase Distorter.exe, matching SDL2.dll, resources and licenses. v0.5 is a development release. Its default gameplay path runs each game’s compiled program; the separate --native-session engine route remains experimental and is not enabled by this guide. Do not claim a completed wholly native engine or inherit another platform’s observations. Project, component and original-game permissions remain separate.

  2. Import your own exact game separately

    Supply your own supported EarthBound US or Mother 2 Japanese SNES ROM through the application’s first-run picker. Headerless content is 3,145,728 bytes; an optional 512-byte copier header is accepted before validation. EarthBound SHA-256 is a8fe2226728002786d68c27ddddf0b90a894db52e4dfe268fdf72a68cae5f02e; Mother 2 is 1f8cfd13177d86b0eb2c8adcf9e1a4f0ec8966fa1583072b65a1b1c0e7961a5d. Patched ROMs and other revisions are unsupported. Import each separately; their language, program, asset pack and saves remain distinct. No original or extracted asset pack is supplied by Portcove.

  3. Add the ordinary native desktop frontend

    Select Phase Distorter.exe, choose its complete extracted Windows release folder as working directory and leave arguments empty to use the remembered/default game and upstream import UI. Review the selected program, folder and arguments, then choose Play when ready. An existing explicit --game earthbound or --game mother2 choice can remain unchanged. Import leaves originals and the executable unchanged; later starts use the locally imported pack. Do not select a headless, coverage or experimental native-session command as the ordinary player.

  4. Preserve the external imported packs and saves

    Keep %APPDATA%/ebsrc/EarthBoundCpp on Windows, including earthbound.ebpak, mother2.ebpak, earthbound.srm, mother2.srm, display.cfg, controller preferences, snapshots/earthbound, snapshots/mother2 and other user files as present. Preserve existing --save, --assets and --config overrides and their actual locations. Save normally in game and exit normally to write battery RAM. Battery saves and named execution snapshots are different formats; no conversion or cross-game/build compatibility is inferred. A new release can find an old import in this external folder; that does not mean the download contains original game data.

  5. Leave maintenance and recovery upstream

    Quit the actual game/helpers before upstream replacement or recovery, retain previous complete application/data and extract a new version into its own folder as upstream recommends. Review/select the current executable after changes. Portcove observes only the selected program, removes only its reference and performs no original import, pack rewrite, save migration, backup or restore. Managed installation/update/rollback, full-session tracking and Supported qualification are unavailable; upstream gameplay, controller and real-save reports remain separate from Portcove observations.

Limitations and evidence

  • Select Phase Distorter.exe in the complete Windows v0.5 folder. Keep the separate EarthBound/Mother 2 packs and saves under %APPDATA%/ebsrc/EarthBoundCpp or existing overrides; experimental native-session and snapshot formats are separate.
