Setup

  1. Keep the complete Windows player and your own supported original

    The inspected Windows package contains eternalsonata.exe and its matching rexruntime.dll. Use your own original supported by upstream’s game-library picker and validation: the selected source lists Xbox 360 and PS3 PAL, USA and Japanese variants independently. The PAL-only Xbox 360 source-build prerequisite does not narrow every runtime input. Complete upstream’s normal preparation, keep the selected original/version directory and do not substitute another variant’s executable or files. Portcove imports no disc or generated game code.

  2. Attach the completed native player

    Select eternalsonata.exe, its existing package directory as working directory and no arguments for the normal in-process start screen/library selection. Retain existing literal arguments only when your working setup requires them. Keep matching resources, configuration and the established library/version selection; a selected game folder can live outside the library root.

  3. Review launch details, then choose Play

    Select the completed game executable, its working folder and supported launch arguments. Review those details and agree to use them, then choose Play separately. You manage setup, game replacement and recovery using the project’s tools. Removing its registration leaves external files in place. Before changing versions, close the game and its companion programs and keep the working copy and all data. Review and select the changed executable before playing again.

Setup notes
Keep upstream updates and restarts outside the attached session
The inspected title and pinned Windows SDK offer game updates and restarts. Applying an update starts a helper that outlives the old process and can replace files and launch a successor. Treat deliberate update/restart as upstream maintenance outside the active attached session: close the actual player and companions, retain the old runtime and all data, then review and relink changed selected bytes. Turning off an update check alone does not give Portcove exclusive replacement ownership; this guide disables no upstream feature and adopts no successor automatically.
Preserve every effective library, profile and configuration root
Keep the complete creating runtime and every actual game, user, cache, mod, mod-dump, update, metadata and custom root, including external game-version links. Relative path settings resolve against the configuration’s parent directory in the inspected SDK. A portable.txt beside the executable makes the default user directory user/ beside it; other configurations use platform folders. Preserve settings.toml, runtime configuration, selected-version metadata, install/migration staging, saves, mods, caches, backups and temporary files. Keep established paths and creating-runtime compatibility; the working directory alone does not identify all player data.

Limitations and evidence

  • Use only a copy and components you are permitted to use. Before changing versions, keep a copy of the complete working game, original files and every profile, save, cache, mod, backup, temporary file and custom data location. Another executable may use the same data. Portcove does not offer updates, backups, rollback, data migration or deletion for these external files.
