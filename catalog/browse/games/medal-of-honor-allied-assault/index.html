Setup

  1. Prepare the matching PC game

    Before Play, prepare your own complete Allied Assault PC data. Upstream recommends GOG Warchest; CD copies need the matching language patches (Allied Assault 1.11). Keep the originals unchanged in a separate installation. Copy only the original PK3 files and sound/video resources into main beside the official player. Preserve the matching folder names and all required original resources; do not copy old executables, DLLs or unrelated expansion files over this runtime. Portcove does not verify original-game identity. Console editions and demos are different products. Keep the whole official runtime together. On Windows x64, install the upstream Visual C++ runtime if needed and use a short plain ASCII library path. Linux x64 needs glibc 2.34, libstdc++ with GLIBCXX_3.4.29 and system SDL2. The universal Mac package needs macOS 10.15 on Intel or macOS 11 on Apple Silicon.

  2. Keep an existing prepared copy

    Use a private working copy of the original game folder. Extract the complete official Windows x64 ZIP into it, preserving DLLs and companions. Follow upstream Visual C++ x64 runtime prerequisites when needed. Register launch_openmohaa_base.exe with the game root as working directory. This title-specific launcher selects Allied Assault and waits for openmohaa.exe to exit. Do not select omohaaded.exe, PDB archives or another expansion launcher. This remains a non-owning external registration. You and upstream own runtime replacement and every file; removing its registration preserves them. A catalog update does not migrate or adopt that copy.

Setup notes
Preserve your actual game data
Back up the game’s external profile separately. The normal locations are roaming application data on Windows, ~/.openmohaa on Linux and ~/Library/Application Support/openmohaa on Mac. When FLATPAK_ID is set and nonempty on Linux, the engine uses openmohaa under XDG_DATA_HOME or ~/.local/share. The Unix managed offer checks that the selected profile is outside the managed runtime and leaves it in place.
Set up the native Linux or Mac archive
For a separately prepared copy, extract the official Linux amd64 or arm64 ZIP or the universal Mac ZIP. Keep the executables and libraries together. If the extracted launcher and engine have no execute permission, make those two files executable with chmod u+x launch_openmohaa_base openmohaa. From that folder, run ./launch_openmohaa_base with your own patched PC data in main.
Use the Windows ARM64 package
On Windows ARM64, choose the official ARM64 ZIP. After preparing the same original files, use launch_openmohaa_base.exe in the extracted folder. You and upstream own that copy and its profile.

Limitations and evidence

  • Back up the actual external profile and your originals separately before changing runtimes.
  • A separately prepared copy can use a custom profile or fall back to its runtime when the engine cannot find a home directory. Preserve the actual profile with its creating runtime.
