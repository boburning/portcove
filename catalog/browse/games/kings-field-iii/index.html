Setup

  1. Prepare the complete permitted official player

    Use an already permitted completed official Verdite3 v0.2.0 Windows x64 portable copy for US King's Field II, under the project, vendored RecompOne/verdite-core MIT terms and applicable component notices. These grants do not cover the original FromSoftware game/media or certify arbitrary binaries. Keep the entire extracted installation, including bin, content and licenses. Upstream/player owns preparation, repair and replacement; do not select the setup.exe installer as the game.

  2. Keep your matching disc with the game version that used it

    Use your own North American King's Field II disc, SLUS-00255: a CUE with every referenced BIN, or an upstream-supported CHD. Retain the original path and related files for streamed game data; the generated assembly is not a replacement for the disc. The selected source supports CHD cdzl/cdlz/cdfl/zlib/lzma codecs, not cdzs. Upstream checks boot serial and selected-file presence, not independently authenticated full-disc identity. Other regions, masterings, different King’s Field games and emulator states are not qualified by this guide.

  3. Complete upstream onboarding before registration

    Finish the normal upstream disc picker and first-run preparation outside Portcove. On a cache miss the launcher regenerates and compiles KingsField3.dll in its own profile, then invokes the game synchronously in the same apphost; registration does not perform that preparation. Keep the generator, content, original, settings and build cache together with their creating version. A prepared copy still retains its upstream generator; this does not make it a plain immutable native-runtime package.

  4. Select the complete player and its working folder

    Select bin/Verdite3.exe with zero launch arguments and the complete installation root as initial working directory. Keep all adjacent self-contained .NET/native dependencies; this selected entry does not require a separate system .NET10 installation. Do not select a cached DLL, dotnet host, build helper or installer. The apphost resolves its profile and deliberately changes working directory there; changing the initial directory alone does not redirect all player data. Preserve established custom-profile path interpretation.

  5. Review launch details, then choose Play

    Review and consent to the exact executable, initial working directory and empty argument list. Registration does not build or launch the game; choose Play explicitly. Core observes this long-lived selected apphost, not an exclusive process family or network sandbox. Upstream update checking only notifies and opens its release page; it does not replace or relaunch the game. Upstream/player owns actual replacement. Close all real instances before replacing the copy and review a replacement executable through a fresh relink.

  6. Preserve the whole profile and every custom card path

    Keep the entire actual runtime and %LOCALAPPDATA%/Verdite3 profile, or its established override: settings.json including CdPath/CardAPath/CardBPath, interface.ini, carda.sav/cardb.sav and backup/damaged companions, mods including mods/.cache and profile-root .mods-seeded, builds including KingsField3.dll and profile-root build.log, update.json, icon files, crashes, dumps/diagnostics and all unknown/custom paths. Relative card paths resolve under the active profile working directory; absolute cards may live elsewhere and must also be preserved. Keep each creating version and original; no save/card/state/mod migration or cross-build compatibility is established. Removing registration deletes only Portcove metadata and preserves every external byte.

Limitations and evidence

  • An existing VERDITE3_DATA environment override is an upstream profile choice; relative values resolve from the initial working directory before the apphost changes it. Core registration records executable, directory and arguments, not a per-entry environment override. Do not assume a shell-only setting follows GUI Play, or silently move/redirect a profile. Preserve an already reproducible environment and its actual data paths.
  • Windows upstream code can refresh icons of matching Desktop, Start Menu and pinned-taskbar shortcuts; KF3_ICON_INSTALL=0/off is its environment opt-out. These are upstream actions, not a Portcove shortcut/profile ownership promise.
  • Upstream memoization uses image path/size/mtime; an unchanged CUE can conceal a changed BIN. Build keys cover selected disc files, source/config and launcher version rather than every media byte. Choosing the program in Portcove does not verify the original files, package, generated DLL or full disc image.
  • No Portcove-managed acquisition/setup/Install/Update/Backup/Rollback/migration/external deletion is supplied. Source inspection and inert Core probes are not actual game, gameplay/save-load/state/mod compatibility, other-platform, installed-app or protected acceptance. Memory cards, generated assemblies and crash dumps remain distinct evidence/data.
