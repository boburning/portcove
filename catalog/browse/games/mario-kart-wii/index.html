Setup

  1. Prepare your Mac copy upstream

    On an Apple Silicon Mac with macOS 14 or newer and Xcode, use the current PadMint and choose Mario Kart Wii, your own supported PAL RMCP01 revision 0 disc and This Mac. Follow KartPad's current Mac guide and game-owned build recipe. Keep completed builds and original files. The ready-made Mac releases from 0.7.9 through 0.7.13 are a legacy alternative and receive no updates; current mobile packages are not Mac players. If a tool download fails, keep certificate verification enabled and use upstream troubleshooting or its documented manual build.

  2. Keep the complete app and reuse your game data

    Move the completed KartPad app to Applications and open it using upstream macOS instructions. When it asks for game data, choose your existing matching extracted DATA folder, or copy PadMint's prepared disc folder to a location you will keep. Reuse valid remembered choices. Retro Rewind needs the exact version named by this app and its separate whole data folder; replacing mod data alone does not update translated game code. Keep upstream Data, controls, Mii and save tools.

  3. Use the app or optionally register its native player

    Opening the finished app upstream is the simplest route. To keep an existing copy in Portcove, select KartPad.app/Contents/MacOS/KartPad, keep the complete app intact, and use its Contents/MacOS folder as the working directory. Save launch details without starting it, then choose Play explicitly.

Setup notes
Keep your actual saves and profile recoverable
Before a rebuild or update, close KartPad and back up ~/Library/Application Support/KartPad, your chosen original-game files, and the whole enclosing Retro Rewind folder because it can hold saves beside the selected data. Keep ~/Library/Caches/KartPad and custom roots if needed, the current working app and your original disc. Changing player folders does not isolate the existing profile. Preserve the app and signing identity; do not uninstall or clear data to update.
Keep KartPad updates and backups upstream-owned
Upstream update notices do not replace the app: rebuild the compatible version, close the old app, preserve its profile and replace the app. You or upstream own updates and data backups; Portcove registration supplies no managed Update, Backup or Rollback, and removal leaves every external file untouched.

Setup

  1. Finish upstream setup first

    Use the official WiiCompiled setup through Wheel Wizard with your own clean, supported Mario Kart Wii disc. The reviewed route uses the resolved PAL RMCP01 source identity. Complete upstream preparation and establish a working vanilla player before registration; Portcove does not extract, translate, compile, repair or validate game data.

  2. Select the prepared game player

    Choose Base/WiiCompiled.exe inside the existing installation, with that Base folder as the working directory and no arguments. Keep the complete installation and its configured GameAssets together. Do not select WiiCompiled-Setup.exe, Wheel Wizard or a compiler as the player. This route covers the vanilla game, not Retro Rewind.

  3. Confirm and choose Play separately

    Review the game program, start folder and launch arguments. Add the game, then choose Play when you’re ready. Portcove retains the selection for restart or relink and observes the selected player process.

Setup notes
Preserve your actual profiles and originals
Keep the whole portable folder, portable.txt marker and UserData together. Otherwise the normal Windows profile is LocalAppData/WiiCompiled; if that known folder is unavailable upstream can use WiiCompiled under the working directory. Preserve Config.toml, NAND saves/settings, Cache, Logs and all original disc files and game assets. Configured relative NAND and DVD paths resolve from the Config.toml folder; preserve every actual custom path too.
Keep one update owner
Wheel Wizard and upstream retain preparation, repair and runtime replacement. Direct player registration does not run their provenance checks, moved-install healing or install-operation lock. Close every actual player and preserve all working files and data before upstream repair or updates. Removing the registration removes only Portcove metadata and preserves all external files.

Limitations and evidence

  • Do not move the Base folder alone or add/remove portable.txt to change profile locations. Different installations may share LocalAppData/WiiCompiled. Portcove registration does not authenticate the game disc, setup package, generated player or source/build provenance.
  • The upstream runtime writes its profile, may seed missing files in a configured NAND and prunes entries older than four days in its Logs folder. Preserve diagnostic evidence before Play when needed. External files remain upstream/player owned; Portcove cannot guarantee their retention by the game.
  • Managed Install, Update, Backup, Rollback, migration and external deletion are unavailable. No original-game redistribution, Retro Rewind compatibility, gameplay/save-load or other-platform qualification is implied.
  • Configured relative NAND and DVD paths resolve from the Config.toml folder; preserve every actual custom path too.
  • Close every actual player and preserve all working files and data before upstream repair or updates.
