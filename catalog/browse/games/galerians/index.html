Setup

  1. Prepare the exact three owned discs upstream

    Use a complete kit, components and a privately prepared player you are independently permitted to use for noncommercial purposes under the pinned framework terms. Supply your own Galerians USA CUE/BIN discs 1/2/3, serials SLUS-00986, SLUS-01098 and SLUS-01099; keep every companion track and each CUE together, with all three discs in the same folder. Upstream identifies their dataTrack01 MD5s as 217885a22fbb0f3092f8405ce42419ea, 5bc6de661cb074cd5218ac0b9daecda2 and 992e16e5164febd23c8242ede1fc0d8c. Those are data-track identifiers, not whole-set/CUE hashes or permission to acquire the discs. Disc 1’s preparation config also specifies 695399376 bytes and SHA-1 f69e7299e5cea91a74e1e4c9893e6781d1227d1d; do not substitute another region or edition.

  2. Finish the supported private preparation before attachment

    The Windows release ZIP is a setup kit without generated game code. Complete its upstream wizard with Disc1 and Generate & rebuild outside Portcove, using its supplied OpenBIOS and supported tools. The source-build recipe additionally applies this title’s three patches and uses --force-emitters; follow the matching upstream recipe instead of mixing framework revisions. Preserve all three originals separately. Generation starts from Disc1; the one resulting program uses the later discs as data. Reachable discovery retains interpreter fallback for unreached code; this is not an all-code-ahead-of-time guarantee.

  3. Select the completed native game product

    Select the successful build-release/Galerians_Recompiled.exe product, use its complete build-release directory as working directory and leave arguments empty. Keep matching bios/, mods/, assets, game.toml and runtime companions and the selected own disc paths. The completed player runs its normal launcher and game in the selected process. Do not register the root setup host, scripts, toolchain or unfinished output: a Windows setup host can forward to another process and exit. Saving launch details and requesting Play are separate actions requiring your consent.

  4. Keep legacy state migration and disc selection explicit

    Upstream’s first legacy-state migration can move loose state_*.pst files into openbios/ or scph1001/ subfolders and writes .pst_bios_isolated even when some files are skipped. Preserve the old and new save folders and marker together in separate pre-start backups; no automatic retry or cross-BIOS compatibility is promised. Use the native player’s own Disc Selection/Change disc controls for later owned CUEs and retain every source disc; Portcove does not import saves, switch discs or migrate profiles.

  5. Leave rebuilds, mods and runtime replacement with upstream

    Upstream/user owns generation, rebuilding, updates, recovery and save writes. Builds stage their mod catalog and can clear/replace mods/packages before copying title packages; back up custom mods and the complete working output outside all build/staging destinations before rebuilding. Optional Generate & rebuild/PGO/restart actions can create successors and are outside this tracked-player route. Close all actual games/helpers/successors before maintenance or another attachment, then review/relink changed bytes. Removing registration preserves every external file; no Core-managed update, rollback, backup, migration or deletion is offered.

  6. Retain title-specific requirements and limitations

    Keep applicable PolyForm Noncommercial framework, separate MIT launcher/OpenBIOS and other component notices; these do not grant original-game redistribution rights. The inspected release is early. Upstream reports early gameplay but has not established play beyond the first room, save/load, mid-game disc changes, a full playthrough or PGO. Those limits remain; optional cheats, controllers and graphics features are not compatibility promises. Retain known-working copies when updating.
