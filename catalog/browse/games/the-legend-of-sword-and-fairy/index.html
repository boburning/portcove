Setup

  1. Prepare a working copy of your game data

    Keep your originals safe and make a separate working copy of the matching DOS or Windows game-data folder. Extract the Windows MinGW ZIP’s sdlpal.exe into that working copy.

  2. Set the save path for a separate runtime

    For a separate runtime folder, explicitly configure an absolute SavePath before your first game session; changing GamePath alone in the Windows dialog does not change that session’s save location.

  3. Keep the player and save folder together

    Finish setup with that sdlpal.exe and the same folder as its working directory. On first Play, keep SDLPAL’s game folder pointed at this copy. This keeps the initial save folder and later launches at the same location.

  4. Set up the upstream Linux AppImage

    Open the official x86-64 AppImage with the host’s AppImage support. The v3.0.2025.0616 player needs glibc 2.34 or later. Its launcher runs inside the mounted image, so put your matching DOS or Windows data in a separate writable folder. Select that folder in the settings window before starting the game. The Linux settings dialog uses the selected game folder as the save folder and the AppImage stores sdlpal.cfg under ~/.config. Use lowercase game filenames on case-sensitive filesystems. Keep the config, data and .rpg saves backed up.

  5. Prepare a writable folder for the Mac app

    Copy Pal.app out of the official DMG into a permanent writable folder with your matching game files. The v3.0.2025.0616 bundle supports Intel and Apple Silicon and requires macOS 11 or later. The Finder launch uses the app’s enclosing folder for default game data and saves. Keep sdlpal.cfg and the .rpg saves with that working copy. If you launch the player from a terminal, start it with that same working directory.

  6. Choose the Android game folder

    Install the official SDLPAL APK and prepare a writable folder on the device or SD card containing your matching game data. Select that folder with Android’s document picker when SDLPAL requests access. Its settings use the selected game folder for both data and saves. Keep that folder, sdlpal.cfg and the .rpg saves recoverable when replacing the APK. Preserve your accessible backup before clearing data or changing to another package or signer.

Setup notes
Preserve your saved games
Back up that working folder, including its .rpg saves and sdlpal.cfg, when applying upstream updates.

Limitations and evidence

  • Keep saves matched to the DOS or Windows data edition. Portcove does not update or back up this externally owned copy.
  • Back up that working folder, including its .rpg saves and sdlpal.cfg, when applying upstream updates.
  • For a separate runtime folder, explicitly configure an absolute SavePath before your first game session; changing GamePath alone in the Windows dialog does not change that session’s save location.
  • The Linux, Mac and Android packages use upstream setup and replacement. Their files and saves are outside the managed Windows profile.
