Setup

  1. Set up Render96 before adding it

    Follow the Render96 project’s instructions to prepare a permitted Windows installation using your own matching Super Mario 64 original. Finish extraction or compilation, then start and close the game successfully before adding it. Portcove does not build Render96 or import the original game. Optional model and texture packs have separate requirements; you do not need them to add the game to Portcove.

  2. Choose the game program

    Choose the program from your working build, rather than its compiler, build script or a launcher that starts a separate process. Keep its resources and companion files together. Use the same start folder and launch options as your working installation. Review and save the launch details, then choose Play separately.

Limitations and evidence

  • Use only originals, prepared copies and optional packs that you are permitted to use. Adding a program does not verify that the whole package came from its publisher or grant content rights.
  • These instructions describe the inspected build. Check the actual locations and behavior of your working copy; other build options and platforms may differ.
  • Separate program folders can share saves. Do not move or change your save folder just to add the game to Portcove.
  • Back up the complete working installation, originals, resources, dynos/packs, mods, saves, settings and any unknown files before changing it.
  • Portcove will not back up or update this external installation. Back up its saves, settings and custom folders separately.
  • The inspected SDL2 build can copy older saves and settings into its shared profile folder when newer files are missing. Keep both profile folders before trying another copy.

Setup

  1. Keep the matching original

    Use your own unchanged US Super Mario 64 game in big-endian .z64 format. Drag the .z64 file into the game window or place a copy beside the game program before opening it. Keep your original separately. The game can copy it to your profile as baserom.us.z64. If a copy already exists there, the game keeps it when you select another file.

  2. Prepare the Windows game

    Unpack the complete Windows ZIP into a writable folder and finish the original-file setup. Keep the game program, lang, dynos, mods and libraries together. Add the working sm64coopdx.exe to Portcove with its containing folder as the start folder and retain your existing launch options.

  3. Play or replace your working game

    After adding your Windows or Linux game, choose Play. Use upstream tools to replace the game or manage its saves. Removing the Portcove registration leaves the game and data in place. Close the game and its updater before replacing files.

  4. Open the Linux or Steam Deck game

    Unpack the complete x64 Linux ZIP and run sm64coopdx from that folder so it can find its bundled libraries. If Portcove offers Use an existing installation, select the working Linux sm64coopdx program and set the unpacked folder as its start folder. The game needs glibc 2.34, GLIBCXX 3.4.29, OpenGL, SDL2, zlib and curl. The separate SteamOS archive in v1.5.1 has the same requirements and different default settings. The publisher directs Steam Deck players to the Linux package from v1.6 onward.

  5. Open the macOS app

    Choose the Intel or Apple Silicon ZIP that matches your Mac and keep the complete sm64coopdx.app. Start it directly and drag your original .z64 file into the game window. The v1.5.1 game requires macOS 11 or later. Its bundled updater requires macOS 12 or later.

Limitations and evidence

  • To move to v1.5.1 on Linux or Mac, replace the game using the complete upstream archive after backing up your actual profile. Upstream requires a manual update to replace the earlier updater.

Setup

  1. Check the required game files

    Use your own Super Mario 64 Nintendo 64 USA ROM. Check the required size and SHA-1 in games/sm64-us/profile.toml before importing. Keep the original separately. These instructions do not download or run it.

  2. Build from source on Linux

    Follow the upstream Linux prerequisites. From the checkout root, run .venv/bin/python tools/import_rom.py --profile games/sm64-us/profile.toml --rom "/path/to/your-ROM.z64" with your own .z64, .n64 or .v64 file. Run cmake --workflow --preset sm64-us-release, then ./build/sm64-us-release/bin/sm64-us. The default keeps the ROM external. Keep the ROM and any locally generated game code private, including builds that embed it.

Limitations and evidence

  • The project provides a Castle Grounds screenshot. A complete playthrough has not been confirmed, and results from another game do not establish that this one works. Portcove has not confirmed setup or gameplay.
