Setup

  1. Keep your current Ghostship installation

    If Ghostship already works in Portcove, keep using Play and the management operations available for that installation. Do not replace it or move its data to use this alternative Windows setup. For a separately prepared copy, follow the steps below.

  2. Download the official Windows package

    Use HarbourMasters/Ghostship on GitHub and its official 3.0.0 release. Download Nautilus-Alfa-Win64.zip and extract every file into a new folder outside your Portcove library. Keep existing installations and originals in place; do not extract over them.

  3. Prepare your own Super Mario 64 files

    Use your own Super Mario 64 US .z64 file and keep it unchanged. Open Ghostship.exe, choose the file and let setup finish. Keep sm64.o2r with the rest of the extracted files. Close Ghostship before adding it to Portcove.

  4. Add the prepared executable and play

    Open this game’s Files tab, expand Use an existing installation · Installation options, then choose Use an existing installation. Choose game executable and select Ghostship.exe from the prepared folder. Set Start in folder to that same folder and leave launch arguments empty. Review launch details and confirm the registration, then choose Play. Selecting a program records your intent to run it; it does not authenticate a publisher package.

Setup notes
Original file editions
The Windows 3.0.0 route was checked with the US edition. The project’s guide also describes JP input, which was outside that check.
Updates and backups
For this external copy, use the project’s tools to update it. Close the game and helpers, preserve the whole working folder including sm64.o2r, saves, mods, screenshots, ghostship.cfg.json and imgui.ini, then prepare a new version separately before changing launch details. Portcove offers launch and registration removal for this copy; it does not offer managed updates, backups, rollback, migration or deletion of its files. Removing the registration leaves the game and data in place. Existing Portcove-managed copies keep their own available update and recovery actions.

Limitations and evidence

  • Do not replace only the Ghostship 3.0.0 program with 2.0.0 while using newer saves. For a managed copy, use the legacy save recovery review in Saves & backups if Portcove offers it. For an installation you maintain, keep the newer files and use your own recovery copy.
  • This guide covers Windows. Existing data, source and execution safeguards still apply; a held update or recovery does not by itself prevent an otherwise safe Play.

Setup

  1. Set up Render96 before adding it

    Follow the Render96 project’s instructions to prepare a permitted Windows installation using your own matching Super Mario 64 original. Finish extraction or compilation, then start and close the game successfully before adding it. Portcove does not build Render96 or import the original game. Optional model and texture packs have separate requirements; you do not need them to add the game to Portcove.

  2. Choose the game program

    Choose the program from your working build, rather than its compiler, build script or a launcher that starts a separate process. Keep its resources and companion files together. Use the same start folder and launch options as your working installation. Review and save the launch details, then choose Play separately.

Setup notes
Build output and executable names
The inspected standard Windows US build normally produces build/us_pc/sm64.us.exe; region and renderer options can change its name.
Save folders and supported launch options
The inspected SDL2 build uses the sm64ex preferences folder by default. When the newer save is absent, it can copy an older sm64pc save and settings into that folder. Keep the actual sm64ex and sm64pc folders, sm64_save_file.bin, sm64config.txt and any custom data. Keep your existing --savepath, --configfile and --gamedir launch options only where your build supports them; ! in a supported save path means the executable folder.
Updates, backups and file ownership
You or the Render96 project’s tools handle updates, optional packs, resources and recovery. Portcove watches the selected game process and can remove its saved launch details. It won’t update, back up, restore, switch to older versions, move or delete this external copy. Older copies installed by Portcove keep their existing setup and update behavior.

Limitations and evidence

  • Use only originals, prepared copies and optional packs that you are permitted to use. Adding a program does not verify that the whole package came from its publisher or grant content rights.
  • These instructions describe the inspected build. Check the actual locations and behavior of your working copy; other build options and platforms may differ.
  • Separate program folders can share saves. Do not move or change your save folder just to add the game to Portcove.
  • Back up the complete working installation, originals, resources, dynos/packs, mods, saves, settings and any unknown files before changing it.
  • Portcove will not back up or update this external installation. Back up its saves, settings and custom folders separately.
  • The inspected SDL2 build can copy older saves and settings into its shared profile folder when newer files are missing. Keep both profile folders before trying another copy.

Setup

  1. Keep the matching original

    Use your own unchanged US Super Mario 64 game in big-endian .z64 format. Drag the .z64 file into the game window or place a copy beside the game program before opening it. Keep your original separately. The game can copy it to your profile as baserom.us.z64. If a copy already exists there, the game keeps it when you select another file.

  2. Prepare the Windows game

    Unpack the complete Windows ZIP into a writable folder and finish the original-file setup. Keep the game program, lang, dynos, mods and libraries together. Add the working sm64coopdx.exe to Portcove with its containing folder as the start folder and retain your existing launch options.

  3. Play or replace your working game

    After adding your Windows or Linux game, choose Play. Use upstream tools to replace the game or manage its saves. Removing the Portcove registration leaves the game and data in place. Close the game and its updater before replacing files.

  4. Open the Linux or Steam Deck game

    Unpack the complete x64 Linux ZIP and run sm64coopdx from that folder so it can find its bundled libraries. If Portcove offers Use an existing installation, select the working Linux sm64coopdx program and set the unpacked folder as its start folder. The game needs glibc 2.34, GLIBCXX 3.4.29, OpenGL, SDL2, zlib and curl. The separate SteamOS archive in v1.5.1 has the same requirements and different default settings. The publisher directs Steam Deck players to the Linux package from v1.6 onward.

  5. Open the macOS app

    Choose the Intel or Apple Silicon ZIP that matches your Mac and keep the complete sm64coopdx.app. Start it directly and drag your original .z64 file into the game window. The v1.5.1 game requires macOS 11 or later. Its bundled updater requires macOS 12 or later.

Setup notes
Keep the game version and data you use
Before explicit Play, preserve the actual existing user profile and creating runtime. On Windows the upstream default checks %APPDATA%/sm64coopdx and can instead reuse a populated %APPDATA%/sm64ex-coop folder; an existing --savepath override changes that selection. Preserve both relevant roots and the actual selected path, copied ROM, saves, configuration, mods and caches. A new executable folder does not isolate these profiles. Do not change the path, adopt populated legacy data, add mods or migrate profiles through this guide. Upstream can start its own updater and successor process; close all game/updater windows and confirm they stopped before copying or replacing files.
Find your Linux or Mac profile
The game uses SDL’s per-user data folder. On Linux look in $XDG_DATA_HOME or ~/.local/share. On Mac look in ~/Library/Application Support. The game can reuse a populated sm64ex-coop folder when sm64coopdx is empty. Preserve the actual folder with your original copy, saves, mods and settings. If you use --savepath, preserve that selected folder.
Check the original game file
The v1.5.1 game accepts the big-endian US original with MD5 20b854b239203baf6c961b850a4a51a2. Other regions, byte-swapped images and modified files are different inputs.

Limitations and evidence

  • To move to v1.5.1 on Linux or Mac, replace the game using the complete upstream archive after backing up your actual profile. Upstream requires a manual update to replace the earlier updater.

Setup

  1. Check the required game files

    Use your own Super Mario 64 Nintendo 64 USA ROM. Check the required size and SHA-1 in games/sm64-us/profile.toml before importing. Keep the original separately. These instructions do not download or run it.

  2. Build from source on Linux

    Follow the upstream Linux prerequisites. From the checkout root, run .venv/bin/python tools/import_rom.py --profile games/sm64-us/profile.toml --rom "/path/to/your-ROM.z64" with your own .z64, .n64 or .v64 file. Run cmake --workflow --preset sm64-us-release, then ./build/sm64-us-release/bin/sm64-us. The default keeps the ROM external. Keep the ROM and any locally generated game code private, including builds that embed it.

Setup notes
Build from source on Windows x64
Follow the Windows setup guide in the upstream README for Visual Studio, Python and vcpkg. Use the same ROM profile with the Windows Python environment. From the checkout root, run .\tools\build_msvc_project.ps1 -Game sm64-us -Configuration Release in PowerShell. Start the resulting build/msvc/sm64-us/release/bin/Release/sm64-us.exe from the checkout root and keep its dependency DLLs beside it. Preserve the checkout’s private local/ directory and any custom data paths before rebuilding.
Prepare a private Steam Deck copy
Follow the upstream Steam Deck container guide on an x86-64 Linux PC and run ./tools/build_steamdeck.sh sm64-us after importing your ROM. Keep the resulting package folder together. Supply your matching ROM at the local/ path named in its included instructions, then add launch.sh to Steam as a non-Steam game with compatibility tools disabled. Preserve local/ from the old copy before rebuilding or replacing it. Keep private packages and generated game code to yourself. Portcove has not observed Deck setup or gameplay.

Limitations and evidence

  • The project provides a Castle Grounds screenshot. A complete playthrough has not been confirmed, and results from another game do not establish that this one works. Portcove has not confirmed setup or gameplay.
  • Portcove has not confirmed setup, gameplay, saves or updates for this experimental port.
