Setup

  1. Choose the single-player native client

    Use an already permitted complete iortcw1.51c Windows x64 package with matching game/renderer libraries. Select iowolfsp.x64.exe: the selected Windows producer uses the x64 suffix. Do not substitute original WolfSP, the dedicated server, another architecture or the separate multiplayer client. Its native SP main owns the normal frame loop.

  2. Prepare your own complete RTCW data upstream

    Finish upstream single-player setup with your own supported RTCW Main data, including pak0.pk3 and applicable sp_pak1/sp_pak2/sp_pak3 and patch-data-141/locale files. Use the upstream instructions matching the actual edition/language; keep compatible code/data together in a separate recoverable working copy. Multiplayer requires its own data/code and is outside this SP route. Core neither downloads patches nor imports/authenticates original PK3s or runs a setup script.

  3. Keep your launch settings and profile paths

    Use the actual prepared working directory and same supported literal arguments. Preserve established fs_basepath/fs_homepath/fs_game choices and absolute custom roots as actually configured. Review exact intent/consent, then choose Play separately. Do not override the host profile root or force an unrelated empty profile to attach the player.

  4. Preserve complete external state

    Default Windows home data follows the actual Documents/RTCW known-folder location; configured roots and Main/game subdirectories may differ. Preserve the whole runtime and original data plus actual configs/profiles/saves/screenshots/demos/mods/unknown files in every base/home/game/custom/legacy root. Keep the old creating tuple before any upstream replacement. GPL engine and additional SP/component terms do not license the original game; no multiplayer, mod, or cross-version save compatibility follows from this registration.

  5. Update the game and remove its registration

    Close every running copy before changing external files. You manage setup, game replacement, profile changes, data migration and recovery. Keep the working game version and every data folder, update it with the project’s tools, then review and select the changed executable before choosing Play. Portcove monitors only the process you selected and agreed to launch. It does not prevent other copies from running, restrict file access or take over unrelated helpers or replacement processes. Removing the registration leaves external files in place. This route does not offer Portcove downloads, setup, updates, backups, rollback, data migration or deletion.

Limitations and evidence

  • Use only a copy and content you are already permitted to use. These instructions do not establish permission for the original game or other components, or confirm the resulting game files.
  • These instructions do not confirm gameplay, saving, mods, network play, physical controls or behavior on other platforms.
  • Before updating the game, keep a recoverable copy of its working files and every location containing saved data. Another game folder may use the same profile.

Setup

  1. Choose the upstream build

    On Linux x64, choose the AppImage, Flatpak bundle or tar.gz. The tar.gz clients require glibc 2.38 or later, SDL2, zlib, Opus, Opusfile and Vorbisfile. The two desktop tar.gz archives need executable permission on the client files after extraction.

  2. Supply the original game data

    For an owned Steam installation the upstream engine can search standard Steam paths. For a manual desktop archive setup, copy the original files into main beside the extracted clients. For the AppImage, you can set an accessible game data root with +set fs_basepath and put main under that root. Single-player needs pak0.pk3 and sp_pak1.pk3 through sp_pak3.pk3. Follow the upstream list for the multiplayer packs. Leave the original game installation intact.

  3. Choose the client and preserve your profile

    Run iowolfsp for the campaign or iowolfmp for multiplayer using the executable for your computer. The Linux AppImage and Flatpak launch single-player unless --mp is the first argument. The iowolfded executable is the dedicated server. Before replacing the engine, back up the active fs_homepath and retain any custom fs_basepath and fs_game settings.

Limitations and evidence

  • The Apple Silicon archive requires macOS 15 or later and loads sdl2, opusfile, opus, libvorbis, libogg, jpeg-turbo, and freetype from /opt/homebrew. The publisher supplies no Intel Mac, Linux ARM64, or Android package in this release.
  • The Windows x64 clients need a compatible zlib1.dll, which is missing from the publisher's 1.0.0 ZIP.
