Setup notes
Set up CorsixTH on Linux
For a separately prepared copy, use the official x86-64 AppImage with FUSE support. Keep it in a writable folder, make it executable and open it yourself. The inspected build needs glibc 2.34 and libstdc++ with GLIBCXX_3.4.30. CorsixTH also documents the Flathub package com.corsixth.corsixth for x86-64 and ARM64. Open the installed app and select the folder with your Theme Hospital data. The Flatpak uses its own profile.
Set up CorsixTH on Mac
Open the upstream DMG and copy CorsixTH.app out of it. The reviewed bundle contains Intel and Apple Silicon binaries. Open the app and select your Theme Hospital data. Keep the complete bundle and open the app directly to play.
Keep the actual CorsixTH profile
The regular Linux and Mac builds normally use ~/.config/CorsixTH, or CorsixTH under XDG_CONFIG_HOME. A config.path.txt override can change that. Keep config.txt, hotkeys.txt, Saves, campaigns and any custom music or data paths. The Flatpak has a separate config tree under ~/.var/app/com.corsixth.corsixth. Close CorsixTH and preserve the actual profile and originals before updating the external copy.

Setup

  1. Use the appropriate runtime

    This reconstructs the DOS Theme Hospital executable. Its hospital.exe/hosp.exe outputs use DOS/4GW and DOSBox; they are not native Windows players to register directly. Before following the source build, establish the needed input and toolchain/component permissions: the guide names its accepted GOG offline installer/HOSPITAL.EXE, its first Nix shell downloads proprietary Watcom 10.5/10.6 CDs, and tools GPL does not grant rights to reconstructed, Miles, Smacker or Watcom code. An owned GOG copy alone does not settle every component. The conditional DOS build/run guide remains upstream; Portcove invokes no installer or toolchain. For a distinct managed native alternative, find CorsixTH in Discover.

Setup notes
Follow the current DOS build
The pinned master revision documents the DOS reconstruction. Use the matching owned GOG installer identified by upstream. After closing DOSBox, preserve build/run, including HOSPITAL.CFG and your saves, and keep the original data it links from orig. The earlier native branch instructions apply to a different revision.
