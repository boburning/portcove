Setup

  1. Prepare the Windows player with upstream

    Obtain an authorized upstream Windows package and extract the complete folder with its DLLs, GPU plugin, configuration and licenses. Follow the selected release README. The project code is MIT No Attribution; bundled ReXGlue and LGPL components have their own notices and source obligations. Those terms do not grant Pac-Man game rights. Public release digest metadata is not a local verification of downloaded package bytes.

  2. Supply your own 2007 Xbox 360 original

    Place your own Pac-Man Championship Edition 2007 package in game/ beside pacman.exe, or supply default.xex with media/ and data/. The selected source recognizes Xbox 360 STFS LIVE/CON/PIRS packages and XEX execution-info title ID 58410877. This title-ID check is not a full original-content hash or an entitlement check; the exact accepted original digest is not confirmed here. Check upstream’s requirements before setup. The supported SDK mounts a selected package read-only. Preserve your original dump; other Pac-Man editions are not equivalent.

  3. Add the prepared native player

    Finish upstream preparation deliberately outside Portcove. Choose pacman.exe with its containing package folder as working folder and no arguments for the documented portable layout. This is the native application using the ReXGlue event loop, not a setup launcher. If you intentionally use --game_data_root, --user_data_root or --cache_root overrides, retain those exact working paths. Saving launch details and Play remain separate actions. Steam Deck instructions use this Windows build through Proton and do not establish a native Linux player.

  4. Preserve portable data and upstream ownership

    Upstream/player owns installation and runtime replacement. Preserve game/, configuration, and userdata/ beside pacman.exe, including achievements, save-backups/ and cache/. If userdata/ cannot be created, the selected source falls back to Documents/pacman; explicit user/cache roots remain in effect. Upstream creates changed-save snapshots in save-backups/ and retains ten; that is upstream behavior, not Portcove backup coverage or a guarantee of save compatibility. Keep every active root and your own backup before updates; Portcove does not delete or roll back these external files.

Limitations and evidence

  • This guide follows the selected upstream source and release descriptions. Portcove has not checked the archive’s contents or checksum, installed prerequisites, or tested launch, graphics, gameplay or restoring real saves.
