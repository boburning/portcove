Setup

  1. Keep the complete compatible Half-Life engine tuple

    Use a permitted complete official FWGS Windows copy with your own compatible Half-Life valve data and the game libraries matching that engine. Select native xash3d.exe with its companion engine DLLs/resources. The normal launcher loads the engine in the same process. The default Windows engine is 32-bit for Steam game-DLL compatibility; a 64-bit engine needs compatible game libraries and does not automatically run 32-bit DLLs. Keep an already working tuple rather than mixing architectures, substituting a DLL/server, rebuilding an SDK or assuming arbitrary GoldSrc mods work.

  2. Retain the creating root and write directories

    Keep the actual prepared working directory, established game arguments and original valve/game trees. The engine can resolve its root from existing XASH3D_BASEDIR, otherwise its SDL base path with a working-directory fallback; it then changes to that root. An existing -rodir argument or XASH3D_RODIR can select a separate read-only data root. Preserve the creating environment and both actual roots; Portcove does not inject environment variables or force a new data layout. Keep the full writable game directory, saves, configuration, custom downloads/mods, logs and unknown files, plus all matching runtime libraries and read-only originals. Do not assume Steam’s profile or another runtime folder owns all state.

  3. Check the working copy before registration

    Finish setup with the project’s tools, then start and quit the copy you intend to add. Keep its game executable, working folder and supported launch arguments. Review those details in Portcove and agree to launch them, then choose Play separately. Adding a copy does not confirm its game files or save compatibility.

  4. Keep updates and removal under the existing owner

    Close every running copy of the game before changing files. Keep the working game version and every data and profile folder recoverable. Update it with the project’s tools, then review and select the changed executable in Portcove before choosing Play. You manage setup, updates, file changes, data migration and recovery. Portcove monitors the process you selected; it does not prevent other copies from running or restrict the game’s file access. Removing the registration leaves external files in place. This route does not offer Portcove downloads, setup, updates, backups, rollback, data migration or external-file deletion.

  5. Prepare a matching Mac engine and game tree

    Choose the official Xash3D FWGS Apple amd64 or arm64 tarball for Intel or Apple Silicon. Unpack it into a writable folder and keep its packaged Half-Life client and game libraries. Merge your compatible original Half-Life valve game data into that tree, preserving the matching engine libraries. Run the supplied xash3d from that folder.

Setup notes
Keep the external Mac game tree
Back up the complete working Xash3D folder and its actual save, config, mod and data roots before using an upstream replacement. Retain any separate read-only data root and the engine and game libraries that created the profile.

Limitations and evidence

  • Use only a copy and content you are already permitted to use. Engine licensing does not grant rights to original game assets, music, mods or bundled components.
  • Before updating the game, keep a copy of its working files and every location containing saved data. Choosing a different executable does not give it a separate profile.
