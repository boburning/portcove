Setup

  1. Supply your matching original

    For the managed Windows route, choose your own exact GoldenEye 007 NTSC-U USA big-endian .z64 original. Portcove verifies its declared identity and copies it to data/ge007.ntsc-final.z64 beside the player. PAL, Japanese, byte-swapped and modified images are not accepted by this contract. No BIOS or separate installer is required.

  2. Choose Play for first-run preparation

    Keep the complete official Windows ZIP together. Play starts ge007.x86_64.exe, which invokes its bundled frozen converter when generated sidecars are missing. Portcove does not run a discovered helper during download or setup, and does not certify successful upstream conversion or gameplay. If conversion fails, follow the selected upstream troubleshooting instructions and keep your original and saves recoverable.

  3. Use an existing copy on Linux or Windows

    For a copy you already have, keep the complete v0.5.0 folder and place your own matching USA NTSC-U big-endian ROM at data/ge007.ntsc-final.z64. Choose ge007.x86_64.exe on Windows or ge007.x86_64 on Linux, with its containing folder as the start folder. The Linux x64 kit uses glibc 2.29 or newer, system zlib and OpenGL, and its adjacent SDL2 library. Save your details in Portcove, then choose Play.

Setup notes
Preserve your actual data before changing copies
For an externally owned copy, preserve data/ge007.ntsc-final.z64, data/ge007.eep, data/ge007.ini, emulator-import backups and ppm screenshots, plus any selected custom locations. The upstream importer has 99 backup names and can overwrite its last slot when full. Keep generated sidecars and shader lists with their producing runtime; optional source/Python tools are separate deliberate actions. You or upstream provide external updates. Portcove registration does not update, back up, roll back or delete those external files.

Limitations and evidence

  • The upstream importer has 99 backup names and can overwrite its last slot when full.
  • On Linux v0.5.0, the in-game settings restart starts a new process that Portcove cannot track. Quit the game and choose Play again to keep the whole session visible in Portcove. If you already used the restart, close the new game window before changing the runtime or copying its data.

Setup

  1. Prepare the stock USA N64 data upstream

    Use a complete copy and components you are independently permitted to use, with your own stock GoldenEye007 USA N64 cartridge image. The reviewed 1.0.2b instructions accept .z64 big-endian, .v64 byte-swapped and .n64 word-swapped inputs; names/extensions are not identity checks. The expected stock size is12,582,912bytes; source normalizes byte order and checks header CRCs DCBC50D1/09FD1AA3 and full normalized CRC32 B6330846. These checks are not cryptographic authenticity or entitlement proof. Follow upstream preparation outside Portcove, retaining the original image. This is not the Xbox360 XBLA edition or another GoldenEye port.

  2. Keep the actual Windows package together

    The inspected ProjectMidas-v1.0.2b-windows.zip contains ProjectMidas.exe as an x86 (32-bit, PE machine014c) native player, SDL2.dll, Data, Mods, controller mappings and notices. Keep the complete extracted folder in a writable location. Do not infer AMD64 from the Windows asset label or transfer Linux/Deck results to it. This attachment obtains or executes no original, extractor, compiler, helper, launcher script or game.

  3. Select the normal prepared player

    After upstream setup has the intended ROM in Data or its already configured location, select ProjectMidas.exe, use its complete extracted package directory as working directory and leave arguments empty. Review the exact selected intent, then request Play separately. The source locates ordinary data/settings relative to its executable and runs the game in that process. An existing GE_ROM, midas.ini [data] rom value or explicit upstream source selection may choose another original; confirm the intended copy rather than creating an override here.

  4. Preserve the complete local data and settings

    Keep midas.ini, gamecontrolleruser.txt and the entire Data tree: Saves/eeprom.bin, Profiles, WeaponSets, MatchSettings, Devices, Logs and shader lists, plus Mods and all original/custom ROM locations. Older ge.ini can be renamed to midas.ini once by upstream, so preserve its existing predecessor and recovery copy too. Player profiles, controller layouts and multiplayer settings are part of the retained external data. This guide performs no migration, import, backup or deletion and promises no cross-port/save compatibility.

  5. Check maintenance, permissions and reported limits

    Quit the actual game normally before upstream repair or replacement; retain independent copies and review/relink changed executable bytes. Keep LICENSE.txt and THIRD_PARTY_NOTICES.txt. MIT covers Project Midas port code, not the decompiled game, GoldenEye or its assets; build-tool notices do not grant original-game rights. Linux blank-triangle limitations and upstream co-op/netplay/mod work remain at their own scope. No Portcove gameplay, multiplayer, save/reload, native-installed or Supported acceptance is claimed. Removing registration preserves all external files; managed install/update/rollback/backup/removal are unavailable.

Limitations and evidence

  • Keep the exact stock USA N64 image and the complete package-local Data/settings tree; this Windows player is x86, not an assumed x64 build.

Setup

  1. Check the required game files

    Use your own GoldenEye 007 Nintendo 64 USA ROM. Check the required size and SHA-1 in games/goldeneye-us/profile.toml before importing. Keep the original separately. These instructions do not download or run it.

  2. Build from source on Linux

    Follow the upstream Linux prerequisites. From the checkout root, run .venv/bin/python tools/import_rom.py --profile games/goldeneye-us/profile.toml --rom "/path/to/your-ROM.z64" with your own .z64, .n64 or .v64 file. Run cmake --workflow --preset goldeneye-us-release, then ./build/goldeneye-us-release/bin/goldeneye-us. The default keeps the ROM external. Keep the ROM and any locally generated game code private, including builds that embed it.

Setup notes
Build from source on Windows x64
Follow the Windows setup guide in the upstream README for Visual Studio, Python and vcpkg. Use the same ROM profile with the Windows Python environment. From the checkout root, run .\tools\build_msvc_project.ps1 -Game goldeneye-us -Configuration Release in PowerShell. Start the resulting build/msvc/goldeneye-us/release/bin/Release/goldeneye-us.exe from the checkout root and keep its dependency DLLs beside it. Preserve the checkout’s private local/ directory and any custom data paths before rebuilding.
Prepare a private Steam Deck copy
Follow the upstream Steam Deck container guide on an x86-64 Linux PC and run ./tools/build_steamdeck.sh goldeneye-us after importing your ROM. Keep the resulting package folder together. Supply your matching ROM at the local/ path named in its included instructions, then add launch.sh to Steam as a non-Steam game with compatibility tools disabled. Preserve local/ from the old copy before rebuilding or replacing it. Keep private packages and generated game code to yourself. Portcove has not observed Deck setup or gameplay.

Limitations and evidence

  • The project provides a gameplay screenshot. A complete playthrough has not been confirmed, and results from another game do not establish that this one works. Portcove has not confirmed setup or gameplay.
  • Portcove has not confirmed setup, gameplay, saves or updates for this experimental port.
