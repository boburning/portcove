Setup

  1. Prepare the exact European DS original

    Use the official v0.1.4 Windows setup with your own European Kingdom Hearts 358/2 Days DS ROM, game code YKGP/revision 0. The selected supported-ROM table gives SHA256 1ecf5e7a41a2ae48e7c5fd3f678e5a79e854d843f1a1fa3a952a41b14e51ec4f and header-free SHA256 d9e103c6ccd39d5b91e44d865983badc5e2af1674db404b3768557712038a373. Complete its own verification/extraction and settings first. Optional HD menus/videos/fonts require your own separately supported HD collection inputs; they are not necessary to attach the base player.

  2. Keep the complete prepared install

    The supported installer carries its Python/tools and prepares data locally; a developer SDK/build is a separate route. Retain the installed game, DLLs, data/, tools/, port/tools/, installer/, setup/state.json, mods/ and notices. Upstream’s default Program Files install uses an explicit writable-folder grant; this guide changes no permissions or system software. Preserve the actual already chosen per-user or administrator-created installation and do not select an unprepared read-only folder.

  3. Attach the native game, not its tools

    Select the installed khdays-native.exe, set working directory to its complete prepared install root and leave arguments empty for ordinary Play. Review the selected program, working folder and arguments and choose Play when ready. This matches the installer’s actual game shortcut. KH Studio and khdays-server.exe are separate editor/server programs, not the player. The native port finds data/extracted from its prepared root and runs the game there; no ROM-loader or shell wrapper is added. Close the actual game normally before upstream maintenance.

  4. Preserve saves, settings and generated user data

    Keep the whole writable install, especially saves/khdays.sav, saves/settings.ini, other slots/states/logs, original ROM, mods, locally generated HD data, setup receipts and recovery copies. The normal backup is a 64 KiB raw DS save; the selected Windows writer uses a sibling temporary file and replacement, but that source behavior is not a real-save restore observation here. Preserve original DS/save copies separately and do not infer every state or mod format is compatible. No save transfer, profile edit, import, permission change or deletion is performed.

  5. Keep optional content and maintenance ownership upstream

    Retain project, decompilation, SDL and other component notices; original DS and HD assets/fonts remain the user’s separately obtained content, not licensed by the tool’s source license. Example mods remain inactive until explicitly adopted upstream. Setup/repair and its self-update installer own replacement; finish those outside a running session, retain populated data/recovery and review/relink changed bytes. No private collection discovery, Steam registration, account/credential operation, online/multiplayer, full-campaign, native/installed, Supported or managed lifecycle acceptance is asserted.
