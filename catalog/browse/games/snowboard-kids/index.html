Setup

  1. Select your original game on first Play

    Choose Play, then select your own North American or Japanese Snowboard Kids ROM in the game menu. The player checks the game identity, normalizes supported byte orders and keeps its own copy in its profile, so keep your original separately.

  2. Keep the complete player package

    For a copy you manage yourself, keep the whole player folder together: SnowboardKidsRecompiled.exe on Windows, or the native player and its folder on Linux. Flatpak and macOS application bundles keep their upstream installation and launchers. To add that copy to Portcove, select the player and its folder.

Setup notes
Preserve your actual profile when updating
Keep the player's profile when updating: normally %LOCALAPPDATA%\SnowboardKidsRecompiled on Windows, ~/.config/SnowboardKidsRecompiled on Linux, or ~/Library/Application Support/SnowboardKidsRecompiled on macOS. It holds the copied originals, game_region.txt, saves, settings and mods, and on Windows local crash reports. On Windows and native Linux, portable.txt in the working folder stores data there instead; on macOS the marker belongs beside the application bundle. Portcove does not back up or remove the profile.
Keep Flatpak data alongside the actual profile
For Flatpak, also preserve the complete ~/.var/app/io.github.snowboardkidsrecomp.snowboardkidsrecomp folder. This build keeps additional writable mod data in its Flatpak data area, while the profile resolver still uses HOME/.config/SnowboardKidsRecompiled unless APP_FOLDER_PATH or portable mode selects another folder. Keep both the app data and actual profile when updating; Portcove does not back up or remove them.

Limitations and evidence

  • Upstream lists graphics and CPU requirements and Windows runtime prerequisites. Portcove has not observed native setup, gameplay or saves.
  • The package includes a modified RecompFrontend fork by cdlewis that the project license does not cover. Portcove downloads the package only from the project’s own releases. You need your own original game files.

Setup

  1. Select your own supported original on Play

    Choose Play, then select your own Snowboard Kids (USA) ROM, game code NSKE, in the player's file chooser. Upstream ROM-IDENTITY.md specifies its normalized identity and the supported N64 byte orders. The player remembers where your ROM is, so keep the original where you selected it.

  2. Keep the complete package for your system

    For a copy you manage yourself, keep the whole package together: SnowboardKidsEngine.exe on Windows or SnowboardKidsEngine on Linux, the matching modules/snowboardkids-us game module, assets and runtime libraries. The published beta includes a precompiled module, so normal players compile nothing. To add that copy to Portcove, select the engine and its folder.

Setup notes
Preserve the actual profile and active module
Back up the player's profile before changing versions: normally %APPDATA%\SnowboardKids on Windows or ~/.local/share/SnowboardKids on Linux, unless SBK_USER_DATA_DIR selects another folder in a copy you manage yourself. It holds settings, the remembered ROM location, Controller Pak .mpk saves, .sbks save states, logs and any user game modules. Loading a save state does not rewind Controller Pak storage. A game module in that folder, or one named by --module or SBK_GAME_MODULE, takes priority over the packaged module, so remove an old one after updating. Close the player before replacing a copy you manage yourself.

Limitations and evidence

  • The package includes a modified RecompFrontend fork by cdlewis that the project license does not cover. Portcove downloads it only from the project’s own releases. You need your own original game files. Source and first-party checks do not confirm gameplay, real saves or installed behavior.
  • This is an upstream beta. Portcove has not observed native setup, gameplay or saves. A game module left in the profile's modules folder overrides the packaged one.
