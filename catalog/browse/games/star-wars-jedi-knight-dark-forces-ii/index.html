Setup

  1. Complete original-game setup in OpenJKDF2

    Extract the complete Windows player package and choose openjkdf2-64.exe with its containing folder as the working directory. On first Play, follow OpenJKDF2’s picker to import your own supported Jedi Knight: Dark Forces II installation. Upstream recommends GOG and also supports Steam/original game layouts. Soundtrack disc extraction is separate; the player does not supply original game data. The published player is a debug build and includes an upstream runtime updater.

  2. Save launch details before Play

    Save launch details in Portcove, then choose Play separately. Registration does not adopt the files or grant managed Backup, Rollback or removal of the external folder.

  3. Add the game and manage your files

    Register the real Windows player with its matching working directory and separate literal arguments; do not select a converter, installer or updater as the game player. Complete any original-data or prerequisite setup deliberately through upstream instructions. Registration does not perform or authenticate that preparation, and Play is a separate explicit action.

  4. Prepare the Apple Silicon build

    Unpack the official v0.9.9 macos-debug.tar.gz using Mac archive tools and open OpenJKDF2_universal.app on Apple Silicon with macOS 12 or newer. Choose your own complete Jedi Knight: Dark Forces II installation in its setup flow. Keep the Resource and Episode folders from the same game edition.

  5. Prepare the upstream Android build

    Install the official v0.9.9 ARM64 Android APK on an OpenGL ES 3 device. In Android Files, open the OpenJKDF2 files and put your own Jedi Knight: Dark Forces II game folders inside jk1/. Keep the Resource and Episode folders together. Preserve your jk1/ profile before app removal and use a same-signed upstream APK for in-place replacement.

Setup notes
Build and run upstream on Linux
For Linux x86-64 or ARM64, follow the 64-bit Linux/SDL2 section of the v0.9.9 build guide at https://github.com/shinyquagsire23/OpenJKDF2/blob/v0.9.9/BUILDING.md. Check out tag v0.9.9 before initializing the submodules. Use the guide’s Clang setup and launch the built player from the checkout as documented so it can find its libraries. Copy the Resource and Episode folders from your own matching Jedi Knight installation into the working folder as lowercase resource/ and episode/. Linux filenames can be case-sensitive. Keep the working copy and actual profile when rebuilding. You build, launch and update this Linux copy through upstream.
Preserve imported Jedi Knight data and profiles
Before changing versions, preserve the actual imported game-data folder and player profiles/saves, resource, episode, MUSIC, expansions and custom mods, plus local cvars/binds/registry JSON, screenshots and any selected custom paths. Setup may use the user AppData location or an existing working-folder resource/jk_.cd layout; copying just the executable is not a data backup. Follow the upstream game folder import and keep the exact profile containing saves, settings and imported data. Retain the creating app before changing upstream versions.
Keep external ownership and all player data
You and upstream own this external runtime, original files, saves, settings and profiles. Preserve the complete working copy and every actual data/profile location with the game closed before upstream replacement. Registration-only removal preserves all external files; managed Install, Update, Backup, Rollback, migration and external deletion are unavailable. Keep the current working copy until another version is ready.
