Setup

  1. Use the complete upstream player

    Keep the complete downloaded or existing player together. Its BSD-3-Clause license covers the project code, not the generated game code or your original files.

  2. Prepare your own supported original upstream

    Use your own supported Xbox 360 Tony Hawk’s Project 8 World v1.0 USA/Europe original. Upstream expects title415607DD/media2CB96AE4 and default.xex 8,237,056 bytes with SHA256 cfc732340e55defda400e25f03231aa9bb65fd9545b618212f69a4952384a5dd. Complete normal upstream ISO/extracted-tree verification outside Portcove; Japan, demo and Korean inputs are not interchangeable. For 0.3 prepare a fresh full player folder rather than mixing 0.1/0.2 binaries.

  3. Add the completed game player

    Select upstream’s documented public native supervisor in the complete prepared package folder: thps_p8_launch on Linux and macOS, thps_p8_launch.exe on Windows. Do not select Project8Recomp or thps_p8_gui: those entrypoints spawn and exit. The public supervisor waits for its child. Use the established supported literal game arguments from the working GUI setup, including --game_data_root=<actual prepared game directory>, --mnk_mode=true and --gpu_plugin=xenos where these are the established settings. Preserve other existing supported GUI settings/performance flags and optional breadcrumb path. Keep the default single-instance guards; do not add force, sweep-only, check-only or custom-child switches.

  4. Review launch details, then choose Play

    Review the selected game executable, working folder and launch arguments, then agree to use them. Choose Play separately when you are ready. Adding this copy does not prepare, update or replace its external files. Removing its registration leaves all external files in place. Before changing versions, close the game and its companion programs and keep the working copy and all data. Review and select the changed executable before playing again.

  5. Keep upstream maintenance outside the attached session

    Upstream preparation and the public supervisor retain child and cleanup ownership. Its normal launch waits for the game, preserves active-instance guards and performs upstream cleanup; Portcove does not create a wrapper or select an internal child. Close supervisor/game/companions before upstream replacement; retain old data and review changed selected bytes.

Setup notes
Keep your working game and every data folder it uses
Preserve the complete creating player, original game/ tree, saves/, config/settings.toml, config/install.toml, logs/ and every effective external save, data, cache, profile, mod, backup or custom root. Retain all companion native files. Keep the supported frame cap and existing configuration; never infer save migration from the engine family.

Limitations and evidence

  • Before changing versions, keep a copy of the complete working game, original files and every profile, save, cache, mod, backup, temporary file and custom data location. Another executable may use the same data. Portcove does not offer updates, backups, rollback, data migration or deletion for these external files.
  • The package includes recompiled game code that the project license does not cover. Portcove downloads it only from the project’s own releases. You need your own original game files.
  • Upstream verifies Linux x86_64 (its main platform) and macOS on Apple Silicon, where heavy scenes are still slow. Windows is experimental: upstream has tested it only under Proton. Upstream warns uncapped cutscenes can run 3–5x speed; retain the default cap. Portcove has not run it.
