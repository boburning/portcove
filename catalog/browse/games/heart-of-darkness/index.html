Setup

  1. Prepare a coherent desktop Heart of Darkness copy upstream

    Use a permitted, already working native desktop hode build with your own supported Windows Heart of Darkness data: hod.paf, setup.dat and the matching *_hod.lvl, *_hod.sss and *_hod.mst files. Keep the complete same-edition tree. The selected source’s RELEASES.yaml records specific French/German/Italian/Japanese Win32 sets and separate demo/promotion/PlayStation tuples; those are not interchangeable or evidence for every retail patch. Observed official Switch/Vita binaries are not desktop packages. Complete any upstream desktop build outside Portcove; no compiler or converter is run here.

  2. Select the actual desktop player and paths

    Select the prepared native hode player for the current host, not hode.nro, hode.vpk, a setup script or original-game executable. The selected desktop Makefile produces hode; an actual Windows build must be prepared upstream rather than inferred from console assets. Keep its established working directory and literal --datapath=ABS and --savepath=ABS options if configured; defaults use the working directory.

  3. Retain progress and the creating data roots

    Keep hode.ini in the creating working directory, setup.cfg and screenshot-*.bmp in the effective save path, complete originals, runtime dependencies, custom and unknown files. The source writes setup.cfg through that selected save path; a relative save path depends on the creating working directory. Keep compatible old runtime and saves; no backward-save or full-campaign observation is claimed.

  4. Review the completed player and intent

    Finish setup with the project’s tools, then start and quit the permitted copy you intend to add. Keep its game executable, working folder and supported launch arguments. Review those details in Portcove and agree to launch them, then choose Play separately. Adding a copy does not confirm its original game files, gameplay or save compatibility.

  5. Retain upstream replacement and external ownership

    Close every running copy of the game before changing files. Keep the working game version and every original-file, profile and data location it uses. Update it with the project’s tools, then review and select the changed executable in Portcove. You manage setup, replacement, file changes, data migration and recovery. Portcove monitors the process you selected; it does not restrict file access or prevent other copies from running. Removing the registration leaves external files in place. This route does not offer Portcove downloads, setup, updates, backups, rollback, data migration or external-file deletion.

Limitations and evidence

  • Use only a copy and components you are already permitted to use. Engine licensing does not grant original-game, music, mod, middleware or redistribution rights.
  • Before changing versions, keep a copy of the working game and every data and profile folder it uses. Another executable may use those same folders.
