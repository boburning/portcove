Setup

  1. Run the upstream Windows setup

    Open the download folder and run the portable Windows EXE yourself. It is a setup program: choose a folder for the upstream Wargus copy.

  2. Choose your Warcraft II files

    Start the installed Wargus player. When it asks, select your Warcraft II DOS or Battle.net game files, or GOG offline installer. Wargus extracts the required data using its own setup tools.

  3. Use the installed player

    Select the installed player in Portcove, using its own folder as the start folder. Review the launch details and add the game, then choose Play.

  4. Keep the complete prepared runtime

    Finish extraction with upstream before registration. Keep wargus.exe, its matching Stratagus engine, DLLs, scripts, campaigns and extraction tools together; the portable setup includes these components. Select wargus.exe with its installed folder as working directory and leave arguments empty for the normal game. Do not select the downloaded setup program, wartool.exe, a converter, the MIDI helper or uninstaller. The documented Windows launcher waits for its engine; Portcove supervises the selected launcher rather than adopting arbitrary replacement processes.

Setup notes
Preserve converted data and player settings
Keep your original DOS or Battle.net/GOG inputs and the complete actual converted-data directory. A portable-install marker can keep data in the application folder; otherwise the launcher can use Documents/Stratagus/data.Wargus. An existing local data set can also be reused. Engine preferences, logs and saves can use the application/data folder or Documents/Stratagus, and a deliberate -u option changes the user directory.
Updates and backups
Close the game before using its setup or update tools. Back up your converted data, settings and saves first. Review the changed launch details before playing again. Portcove leaves this installation’s files in place when you remove the entry and does not update or back them up.

Limitations and evidence

  • Preserve the complete actual locations with the creating runtime. Upstream version checks can trigger in-place extraction or migration; back up before changing versions and do not infer older-save, mod or expansion compatibility.
