Setup

  1. Prepare the official desktop variant and your own Source data

    The source project links official desktop packages from deathkiller/jazz2. Use a permitted complete Windows package for your CPU and chosen renderer, including its companion DLLs and Content directory. The 3.9.0 archive has separate x64, x86 and ARM64 trees; select the actual working tree’s normal Jazz2.exe, not Jazz2.Server.exe or a different renderer/CPU by filename alone. Follow upstream’s instructions to copy your permitted supported Jazz Jackrabbit 2 original/shareware data into that tree’s Source directory before running.

  2. Complete preparation without replacing your state

    Keep the selected tree as working directory so Content, Source and Cache resolve together. Missing Anims.j2a/AnimsSw.j2a does not produce a playable installation. With originals present, upstream converts data during startup, can replace converted cache contents, and records its own binary Source.idx; Portcove does not perform that conversion or confirm it succeeded. Preserve the full original Source, custom Content, complete Cache and unknown files before changing versions. The package-owned Source/_Readme.txt does not make the entire Source directory disposable.

  3. Keep the creating settings and progress location

    Retain an existing working-directory Jazz2.config or the actual per-user Jazz² Resurrection settings directory used by the copy. If already configured, preserve the literal /config argument and its actual path; it is /config, not --config. Do not create a portable config or use /reset-config just to attach the game. Preserve the full selected config/user directory, progress, resume state and runtime/cache trees, including shader/download/custom content, before upstream updates. Another renderer or runtime folder can still use the same user profile.

  4. Check the working copy before registration

    Finish setup with the project’s tools, then start and quit the copy you intend to add. Keep its game executable, working folder and supported launch arguments. Review those details in Portcove and agree to launch them, then choose Play separately. Adding a copy does not confirm its game files or save compatibility.

  5. Keep updates and removal under the existing owner

    Close every running copy of the game before changing files. Keep the working game version and every data and profile folder recoverable. Update it with the project’s tools, then review and select the changed executable in Portcove before choosing Play. You manage setup, updates, file changes, data migration and recovery. Portcove monitors the process you selected; it does not prevent other copies from running or restrict the game’s file access. Removing the registration leaves external files in place. This route does not offer Portcove downloads, setup, updates, backups, rollback, data migration or external-file deletion.

Limitations and evidence

  • Use only a copy and content you are already permitted to use. Engine licensing does not grant rights to original game assets, music, mods or bundled components.
  • Before updating the game, keep a copy of its working files and every location containing saved data. Choosing a different executable does not give it a separate profile.
