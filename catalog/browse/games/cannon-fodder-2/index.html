Setup

  1. Use this original game and edition

    For the documented DOS CD route, copy all files from your own Cannon Fodder 2 CD/GOG installation into OpenFodder/Data/Dos2_CD, not just CF_ENG.DAT. Keep the matching upstream Campaigns data pack. Cannon Fodder 1 and its demos do not supply this game. Keep your originals elsewhere unchanged; upstream handles its own data recognition and preparation. A Portcove registration does not authenticate original-game files.

  2. Prepare upstream and select the real player

    The official Windows EXE is the upstream installer. Run setup deliberately, choose its data destination and complete the campaign/data layout, then register the installed OpenFodder.exe with its installation folder as working directory. Do not select the installer, bundled VC runtime setup or uninstaller as the player. The Campaigns data pack is required even when original retail data is present. Use the upstream campaign menu to select this game.

  3. Prepare the Linux source build

    Use upstream’s tagged Git checkout with its submodules, SDL2 and SDL2_mixer. Also install your distribution’s Vorbis development library, because linking the player can fail without it. Follow the supplied build instructions. The supplied Makefile puts the player in Run/OpenFodder. Set up the separate upstream campaign data pack and your own Cannon Fodder 2 inputs. Use your own Cannon Fodder 2 AmigaDOS files and an appropriate ADF extraction tool. The first game’s DOS data and SOS Unpacker do not supply this sequel. The engine first checks its working directory, then XDG_DATA_HOME/OpenFodder and each XDG_DATA_DIRS/OpenFodder, followed by ~/.local/share/OpenFodder and /usr/local/share/OpenFodder. Keep the actual data, Campaigns, Saves and configuration roots together. On Linux x86-64, select the native Run/OpenFodder executable from your completed upstream build and its Run folder as the working directory. Keep the upstream data pack and the full Scripts, Data and Campaigns layout there. Review your selection and save it, then choose Play and select this game’s campaign upstream. The separate Flatpak instructions use its own launcher.

  4. Add the game and manage your files

    Finish setup with the project’s tools before adding the game. Portcove saves your selected executable, working folder and launch arguments; choose Play separately when you are ready. You manage this game’s files, original files and profile. Removing its registration leaves those files in place. Portcove does not offer updates, backups, rollback, data migration or file deletion for this external copy. Keep a working copy and its data before changing versions.

Setup notes
Use the Linux Flathub package
Install org.openfodder.OpenFodder from Flathub on x86-64 or ARM64. It supplies the campaign definitions and first-game demos. Start the installed app through your applications menu. For original data or writable saves, create Data and Saves folders under ~/.var/app/org.openfodder.OpenFodder/data/OpenFodder. For the sequel's DOS CD campaign, put all its own DOS CD or GOG source files in Data/Dos2_CD under that root. Follow upstream instructions for the sequel's Amiga data. The bundled demos are from Cannon Fodder 1. The Flatpak package manager owns installation and updates. Preserve the actual data and save folders before changing versions.
Keep the actual original and player data
The installer can choose Documents/OpenFodder or an installation-local data layout. The complete root contains Data, Campaigns and Saves; openfodder.ini in the working directory can add other search paths. Preserve the actual chosen root, Saves, campaign/mod files and configuration with the player closed before upstream replacement. The original Amiga/DOS, demo and sequel data have separate preparation requirements.

Limitations and evidence

  • Preserve the actual chosen root, Saves, campaign/mod files and configuration with the player closed before upstream replacement.
  • These sibling routes use upstream setup, launch and replacement. Keep the creating runtime and actual player files recoverable before changing versions.
