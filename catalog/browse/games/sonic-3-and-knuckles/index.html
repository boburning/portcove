Setup

  1. Choose the managed base game or the upstream launcher

    The managed Windows route uses your matching Sonic 3 & Knuckles raw Genesis original and starts the combined base game directly. Portcove manages its declared local saves, settings and quickstate thumbnails. For the full launcher and optional imported campaigns, extract the complete official Sonic3KRecomp package into a separate folder you control, keep that folder stable across upstream updates, and select your own matching ROM there. Sonic3Recomp and SonicAndKnucklesRecomp are different game variants.

  2. Keep optional campaign preparation with upstream

    The optional Sonic CD, Sonic 1/2 and Megamix campaigns and Mighty/Shadow are experimental and off by default. Follow the included upstream guides and supply the extra originals only if you choose those features. Sonic CD import needs Python 3.11+ and Pillow, and records absolute paths under sonic-cd-imports beside that copy’s settings. Use that importer in your stable external copy, not a managed version folder that will change after updates. Portcove never runs the converter during discovery. Register the external player or launcher deliberately, save launch details, then choose Play separately.

Setup notes
Keep current progress and the creating build for quickstates
Before changing an external copy, close the game and back up its settings, cartridge saves, campaign companions, quickstates and thumbnails, and the separately selected original/converted packs. Quickstates require the same build and configuration; runtime rollback does not rewind saves or guarantee old-reader compatibility. Upstream or you update the external copy, which has no Portcove-managed Backup or Rollback. An older managed v0.5.3 copy keeps working. A version change can proceed when the extra data locations are empty; otherwise Portcove reports the conflicting paths and keeps the current copy. Keep that working version and its data rather than deleting it to get the newer copy.

Setup

  1. Keep the matching original

    Use your own compatible original combined Sonic 3 & Knuckles ROM, such as Sonic_Knuckles_wSonic3.bin from an existing lawful Steam copy. The separate Sonic 3 or Sonic & Knuckles games and unrelated collections are different inputs. Upstream can discover an existing Steam copy or ask for the ROM on first startup; it does not provide the original. The old Steam product is no longer sold.

  2. Finish upstream setup and select the real player

    Use the publisher-recommended Windows stable v26.03.28.0 package linked from sonic3air.org, rather than silently selecting a newer test release. Extract the complete sonic3air_game folder and finish its Manual.pdf setup, including the matching original. Keep data, scripts and companions together. Register the real Sonic3AIR.exe; bonus/oxygenengine/OxygenApp.exe is an engine/development helper, not this game. Use the selected player’s containing folder as working directory and keep the already working literal arguments; do not invent shell commands.

  3. Prepare the Linux x64 player

    Extract the official sonic3air_game.tar.gz into its complete sonic3air_game folder and follow its Manual.pdf. Open sonic3air_linux from that folder for upstream setup and original selection. The reviewed player needs glibc 2.34, GLIBCXX 3.4.29, OpenGL and curl. Use the same folder when adding the working player to Portcove. The optional setup_linux.sh only installs and marks its desktop shortcut executable.

  4. Prepare the macOS app

    Open the official stable Mac disk image and use the complete Sonic 3 AIR.app. The bonus Oxygen app is a development tool. The reviewed build requires macOS 10.15 on Intel or 11 on Apple Silicon. Finish original selection in the upstream app and follow its Manual.pdf for the data folder.

  5. Prepare the Android app

    Install the official stable Android APK and select your own combined Steam ROM using the app’s file picker. If the picker is unavailable, close the game and open the ROM with Sonic 3 A.I.R. from your file manager. Use Options > System > File Browser to access data in Android/data/org.eukaryot.sonic3air/files. Keep an independent copy of saves, settings and mods before updating, and leave the old app installed when applying a compatible in-place update.

  6. Register the existing player and use explicit Play

    You manage this external game and all its original files and saved data. Portcove saves the executable, working folder and launch arguments you select; it does not authenticate the complete package or original game files. Choose Play explicitly when you are ready. Removing the registration leaves external files in place. Portcove does not offer updates, backups, rollback, data migration or external-file deletion for this copy. Finish setup with the project’s tools and add only a working game. These instructions do not confirm successful setup, gameplay or save-state compatibility.

Setup notes
Keep the game version and data you use
Before explicit Play, preserve the actual existing saved-data folder and its creating runtime. The upstream Windows default is %APPDATA%/Sonic3AIR, shared across separate player folders; a savedata folder beside Sonic3AIR.exe selects portable data instead. Preserve whichever is actually in use, including settings, progress and mods. A separate ZIP folder does not isolate the shared profile. Do not create a portable folder over old data, transplant profiles or infer downgrade/rollback compatibility. Optional soundtrack download and mods remain upstream/user choices.
Find the data folder on Linux or macOS
Linux normally uses $XDG_DATA_HOME/Sonic3AIR or ~/.local/share/Sonic3AIR. A savedata folder beside sonic3air_linux selects portable storage. The upstream macOS app uses ~/Library/Application Support/sonic3air/Sonic3AIR. Use the app’s data or mods folder command to confirm the actual location before replacing the player.

Limitations and evidence

  • Add your prepared game to Portcove, then choose Play separately. These instructions do not establish Portcove-managed installation, the authenticity of original game files, gameplay or save-state compatibility.
  • Managed original selection and complete external/portable data ownership need separate qualification. The guide does not admit upstream first-start discovery as a Core source contract or authorize populated-profile migration.

  • A separate ZIP folder does not isolate the shared profile. Do not create a portable folder over old data, transplant profiles or infer downgrade/rollback compatibility.
