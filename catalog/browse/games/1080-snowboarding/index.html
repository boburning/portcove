Setup

  1. Check the required game files

    Use your own 1080° Snowboarding Nintendo 64 JU revision 0 ROM. Check the required size and SHA-1 in games/1080-us/profile.toml before importing. Keep the original separately. These instructions do not download or run it.

  2. Build from source on Linux

    Follow the upstream Linux prerequisites. From the checkout root, run .venv/bin/python tools/import_rom.py --profile games/1080-us/profile.toml --rom "/path/to/your-ROM.z64" with your own .z64, .n64 or .v64 file. Run cmake --workflow --preset 1080-us-release, then ./build/1080-us-release/bin/1080-us. The default keeps the ROM external. Keep the ROM and any locally generated game code private, including builds that embed it.

Setup notes
Build from source on Windows x64
Follow the Windows setup guide in the upstream README for Visual Studio, Python and vcpkg. Use the same ROM profile with the Windows Python environment. From the checkout root, run .\tools\build_msvc_project.ps1 -Game 1080-us -Configuration Release in PowerShell. Start the resulting build/msvc/1080-us/release/bin/Release/1080-us.exe from the checkout root and keep its dependency DLLs beside it. Preserve the checkout’s private local/ directory and any custom data paths before rebuilding.
Prepare a private Steam Deck copy
Follow the upstream Steam Deck container guide on an x86-64 Linux PC and run ./tools/build_steamdeck.sh 1080-us after importing your ROM. Keep the resulting package folder together. Supply your matching ROM at the local/ path named in its included instructions, then add launch.sh to Steam as a non-Steam game with compatibility tools disabled. Preserve local/ from the old copy before rebuilding or replacing it. Keep private packages and generated game code to yourself. Portcove has not observed Deck setup or gameplay.
