Setup

  1. Play the managed Windows copy

    Choose Play to open the packaged houses. Aerofoil creates its player profile in your Windows Documents location. Use the separate upstream tools and a prepared copy if you want to import and manage other content outside this route.

  2. Prepare a separate copy from upstream

    Choose the official package ending in -win64.zip and extract it to a separate folder. Keep Aerofoil.exe and its packaged companions together. The tools ZIP is a separate download for importing additional original-format content. For a prepared copy, use documented literal arguments if your chosen version needs them. Close the player before applying upstream updates.

  3. Select the prepared player

    Select Aerofoil.exe and use its containing folder as the working directory. Leave arguments empty. Keep the complete independently permitted runtime and finish the title-specific preparation before Play.

Setup notes
Keep custom houses and saved games
Aerofoil stores custom houses, saved games, scores, preferences, logs and exports in the Aerofoil folder in your Windows Documents location. Managed and prepared copies can share this profile. Back it up separately and check compatibility before changing versions.
Registration ownership and removal
Portcove records the selected executable, working folder and literal arguments after review. Play is separate and only the selected process is supervised. You and upstream own replacement and updates; relink changed executable bytes after reviewing them. Removing this registration preserves every external file. Managed installation, backup, rollback, migration and deletion are not offered for this external copy.
Player-data ownership
You and upstream own the external copy's data: the actual Aerofoil folder in your Windows Documents location, including custom houses, saves, scores, preferences, logs and exports. Back up these locations separately; registration does not migrate or certify their compatibility.
Managed runtime ownership
Portcove installs and replaces its separate official runtime using the declared release rules. Existing external registrations retain their files and user/upstream ownership. Runtime rollback carries current declared data; it does not rewind saves or establish older-runtime compatibility. Gameplay and populated-save compatibility remain separate qualification. The managed copy has no declared local player data to back up. Back up the external profile separately.
