Setup

  1. Set up Mega Man X4 with your matching disc

    Use your own unmodified USA Mega Man X4 PlayStation disc, serial SLUS-00561, represented as its CUE plus every referenced BIN. Keep the complete disc set and follow upstream’s normal release setup outside Portcove. A patched/undubbed disc, another region or a bare filename is not this accepted source contract. Upstream documents compatibility SHA-256 3ceab06ac99add4035f912188bcbf5b16c02056f46a33d38ff0c8dbce6cb613b; Core does not acquire or authenticate original media. The release includes OpenBIOS; separately owned retail BIOS and optional Japanese movie inputs remain optional and separate.

  2. Keep the completed player and toolchain together

    The reviewed v1.0.22 Windows x64 package’s native player is MegaManX4Recomp.exe. Keep game.toml, input.ini, bios, assets, mods and the complete overlay_toolchain beside it. Runtime-native overlay generation/caching can invoke bundled psxrecomp helpers and compiler components upstream; this guide neither runs those helpers nor gives Core authority to build or trust a mutable native-code cache. Attach only the intended completed native player, with its established working directory.

  3. Add the completed native player, then choose Play

    Finish setup with the project’s tools, then select the Windows game executable, working folder and supported launch arguments in Portcove. Review and agree to those details, then choose Play separately. Keep the complete package together and close the game and companion programs before changing files. You manage this external copy; Portcove does not replace it or back up, convert, migrate or delete its data. Removing its registration leaves those files in place. Source review and automated registration checks do not confirm an installed game session, successful forced exit, gameplay or save compatibility.

  4. Keep matching game versions, cards, states, mods and caches

    Upstream remains the single runtime, toolchain and data owner. Preserve the entire installation, original disc/BIOS inputs and every effective profile before changes. Selected Windows source reads settings.toml beside the executable; the release game.toml sets memcard_dir to saves, while settings or --memcard-dir and explicit per-card paths can override it. Relative card directories resolve from the executable; the framework fallback without a configured directory is the executable directory. Preserve both card slots, states/rewind data, settings.toml.bad, mods, generated native overlays and all custom paths. State/rewind compatibility depends on the creating release and mod layout, and co-op/netplay profile behavior is not qualified here. Optional diagnostics can include initial private cards under executable-local saves/diagnostics independently of a card override; leave capture disabled and preserve any existing diagnostics-location.txt and reports. Updating the selected executable requires deliberate upstream-compatible replacement and fresh attachment review, not a Core migration or universal PS1 infrastructure campaign.

Limitations and evidence

  • Before changing versions, keep a copy of the working game and all original files, profiles, mods, generated caches and custom data locations. Another executable may use the same saved data.
