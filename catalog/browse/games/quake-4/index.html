Setup

  1. Prepare your own Xbox 360 Quake 4 files

    Use your own Xbox 360 Quake 4 ISO, or complete matching extracted files including default.xex and the game’s PK4 data. PC Quake 4/openQ4 files are not interchangeable. Complete the supported upstream setup/build and original selection before attachment. The selected v0.2.0 source documents ReXGlue SDK v0.10.0 plus this title’s patches, generation from the owner’s XEX and a completed Windows native player; the observed setup EXE is a preparation program, not the locally generated game.

  2. Keep the actual completed native-renderer unit

    Use the completed q4hle.exe from the upstream player or documented Q4_HLE-enabled build, retaining all matching runtime/rendering DLLs, settings/resources and original files. Its selected Q4HleApp is the normal q4 application with a title-specific native Direct3D 11 renderer; the SDK/Xenos q4.exe and legacy-runtime builds are distinct variants, not interchangeable qualification. Do not register Quake4-Setup-0.2.0.exe, a compiler, profiler or renderer-shadow test as normal Play.

  3. Attach the in-process game

    Select the completed q4hle.exe, use its complete player/build-output directory as working directory and leave arguments empty after upstream original/settings preparation. Review the selected program, working folder and arguments and choose Play when ready. The native entry inherits the q4 application’s ordinary path selection and runtime loop; it remembers the existing game location in q4.toml and can request a valid own ISO or extracted default.xex when missing. Finish those prompts upstream before retrying. Keep Q4_HLE_NATIVE/shadow/debug choices at the installation’s intended ordinary settings and close the actual game normally.

  4. Preserve q4 settings, original location and user data

    Keep q4.toml beside the executable, the original ISO or complete extracted game tree at its configured location, and the full active user/cache/data roots. The pinned SDK’s Windows default user root is Known Documents/q4, including relocated Documents folders; existing user_data_root/cache_root flags or configuration override it. This title’s inspected SDK patch allows an ISO file as game_data_root and does not replace that user-root selection. Preserve saves, profile/settings, caches, logs, historical variants and recovery separately; do not merge legacy, PC openQ4 and Xbox-runtime saves or create a fresh replacement root.

  5. Keep renderer, compatibility and maintenance limits

    Retain title, patched ReXGlue SDK, compiler, shader/audio/library and all other component notices, separately from the original game. The initial-level/menu observations and native-renderer claims are upstream evidence, not full campaign, physical-controller or real-save restore qualification here. Upstream/player owns preparation and replacement: quit normally, preserve data/recovery and review/relink changed bytes after updates. This existing-player route grants no source/distribution rights and supplies no Portcove managed install/update/backup/rollback/migration/external deletion.

Limitations and evidence

  • Select the actual completed q4hle.exe and preserve q4.toml, the original location and existing q4 data root. PC openQ4, the SDK renderer and legacy builds have separate compatibility and maintenance scope.

Setup

  1. Use your own PC Quake 4 installation

    Use the official v0.13.2 Windows x64 package and a legitimate supported PC Quake 4 installation, such as Steam or GOG. This is the PC engine route, not the Xbox 360 recompilation or a standalone replacement for original assets. Keep all selected package/components you are independently permitted to use and the original installation.

  2. Keep the complete client and game modules

    Retain openQ4-client_x64.exe, OpenAL/renderer libraries, baseoq4/ with its SP/MP game modules and runtime packages, docs and notices together. The separate openQ4-ded_x64.exe is a server, not normal Play. Retail game assets remain under the original installation’s q4base/; do not copy them into baseoq4/. The selected player route uses OpenGL by default; experimental Vulkan, Windows ARM64, Linux/Deck and macOS claims remain separate, unobserved qualifications.

  3. Attach the native client with its retail root

    Select openQ4-client_x64.exe, use its complete extracted package root as working directory, and set +set fs_basepath "the actual PC Quake 4 root containing q4base". Review the exact path and intent and choose Play when ready. Point at the root, not q4base/ or baseoq4/. Retain any already chosen supported fs_savepath or mod configuration rather than selecting a new profile. Quit the client normally before ending the session; developer, replay and dedicated-server modes do not replace ordinary Play.

  4. Preserve the actual openQ4 save root and compatibility

    The selected Windows source normally resolves Known LocalAppData/openQ4, with environment/Saved Games fallbacks; +set fs_savepath can select an existing explicit root. Keep the actual resolved root, configs, saves/screenshots, logs, mods, cache and recovery, plus legacy/stock Quake 4 saves separately. The current policy writes v3 and gates an exact wire ABI, verified build floor and integrity; it rejects v2, newer payloads and unsupported ABI tuples. Format eligibility is not runtime certification, and stock/old/cross-platform saves are not automatically compatible. No save conversion, restore, merge or deletion is performed.

  5. Keep distinct licenses and upstream replacement

    Engine code is GPLv3 with retained Doom 3/Doom 3 BFG notices and accompanying Additional Terms. The openQ4-game libraries are Quake 4 SDK-derived and retain the SDK EULA; original Quake 4 assets have separate ownership. Retain all accompanying terms; the provenance inventory is an engineering record, not a blanket permission or compatibility conclusion. Upstream/player owns runtime replacement and recovery: finish updates outside a session, preserve data and review/relink changed bytes. No campaign, physical controller, multiplayer, installed/native, Supported or managed install/update/rollback/backup/deletion acceptance is asserted.

Limitations and evidence

  • Select the native x64 client and point fs_basepath at the PC Quake 4 root. Keep q4base and baseoq4 separate; preserve the actual save root and do not infer stock, legacy or cross-platform save compatibility.
