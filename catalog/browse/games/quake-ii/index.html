Use the publisher’s Windows nightly and the matching SDL dependency. For Linux, build from the pinned source.

A release may contain research reports rather than a playable package.

Setup

  1. Prepare the Windows nightly

    On Windows x64, choose q2repro-rerelease-client_win64_x64.zip from the publisher. Use a separate writable engine folder and install the Microsoft Visual C++ x64 runtime. For the November 12, 2026 build, extract SDL3.dll from the official SDL 3.4.14 Windows x64 runtime ZIP at https://github.com/libsdl-org/SDL/releases/tag/release-3.4.14 and place it beside q2repro.exe. Check a newer build’s requirements before replacing either file.

  2. Use your installed Quake II rerelease

    Run q2repro.exe from the extracted engine folder. It can discover an installed Quake II rerelease. Keep the complete original installation, with its rerelease PAK files and game DLL, in place. To add the Windows player to your Library, select q2repro.exe and use its own folder as the working directory.

  3. Build the Linux player

    Check out commit 9619f8e20a74dec67dff0b20eb8f34a3adf926da with its submodules. Follow BUILDING.md for Meson, a C and C++ toolchain, and the Linux dependencies. Install the build with Meson so it places the native game library in baseq2 under the configured library directory. For an uninstalled build, pass the absolute Meson build directory containing baseq2/game_x86_64.so with +set libdir. Use +set basedir with the folder containing the rerelease baseq2 directory and +set homedir with a separate writable profile. Keep the source installation intact.

Limitations and evidence

  • On Windows in rerelease mode the engine uses the Windows Saved Games folder under NightDive Studios/Quake II. Back up that shared profile before switching engines. A separate executable folder does not isolate the profile.
  • The publisher marks native rerelease game-DLL multiplayer as unfinished. The nightly release can replace its ZIP in place.

Setup

  1. Select the actual Yamagi player

    Use an already permitted complete official Yamagi Windows8.70a copy matching your architecture, including its compatible renderer/game/SDL libraries. The official site identifies8.70a as an SDL-library repack of engine8.70; this source binding is not new artifact-byte verification. Select yquake2.exe itself. On Windows quake2.exe is a wrapper that starts and waits for yquake2.exe; it is not the direct game entry, and the original retail executable shares that wrapper name. Do not select q2ded or infer player identity from a basename alone.

  2. Finish classic original-data and patch preparation

    Follow upstream8.70 installation instructions in a separate recoverable working copy. Classic retail/CD/QuakeIV/Steam/GOG data still requires the full QuakeII3.20 CTF patch. Your own baseq2/pak0.pak and video directory combine with the required patch pak1.pak/pak2.pak and compatible engine/game DLLs; incorrect/mixed patch sets can crash. Upstream instructions about replacing old executables/DLLs apply to that separate prepared copy, not deletion of your only originals by Core. Core invokes no patch EXE/extraction/helper and authenticates no original data.

  3. Keep expansions and remaster data separate

    The Reckoning/xatrix and Ground Zero/rogue each need their own original pak/video and matching addon code; do not infer those from base-game setup. QuakeII Remaster uses a separate Yamagi project/data contract and is not a substitute for classic assets. Keep complete original and prepared sets plus each compatible addon/runtime tuple recoverable. Engine/component terms do not grant rights to originals, music, mods or sibling renderer packages.

  4. Keep your working folder, data and profile choices

    Use the actual prepared runtime directory as working directory and retain established supported literal arguments, including actual -datadir, -cfgdir and -portable choices. The default Windows user root is actual Documents/YamagiQ2; -cfgdir changes its selected subdirectory and -portable omits that home-profile search. Do not force portable mode or rewrite a host root during registration. Preserve complete runtime/DLLs, baseq2 and other selected game directories, actual config/saves/screenshots/demos/music/mods/custom/legacy roots and unknowns. Finish upstream normal start/quit, review intent/consent and choose Play separately. No actual backward-save or addon compatibility is certified.

  5. Update the game and remove its registration

    Close every running copy before changing external files. You manage setup, game replacement, profile changes, data migration and recovery. Keep the working game version and every data folder, update it with the project’s tools, then review and select the changed executable before choosing Play. Portcove monitors only the process you selected and agreed to launch. It does not prevent other copies from running, restrict file access or take over unrelated helpers or replacement processes. Removing the registration leaves external files in place. This route does not offer Portcove downloads, setup, updates, backups, rollback, data migration or deletion.

Limitations and evidence

  • Use only a copy and content you are already permitted to use. These instructions do not establish permission for the original game or other components, or confirm the resulting game files.
  • These instructions do not confirm gameplay, saving, mods, network play, physical controls or behavior on other platforms.
  • Before updating the game, keep a recoverable copy of its working files and every location containing saved data. Another game folder may use the same profile.
