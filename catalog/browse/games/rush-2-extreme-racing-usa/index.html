Setup

  1. Prepare the exact Rush 2 original

    Use your own Rush 2: Extreme Racing USA N64 ROM. The selected native entry requires normalized ROM hash XXH3-64 ee71d0c9ca3a66df, internal name RUSH 2, game ID rush2.n64.us. Finish original selection, controls and settings in the complete official v1.0.38 Windows player first. Optional Rush 1/Rush 2049 or arcade/DC imports require their own originals and qualification; they do not replace the separate ProjectR implementations or their outstanding conditions.

  2. Keep the complete independently permitted player

    Retain Rush2Recompiled.exe, its DLLs, assets/fonts, controller database and accompanying files as one complete player you are independently permitted to use. A shared N64 runtime or frontend does not establish another title’s permissions, layout or save compatibility. The selected RecompFrontend revision d0d90ba49f46f4896aaeda362056c21b1e342561 is distinct from the separately recorded unchanged-b1 grant; no source reuse, modification or redistribution permission is inferred here.

  3. Attach the integrated native game

    Select Rush2Recompiled.exe, use its complete extracted player directory as working directory and leave arguments empty after upstream setup. Review the selected program, working folder and arguments and choose Play when ready. The selected executable hosts the frontend and native runtime together. Do not register a simulator, developer capture tool, importer-only utility or another racing port. Quit the actual game normally before maintenance.

  4. Preserve the existing data choice and Controller Pak

    Without an existing portable.txt in the working directory, the exact frontend selects Known LocalAppData/Rush2Recompiled on Windows; an existing marker selects that directory instead. Keep this choice and any pending data_move.txt state unchanged. Preserve the entire active root, saves/, mods/, mod_config/, old ghosts and recovery, stored ROMs, control/settings JSON and backups. This title implements its own 32 KiB Controller Pak image beside the save path under saves/, normally rush2.n64.us.mpk; port 1 owns that Pak and other ports report Rumble Paks. SaveType::None in generic registration does not mean progress is disposable. Do not merge Paks, switch roots or infer state/save compatibility from another game.

  5. Leave data moves and replacement upstream

    The upstream data-location workflow schedules a copy for the next launch, and its migration code handles older ghost layout. Complete any already scheduled move upstream and retain both roots/recovery before attachment; this guide performs no move or deletion. Upstream/player owns runtime replacement: close the game, retain data and review/relink changed bytes. Component rights, physical multiplayer/rumble, native gameplay and real-save restore remain separately scoped. Portcove attachment supplies no managed install/update/backup/rollback/migration/deletion.
