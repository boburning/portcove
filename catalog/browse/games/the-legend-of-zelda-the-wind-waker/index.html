Setup

  1. Use the exact GameCube edition and Windows route

    Use your own The Legend of Zelda: The Wind Waker GameCube USA GZLE01 revision 0 disc image in the supported ISO/GCM representation. Wind Waker HD for Wii U and other revisions are separate contracts. The Windows release is a native x86-64 host using translated game code and a Dolphin-derived runtime; this does not establish a completely native implementation. Follow the selected upstream release or its supported owned-disc source build; do not redistribute a private game-derived build.

  2. Keep the complete Windows package or completed build

    Retain the complete BlueWake folder, BlueWake.exe, game module, DLLs, resources and notices. The inspected selected release is v0.10.0; some README/build-page links still name v0.9.0, so do not combine their files or treat that older text as a second artifact selection. Windows 10/11 x64, Direct3D 12 and the release CPU requirements apply; the normal game module uses x86-64-v3 features including AVX2, FMA and BMI2. A source build has its own Visual Studio/Clang, Python, Git, CMake and Ninja prerequisites; the packaged player and build tools are different routes.

  3. Add the existing native frontend

    Select BlueWake.exe in the complete BlueWake folder, use that containing folder as working directory and leave arguments empty. Review the selected program, folder and arguments, then choose Play when ready and use its own disc picker. Keep the selected disc at its existing location. RVZ and other compressed formats require their separate upstream conversion/preparation; Portcove does not acquire originals, run a converter or supply keys. Preserve project, runtime, original-game and optional texture-pack rights separately.

  4. Preserve the active memory card and configuration

    Keep the whole %APPDATA%/BlueWake folder, including GZLE01.card, sram.bin, settings.ini, logs, caches, texture/mod data and existing backups. An existing portable.txt beside BlueWake.exe instead selects its adjacent user folder; preserve that marker and populated folder. Do not create a new portable marker to add the reference or assume data moves automatically. Wind Waker Recomp 0.4 can share the same Windows data root; preserve a separate copy before switching upstream builds. Renaming a Dolphin .gci to .card is not a save conversion, and Dolphin save states are not game saves.

  5. Keep maintenance and observations separate

    Close the actual game and helpers before upstream replacement, rebuild, save import or recovery. Use upstream’s documented save tools on retained copies; Portcove does not migrate or repair cards. Review/select the executable after changes. Only the selected program is observed; removing the reference preserves external files. Managed acquisition/update/backup/rollback and Supported qualification are not supplied. Upstream playability, save-survival and controller reports are not Portcove gameplay, native or real-save observations.

Limitations and evidence

  • Keep BlueWake.exe with its complete Windows release/build and your own GameCube USA revision 0 disc. Preserve the actual %APPDATA%/BlueWake or existing portable user folder, including GZLE01.card; Wii U HD and Dolphin save states are separate.

Setup

  1. Prepare the supported Wii U base game upstream

    Use your own The Legend of Zelda: The Wind Waker HD USA title 00050000-10143500 or Europe 00050000-10143600, version 0. The selected setup accepts a supported extracted game or archive; updates contain different code and are not interchangeable with the base version. Complete upstream validation, extraction and local native-code build using the official v0.5.0-devel.f5554821 Windows x86-64 package. An already extracted supported game needs no console-key operation. Private originals, decryption keys and any optional imports remain entirely upstream/user-owned.

  2. Keep the complete completed-build tree

    Retain the full release and data/ tree: install.json, guest-sdk.json, bin/wwhd.exe and its matching runtime DLLs, prepared game/, save/, user/, captures, tools/ and sdk/. The packaged Wind Waker HD.exe is the setup interface, not the locally generated game. The ordinary translated product is distinct from the optional decomp product and code-mod builds; keep their maintenance and compatibility separate. Retain project MPL-2.0 and all Cemu/runtime/library/component notices without treating them as a license to original game data.

  3. Attach the actual native product

    Select the completed data/bin/wwhd.exe, set working directory to that actual data/ directory and use --game "the existing prepared game directory" --save "the existing active save directory". This matches the selected producer’s native-game shortcut and bypasses the detaching Windows setup launcher. Review the exact paths and intent and choose Play when ready. Preserve an existing --user-dir or --data-dir override if already used; do not add one to create an empty profile. Keep the game and matching DLLs together and close its actual native window normally.

  4. Preserve portable saves, settings and custom roots

    The release’s existing portable.txt beside the native EXE keeps user settings/controls/states/shader caches under data/user; the game save normally stays under data/save. Without that marker, source-build user configuration can use %APPDATA%/WWHD; an existing WWHD_USER_DIR/--user-dir takes precedence. Preserve every actually active root, original/base game, install receipt, save backups, user data, captures and prior installation. Cemu/Wii U, GameCube or earlier-port save import is an explicit upstream conversion/copy step, not an attachment guarantee. Do not change markers, merge saves, copy a new empty user tree over an old one or delete recovery.

  5. Keep preview, setup and maintenance limits

    The selected artifact is a development preview; Windows ARM64, Android, Linux and macOS have separate setup/runtime evidence. Upstream owns toolchain/source preparation, updates, optional code mods and recovery. Finish rebuilds/replacement outside a game session, preserve populated data and review/relink changed bytes. This route does not run setup, obtain private input or assert full gameplay, native/installed observations or real-save restore. Portcove supplies no managed installation/update/backup/rollback/migration/external deletion for the selected player.

Limitations and evidence

  • Select completed data/bin/wwhd.exe with the actual prepared game and save paths. Keep the whole data tree and existing portable/user-root choice; the top-level Windows setup interface detaches.
