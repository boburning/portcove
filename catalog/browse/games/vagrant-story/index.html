Setup

  1. Use the exact USA PlayStation original

    Use your own Vagrant Story USA SLUS-01040 CUE/BIN disc. The selected game.toml identifies data Track 01 by size 750643152 bytes and SHA1 38c63db6c49a06b91d87cd5a4e31b1ec68fe212c, boot SLUS_010.40; this is not a whole-CUE or all-region fingerprint. Finish original selection and settings in the upstream integrated launcher first.

  2. Keep the complete hybrid Windows package

    Use the official v0.1.11 Windows x64 package as one complete unit, including VagrantStory_Recompiled.exe, game.toml, bios/, assets/, mods/, licenses/ and overlay_toolchain/. The player reads original code/data from the user’s disc and locally compiles battle/menu/title overlays with bundled gcc in the background, retaining cache/; other code still uses the interpreter and TinyCC. First preparation can take an hour or more and resume later. Do not call this fully static coverage, impose a short first-use gameplay deadline or substitute an interpreter-only demo for a prepared route.

  3. Attach the integrated native player

    Select VagrantStory_Recompiled.exe, use its full player directory as working directory and leave arguments empty to retain the ordinary integrated launcher and settings. Review the selected program, working folder and arguments and choose Play when ready. Its selected native runtime hosts the frontend/game in process. Do not select codegen setup, overlay_toolchain tools, profiling/headless modes or another Vagrant Story implementation. Finish upstream preparation/maintenance and close the actual game normally.

  4. Preserve executable-relative cards and generated cache

    The selected Windows runtime resolves relative settings and data from its actual executable directory. Keep the complete writable root, settings.toml, disc.cfg/bios.cfg where present, game.toml, input/bindings, mods, cache/ and all actual card paths. game.toml configures saves/, normally card1.mcd and card2.mcd, with existing explicit slot/directory overrides retained. Preserve durable cards separately from states and original disc/legacy copies. Do not clear slot paths through a new --memcard-dir argument, merge roots or discard generated overlay work. No migration, card restore or deletion is performed.

  5. Retain exact component and maintenance terms

    The selected psxrecomp revision uses PolyForm Noncommercial 1.0.0; the exact recomp-ui revision is MIT. Keep those distinct terms plus OpenBIOS, bundled GCC/Binutils/mingw-w64, TinyCC, font and other notices; a project or UI license does not replace noncommercial restrictions or license original assets. Only use components you are independently permitted to use. Upstream/player owns updates and locally generated output: quit normally, keep populated cards/cache/recovery and review/relink changed bytes. No full playthrough, physical controller, real-save restore, native/installed, Supported or managed lifecycle acceptance is asserted.

Limitations and evidence

  • Keep the complete player, local compiler/cache and existing card roots. Preserve the hybrid execution and exact noncommercial/component terms; another Vagrant Story port is a separate qualification.

Setup

  1. Use the full experimental Windows tester package

    Keep VS-NativePort-0.0.11-win-x64.zip intact with VS.Launcher.exe, VS.Desktop.exe, VS.Extract.exe, runtime DLLs, resources, licenses and release.json. This is an unfinished Vagrant Story port for Windows 10 1903+/11 x64, with gameplay, cutscene, rendering and audio limits. Native game saves and memory-card/ending conversion are different contracts; complete original memory-card support is not established. No finished-game, native/controller, real-save or Supported acceptance is claimed.

  2. Complete the upstream exact-disc and converter checks

    Supply your own USA SLUS-01040 single-track MODE2/2352 disc as BIN, supported CUE/BIN or parentless single-data-track CHD. The decompressed BIN must be exactly 750,643,152 bytes, SHA-256 25221D7F8FDB2C4490AF12D9E82F0E58BDD6ACB43387F9082B3C5E79DFE090C0, SHA-1 38C63DB6C49A06B91D87CD5A4E31B1EC68FE212C. A matching name is insufficient; CHD hashes apply to its decoded content, not container bytes. Complete upstream Start-Game.cmd dependency checks and launcher setup first, including an explicitly chosen compatible FFmpeg with the required encoders. Software installation and original/converter acquisition remain separate user/upstream actions, not Portcove operations.

  3. Add the ordinary native launcher

    Select VS.Launcher.exe in the complete tester folder, use that containing folder as working directory and leave arguments empty. Review the selected program, folder and arguments, then choose Play when ready. Use the upstream disc, save-folder and converter pickers and its Play control. The launcher verifies the full image for each Play, prepares assets and starts VS.Desktop.exe with their context. Do not substitute VS.Extract.exe, Start-Game.cmd, a converter, or context-free VS.Desktop.exe as the same route; no integrity refusal is bypassed.

  4. Keep per-user prepared assets and separately selected saves

    Preserve the full %APPDATA%/VS-NativePort/VagrantStory directory with prepared assets, completion inventories, launcher selections, logs and retained failed/replaced staging as present. Also retain the exact game-save folder you selected, including slot00.vssave through slot99.vssave and recoverable .bak files as present; it is independent of installed program files and prepared assets. Keep the original disc available for later verification and preserve custom --save-dir choices. Do not delete retained failure directories, merge original memory cards or reset path selections to register the game. Portcove performs no source conversion, save migration, backup or restore.

  5. Leave updater and recovery ownership upstream

    The launcher owns its offered update checks, consent and replacement/recovery flow; registration does not select an update or install FFmpeg. Quit the actual game/helpers before maintenance or recovery, retain prior complete program/data/save copies and review/select the current launcher after changes. Portcove observes the selected launcher only; a finished activity does not prove all child processes stopped. Removing its reference preserves external files. Managed installation/update/backup/rollback, full-session tracking and Supported qualification are not offered. CC0 project terms, retained earlier GPL grants, third-party libraries and original-game rights remain separate.

Limitations and evidence

  • Select VS.Launcher.exe in the complete Windows tester package after upstream dependency/disc setup. Keep the exact USA image, %APPDATA%/VS-NativePort/VagrantStory assets and independently selected save folder; experimental limits and original memory-card conversion remain explicit.
