Setup

  1. Prepare your own Xbox 360 game upstream

    Use a complete copy and components you are independently permitted to use, with your own supported The Bigs 2 Xbox 360 disc image. Complete the upstream first-launch extraction and settings outside Portcove, keep independent original media, and retain the exact accepted edition/revision. This reviewed route does not establish every region or patched image as compatible. No disc, helper, compiler or game is obtained or executed by this guide.

  2. Keep the complete official player

    The inspected v1.1 Windows ZIP contains TheBigs2-windows-x64/thebigs2.exe as an AMD64 native player with matching runtime libraries. It already contains the native game program; the first-launch UI extracts the original game data rather than compiling a new native player. Keep the complete package and notices. A development source build requiring Clang 20/ReXGlue is a separate route, not a prerequisite inferred for this existing player.

  3. Add the prepared player

    Select thebigs2.exe, use the complete extracted TheBigs2-windows-x64 directory as working directory and leave arguments empty. Review the exact intent and request Play separately. The selected source configures paths, handles setup and resumes the linked game in process. If setup or disc extraction is still required, finish it outside the attached attempt. Quit the game normally; forced termination does not guarantee save flushing.

  4. Preserve the actual portable and external roots

    On Windows a writable executable folder enables upstream portable mode: preserve game/, config/thebigs2.toml, saves/ with profiles and achievements, cache/ and logs/. A non-writable folder instead uses the existing platform configuration path, normally %APPDATA%/thebigs2, and the runtime’s actual user-data/cache roots; preserve those independently rather than assuming all saves are in APPDATA. Existing command-line data/cache overrides and configuration take precedence. Upstream can copy old profiles into a new portable saves/ folder when it is absent; retain both originals and destinations. This guide performs no migration or deletion.

  5. Keep original and component permissions separate

    Retain the selected project’s Unlicense notice and its explicit exclusion of original/recompiled game code, the ReXGlue BSD-3-Clause notice and all other dependencies. Roboto and Barlow have separate Apache/OFL terms. No component grant licenses the original game or third-party mods; use only a complete copy you are independently permitted to use.

  6. Maintain the external copy and its limits

    Quit the actual game before upstream replacement, changing extraction/settings or restoring profiles. Keep independent recovery copies and review/relink changed executable bytes. Upstream explicitly reports the Windows package was cross-compiled and tested only through Wine; that does not establish physical Windows, full-game, save/reload or installed-app acceptance. Removing registration preserves external files; managed install/update/rollback/backup/removal and Supported status are not offered.

Limitations and evidence

  • Preserve the active portable saves/configuration or external runtime paths. Wine-only upstream package testing is not Windows or complete-game qualification.
