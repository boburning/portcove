Setup

  1. Start from a permitted, fully prepared Windows copy

    Use an already-permitted working v2.0.2 Skate 3 Recomp copy prepared through its supported upstream flow with your own legally obtained Xbox 360 base game and required Title Update 3. Fresh package use/component/notices acceptance remains held separately. Finish original extraction, TU3 staging and one successful normal startup outside Portcove before adding it. Core does not ingest the disc/TU package, run code generation or authenticate the whole prepared tuple. Do not treat a filename or size as complete original identity.

  2. Check the required update and optional DLC

    This build executes TU3 code. Upstream rechecks its two TU payloads at normal startup and can return to its setup wizard if they are missing or changed; finish upstream recovery again before Core Play or relink. Upstream defaults skate3_auto_install_dlc to true and may import owned DLC found in executable-side, game-side or user-data dlc folders into the profile. Complete desired owned-DLC handling upstream and preserve those folders and the actual setting; configure it off upstream if you do not want that import. Portcove does not authorize DLC acquisition or perform this preparation.

  3. Select the actual prepared native game

    Select skate3.exe with the actual working copy’s creating working directory and literal arguments. A prepared copy can use normal zero arguments; retain the supported --game_data_root path form used by your working launch when required. Keep actual --user_data_root and --cache_path overrides when used; cache_path is this SDK’s option, not an invented cache_root argument. Without an explicit game root, upstream can resolve game below the working directory or configuration directory, so changing CWD can select other data. Save launch details, then choose Play separately.

  4. Use a permitted Linux copy upstream

    Keep the v2.0.2 Linux x64 skate3 executable and its matching librexruntime.so together in a writable folder. The archive needs Vulkan, GTK 3, glibc 2.35 and libstdc++ with GLIBCXX_3.4.30. Run skate3 from that folder. Complete the base game and TU3 setup with your own inputs in the upstream wizard.

  5. Use a permitted Apple Silicon copy upstream

    Keep the experimental v2.0.2 skate3recomp.app intact in a writable folder you control. Open it there and use the upstream wizard with your own base game and TU3. Keep the adjacent game and config data with this app. The bundled player targets macOS 12 on Apple Silicon.

  6. Leave replacement, restart and data management upstream

    Upstream owns runtime and player-data mutation. Backend Apply & Restart can start a successor and close the selected process; complete that separately before relinking and choosing Play again. Core supervises the selected native process, not every successor. The SDK has a ten-second forced-exit shutdown watchdog, so an exit code is not proof of graceful saving or clean shutdown. Registration offers no managed update, backup, rollback, migration or external-file deletion. Removing registration preserves all external files.

Setup notes
Find Linux and Mac player data
Back up the actual game, settings, saves and mods before replacing the copy. Preserve data beside the Linux executable or Mac app and any separate profile. The default POSIX profile is under XDG_DATA_HOME/skate3, or ~/.local/share/skate3 when XDG_DATA_HOME is unset. Keep any existing portable marker, saves folder and custom roots with their creating copy.
Preserve the creating profile and portable choices
The normal Windows user root is APPDATA/skate3, with its actual Documents fallback/history and explicit user-root choices preserved. Existing portable.txt beside the executable takes precedence for the whole user root; an explicitly custom cache can remain separate. A pre-existing saves directory beside the executable redirects saved-game content only and does not migrate earlier saves. Do not create/remove portable markers or switch profiles as part of registration. Keep the whole runtime, game/TU3/originals, DLC/imported content, settings/profile files, saves, caches, mods, logs, unknowns, old histories and all custom paths before upstream changes.
