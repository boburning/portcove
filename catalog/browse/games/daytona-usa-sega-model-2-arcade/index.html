Setup

  1. Complete the documented upstream build deliberately

    Use source and components you are independently permitted to use. This route has no observed public runtime release: finish the documented Windows setup/source build outside Portcove before registration. Upstream setup can install Visual Studio C++/Clang and other development tools and fetch pinned dependencies; review that activity yourself. A source checkout or generated C++ alone is not a completed player. Keep the complete working project, build outputs, supplied runtime companions and notices.

  2. Supply the exact arcade ROM set for that build

    Use your own MAME-format daytona93.zip/.7z for Daytona USA Deluxe ’93, or daytona.zip/.7z for Revision A (1994), with the upstream-required members. These are separate compiled variants, not interchangeable input names. The source has per-file size and CRC checks for the selected set, including the different program/sound ROMs; a matching filename alone is insufficient and CRC is not cryptographic entitlement or whole-archive authentication. Keep all original archives unchanged. Console Daytona titles and other arcade revisions are outside this guide.

  3. Add the actual completed Windows player

    Select the matching completed daytona.exe from the output location printed by upstream setup: normally build/Release/daytona.exe (or build/daytona.exe with Ninja) for daytona93, and the corresponding build-daytona/ output for Revision A. Use the project root containing roms/ and those build folders as working directory. Supply --rom and the absolute path to your own matching archive as two literal arguments. The native process owns both its launcher and game loop. If your established setup also uses --profile <name>, preserve that exact profile argument. Do not select a setup/recompile script, test/oracle executable or another variant. Saving launch details and Play are separate actions.

  4. Check the Revision A cabinet choice

    Revision A’s initial twin-cabinet configuration may require upstream Test mode to choose a single cabinet; no network/link/wheel acceptance is supplied.

Setup notes
Preserve separate settings and runtime ownership
Upstream/player owns toolchain setup, ROM generation, rebuilding and runtime replacement. Windows settings, EEPROM, backup RAM and logs use %APPDATA%/daytona-recomp/daytona93 or daytona, with a separate <set>-<profile> folder when --profile is used; preserve launcher.ini, ioboard_eeprom.bin, backup_ram.bin, daytona.log and every active profile. Retain the entire working project, originals and old complete player before updating/rebuilding, then review/relink changed selected bytes. Removing registration preserves external files; Portcove does not own backups, rollback, save migration, compatibility or deletion.
