Setup

  1. Keep a permitted complete native player

    Use an already working official v1.5.5.5 Windows x64 dbz3.exe and components you are independently permitted to use. Keep all matching runtime and GPU DLLs, and the graphics and VC++ prerequisites used by that installation. The project’s MIT licence does not grant rights to original media or every packaged component. Older v1.2.1 test results do not apply to this version. This game is Budokai 3 HD; do not select the HD Collection menu, Budokai 1 or another project.

  2. Finish original selection and onboarding upstream

    Use your own Xbox 360 Budokai 3 HD US/NA or EU/PAL original. Keep the matching 4,890,624-byte yae3_xenon.xex or yae3_xenon_eu.xex and regional us/ or eu/ files, or the complete supported ISO at its current path. Compare the separate XEX and AFS hashes in the tagged baserom.md; a filename, menu match or short runtime checksum does not check the full disc. Complete the game’s picker, cache, region and settings setup before adding it to Portcove. The HD Collection root menu XEX, PS2 files and optional cross-game or modding tools are different inputs.

  3. Select the normal completed application

    Select dbz3.exe itself with its writable installation folder as the working directory. A normally configured copy needs no arguments; keep any supported arguments or custom profile settings your working copy already needs. The launcher’s PLAY button starts the game inside this application; close the application to end the selected session. Finish original-file setup first: its missing-data picker can start another instance and close the selected one, which Portcove may not follow. Do not select diagnostic or automation modes, an SDK, a build script or a modding kit.

  4. Review Play and manage updates yourself

    Review and consent to the selected executable, working directory and arguments, then choose Play separately. Portcove tracks the selected process; other game instances run separately and the game is not sandboxed. You and upstream manage preparation, repairs, profiles and updates. Close every game instance before changing files, keep the previous working runtime and current data, then relink and review the changed executable. Removing the registration leaves all external runtime, original and player files in place.
