Forza Horizon (Forza Horizon 1: ReImagined)

An independent Forza Horizon 1: ReImagined implementation with project-reported racing, free roam and co-op. The Windows installer or Linux Flatpak/tar.gz launcher downloads tools and builds locally from your own 2012 Xbox 360 disc, GOD or extracted game. TU4 is optional for Rally and 1000 Club. The launcher manages setup and updates. macOS is a source experiment without a launcher download: opening drives render, but full races, save/reload and physical controllers remain unconfirmed. Exact PC package architecture, original revision/hashes and further BIOS/firmware requirements are unconfirmed. Portcove has not confirmed setup or gameplay.

Setup

  1. Prepare your own Xbox 360 original upstream

    Use the official v0.2.4 Windows setup and complete its supported original-file selection, game-code build and graphics/settings preparation. Inputs are your own Forza Horizon Xbox 360 disc image, Games on Demand package or complete extracted folder, title ID 4D5309C9. The selected base manifest identifies XEX module hash D48ABF1704CE5C4A; optional Title Update 4 uses version 0.0.4.12/module hash 336A44DC03EC8782. These module identifiers are not whole-disc cryptographic hashes. Retain owned update/DLC inputs separately.

  2. Select the installed waiting launcher

    After setup succeeds, select the actual installed forza-launcher.exe, use its complete installed directory as working directory and leave arguments empty. Keep its bundled files intact. Review the selected program, working folder and arguments and choose Play when ready, then use its ordinary Play. The selected GUI creates a game Session, polls its child until exit and waits for that child when closing. Keep the launcher open while the game runs, then close both normally. Do not select ForzaHorizon1-ReImagined-Setup-0.2.4.exe, an update helper, bare forza.exe, server or command-line build/extract mode.

  3. Keep the exact launch context

    The launcher passes the actual game-data root and selected user/cache/profile paths, writes the game configuration and supplies graphics/session environment. It also handles save preparation and post-session processing. Directly starting forza.exe with default paths would instead risk selecting Documents/forza and omit that context. Keep the already selected local or Xenia-derived profile, original/base or TU4 build, DLC and graphics configuration; do not switch them merely to attach the player. Optional online, public sharing, haptics, VR, account or token operations remain upstream/user choices and are not performed here.

  4. Preserve both settings and game-data roots

    Keep %APPDATA%/ForzaReImagined with launcher.json, settings/logs and private profile information, plus the actual game-data root. New Windows data normally uses %LOCALAPPDATA%/ForzaReImagined; an existing Documents/forza install can remain active, and configured data roots or a failed legacy carry can retain another actual root. Preserve originals, saves, profile/Xenia copies, DLC, photos, backups, cache and both historical/active roots. Upstream carry operations copy without deleting the source and do not justify merging or deleting existing profiles. No data relocation, save editing, migration, restore or deletion is performed here.

  5. Keep upstream ownership and qualification limits

    The upstream launcher owns compiler/source staging, preparation, self-update and failed-build recovery. Retain project GPLv3-or-later, ReIGlue/ReXGlue, compiler, bundled libraries and component notices; they do not license the original game, DLC, mods or shared content. Finish updates outside a game session, preserve recovery and review/relink changed bytes. The observed setup EXE header is the installer, not proof of the compiled game’s architecture or behavior. No native/installed, online/multiplayer, full campaign, real-save restore, Supported or managed lifecycle acceptance is asserted.

Limitations and evidence

  • Select the installed forza-launcher.exe after upstream preparation. Its waiting session preserves the actual data/profile context; keep both launcher settings and all active/historical game roots.

Setup

  1. Finish upstream preparation first

    Use the official v0.7.1 Windows launcher package, keeping PinyonShiftLauncher.exe and pinyon-shift-source.zip together. Supply your own USA retail Forza Horizon Xbox 360 disc, serial MS-2505/title ID 4D5309C9, whose selected source policy requires size 8738846720 bytes and SHA256 83dfc7d0b58b804232385de6f794d9acb92b89a37cf13da14b824b286c824490 (locally verified upstream, not Redump-hash matched), and finish the supported launcher’s original checks, local game-code build, graphics preparation and settings before attachment. This is not the PC release or Forza Horizon 2. Windows 10/11 x64 and Vulkan 1.3 are the selected route; upstream NVIDIA observations do not qualify AMD/Intel, Linux, Android or this host.

  2. Attach the normal waiting launcher

    Select PinyonShiftLauncher.exe, use its full extracted package directory as working directory and leave arguments empty for an existing ordinary installation. Review the selected program, working folder and arguments and choose Play when ready, then use upstream Play. The selected WPF caller supplies the actual repository and state root to launch-preview.ps1 and waits for it; that normal script waits for the game without the optional render-test timeout. Keep the launcher open until the game exits normally, then close it. Do not register the setup script, bare locally compiled game, diagnostic mode or a launcher from a different platform.

  3. Keep the active install and state choices

    The packaged launcher normally installs its versioned source beneath %LOCALAPPDATA%/PinyonShift, or its already chosen install folder/PINYON_SHIFT_INSTALL_ROOT. State defaults to that versioned source’s .local/preview, with an existing PINYON_SHIFT_STATE_ROOT override; retain any existing game-root override too. Keep the complete chosen trees, build/tools, originals, imported owned DLC, settings, saves, photos, logs, backups and shader caches. Do not assume that a fresh version’s empty folder replaces the active profile.

  4. Preserve portable and title-update separation

    An existing portable.txt beside the launcher, or an already chosen --portable launch, uses launcher/data and ignores install/state/game environment overrides. Preserve that choice; for an existing switch-based portable setup, retain --portable in the reviewed arguments instead of silently changing roots. This guide creates/removes no marker or override. Keep base-disc, optional v4 title-update and XE-mod profiles/backups distinct; upstream XE uses the base disc and its own save. Do not downgrade, merge or move profiles, import content, restart Windows or alter developer tools here.

  5. Keep upstream maintenance and component limits

    Upstream owns source staging, toolchain preparation, title updates, DLC verification and launcher maintenance. Retain title, SDK, shader, compiler and third-party notices; their licenses do not license the original disc, DLC or unrelated mods. Finish maintenance outside a running session, keep recovery and review/relink changed bytes. A checked outer archive and source wait chain do not prove nested-source extraction safety, installed/native behavior, campaign completion, controller or real-save restore acceptance. No Supported or managed install/update/rollback/backup/deletion outcome is asserted.

Limitations and evidence
