Setup

  1. Prepare the exact N64 original

    Use a complete player/components you are independently permitted to use and your own Battlezone: Rise of the Black Dogs USA Rev0 N64 ROM, internal name BATTLEZONE/game code NZOE. Upstream documents SHA1 cdd1d1dec9763ce6b7b1a70668effcead0a185a0 for its .n64 dump and 85b4febbe6fbd1ecfc883905e43e68e7188c44f9 for big-endian .z64. The selected native mapping gates normalized big-endian XXH3-64 f5f240b373301b9d, game ID bz.n64.us.1.0; filename extensions alone do not identify an original. Finish original selection/settings upstream.

  2. Keep the complete Windows beta player

    Use the official v0.1.0-beta Windows package and its complete prepared player/resources/notices, retaining the original independently. Do not substitute the arcade Battlezone game, a different N64 region or a Linux AppImage. The project uses its own title mappings and library patches; a shared N64 framework does not establish identical saves, input or compatibility. Multiplayer and hardware claims remain upstream evidence, not this host qualification.

  3. Attach the normal integrated player

    Select BattlezoneRecompiled.exe, use its complete extracted player directory as working directory and leave arguments empty after upstream setup. Review the selected program, working folder and arguments and choose Play when ready. Its native main sets bzrecomp as the UI program ID and enters the integrated frontend/runtime. Finish missing-ROM/settings prompts upstream before retrying. Do not use a recompiler, an AppImage, test/probe options or another port’s runtime as normal Play.

  4. Preserve controller paks and the selected data root

    Without an existing portable choice, the exact frontend base resolves Windows data under Known LocalAppData/bzrecomp. An already existing portable.txt in the working directory selects that directory instead; this guide creates/removes no marker. Keep the whole selected root, configs, retained ROM, mods and saves/ with every player’s .mpk Controller Pak, plus historical/external roots and recovery. Paks are standard 32 KiB, separate per player; swapping to a Rumble Pak is not a save conversion. SaveType::AllowAll in the source is not proof that the game uses every EEPROM/SRAM/Flash device. States remain separate from durable pak saves; no migration, restore or deletion is performed.

  5. Keep component and replacement boundaries

    Keep project GPLv3 and runtime, RT64, Exo 2, Noto Emoji, PromptFont, shader and compiler notices. RecompFrontend is the exact official b1a1477c6556aeb7ed45defbfb5924f721efebc1 base covered by the retained unchanged-base GPL grant; this title’s direct-RDP patch and font-specific terms remain distinct, and the grant does not license originals. Quit the actual game normally before upstream replacement, retain recovery and review/relink changed bytes. No native/installed, campaign, physical multiplayer/controller, real-save restore, Supported or managed lifecycle acceptance is asserted.
