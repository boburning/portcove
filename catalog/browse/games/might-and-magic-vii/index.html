Might and Magic VII (OpenEnroth)

OpenEnroth runs Might and Magic VII with files from your own installed PC game. The project provides nightly builds for Windows, Linux, Mac and Android and reports VII is playable. Might and Magic VI and VIII are planned separately.

Setup

  1. Use a complete compatible Might and Magic VII copy

    Prepare OpenEnroth upstream using your own supported Might and Magic VII installation and its ANIMS, DATA, MUSIC and SOUNDS trees. Planned Might and Magic VI/VIII support does not make their data interchangeable. Choose the actual compatible Windows CPU/build variant and native OpenEnroth.exe, retaining its libraries and resources. A moving nightly name does not establish compatibility with an arbitrary copy.

  2. Keep the separate game-data and user-data paths

    Keep the actual working directory and established literal --data-path and --user-path arguments. --portable defaults both paths to the working directory; an existing .portable file can also select portable mode. Do not add either merely to register. Existing OPENENROTH_MM7_PATH and upstream automatic discovery can affect data selection; Portcove does not inject that environment. Windows normally uses Saved Games/OpenEnroth for user state, with a working-directory fallback when the known-folder lookup is unavailable. Preserve the actual selected paths and openenroth.ini.

  3. Preserve both sides of upstream save copying

    When the data and user roots differ and the destination saves directory is empty, startup can copy regular files from the data saves directory into the user saves directory. It leaves the originals in place and skips copying into a nonempty destination. Keep both complete trees, all configuration, saves, modifications and unknown files before running a changed build. This upstream copying does not establish backward-save compatibility or a Portcove migration.

  4. Check the working copy before registration

    Finish setup with the project’s tools, then start and quit the copy you intend to add. Keep its game executable, working folder and supported launch arguments. Review those details in Portcove and agree to launch them, then choose Play separately. Adding a copy does not confirm its game files or save compatibility.

  5. Keep updates and removal under the existing owner

    Close every running copy of the game before changing files. Keep the working game version and every data and profile folder recoverable. Update it with the project’s tools, then review and select the changed executable in Portcove before choosing Play. You manage setup, updates, file changes, data migration and recovery. Portcove monitors the process you selected; it does not prevent other copies from running or restrict the game’s file access. Removing the registration leaves external files in place. This route does not offer Portcove downloads, setup, updates, backups, rollback, data migration or external-file deletion.

Setup notes
Version and platform notes
Nightly downloads include Windows x86 and x86-64 ZIPs, a Linux x86-64 Flatpak, Mac Intel and Apple silicon disk images, and an Android universal APK. Nightly builds can have bugs. The exact accepted language and retail patch are unconfirmed.
Use the experimental Android nightly
The upstream OpenEnroth nightly APK includes ARM64, ARMv7, x86 and x86-64 libraries. Copy ANIMS, DATA, MUSIC and SOUNDS from your own supported game to Android/data/io.github.openenroth.openenroth/files. The project describes this package as experimental. Retain the app’s data when replacing a nightly.

Limitations and evidence

  • Use only a copy and content you are already permitted to use. Engine licensing does not grant rights to original game assets, music, mods or bundled components.
  • Before updating the game, keep a copy of its working files and every location containing saved data. Choosing a different executable does not give it a separate profile.
