Setup

  1. Supply the matching original game files

    Supply DOOM.WAD from your original PC retail/Ultimate Doom copy. DOOM1.WAD provides only the separate shareware episode, not the full game. Keep your originals and edition identity; renaming another game’s WAD does not convert it. Originals are not included or authenticated by Portcove. Use a recognized upstream installation, or deliberately copy matching files into the originals subfolder (named exactly originals) of this entry’s fresh private data folder; keep your original copies.

  2. Use the upstream setup and launch controls

    Play opens crispy-doom-setup.exe. Configure controls and use F2 Warp for single-player launch; choose the matching detected IWAD there. The main-menu launch command forwards its existing arguments. The PWAD/mod browser is not an original-IWAD browser. Keep different title entries separate. Do not switch this entry’s original edition in place: its retained runtime versions share data. Use a separate Portcove library or independently owned upstream copy for another source variant. No automatic switching or cross-variant save compatibility is established. An upstream setup exit does not establish that the game loaded or ran successfully.

  3. Keep the declared private data scope

    Portcove retains originals deliberately copied under originals, this entry’s default configuration, saves under saves, known default save locations, numbered screenshots and declared recording files. Put custom recordings under demos or use a demo-prefixed .lmp filename. Upstream may read and write its music-pack profile on Play. Music packs and custom paths outside this installation remain external and outside Portcove backups. Extra files written inside the installation outside its declared folders are outside this offered scope and can block maintenance. Keep the creating runtime, original files and actual data before changing a source variant or using an older runtime.

  4. Keep updates in one place

    Portcove manages this new official game installation and the data listed for it. It does not import an existing project profile or convert a separately registered game. Existing registered copies keep their external files and update tools. Back up those external profiles and original files separately. Automated fixture checks and reaching a setup menu do not establish original-file or gameplay compatibility.

Setup notes
Install the native package on Linux or Mac
On Debian, install the crispy-doom package through the package manager. On Mac, use the upstream-documented MacPorts port or a supported Homebrew formula. Start crispy-doom with -iwad followed by the quoted path to your own DOOM.WAD from retail or Ultimate Doom. Use the external package manager for replacement.
Keep the existing Crispy profile
Preserve the actual Crispy config, saves, demos and original IWADs. Linux normally uses ~/.local/share/crispy-doom or XDG_DATA_HOME/crispy-doom. Mac normally uses ~/Library/Application Support/crispy-doom. Keep any custom locations and the creating runtime before switching package versions. The external profile can be shared across games.

Limitations and evidence

  • Play opens the project’s setup and launch controls. Supply your own matching original game files that you are permitted to use.
  • Portcove backups exclude external music packs, custom paths and data belonging to separately registered games.
