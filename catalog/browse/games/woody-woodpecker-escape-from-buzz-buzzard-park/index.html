Setup

  1. Use the prepared native Windows player

    Use an already permitted complete v1.0.11 WoodyRE.exe copy. The GPL-3.0 reimplemented engine reads original CD data; its terms do not license that data. Do not select build.bat, a compiler/download helper or a private standalone bundle as a redistributable release. The optional bundle tool embeds original files for private use; Core does not acquire or publish them.

  2. Finish original-file setup before adding the game

    Use your own supported Woody Woodpecker: Escape from Buzz Buzzard Park PC CD: English 1.00/Spanish or the documented February 2002 Brazilian Portuguese, Polish or Russian versions. Complete upstream CD/folder selection, private copying and verification before registration. Preserve the original Data, Common, Logo, Game and Music.bf and any existing saves/configs. The --verify upstream check is not a Portcove original/package or compatibility qualification; other editions are not inherited.

  3. Keep your existing data and working folders

    Normally the prepared executable finds data beside itself and uses that writable root; read-only/temporary executable locations can use LOCALAPPDATA/WoodyRE instead. data_find may change the working directory to the actual writable home, while originals can remain elsewhere. Explicit data-directory arguments or WOODY_DATA bypass that automatic choice, so keep the exact established working directory and absolute original-data path; Core does not inject environment variables. Finish preparation externally rather than letting registration silently import a new original.

  4. Select the normal game and review intent

    Select WoodyRE.exe with the working setup’s actual directory and only its established literal arguments; a supported explicit data directory is one absolute token. Normal WinMain calls main and its game loop through cleanup in the same process. Do not select --verify, scripted screenshot/automation/test switches or bundle/build tools for ordinary Play. Review exact executable/CWD/arguments and consent; choose Play separately. Core observes that process, not an exclusive session or sandbox.

  5. Preserve every save, config and private copy

    Preserve the whole external runtime/originals and every actual profile root: portable executable side, actual LOCALAPPDATA/WoodyRE, explicit/custom CWD and WOODY_DATA locations. Keep woodyre.sav, woodyre.sav.new, woodyre.cfg, woodyre.log, mods, old Woody.sav in game/ or CWD, unknown files and private bundled copies. The port imports compatible original save layouts and can convert its old one-slot format; this is upstream source behavior, not verified save roundtrip or downgrade compatibility. Keep old runtime and state together; do not regenerate or overwrite data just to register.

  6. Leave maintenance and replacement upstream

    Close every real instance before upstream changes, preserve the full old creating copy and actual data, and relink any changed executable for new intent review. Registration-only removal preserves external files. No Core-managed CD copying, archive extraction, compiler/bundle execution, update, backup, rollback, migration or deletion is offered; other operating systems and experimental Switch/mobile routes require separate qualification.

Setup notes
Use the Android WoodyRE package
WoodyRE v1.0.12 includes an APK with ARM64 and x86-64 libraries. On first start, choose your original CD image or copied files. Open the installed app again to use that copy. The app keeps the imported files under Android/data/io.github.jjmhalew.woodyre/files/data, with woodyre.sav and woodyre.cfg in the parent folder.
