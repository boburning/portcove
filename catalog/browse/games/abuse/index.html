Setup

  1. Keep the permitted working player and data together

    For an existing copy you are permitted to use, select abuse.exe on Windows or abuse on Linux with its game folder as the working directory. Keep its compatible data and libraries together; ABUSE_PATH overrides the asset root. The current release offers Windows and macOS packages; Linux here describes an already prepared native copy, not an offered Linux archive or a Portcove build. macOS uses the upstream application through the OS, not a private bundle binary.

Setup notes
Back up the actual save directory
The reviewed SDL code normally uses SDL_GetPrefPath("abuse", "data") for saves/settings: %APPDATA%/abuse/data on Windows, or $XDG_DATA_HOME/abuse/data (normally ~/.local/share/abuse/data) on Linux. ABUSE_SAVE_PATH overrides it; if preference-path creation fails upstream falls back to the current working directory. Preserve that actual location, custom levels/mods and the working data folder with the game closed. The local_save flag alone is not proof that saves are beside the executable.
Keep a working copy before updating
Removing the registration leaves the external files in place. You and the project manage updates and backups; Portcove does not back up or roll back this copy. Although the project mentions a public-domain data subset, this guide does not identify a complete compatible subset. Keep your working assets together; do not assume the code license also permits use of music, soundfonts or every bundled asset.
