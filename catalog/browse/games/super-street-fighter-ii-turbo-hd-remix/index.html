Setup

  1. Prepare the exact base and optional update upstream

    Use a complete player and components you are independently permitted to use, with your own purchased XBLA game, title 584108A4 / media 37B7D7D3. Base013 uses default.xex version 0.0.1.3, 3,932,160 bytes, CRC32 B734F075, SHA256 6E1C2F9ED7D1102A311A5F5626563527EDA5F85B2FBE8DB8405B866DED3F31EE. Optional official Title Update #1 is a separate 000B0000 package with default.xexp, 2,166,784 bytes, CRC32 38DE2310, SHA256 A2E8E66B482C5D3A0D3A5D3F67A3CECB7A12CE1F6189196694FD3E765910606C, selecting TU023 / 0.0.2.3. The game package is 000D0000. These identify known files, not entitlement or publisher authentication. Before first start or upgrade, keep independent copies of legacy saves/settings: upstream can migrate and remove the old data folder.

  2. Keep the complete matching player

    The inspected official 0.3.0 Windows ZIP contains AMD64 ssf2t_hd_remix.exe, its matching runtime/GPU libraries and separate trg-updater.exe. Keep the complete package; do not attach the updater. Both supported compiled game images are in the same player, selected from the prepared base/update files. Finish upstream game import, optional TU import, data migration, settings and any requested restart outside Portcove. No game package, TU, helper, compiler or native game is obtained or executed by this guide.

  3. Add your configured game

    In the upstream Play page, finish all settings and set Show this launcher to Off. Then select ssf2t_hd_remix.exe, use the complete extracted player folder as working directory and leave arguments empty. Review the intent and request Play separately without holding Shift. With ready files the app selects the appropriate image and continues into the linked game in process. Installing/removing a TU or changing restart-required settings in an open launcher can relaunch the program; finish those operations before attachment. This guide uses no internal skip flag or tracking promise across a successor.

  4. Preserve portable, legacy and explicit roots

    Normally keep user_data/ beside the program, including settings.toml, saves, profiles, achievements and caches, plus game/, logs and original package/TU files. The selected source can copy/verify legacy runtime data into user_data and remove the old folder after success; failures can keep using the legacy root and retry later. An existing --user_data_root explicitly selects another root. Use the upstream folder/status display to identify the active layout, retain independent copies of both old/new roots before maintenance, and preserve external paths. This guide performs no migration, restore, backup or deletion.

  5. Keep permissions and online versions separate

    Retain the project GPLv2 and all ReXGlue/Xenia, TRG UI, SDL, renderer, font and other component notices. They do not license the original Capcom game, title update or third-party content. Use only components you are independently permitted to use. Base013 and TU023 online peers must use matching builds; direct/relay servers, connection tests and online play remain upstream choices, not real multiplayer qualification. Linux/Steam Deck remains experimental and is not qualified by the Windows package.

  6. Close the game before maintenance

    Quit the actual game normally before upstream updates, TU changes, migration recovery or data operations. The upstream updater owns runtime replacement and can restart; preserve independent recovery copies and review/relink changed executable bytes. Unsupported update files can block Play; this guide does not silently remove them. Forced termination is not a save-flush guarantee. Source, archive and upstream gameplay reports are not native/installed, full-game, save/reload or Supported acceptance. Removing registration preserves external files; managed lifecycle operations remain unavailable.
