Setup

  1. Keep a permitted complete installed Windows player

    Use an already permitted, fully working v1.3.1 Windows x86-64 reblue.exe installation with all of its creating runtime, original-derived game tree, profiles, mods and companions. Select the installed executable at its established root, not the freshly extracted setup copy or a repair/updater/build helper. The ordinary release uses DirectX12; a separately built Vulkan variant is not inherited. Project BSD3 terms do not license original game data, optional DLC or all private/generated/component material.

  2. Complete all three supported originals upstream

    Finish the normal upstream wizard with all three disc images from your own supported Global US/EU Blue Dragon copy before registration. Keep one supported set, its originals, recorded fingerprints and full resulting installation; Asia/JP or arbitrary cross-region/revision mixing is not established. Upstream marker/container/title checks and fingerprints are not Core exact three-disc authentication. The wizard copies itself, restarts, installs game files and writes its registration outside Core; wait for that preparation and any repair to finish. Core does not parse/assemble/generate/admit the triple.

  3. Settle replacement and recovery before selecting

    Finish any pending upstream update or recovery and a normal upstream start/quit before registration. Do not delete or ignore .update staging, ready markers, replaced-file or recovery history as a workaround: startup can apply a staged update and relaunch before the update-check setting is read. Turn the normal upstream startup update/content check off for this route. A new download, update, repair or backend/warm reboot must be completed externally before the next reviewed Play; Core does not adopt its successor.

  4. Select the installed player and its exact paths

    Select root/reblue.exe with the actual installed-root working directory and one literal --game_data_root=<absolute prepared game-data directory> argument (ordinarily root/game containing default.xex for this upstream installer), --profile=<actual existing profile name>, and --no-bd_update_check. Keep spaces inside each single token; these are arguments, not a shell command. The game-data directory must belong directly beneath that same creating installation root: its parent becomes the profile/cache root and must match the installed executable directory. Preserve an established supported custom direct-child tree rather than rename it or select an unrelated external directory. Explicit game_data_root selects that installation independently of shared install lookup; default.xex presence alone is not full original or private-output validation. The bound normal Windows entry runs its application/message loop in process. Keep any other supported working flags exactly; generic SDK user_data_root/cache_root flags do not override the title’s profile/cache routing.

  5. Preserve every actual original and player root

    Keep the whole external install, complete originals/private output, game-data tree, mods, installed DLC/content, logs, root/cache, profiles/<actual name>/reblue.toml, profile saves/achievements/content and unknown files, plus all legacy roots and existing shared HKCU installation registration. Preserve actual bd_saves_path and bd_cache_path overrides separately. The title uses the selected installation’s profiles/name as its user root; save/cache overrides and prior layouts are distinct. Do not reset profile/configuration, repoint shared registration or regenerate a private copy merely to register. Core neither backs up these roots nor claims safe save/profile migration or rollback.

  6. Review launch details and manage your copy

    Consent to the exact native executable, working directory and literal arguments, then choose Play separately. A current library-owned installation or active registration/launch cannot be bypassed by this alternative. Existing managed/source contracts remain unchanged; selecting an external copy grants no managed generation, immutable private-output certification or source admission. The program can make normal profile/DLC/cache writes, and its UI can reenable checks; this is not a sandbox or an all-network-off promise. Normal ordered shutdown has a default1.5second forced-exit watchdog, so process exit is not clean-save certification. Close all real instances before upstream changes, retain the old creating runtime/data together and relink changed executables. Registration-only removal preserves all external files.
