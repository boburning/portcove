Setup

  1. Select the original Vyruz data

    Keep your own vz-data.rsc in a writable original-game folder outside the engine. Intro.avi in the same folder is optional. The original and this player can both write vzconf.txt, session and vz.sco there. Back up that whole folder before starting.

  2. Start the Linux player

    The v1.1.0 Linux x86-64 tar.gz contains Vyruz. Use a Vulkan driver and loader, glibc 2.38 or later, and libstdc++ with GLIBCXX_3.4.31. The picker uses zenity or kdialog. You can pass the original archive or folder to the upstream executable if the picker is unavailable.

Setup notes
Find the remembered setup
On Linux the normal profile is $XDG_DATA_HOME/OpenVyruz or ~/.local/share/OpenVyruz. On Windows it is %APPDATA%/OpenVyruz. The game remembers the data path in game-folder.txt. If it cannot locate a user home it can write OpenVyruz relative to its working directory.

Limitations and evidence

  • Keep your original folder and effective user profile. A runtime backup cannot restore files stored in those external folders.

Setup

  1. Prepare your original game files

    Copy your owned Vyruz ISO, or a single-BIN CUE with its BIN, beside the Vurus player, then start it. Keep the CUE and BIN together to import CD music, and keep your original separately. On first start Vurus imports the disc into data/ beside the player and reuses that import later, so you can then delete the copied image. To import a different image after a previous import, use --data with its path.

  2. Use the Mac release

    On macOS 15 or later, pick desktop release v202610242327-beta, extract the Intel or Apple Silicon archive matching your Mac into a writable folder, and run vurus from a terminal. The Mac builds are unsigned.

  3. Keep imports and progress

    Keep data/, saves/, slot1.vzs, options.cfg, vz.sco and benchmark-results/ with the player. Portcove keeps them across managed updates. If you keep a copy you manage yourself, back them up before replacing the player. Keep any resource folder, save file or options file you chose with --data, VURUS_DATA_DIR, --save-file or --options-file.

Setup notes
Set up the upstream PortMaster build on an ARM64 handheld
Use compatible ARM64 firmware with PortMaster installed, SDL 2.0.18 or newer and native OpenGL ES 3.0. Get vurus-portmaster.zip from https://github.com/rzrbld/vurus/releases/tag/portmaster-v202611031626-beta. Extract Vurus.sh, Vurus Benchmark.sh and vurus/ together into the firmware’s Ports folder.
Import and preserve your handheld data
Place your own ISO or single-BIN CUE and its BIN beside vurus.aarch64, or copy an existing data/ import there. Start Vurus from the firmware’s Ports menu. Back up data/, saves/, slot1.vzs, options.cfg and vz.sco before applying an upstream update. Keep these files when updating the engine in place. You manage this copy.

Limitations and evidence

  • The managed routes use the desktop beta packages. The separate PortMaster package needs compatible handheld firmware. There is no Android APK or general-purpose Linux ARM64 desktop package in this release.
