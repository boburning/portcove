Setup

  1. Prepare the exact edition

    Use your independently permitted copy and own Jet Moto 2: Championship Edition USA disc (SCUS-94167), with its CUE and all 17 BIN tracks. The original 1997 Jet Moto 2 shares the serial but is a different build. Keep the complete named disc set in the upstream disc directory; this guide does not establish a full-disc checksum or rights to original data.

  2. Complete upstream preparation

    Use the upstream v0.1.5 Windows kit and .NET 10 SDK, following its README generation and build instructions outside Portcove. The kit launcher compiles locally and version changes can trigger another build. Finish preparation before registering the generated player; keep the complete creating kit, runtime dependencies and output together.

  3. Select the completed player

    Select build/JetMoto2Recomp.exe with its complete build directory as the working directory and no additional arguments. Do not select the root JetMoto2.exe launcher: it starts the player separately and exits. The direct player keeps the game and presentation loop in its own process.

  4. Keep the selected disc and card paths

    The player reuses an existing valid saved disc path; otherwise it tries ../disc/Jet Moto 2 - Championship Edition (USA).cue beside the creating build. Settings can select another disc or card path and require a restart. A custom path does not establish that another edition is compatible.

Setup notes
Back up before starting or rebuilding
With the game closed, keep a separate complete prior kit/build backup and copies of settings.json, interface.ini, carda.sav, cardb.sav and cheats.json in build, plus every configured external card/disc path. Settings and cards are working-directory relative unless customized; cheats.json is beside the player. Missing cards are formatted in memory and later written; unreadable or short existing cards and malformed settings need your recovery copy. Do not assume save compatibility across builds or replace current player data with an older runtime backup.
Keep one replacement owner
Upstream and the player own preparation, rebuilds, runtime replacement, settings and saves. Portcove registers the explicitly selected native player without acquiring originals, building, updating or managing its external data. Finish upstream updates outside a tracked game session, retain a complete recovery copy, then revalidate the selected player.
Respect the early-release limits
Upstream reports a completed Slickrock Gorge race, with sound/CD music, memory-card saving, other tracks, season, gamepad and two-player play untested. Menu art can extend beyond the right edge. Optional JM2 diagnostic/input/cheat environment features are outside this route. Keep the project and RecompOne notices; their MIT grants do not grant original game content. Upstream states that this early release was tested only on Windows 11 x64; this is its reported test scope, not Portcove qualification for Windows 10 or another host.

Limitations and evidence

  • Only an independently permitted completed native copy is offered; upstream setup and replacement remain external.
  • The launcher that compiles and starts a child player is not the registered player.
  • With the game closed, keep a separate complete prior kit/build backup and copies of settings.json, interface.ini, carda.sav, cardb.sav and cheats.json in build, plus every configured external card/disc path.
