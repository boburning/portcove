Setup

  1. Use the complete installation and your own disc

    Use the complete GT4Recomp v1.2.5 Windows installation and your own Gran Turismo 4 USA v2.00 SCUS-97328 plain ISO. Upstream pins the 5314478080-byte ISO with SHA-256 67b6c0075837f3ae1132d608acf2858bf13b2dd62d6eae83dff76df02e4e824f and verifies prepared CORE/ELF identities separately. Keep the original separately.

  2. Finish official upstream setup

    Complete the official installer and launcher disc setup outside Portcove. The launcher copies the ISO, verifies preparation, installs the renderer and checks CPU/Vulkan requirements. Use supported Windows x64, SSE4.1 CPU, Vulkan 1.2 and WebView2; retain the complete matching installation and DLLs. This route uses the official launcher, not the internal gt4vulkan.exe with a guessed environment or another version's renderer.

  3. Back up all current and legacy roots before first startup

    Close the game and launcher; keep a separate complete prior installation and current <install>/data, %APPDATA%/GT4Recomp, %LOCALAPPDATA%/GT4Recomp and Documents/Gran Turismo 4, including any moved-name sibling or recorded previous installation data. Include settings, controls, Saves, Replays, card backups, runtime/card.ps2, original/prepared disc data, custom textures and configured read/fallback roots. Keep the backups outside old installation cleanup targets. Startup can move user and large data, flatten textures and remove the old per-user program/game folder, fixed shortcuts and registry entries. The running installation and its data-folder layout are excluded from that legacy cleanup; do not rely on an old executable folder as your recovery copy.

  4. Register the official outer launcher

    Select GT4Recomp.exe from its complete creating installation, use its installation directory as working directory and leave arguments empty. Start only when a separate GT4Recomp instance is not already running; a second launcher can merely bring the first forward and return. Portcove tracks the selected launcher session, not game-only play time. Save launch details and consent to Play separately; then use the upstream launcher's Play operation.

  5. Let the upstream launcher own the game session

    The launcher stays alive, hides to the tray during Play and watches its child game; when the game exits it harvests the card and returns Home. The launcher supplies required renderer environment, config, per-session files and card locks. Quit/save through the game, wait for the upstream launcher to finish card handling, then close the launcher to end the selected session. Closing it while playing asks first and can end the game through its kill-on-close job. Do not register an internal payload, bypass the owner or assume closing Portcove provides a save checkpoint.

  6. Keep update and restart transitions upstream-owned

    Upstream owns setup, renderer downloads/updates, runtime replacement, data movement and recovery. A launcher update starts its installer and exits; WebView recovery can restart the launcher in safe mode. Complete these transitions outside the registered normal session and revalidate the resulting launcher. Portcove does not reproduce renderer environment, follow replacement processes, acquire originals or delete/restore external data.

  7. Retain component terms and known limits

    Keep MIT code notices, the separately GPL-licensed GSdx/PCSX2 renderer notices and source, and all other component notices. Check upstream’s limits for licence demos, menu backgrounds, wheels, long sessions and hardware. Portcove has not confirmed game execution or save compatibility with this launcher route.

Setup notes
Preserve effective saves and recovery paths
Large data normally stays in <install>/data; a nonwritable install may read that folder while writing to %LOCALAPPDATA%/GT4Recomp. Per-user settings, controls, save/replay libraries and card backups normally use %APPDATA%/GT4Recomp, with upstream fallback/read layers retained during migration. Before Play the launcher builds the runtime card from its library, then harvests after exit; do not edit card/library files concurrently. It prunes older session folders to 20 and may rewrite corrupt update metadata to .json.bad. Preserve all current/fallback/legacy roots before maintenance; do not assume cross-version save compatibility.
