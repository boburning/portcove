Setup

  1. Prepare the complete upstream Windows copy

    Use an already permitted v0.0.7 Windows OpenTIE copy with all supplied resources, shaders and runtime libraries. Select OpenTIE.exe, not the installer, development tools or a different TIE Fighter project. The GPL-3.0 engine terms do not license original commercial game data, third-party components or optional instrument ROMs. Keep the whole creating Windows copy.

  2. Finish original-data and pilot setup upstream

    Use your own complete 1995 Collector’s CD-ROM TIE95 and/or 1998 Windows TIE98 installation; finish the normal upstream folder picker and its validation before registration. It remembers those folders and imports compatible pilot files. Preserve both originals and every existing pilot/profile before setup: source-reviewed import/config conversion is not a Portcove save-compatibility test. Older DOS editions, other revisions and optional SC-55 ROMs are not silently included.

  3. Select the normal native player

    Select OpenTIE.exe with its actual established installation working directory. Keep the supported --tie95-data, --tie98-data and --resource-root directory flags only when your working setup uses them; each directory is its own literal absolute token, including spaces. There is no positional ROM argument. main calls the application and frame loop in the same process through normal shutdown; no setup/helper successor is adopted by Core.

  4. Preserve the full actual user and original roots

    Preserve the whole external installation/resources, both complete selected originals, original pilot files and the actual Aeron/SDL user root for organization TotallyOpen and application OpenTIE, including config.yaml, pilots, progress, records, recordings, temporary files, optional music/model resources and unknown files. The user-root location is resolved by the creating runtime; keep any redirected or fallback location separately. Its temporary root defaults to the same user root. Upstream config loading can migrate keyboard bindings and reset older controller bindings; close every instance and retain the pre-change copy before upstream updates. Core does not relocate or migrate these files.

  5. Review launch details and use the project’s updates

    Consent to the exact executable, working directory and literal arguments, then choose Play separately. Core observes the selected native process; it is not an exclusive session or sandbox. Complete upstream maintenance outside Core, close all real instances, keep the old runtime and data together and relink changed executables for fresh intent review. Registration-only removal preserves every external byte; no managed acquisition, update, backup, rollback or deletion is offered.

Setup notes
Prepare a permitted Linux or Mac copy
For Linux x86-64, use the official v0.0.7 TAR.XZ, keep the complete folder and run OpenTIE with Vulkan, glibc 2.35 or newer and libstdc++ with GLIBCXX_3.4.29. For Apple silicon, copy OpenTIE.app out of the official v0.0.7 ARM64 DMG and use macOS 13 or newer with Metal. Use a copy you are already permitted to use. Follow the same TIE95 or TIE98 original-data setup, preserve the actual TotallyOpen/OpenTIE profile, and maintain each copy upstream.
