The Legend of Zelda: Link's Awakening (2019 Switch) (LASRecomp)

An experimental Link’s Awakening 2019 Switch recompilation. Release packages include a generator and compiler that prepare game code locally on first setup. Documented hosts are Windows x64 AVX2/Vulkan 1.3, Apple Silicon macOS 15+ and Linux x64; Linux ARM64 is experimental. Use your own prepared v1.0.0, v1.0.1 or v1.1.0 files. Your own Switch fonts are optional because replacements are used by default. Portcove offers no setup or launch integration and has not tested gameplay.

Setup

  1. Finish the supported game-file setup

    Use your own already extracted Switch Link’s Awakening v1.0.0, v1.0.1 or v1.1.0 files, with exefs and romfs or their supported contents. Complete the official player’s Game Files preparation and local game-code build before attachment. This route supplies no originals, keys, decryption, firmware, Nintendo fonts or game-data download. Other Zelda games and versions are separate qualifications.

  2. Keep the complete ordinary Windows package

    Use the complete official beta_5.4 Windows LAS Recomp folder, including lasrecomp.exe, DLLs, tools, resources and notices. Keep it writable outside Program Files. The documented Windows route requires x86-64 Windows 10/11, AVX2 and FMA, and Vulkan 1.3 with a suitable current driver. Source/developer builds and test-tag assets have different preparation requirements. Preserve project MIT and separate library, font, compiler and graphics-component notices; original game rights remain separate.

  3. Attach the integrated native player

    Select lasrecomp.exe, use the complete existing LAS Recomp directory as working directory and leave arguments empty. Review the selected program, working folder and arguments and choose Play when ready, then use its ordinary start-screen Play and existing vanilla/seed selection. The native start screen and game loop share a process; the selected Windows restart implementation waits for its successor and propagates its exit. Do not select a code generator, setup script, randomizer tool or test harness as the player.

  4. Preserve the resolved data folder and seed identity

    Windows normally keeps data next to lasrecomp.exe. Retain any existing data_root.txt pointer, LARECOMP_DATA_ROOT override or source-checkout extracted/ working-root behavior; use the actual populated folder rather than creating a replacement profile. Preserve save/, rando/, larecomp.ini, fonts/, gamecontrollerdb.txt, cache/, extracted/, logs and all backups. Keep each randomizer seed and its matching saves distinct from vanilla and other seeds. Preserve existing LARECOMP_SETTINGS overrides and both sides of interrupted .lasrecomp_move_* / .lasrecomp_incomplete recovery; finish upstream recovery separately.

  5. Leave changes and beta acceptance upstream

    Upstream owns game-file import, local compilation, randomizer generation, data-folder moves, updates and recovery. Finish these outside an active game and review/relink changed player bytes. Beta crashes, experimental shuffle logic and graphics limitations remain; no full campaign, solvable-seed, native-controller or real-save recovery qualification is established here. Attachment provides no managed install, update, backup, rollback, migration or external-file deletion.
