Setup

  1. Prepare this fork’s original and complete player

    Use a complete Dab’s Mod copy for your system. Keep this fork distinct from the stock managed Perfect Dark port.

  2. Select normal native play

    After upstream preparation, select pd.x86_64.exe (pd.x86_64 on Linux), use its complete containing folder as working directory and leave arguments empty for the documented normal route. Preserve an already established --basedir, --savedir, --portable or mod-directory choice as separate literal arguments instead of changing its data roots during attachment. Do not attach an updater, standalone replacement download or another fork’s executable.

  3. Finish upstream updates outside the attached session

    Dab’s Mod can stage and replace its executable and restart it. On Windows the restart starts a successor and lets the selected process exit; Portcove does not adopt or terminate that successor. Close the actual restarted game before maintenance, review/relink changed selected bytes, then start a new Play session. Keep optional online, account, recording and added-content actions as your own separate upstream choices.

  4. Keep external ownership

    Review and consent to the selected executable, working folder and literal arguments, then choose Play separately. You and upstream own preparation, runtime replacement, recovery and all external files. Close every actual player and companion before maintenance, retain independent complete working copies and data, then review/relink changed executable bytes. Removing registration preserves external files; Portcove does not offer external update, backup, rollback, migration, conversion or deletion.

Setup notes
Back up the effective save directory before startup
In the selected source, --savedir overrides the save root; --portable uses the executable directory. Otherwise a writable executable directory becomes the save root and can copy older saves into it when pd.ini is absent. An unwritable installation can retain the legacy working-directory or per-user fallback. Keep every actual old and current root, pd.ini, EEPROM, player/progress files, Combat Simulator setups, mods, added content, screenshots, recordings and upstream backups. The startup log names the effective base/save directories; preserve any custom paths independently. A package-folder copy alone is not a complete backup when a different root is active. The per-user fallback is SDL’s perfectdark preference directory, normally %APPDATA%/perfectdark on Windows; retain its earlier data even after a writable portable folder becomes active.
Keep expanded saves with compatible versions
Ordinary stock-format setups can remain readable by the stock port, but setups with more than eight simulants and moved-stat formats need compatible versions. Returning to an older executable does not convert or rewind those files. Preserve the whole creating runtime and data before switching channels, mods or versions; no cross-version or stock/fork save conversion is qualified.

Setup

  1. Check the required game files

    Use your own Perfect Dark Nintendo 64 USA v1.1 ROM. Check the required size and SHA-1 in games/perfectdark-us-v11/profile.toml before importing. Keep the original separately. These instructions do not download or run it.

  2. Build from source on Linux

    Follow the upstream Linux prerequisites. From the checkout root, run .venv/bin/python tools/import_rom.py --profile games/perfectdark-us-v11/profile.toml --rom "/path/to/your-ROM.z64" with your own .z64, .n64 or .v64 file. Run cmake --workflow --preset perfectdark-us-v11-release, then ./build/perfectdark-us-v11-release/bin/perfectdark-us-v11. The default keeps the ROM external. Keep the ROM and any locally generated game code private, including builds that embed it.

Setup notes
Build from source on Windows x64
Follow the Windows setup guide in the upstream README for Visual Studio, Python and vcpkg. Use the same ROM profile with the Windows Python environment. From the checkout root, run .\tools\build_msvc_project.ps1 -Game perfectdark-us-v11 -Configuration Release in PowerShell. Start the resulting build/msvc/perfectdark-us-v11/release/bin/Release/perfectdark-us-v11.exe from the checkout root and keep its dependency DLLs beside it. Preserve the checkout’s private local/ directory and any custom data paths before rebuilding.
Prepare a private Steam Deck copy
Follow the upstream Steam Deck container guide on an x86-64 Linux PC and run ./tools/build_steamdeck.sh perfectdark-us-v11 after importing your ROM. Keep the resulting package folder together. Supply your matching ROM at the local/ path named in its included instructions, then add launch.sh to Steam as a non-Steam game with compatibility tools disabled. Preserve local/ from the old copy before rebuilding or replacing it. Keep private packages and generated game code to yourself. Portcove has not observed Deck setup or gameplay.

Limitations and evidence

  • The project provides a Carrington Institute screenshot. A complete playthrough has not been confirmed, and results from another game do not establish that this one works. Portcove has not confirmed setup or gameplay.
