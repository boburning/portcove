Setup

  1. Prepare your own USA disc upstream

    Use a complete copy and components you are independently permitted to use. Finish upstream preparation outside Portcove, keep independent originals and recovery copies. No original, helper, compiler or game is obtained or executed by this guide. Use your own Mario Party 6 USA GameCube disc image or matching extracted disc tree. Complete the supported upstream content import and configuration first, retaining the independent original and any selected external content root. Another region or Mario Party game is not admitted by the shared engine. The Windows native player, Android APK and browser/iPhone experience are different artifacts, not a shared native-platform qualification.

  2. Keep the complete Windows package

    The inspected official 0.5.0 Windows ZIP contains AMD64 mp6native.exe, renderer libraries, res/ and notices. Keep the complete extracted package. The selected native entry launches the UI and calls GameMain within the same process; do not select a GameCube executable, disc image, browser bundle, Android package or build script. Package presence and source review do not establish complete imports, dependencies or Windows gameplay.

  3. Attach the prepared player

    Select mp6native.exe, use its complete extracted package folder as working directory and leave arguments empty. Review and consent to the selected launch details, then choose Play separately, then use the upstream player UI with its already prepared content. Working directory matters: Windows saves are deliberately relative to it. Complete any missing import/preparation outside the attached attempt. Quit the actual game normally; forced termination is not a save-flush guarantee.

  4. Preserve actual saves and content configuration

    Keep mp6_config.json beside the executable, the saves/ directory relative to the established working directory, memory-card GCIs, states, logs, renderer caches and the selected external content tree. Preserve old working-directory save roots if they differ from the package directory; do not change CWD without reviewing that effect. Upstream states require the same linked build, while GCIs are durable game saves; neither establishes observed restore compatibility. This guide performs no move, migration, backup or deletion.

  5. Retain title-specific permission and font evidence

    Keep docs/PARTYBOARD_PROVENANCE.md, all author credits, res/fonts/LICENSES.txt and runtime/component notices. The selected upstream publicly records its maintainer’s 2026-09-12 confirmation of permission to redistribute the adapted Partyboard launcher and N64 Party font with this MP6 release. It explicitly does not claim a public general license for those foreign materials; this guide does not reuse that confirmation for another project or artifact. Other fonts have separate OFL/Apache terms. Original game code/assets still require a copy you are independently permitted to use.

  6. Maintain the external copy and limited scope

    Quit the game normally before changing files; forced termination may not finish saving. After an upstream update, relink and review the changed executable. Removing the registration leaves all external files in place; Portcove does not install, update, roll back, back up or delete this copy. Upstream reports only 49 of 81 minigames playable, with unsupported board minigames skipped after a notice. Portcove has not confirmed minigames, boards, microphone support, saving or gameplay on Windows or other platforms.
