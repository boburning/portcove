Setup

  1. Prepare the complete owned-disc installation upstream

    Use a complete copy and components you are independently permitted to use. The selected 0.2.2 route needs your own original Xbox Breakdown USA ISO, Windows 10/11 x64, Direct3D 11 and roughly 6 GB for its local build. Keep Breakdown.exe and the entire matching tools/ tree together. Run the supported first-run preparation outside Portcove until the game DLL is ready. The inspected launcher checks Xbox-disc filesystem magic; extraction checks default.xbe exists. Exact accepted full-disc/XBE digest/revision authentication remains Unknown; those checks are not entitlement or a cryptographic USA-identity check. No original, compiler, helper or build is obtained or run by this registration. The official 0.2.2 Windows ZIP unpacks to Breakdown-Recompilation-0.2.2/ with Breakdown.exe and tools/. Keep that folder intact for upstream preparation; the game DLL is created from your own ISO during the local build.

  2. Select the completed normal native launcher

    Select Breakdown.exe in its complete creating Windows package directory, use that directory as working directory and leave arguments empty. Keep the matching prepared installation and companions. The selected launcher loads work/build/breakdown_game.dll and runs the game in its own process/window; it is not an instruction to select a generated DLL, internal standalone executable, build helper or Linux launcher. Review and consent to the selected launch details, then choose Play separately.

  3. Preserve the actual installation and all data roots

    The launcher normally uses %LOCALAPPDATA%/BreakdownRecomp for settings.ini, work/ with extracted game/generated build/ready markers, and logs/. Preserve that complete tree plus the selected original ISO and package. An established BREAKDOWN_DATA or BREAKDOWN_TOOLS override selects different roots; retain them too without creating a new override here. Logs include build/game/launcher records. Keep complete recovery copies outside generated work and staging trees before rebuilding.

  4. Keep the effective save folder separate from rebuild data

    The upstream default save folder is %LOCALAPPDATA%/xboxrecomp. Its Options saved-games setting can select another location and is passed through XBOXRECOMP_SAVE_DIR. Preserve the actual save tree, settings and every established custom/external root; that default name does not establish per-title isolation or save compatibility. Choosing another saved-games folder does not move existing saves. This guide performs no save migration, import, backup or destructive management.

  5. Complete rebuild and restart paths outside attachment

    Ordinary prepared play runs inside the selected process. Upstream repair/rebuild can invalidate ready/build stamps, replace generated work/toolkit/project/build material and request a fresh launcher process; Restart starts a successor and the current process exits. Complete setup, rebuilds and such restarts outside the attached-session scope, close all actual players/helpers/successors, then review/relink changed bytes. Portcove does not adopt or terminate a successor or own runtime replacement; preserve originals and independent recovery copies first.

  6. Retain release and ownership limits

    Upstream 0.2.2 is explicitly early/incomplete: some background music loops, Retry/loading can take a long time and some textures appear late. These remain attributable upstream limitations, not Portcove passes or repaired failures. Keep component notices; project/toolkit/component terms grant no Namco original-game rights. The release assembler takes an external toolkit working checkout, so exact packaged toolkit/source correspondence is not established here. Removing registration preserves every external file. No managed install/update/rollback/backup/removal or Supported/protected acceptance is offered.

Limitations and evidence
