Setup

  1. Extract the exact stock runtime

    Extract the official 1.1-stable Windows.zip outside the Portcove library. Keep its five files unchanged; do not add portable.txt, loader metadata or mods.

  2. Select your original game file

    Choose and check your exact Super Mario Bros. (World) NES original separately in Portcove.

  3. Review the shared account directory

    Choose the extracted runtime folder. Review the resolved Windows account and APPDATA/SMB1R directory, then explicitly accept the shared-data disclosure.

  4. Prepare the cached original manually

    Copy your checked original unchanged into that shared directory as baserom.nes. Refresh readiness before Play. Core never creates or seeds this shared directory.

  5. Linux x64 upstream setup

    On x64 Linux with glibc 2.28 or later, extract Linux.zip from the official 1.1-stable release into a separate folder. Keep SMB1R.x86_64, SMB1R.pck and all three companion libraries together. Allow SMB1R.x86_64 to run, then use its file picker with your own uncompressed Super Mario Bros. (World) NES original.

  6. Back up the Linux profile

    Close the game and preserve the SMB1R profile under XDG_DATA_HOME (normally ~/.local/share). If you already use the upstream portable.txt option, preserve the executable-local config folder as well. Keep the original, generated BaseAssets, settings and saves together. Setup and replacement on Linux are player-managed.

Limitations and evidence

  • Other copies share originals, settings and saves. The game can regenerate or trash caches and prune logs. Portcove does not own, update, back up, restore or delete these files; removal unregisters only.
  • Only vanilla BaseAssets is accepted. Preserve and manually move other packs, custom characters, levels/autosaves, blueprints and Godot loader metadata elsewhere before use. Editor/import operations and extra arguments are outside this route.
