Setup

  1. Keep the complete prepared Windows game

    Use a complete YKnytt copy and components you are independently permitted to use. The inspected 0.7.3 Windows ZIP contains YKnytt_v0.7.3_win/YKnytt.exe as an AMD64 Godot player, YKnytt.pck and the matching data_YKnytt Mono tree. Keep the entire directory together; neither a lone exe nor a source project is the complete player. The package includes several worlds and does not require a player-supplied retail disc or console BIOS by the selected instructions. No Godot editor, compiler, program, level or original game is obtained or executed here.

  2. Retain original-game and level terms

    The project notice grants MIT terms for YKnytt code and describes the included Knytt Stories assets as freeware copyright Nicklas Nygren. The separately retained Knytt agreement allows clearly identified Knytt Stories mods with original-game attribution, while restricting reuse of music/graphics/creatures in other games and entirely new games. Preserve those notices and the original Knytt Stories attribution/link; do not flatten them into an all-assets MIT grant. Community worlds and their components keep their own rights and compatibility limits.

  3. Select the normal native game

    Select YKnytt.exe, use its complete extracted YKnytt_v0.7.3_win directory as working directory and leave arguments empty for the already prepared installation. Review the exact selected intent, then request Play separately. The Godot player runs the authored C# scenes in process; do not select a Mono helper, DLL, PCK file or Godot editor. This guide does not establish native startup, runtime dependencies or correctness of every world.

  4. Preserve the effective world and save locations

    The normal Windows user-data folder is %APPDATA%/YKnytt. An already present Documents/yknytt_data directory takes precedence in the selected source, and an established --data path takes precedence over both; relative --data paths are based on the executable directory. Keep the complete effective directory with Saves, Worlds, settings.ini, input.ini, worlds metadata and cache. Separately configured SavesDirectory or WorldsDirectory can add external roots. Preserve legacy Godot user-data directories too: first migration can move old settings, saves and worlds. This attachment adds no --data option and performs no migration or deletion.

  5. Use the project’s network and maintenance tools

    YKnytt offers a Level Downloader and a complain action that upstream documents as sending the latest save to its server. Use those only through the upstream interface with the intended world/save; this registration does not download a world, submit a report or authorize upload of private data. Finish upstream migration, data-location changes, world repair and runtime replacement outside an attached session, close the actual player, retain independent recovery copies and review/relink changed executable bytes.

  6. Check what has been tested

    YKnytt remains a beta implementation with per-level compatibility limits; a built-in world or one successful level does not qualify the whole community corpus. Quit normally; forced termination is not a save-flush guarantee. Upstream Windows/Linux/macOS/Android/ARM-handheld claims remain distinct and no Portcove gameplay, save/reload, physical-device, installed-app or Supported acceptance is asserted. Removing registration preserves all external data. Managed install/update/rollback/backup/removal are not offered.
