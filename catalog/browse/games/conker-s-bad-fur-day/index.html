Setup

  1. Choose this implementation’s complete player

    Use a permitted sciaschi CBFD-Recompiled copy: ConkerRecomp.exe on Windows or ConkerRecomp on Linux, with its full extracted folder as the working directory. Keep assets, runtime libraries and notices together. The separate Mods.zip contains optional mods, not the player. The upstream macOS application is a separate Apple Silicon/macOS 15-or-later route; retain its bundle and follow upstream instructions.

  2. Load your USA original on first Play

    Choose Play explicitly, then Load ROM in the launcher and supply your own supported USA Conker’s Bad Fur Day dump. Upstream validates and remembers the input; the released player does not need the source-build tools. Keep this implementation separate from Conker64’s scene prototype and the distinct Reloaded player.

Setup notes

Keep saves, stored ROM, settings, achievements, save states, logs and mods together with the working copy. portable.txt selects local data relative to the player working folder on Windows/native Linux or beside the macOS bundle; a custom/test profile can differ. Portcove does not adopt, back up, roll back or delete these external files.

Setup

  1. Check the required game files

    Use your own Conker's Bad Fur Day Nintendo 64 USA ROM. Check the required size and SHA-1 in games/conker-us/profile.toml before importing. Keep the original separately. These instructions do not download or run it.

  2. Build from source on Linux

    Follow the upstream Linux prerequisites. From the checkout root, run .venv/bin/python tools/import_rom.py --profile games/conker-us/profile.toml --rom "/path/to/your-ROM.z64" with your own .z64, .n64 or .v64 file. Run cmake --workflow --preset conker-us-release, then ./build/conker-us-release/bin/conker-us. The default keeps the ROM external. Keep the ROM and any locally generated game code private, including builds that embed it.

Setup notes
Build from source on Windows x64
Follow the Windows setup guide in the upstream README for Visual Studio, Python and vcpkg. Use the same ROM profile with the Windows Python environment. From the checkout root, run .\tools\build_msvc_project.ps1 -Game conker-us -Configuration Release in PowerShell. Start the resulting build/msvc/conker-us/release/bin/Release/conker-us.exe from the checkout root and keep its dependency DLLs beside it. Preserve the checkout’s private local/ directory and any custom data paths before rebuilding.
Prepare a private Steam Deck copy
Follow the upstream Steam Deck container guide on an x86-64 Linux PC and run ./tools/build_steamdeck.sh conker-us after importing your ROM. Keep the resulting package folder together. Supply your matching ROM at the local/ path named in its included instructions, then add launch.sh to Steam as a non-Steam game with compatibility tools disabled. Preserve local/ from the old copy before rebuilding or replacing it. Keep private packages and generated game code to yourself. Portcove has not observed Deck setup or gameplay.

Limitations and evidence

  • This game-specific profile is experimental. Its setup, stability and completion have not been confirmed; results from another game do not establish that this one works. These are the project’s reports; Portcove has not confirmed setup or gameplay.
