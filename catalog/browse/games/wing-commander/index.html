The older MSVC reconstruction and partial DOS route do not inherit this offer or gameplay qualification.

Setup

  1. Use the modern SDL2 player and your own Kilrathi Saga data

    Use the official modern SDL2 package for Windows x64, Linux x86-64 or an Apple silicon Mac with all companion libraries, or an already permitted working copy of that same route. Select normal wc1-modern.exe (wc1-modern on Linux or a Mac) for an attached copy. On an Intel Mac, the official Intel ZIP needs macOS 15 and a compatible Intel SDL3 library supplied separately for its SDL2 compatibility library. The separate win32-msvc420 reconstruction package is not this player. Use your own full Wing Commander Kilrathi Saga installation: GAMEDAT plus STREAMS/PREFLITE.STR, POSFLITE.STR and MISSION.STR. DOS support is partial and does not inherit this offer.

  2. Choose the actual writable original directory in upstream setup

    A new managed engine starts its supported graphical launcher with --gui. Browse to the actual permitted, writable Kilrathi Saga directory, review graphics/joystick choices and choose Launch WC1. Startup checks include GAMEDAT/MODULE.000, CAMP.000 and INSTALL.DAT and the Saga streams; they are not a full original-file identity audit. Portcove does not copy or authenticate those originals. The launcher and game run in the same process; cancelling setup is separate from successful gameplay.

  3. Preserve saves and the shared settings root

    The accepted upstream folder becomes the game working directory. Preserve the whole original tree, including SAVEGAME.WLD, unknown/custom files and any previous compatible runtime. Registry emulation also writes wc1-modern.cfg under the actual SDL preference directory for Origin Systems/WC Kilrathi Saga. These shared/external original, save and profile paths remain player-owned and outside Portcove-managed backups, restore and removal. A different engine folder does not isolate them; close all actual users before changing shared state.

  4. Keep this copy’s launch settings

    For an attached working copy retain its actual prepared working directory and established supported literal arguments. Starting without arguments opens the graphical launcher; existing direct arguments use the creating working directory unless --gui is included. Keep that choice truthful rather than starting a new engine folder with direct-game flags and no original data. Review exact intent/consent and choose Play separately. Do not substitute --check, a compiler, installer or historical reproduction binary for normal play.

  5. Keep runtime replacement and removal ownership separate

    Portcove manages replacement only for its separate managed engine; it does not adopt or move the original installation/profile. An attached copy keeps upstream/player ownership of preparation, runtime replacement, recovery and every external file. Preserve the old creating runtime and all actual state before updates; backward saves, alternate renderers, mods and controllers are not qualified here. Review/relink deliberate external executable replacement before Play. Removing a registration preserves external files; neither route promises to delete or back up outside originals, SAVEGAME.WLD or shared SDL preferences.

Limitations and evidence

  • Use only game data and components you are already permitted to use. The engine license does not grant rights to unrelated assets, music or modifications.
  • External and shared player-data locations remain outside Portcove backups and removal. Preserve the creating runtime, every actual state root and unknown files before changes.
