Setup

  1. Prepare upstream or keep an existing game build

    This project is under construction and has no published player downloads at the reviewed cutoff. Follow its recursive clone and make instructions; the documented native output is build/Kirby64Recompiled and your own supported NK4E.z64 must be in its launch working directory. Keep the selected toolchain and original-file requirements from upstream. Register only a prepared native game output, not the compiler tools.

  2. Keep your files and update through upstream

    Keep the game in a separate folder you control, and retain a working copy. Review its executable in Portcove, then add it without changing its files. Choose Play separately when you are ready. You manage updates, original files, generated data, saves and settings. Portcove does not replace, back up or roll back this external copy. Follow the project’s instructions for the version you use when changing it.

Setup notes
Keep the original with the completed player
The pinned source instructions use a recursive checkout, Clang 21 and make. Select build/Kirby64Recompiled from your prepared copy with a working folder containing your own NK4E.z64. The source expects the US ROM identity with xxHash3 0xD992BD1EBD3F8756.
Keep the profile used by this copy
Preserve saves/NK4E.us.bin and the general.json, graphics.json, controls.json and sound.json files under the effective Kirby64Recompiled profile. On Linux this is normally ~/.config/Kirby64Recompiled. An APP_FOLDER_PATH override or portable.txt changes the location. Back up the full effective folder with the player closed.
