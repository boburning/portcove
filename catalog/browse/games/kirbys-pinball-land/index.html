Setup

  1. Use your own matching Game Boy ROM

    Use your own legally obtained Kirby’s Pinball Land Game Boy ROM with the selected upstream Windows player. Its generated player is named for USA/Europe; other regions and revisions are not automatically interchangeable. Exact accepted ROM fingerprints are not established by the inspected instructions, and Portcove does not supply, convert, authenticate or prepare an original. This is an existing-player route, not an emulator download or proof that every execution path is statically recompiled.

  2. Keep the complete selected Windows package

    The inspected package is Kirby.s.Pinball.Land.zip; unpack it as one complete unit into a writable folder you control. Keep Kirby_s_Pinball_Land__USA__Europe_.exe, SDL2.dll, libc++.dll, libunwind.dll and libwinpthread-1.dll together in Kirby's Pinball Land. The selected files are Windows x86-64; experimental Wine/Proton or proposed Switch support does not qualify a native Linux, Deck or Switch route. The published repository snapshot is not a complete rebuildable source kit; do not treat placeholder CMake examples or packaged build objects as a working source-build recipe.

  3. Add the ordinary native player

    Select Kirby_s_Pinball_Land__USA__Europe_.exe inside that complete package folder, use the same folder as working directory and leave arguments empty for the normal ROM picker. Review the selected program, folder and arguments, then choose Play separately and select your own existing ROM in the upstream dialog. Keep any already working --rom, --save-dir or other supported literal arguments when your existing setup uses them; do not add diagnostic, headless, differential or test modes to normal Play. A compiler-identification a.exe below CMakeFiles is not the game.

Setup notes
Preserve game data and shared runtime preferences
Preserve the complete existing player folder and any title/save-ID .sav, .rtc and .stateN files that are present. Normal persistent paths are based on the executable folder; an already established --save-dir redirects them to its existing directory, so preserve that path and argument rather than choosing a new empty folder. Runtime preferences use %APPDATA%/gbrecompiled/runtime/runtime_prefs.ini through SDL, with a working-directory fallback when the SDL preference path is unavailable. That profile can be shared with another gbrecompiled title. Keep its controls/settings and any imgui.ini; do not reset the shared profile merely to add this reference.
