Setup

  1. Use already prepared OpenJO data

    This managed route accepts only a matching original-data copy already prepared for a working OpenJO installation. On Windows, copy that known-working original base folder beside the official player and keep the complete original installation and creating runtime unchanged and separate. New Outcast first setup remains held until upstream establishes the exact original-data, patch and layout contract. Keep the package's OpenJK game-library folder and all its own DLLs intact; do not copy old executables or DLLs into this runtime. Jedi Academy is a different game. Portcove does not verify original-game identity or perform that first setup. Customized layouts can retain their existing external registration.

  2. Keep the correct player and profile

    The managed player follows the Rolling latest build; this channel does not establish gameplay qualification. On Windows, the managed copy selects openjo_sp.x86_64.exe for single player. OpenJO multiplayer is outside this upstream player; upstream describes Outcast single player as working but still needing attention. This selected Windows package contains the non-portable home-directory branch: normal saves, configuration and logs use the actual Documents/My Games/OpenJO profile.

  3. Keep an existing prepared copy

    Use this route only for an already prepared, working upstream OpenJO installation with your own matching Outcast data. The inspected official OpenJO-windows-x86_64.zip contains openjo_sp.x86_64.exe; keep its companions. Register the existing player and its already working directory/arguments. Do not apply the Academy setup recipe to Outcast or treat this package inspection as original-data acceptance.

  4. Prepare the Linux OpenJO campaign profile

    Put the original archives in $XDG_DATA_HOME/openjo/base when XDG_DATA_HOME is set to an absolute path. Otherwise, with XDG_DATA_HOME unset, use ~/.local/share/openjo/base. Use only matching data archives from an already working Outcast installation. The inspected official build requires glibc 2.34, libstdc++ with GLIBCXX_3.4.29, SDL2, zlib, libjpeg.so.8, libpng16.so.16 and libOpenGL.so.0.

  5. Prepare the Mac OpenJO campaign profile

    Put the same prepared Outcast original archives in ~/Library/Application Support/OpenJO/base. Use the matching Intel or Apple Silicon package. The inspected bundled SDL2 requires macOS 14 or later on Intel and macOS 15 or later on Apple Silicon.

Setup notes
Preserve the actual OpenJO profile and compatibility boundary
Back it up separately with your originals and creating runtime before changing versions. Portable builds, unavailable Documents folders and explicit home-path overrides can change the write location; those configurations need their own preserved external registration. A runtime rollback does not rewind external saves or establish older-runtime, mod or recorded-demo compatibility.
Preserve existing OpenJO registration ownership
Existing registrations keep their selected player/mode, arguments, files and user/upstream runtime owner. Removing their registration preserves those files; this catalog change does not adopt or migrate them.
Keep Linux and Mac profiles
Preserve the Linux OpenJO profile at $XDG_DATA_HOME/openjo or ~/.local/share/openjo, or ~/Library/Application Support/OpenJO on Mac. Keep any explicit fs_homepath, original data, mods and the creating runtime.

Limitations and evidence

  • New Outcast setup remains held until upstream establishes the exact original-data/patch/layout contract. Upstream labels Outcast single player as needing attention and does not support Outcast multiplayer here.
  • Back it up separately with your originals and creating runtime before changing versions.
  • A runtime rollback does not rewind external saves or establish older-runtime, mod or recorded-demo compatibility.
  • Keep the Unix profile and original archives outside the Portcove library and back them up separately. Use a separately prepared copy for profiles with alternate native modules. Managed runtime replacement and rollback leave this external data in place.
