Setup

  1. Check your completed copy and terms

    Use an already permitted completed Windows build from the currently licensed source, under the project and framework PolyForm Noncommercial terms and applicable component notices. The current grant does not backdate permission for arbitrary older packages. Complete upstream generation/build separately; an executable with the expected name can still be a ROM-free setup host.

  2. Keep your exact original and optional donors

    Use your own Mega Man X (USA) (Rev 1) ROM: normalized SHA-256 b8f70a6e7fb93819f79693578887e2c11e196bdf1ac6ddc7cb924b1ad0be2d32. Upstream accepts a raw headerless ROM or strips a 512-byte copier header. Archives, patched ROMs, USA v1.0, Japan and Europe are not this selected route. Optional Zero/X2/X3 content requires its own matching donor and permission; keep those inputs and locally generated caches with their creating copy.

  3. Select the completed native player

    Select the already working generated MegaManXSNESRecomp.exe and its containing runtime folder as working directory. Do not select a setup host, build script or compiler. For direct play use three literal argument tokens: --no-launcher, --rom, and the absolute path to your supported ROM. Keep spaces inside the path token. Preserve any established custom --config path and its working directory instead of changing an existing profile merely to register.

  4. Review consent and choose Play separately

    Review and consent to the exact executable, working directory and literal arguments. Registration retains that intent without running upstream setup or starting the game; choose Play separately. Relink an upstream replacement through a new review. In-game launcher/settings or lobby actions can start a successor even with --no-launcher. Portcove observes the selected process; close every actual player and successor before upstream replacement.

  5. Keep upstream ownership and the full data tree

    You and upstream own preparation, repair and runtime updates. Preserve the whole working tree, original and donor ROMs, generated code and caches, config.ini and any selected custom configuration, rom.cfg, keybinds.ini, saves, mods and preloaded state, logs/reports/captures and all custom paths. Normal configuration anchors to the executable directory; a custom --config preserves its existing working-directory interpretation. Removing registration removes only Portcove metadata and preserves every external file.
