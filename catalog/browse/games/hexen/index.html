Setup

  1. Supply the matching original game files

    Supply HEXEN.WAD from an original PC Hexen retail v1.1 copy. The offered Crispy 7.2 runtime rejects retail v1.0; use the upstream-recommended official upgrade to v1.1 while preserving your original copy. The unsafe -v10override bypass is not offered, and demo/shareware data is not qualified by this managed base-game route. An expansion alone does not supply the base game, and Heretic is a different original. Keep your originals and edition identity; renaming another game’s WAD does not convert it. Originals are not included or authenticated by Portcove. Use a recognized upstream installation, or deliberately copy matching files into the originals subfolder (named exactly originals) of this entry’s fresh private data folder; keep your original copies.

  2. Use the upstream setup and launch controls

    Play opens crispy-hexen-setup.exe. Configure controls and use F2 Warp for single-player launch; choose the matching detected IWAD there. The main-menu launch command forwards its existing arguments. The PWAD/mod browser is not an original-IWAD browser. Keep different title entries separate. Do not switch this entry’s original edition in place: its retained runtime versions share data. Use a separate Portcove library or independently owned upstream copy for another source variant. No automatic switching or cross-variant save compatibility is established. An upstream setup exit does not establish that the game loaded or ran successfully.

  3. Keep the declared private data scope

    Portcove retains originals deliberately copied under originals, this entry’s default configuration, saves under saves, known default save locations, numbered screenshots and declared recording files. Put custom recordings under demos or use a demo-prefixed .lmp filename. Upstream may read and write its music-pack profile on Play. Music packs and custom paths outside this installation remain external and outside Portcove backups. Extra files written inside the installation outside its declared folders are outside this offered scope and can block maintenance. Keep the creating runtime, original files and actual data before changing a source variant or using an older runtime.

  4. Keep updates in one place

    Portcove manages this new official game installation and the data listed for it. It does not import an existing project profile or convert a separately registered game. Existing registered copies keep their external files and update tools. Back up those external profiles and original files separately. Automated fixture checks and reaching a setup menu do not establish original-file or gameplay compatibility.

Setup notes
Install the native package on Linux or Mac
On Debian, install the crispy-doom package through the package manager. On Mac, use the upstream-documented MacPorts port or a supported Homebrew formula. Start crispy-hexen with -iwad followed by the quoted path to your own HEXEN.WAD from retail Hexen updated to v1.1. Use the external package manager for replacement.
Keep the existing Crispy profile
Preserve the actual Crispy config, saves, demos and original IWADs. Linux normally uses ~/.local/share/crispy-doom or XDG_DATA_HOME/crispy-doom. Mac normally uses ~/Library/Application Support/crispy-doom. Keep any custom locations and the creating runtime before switching package versions. The external profile can be shared across games.

Limitations and evidence

  • Play opens the project’s setup and launch controls. Supply your own matching original game files that you are permitted to use.
  • Portcove backups exclude external music packs, custom paths and data belonging to separately registered games.

Setup

  1. Check the required game files

    Use your own Hexen (N64) Nintendo 64 USA ROM. Check the required size and SHA-1 in games/hexen-us/profile.toml before importing. Keep the original separately. These instructions do not download or run it.

  2. Build from source on Linux

    Follow the upstream Linux prerequisites. From the checkout root, run .venv/bin/python tools/import_rom.py --profile games/hexen-us/profile.toml --rom "/path/to/your-ROM.z64" with your own .z64, .n64 or .v64 file. Run cmake --workflow --preset hexen-us-release, then ./build/hexen-us-release/bin/hexen-us. The default keeps the ROM external. Keep the ROM and any locally generated game code private, including builds that embed it.

Setup notes
Build from source on Windows x64
Follow the Windows setup guide in the upstream README for Visual Studio, Python and vcpkg. Use the same ROM profile with the Windows Python environment. From the checkout root, run .\tools\build_msvc_project.ps1 -Game hexen-us -Configuration Release in PowerShell. Start the resulting build/msvc/hexen-us/release/bin/Release/hexen-us.exe from the checkout root and keep its dependency DLLs beside it. Preserve the checkout’s private local/ directory and any custom data paths before rebuilding.
Prepare a private Steam Deck copy
Follow the upstream Steam Deck container guide on an x86-64 Linux PC and run ./tools/build_steamdeck.sh hexen-us after importing your ROM. Keep the resulting package folder together. Supply your matching ROM at the local/ path named in its included instructions, then add launch.sh to Steam as a non-Steam game with compatibility tools disabled. Preserve local/ from the old copy before rebuilding or replacing it. Keep private packages and generated game code to yourself. Portcove has not observed Deck setup or gameplay.

Limitations and evidence

  • The shared README does not confirm gameplay for this game. Check the linked game notes; progress reported for other games does not establish that this one works. A full playthrough and Portcove gameplay checks have not been confirmed.
  • Portcove has not confirmed setup, gameplay, saves or updates for this experimental port.
