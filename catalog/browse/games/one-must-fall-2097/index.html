Setup

  1. Start the managed Windows player

    The official archive includes the freeware One Must Fall 2097 resources and the native OpenOMF player. Choose Play after installation; no commercial source files or generation step are needed. The package also includes an ARM64 player; this route uses openomf.exe for x86-64.

  2. Start the managed Linux AppImage

    Install the stable x86-64 AppImage in Portcove and choose Play. Your Linux system needs AppImage support. The package includes the freeware resources and SDL2. The v0.8.6 AppImage also needs your system’s libjack.so.0 and libpipewire-0.3.so.0. Use your distribution’s packages if Play reports either library missing. For a custom OpenOMF override or alternate resource set, keep a separately prepared copy.

  3. Prepare the upstream Apple Silicon package

    Extract the stable Apple Silicon ZIP into a separate folder. If it contains usr/bin/openomf, check the Homebrew library requirements below and keep the entire usr tree. Set OPENOMF_RESOURCE_PATH to the absolute path to the extracted usr/share/games/openomf folder when launching that player. If the package instead contains OpenOMF.app, keep the app intact and follow its release instructions.

Setup notes
Check the inspected stable packages
The inspected 0.8.6 AppImage needs glibc 2.38 or later for its bundled libraries. The separate 0.8.6 Linux TAR.GZ needs glibc 2.43 and system libraries. The loose 0.8.6 Apple Silicon ZIP needs macOS 14 and Homebrew libepoxy, confuse, enet, sdl2_mixer, libxmp, libpng, opusfile, miniupnpc, libnatpmp and sdl2-compat. The binary loads specific library versions from /opt/homebrew. The macOS 15 app layout was observed on the separate rolling channel.
Find the effective OpenOMF profile
After explicit OpenOMF overrides, upstream checks XDG_CONFIG_HOME for configuration and XDG_STATE_HOME for state, then the SDL preference directory. Preserve settings, saves, scores, recordings, screenshots and user mods at their effective locations.

Limitations and evidence

  • Portcove manages the selected Windows and Linux runtime packages. You and upstream maintain independently prepared copies, including the Mac package. Back up the actual configuration and state folders separately. An explicit OPENOMF_CONFIG_PATH or OPENOMF_STATE_PATH can change those locations.

Setup

  1. Choose the upstream game package

    Choose an OMF-2097-Remastered file for your system from the upstream release. The OMF-Studio files open the separate editor. The game includes its freeware resources and starts without importing a DOS installation.

  2. Start the Windows or Linux player

    On Windows 10 or 11, run the matching upstream game EXE with WebView2 available. The release also offers Windows ARM64 and 32-bit Windows 10 builds. On Linux, choose the x86-64 or AArch64 AppImage, make it executable and launch it. Use your distribution’s FUSE 2 package if the AppImage requires it.

  3. Open the Mac app

    Choose the separate Intel or Apple Silicon ZIP for your Mac. Extract it and keep the complete OMF 2097 Remastered.app bundle. Both packages require macOS 12 or later. The upstream release is unsigned on Windows and lacks Apple notarization on Mac.

  4. Play in your browser

    Use the Play Online link on the upstream project on a computer, tablet or phone. Keep the site data in the browser profile you play in. Android uses this browser route.

Setup notes
Preserve your player profile
Keep the WebView profile with your controls, settings and replays before replacing an upstream desktop copy. On Linux it is under $XDG_DATA_HOME/com.omf2097.remastered, normally ~/.local/share/com.omf2097.remastered. Browser play uses that browser’s separate site data.

Limitations and evidence

  • The upstream packages bundle the freeware original and remastered art used during play. Portcove Download is held for the bundled gameplay art. Use the publisher’s own game page and keep your desktop or browser copy under your control.
