Setup

  1. Prepare your original through upstream setup

    Use a complete player/components you are independently permitted to use and your own Xbox 360 skate (2007) ISO. The selected source uses a USA disc extraction example; an exact accepted XEX fingerprint is not published here, and another revision is not automatically compatible. Finish the official package’s Setup.bat import outside Portcove. The script checks default.xex exists and writes the game’s AllowMovieSkip.txt flag; that is not a cryptographic original-revision check.

  2. Use the actual native test package

    The inspected official v0.2.0 Windows ZIP contains AMD64 Skate1-PC-v0.2.0/skate1.exe, rexruntimerd.dll, matching runtime libraries, skate1.toml, portable.txt and the separate setup/extraction scripts. The packaged player does not require the tagged developer build route merely to start an already prepared game. Keep the full writable unit and game/ tree. Package requirements are Windows 10/11 x64, AVX2 and D3D12; source minimum assumptions do not replace those package requirements.

  3. Attach the prepared normal game

    Select skate1.exe, use the complete Skate1-PC-v0.2.0 directory as working directory and leave arguments empty after upstream import/settings. Review the selected program, working folder and arguments and choose Play when ready. The native app enters its linked game in process; missing or relative game_data_root resolves beside the executable. Do not select Setup.bat, PowerShell, an extractor or a developer compiler as the normal game. Preserve any existing deliberate external game-data settings.

  4. Preserve portable and historical data roots

    The source’s existing portable.txt choice forces user data and cache beneath executable-folder/userdata; keep that marker and the complete userdata tree, profiles/saves/content/cache, skate1.toml, logs and originals. Do not create/remove a marker or move only the EXE. The packaged README says deleting the marker uses %APPDATA%/skate1, whereas the pinned SDK’s fallback uses Known Documents/skate1. This guide changes neither layout: preserve actual roots shown by the prepared installation/logs, historical AppData and Documents copies and existing explicit overrides when portable mode is absent. No conversion, synchronization, backup, restore or deletion is performed.
