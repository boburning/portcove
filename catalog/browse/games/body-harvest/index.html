Setup

  1. Set up the managed copy on first Play

    Use Load ROM to select your own North American Body Harvest cartridge dump. The player verifies and remembers a private copy in its profile, alongside settings and saves. Back up that profile separately before changing versions.

  2. Keep a complete permitted player

    On Windows, select BodyHarvestRecompiled.exe in your existing permitted copy; on native Linux x64, select BodyHarvestRecompiled. Keep its complete extracted folder and supplied assets/libraries together as the working directory. macOS uses the upstream application bundle. Linux ARM64 and Flatpak are separate upstream packages and preparation routes; Windows launch details do not apply to them. Choose Play explicitly, then Load ROM in the player and select your own North American Body Harvest cartridge dump. Upstream accepts .z64, .n64 and .v64 byte orders, checks the game identity and remembers a normalized bh.us.z64 copy. The released player needs no separate compiler or original-game installer.

  3. Keep Flatpak data with the actual profile

    For an existing permitted Flatpak installation, follow upstream preparation and preserve the complete ~/.var/app/io.github.bodyharvestrecomp.bodyharvestrecomp folder alongside the actual profile. Its writable app area and normal/custom/portable profile can be different. Keep the working installation until its replacement is ready.

  4. Select the prepared Windows player

    Select BodyHarvestRecompiled.exe and use its containing folder as the working directory. Leave arguments empty. Keep the complete independently permitted runtime and finish the title-specific preparation before Play.

Setup notes
Preserve the actual profile and working copy
You or upstream provide updates to a copy you prepared yourself. Portcove updates its managed Windows or Linux x86-64 runtime. Keep the complete external copy and actual profile: normally %LOCALAPPDATA%\BodyHarvestRecompiled, ~/.config/BodyHarvestRecompiled, or ~/Library/Application Support/BodyHarvestRecompiled. On Windows/native Linux, portable.txt uses the working folder; on macOS the marker and data belong beside the application bundle. Preserve the ROM copy, saves, settings, bindings and mods, including any APP_FOLDER_PATH override. These external files are outside Portcove backup and rollback.
Registration ownership and removal
Portcove records the selected executable, working folder and literal arguments after review. Play is separate and only the selected process is supervised. You and upstream own replacement and updates; relink changed executable bytes after reviewing them. Removing this registration preserves every external file. Managed installation, backup, rollback, migration and deletion are not offered for this external copy.
Player-data ownership
You and upstream own the external copy's data: the actual BodyHarvestRecompiled profile, normally %LOCALAPPDATA%\BodyHarvestRecompiled on Windows; the working folder for a Windows portable.txt copy; the real custom or platform-specific profile for other copies. Back up these locations separately; registration does not migrate or certify their compatibility.
Managed runtime ownership
Portcove installs and replaces its separate official runtime using the declared release rules. Existing external registrations retain their files and user/upstream ownership. Runtime rollback carries current declared data; it does not rewind saves or establish older-runtime compatibility. Gameplay and populated-save compatibility remain separate qualification. The managed copy has no declared local player data to back up. Back up the external profile separately.

Limitations and evidence

  • On Windows/native Linux, portable.txt uses the working folder; on macOS the marker and data belong beside the application bundle. Preserve the ROM copy, saves, settings, bindings and mods, including any APP_FOLDER_PATH override. These external files are outside Portcove backup and rollback.
  • Use the complete upstream Mac application with its bundled libraries. The libraries in v1.0.0 target macOS 14 or later on both Mac architectures.
  • Use a separate upstream copy for portable.txt mode, an APP_FOLDER_PATH override, Linux ARM64, Flatpak or macOS. Managed and separately prepared copies can share the default profile.
  • The official Linux x86-64 package needs glibc 2.35 and system SDL2, GTK 3, FreeType and GCC runtime libraries.
