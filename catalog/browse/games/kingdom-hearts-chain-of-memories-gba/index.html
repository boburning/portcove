Setup

  1. Complete supported preparation upstream

    Use an independently permitted complete Windows ReKHCoM copy, keeping ReKHCoM.exe, bin, bin64, assets, libraries and notices together. Complete original-ROM setup through its supported launcher upstream before attachment. The root launcher is 32-bit; the package also contains the optional 64-bit runtime. Do not use a private bin/bin64 runner or infer native parity from a package label.

  2. Keep the exact owned original

    Use your own 32 MiB cartridge dump: Europe B8CP SHA-1 8db73586cdb11b3795907edebf43228dbcd3e6b2, USA B8CE 10729bd884f8fdca7a310b6d606c52e46657aa48 or Japan B8CJ 59ec0a0a4ccd1e6acb3bbd7bfb21d63988958cfa. The launcher verifies and places its selected original under roms. No ROM is included. Optional HD imports require separate owned ReMIX assets and are not a base-game prerequisite or a Portcove import operation.

  3. Attach the supported prepared player

    Select root ReKHCoM.exe with the complete package root as working directory and no arguments. Its supported Play path starts the selected 32-bit game or compatible bin64 runtime, supplies the shared data root and selected ROM, hides and waits until that game exits. Automatic 64-bit mode requires the matching host, guest image, SDL3 and SSE4.1; it can fall back to 32-bit. Retain upstream architecture choices instead of bypassing the launcher.

  4. Review Play and retain external ownership

    Review and consent to the exact selected executable, established working directory and literal arguments, then choose Play separately. Removing registration preserves external files. Upstream and you retain one runtime-replacement owner; Portcove provides no external update, backup, rollback, migration or deletion. Close actual players and companions before deliberate maintenance, keep the old working copy and all effective data, then review/relink changed selected bytes.

Setup notes
Keep optional successor sessions separate
Upstream and you own runtime replacement and architecture preference changes. After replacement, close actual games and launcher, retain the old complete copy and every data root, then review and relink changed selected bytes. This guide neither invokes an updater nor claims tracking of an independently relaunched or replaced program. The packaged README retains older version/32-bit-only text; use the inspected v2.3 root launcher and matching complete package rather than that stale architecture description.
Preserve the whole copy and effective data
Preserve the whole package and effective custom data roots: roms, kh_com*.sav and all save banks, kh_com*.ini, decompui.ini, states, backups, kh_com.log, retroachievements.ini, achievements*.dat, netlink.cfg, mods and optional hd assets/import journals. Save states are build-specific and do not contain cartridge SRAM. Upstream can adopt files from a neighboring older install and move HD scenes during startup; preserve both locations before maintenance. Keep account/token-bearing configuration private. CC0 source/decompilation and SDL3/ImGui/rcheevos notices remain separate from Square Enix/Disney artwork and game content.
