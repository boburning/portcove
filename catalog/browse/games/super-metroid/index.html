Setup

  1. Complete the upstream source build

    Use the distinct snesrev/sm implementation under its MIT and component notices with your own supported Super Metroid original. Follow the pinned upstream Windows build instructions outside Portcove. This is an early experimental native implementation with bugs and frame-by-frame comparison against the original; a mismatch writes diagnostic snapshots. It is distinct from mstan Super Metroid and does not inherit its source, saves or qualification.

  2. Choose the completed player and original

    Select your already working sm.exe. The Visual Studio Release recipe writes build/bin-x64-Release/sm.exe; the Make recipe builds the sm target at the project root. Use your established runtime root containing the configuration and saves as the working directory. Do not select run_with_tcc.bat, a compiler or another build wrapper. Keep your supported raw sm.smc, SHA-1 da957f0d63d14cb441d215462904c4fa8519c613; the guide does not establish alternate revisions, copier headers or archive representations.

  3. Keep your configuration and exact launch arguments

    For an explicit invocation use three literal tokens in this order: --config, the absolute path to your actual existing configuration, and the absolute path to your supported ROM. Preserve sm.user.ini if that is your active override; otherwise use your existing sm.ini. Keep spaces inside each path token. This explicit --config avoids upward sm.ini directory discovery, but relative data still uses the chosen working directory. Preserve an already working custom invocation rather than switching profiles.

  4. Review consent, then Play

    Review and consent to the selected executable, working directory and literal arguments. Registration does not build, start or repair the game. Choose Play separately; retained registration and relink remain subject to a new review when the program, folder or launch arguments change. Portcove observes the selected process. Close all actual players before changing the upstream copy.

  5. Preserve the experimental runtime and saves

    Upstream/player own all builds, repairs and updates. Keep the complete runtime/source tree, original, sm.ini, sm.user.ini, every selected custom configuration, saves/sm.srm and sm.srm.bak, save/replay/mismatch snapshots and all custom files. Keep diagnostic states with their creating build; this route does not migrate or establish compatibility with another build or implementation. Removing registration removes only Portcove metadata and preserves all external files.

Limitations and evidence

  • This Windows selected-process route does not provide managed acquisition, compilation, Install, Update, Backup, Rollback, migration or external deletion. Actual game execution/gameplay/save-load, other platforms, exclusive process-family ownership, network/debug behavior and installed/protected delivery are not qualified here.
