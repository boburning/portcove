Setup

  1. Keep the working engine and your original ISO together

    For the v0.9.81 Windows Static Recomp route, finish the supported upstream setup with your own Melee NTSC-U 1.02 ISO and keep the complete package and required Sys/runtime companions. Source Port is a different engine; do not substitute executables, generated output, mod data or profiles merely because both are in the release. Portcove registration does not authenticate the whole original disc or build private output. Keep the complete original and creating configuration recoverable.

  2. Select the direct native player

    Select the working melee_port.exe. Its installation is the normal working directory, but keep a different established working directory when your actual working launch uses one: relative settings, Sys, cards and replays can otherwise point to a new profile. Supply --iso and the absolute path to your original ISO as separate arguments. Retain the actual creating --sys-dir, --settings-path, --card-dir, --replay-dir, --user-dir and any supported renderer/mod arguments rather than inventing a new profile. Do not select a .bat file or MeleeUnlockedLauncher.exe for this direct-player route. Save launch details, then choose Play separately.

  3. Finish upstream restarts and replacement separately

    In the inspected v0.9.81 source, release checks and package installation are called by the separate optional launcher, not the direct Static Recomp player. Select that exact direct-player route; this does not qualify older players or the other engine. The game still offers an explicit DLSS model download that can write a DLL for the next restart, and backend/settings changes can start a successor. Complete those optional upstream changes separately before relinking the working player and choosing Play again. Portcove supervises the selected native process and does not adopt successors, install optional model files or own runtime replacement. This route does not disable every network feature or external write. Online Slippi accounts, controller/adapter setup, mods, crash-report sharing and optional DLSS model downloads are separate choices, not automatic Portcove setup.

  4. Preserve all engine and shared player data

    Before changing versions keep the whole working installation, Versions, Sys, port-settings.ini, launcher.ini, User/GC/CardA and other actual card folders, replays, practice/lab data, PhobGCC settings, Slippi user/account state, shader/pipeline caches, logs, mods, unknown files and all explicit custom paths. Preserve the actual LOCALAPPDATA/MeleeUnlocked launcher history too. Different engine/version folders can share ISO, settings, cards and replays; they do not establish compatibility or isolation. Upstream owns updates. Portcove registration provides no managed update, backup, rollback, migration or deletion; removing registration leaves all external files untouched.

Limitations and evidence

  • Original game data and NVIDIA/Intel/Slippi and other components retain their separate terms. This handoff does not qualify online matches, mod/save compatibility, generated output, gameplay or the optional other engine.
