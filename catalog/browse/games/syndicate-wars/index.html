Setup

  1. Complete the supported PC Syndicate Wars setup upstream

    Use a permitted complete Windows Syndicate Wars Fan Expansion/Port copy with your own supported PC CD/digital data and required upstream graphics, sound and level packages. The reviewed setup distinguishes the tested European multilingual/US data, German-language disc requirements and unsupported Asian fonts; retain the chosen language and edition. Windows installer/setup archives and patch archives are different. Finish all upstream original-data installation, dependencies and preparation first; no installer, helper or original-data fetch is run here.

  2. Select the player with its existing launch settings

    Select the actual native Windows swars.exe with its completed runtime/data directory and supported established arguments; /g is the documented Windows-style normal-start option and is no longer mandatory. Do not select an installer or setup archive. Keep the actual 32-bit SDL/OpenAL/render dependencies for that copy; a 64-bit OS alone does not replace those components.

  3. Preserve user, installation and CD locations separately

    Keep the whole creating runtime/data/CD setup, config.ini, conf/, qdata/savegame, qdata/screenshots, all user/profile INI files, saves, replays, custom and unknown files. Source resolves installation data from the actual registry-backed setup or working-directory fallback. On Windows it uses AppData/Syndicate Wars for user paths only when that installation lookup and AppData succeed; otherwise it falls back to the working directory. The mapped save/screenshot roots follow that choice. Preserve every actual effective root and compatible old runtime before upstream changes; no profile/registry migration or backward-save qualification is offered.

  4. Review the prepared player and launch details

    Finish setup with the project’s tools, then start and quit the permitted copy you intend to add. Keep its game executable, working folder and supported launch arguments. Review those details in Portcove and agree to launch them, then choose Play separately. Adding a copy does not confirm its original game files, gameplay or save compatibility.

  5. Retain upstream replacement and external ownership

    Close every running copy of the game before changing files. Keep the working game version and every original-file, profile and data location it uses. Update it with the project’s tools, then review and select the changed executable in Portcove. You manage setup, replacement, file changes, data migration and recovery. Portcove monitors the process you selected; it does not restrict file access or prevent other copies from running. Removing the registration leaves external files in place. This route does not offer Portcove downloads, setup, updates, backups, rollback, data migration or external-file deletion.

Setup notes
Version and platform notes
The project was formerly mefistotelis/swars. The installer can convert music and does not need the disc image after completing setup. The project also documents a Windows MinGW32 source path. Confirm the selected package architecture and retail revision upstream.

Limitations and evidence

  • Use only a copy and components you are already permitted to use. Engine licensing does not grant original-game, music, mod, middleware or redistribution rights.
  • Before changing versions, keep a copy of the working game and every data and profile folder it uses. Another executable may use those same folders.
