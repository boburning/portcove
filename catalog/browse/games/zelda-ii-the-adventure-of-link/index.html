Setup

  1. Drop your own Zelda II USA ROM into the game window

    Choose Play to start the direct z2rs player. Drag your own supported USA NES ROM onto the game window. The player reads it in place and remembers its path. Keep the ROM outside the managed runtime. Use upstream setup for the separate launcher and Android.

  2. Keep the upstream package and prepare your own original

    Use the complete extracted official Windows x64 z2rs package (the ZIP ending in -x86_64-pc-windows-msvc.zip) with z2rs-launcher.exe, z2rs.exe, companions and notices. z2-signal.exe is an optional signalling server, not the player. This is a Rust reconstruction with a native desktop frontend; upstream frame-comparison and enhancement claims do not establish a Portcove playthrough or native/controller observation. In the upstream launcher choose your own Zelda II: The Adventure of Link (USA) NES ROM. Its accepted ROM body, after stripping the 16-byte iNES header, has CRC32 BA322865 and SHA-1 11333adb723a5975e0ecca3aee8f4747aa8d2d26. These identify the body, not the complete headered file. The game reads the ROM in place and remembers its path; keep it at that location. The project’s MIT code grant and original-ROM/HD-pack rights are separate; no ROM or extracted asset redistribution is granted. On Linux x86-64, keep the complete official archive together and start z2rs-launcher. On macOS, choose the archive for Intel or Apple Silicon and start z2rs.app. Pick your own supported USA ROM in the launcher. Preserve the actual profile, normally ~/.local/share/z2rs on Linux or ~/Library/Application Support/z2rs on Mac, including any XDG_DATA_HOME or custom data directory. On Android 8 or newer, use the official release APK and choose the ROM with Android's file picker. Keep an independent copy of the original. The app copies the ROM and keeps saves in private storage. A same-signature update preserves that data, while uninstalling deletes the private copy and saves. Use the upstream app and its backup guidance for these platforms.

  3. Attach a separate prepared launcher

    Select z2rs-launcher.exe, use its complete release directory as working directory and leave arguments empty. Review the selected program, folder and arguments, then choose Play when ready and use the launcher’s ROM picker and Play control. Keep z2rs.exe beside it. This launcher is an external registration choice. To attach the direct player instead, use the last step after preparing the same package. Preserve any existing Advanced game-binary override or Z2RS_GAME_BIN choice; do not substitute the server helper.

  4. Preserve settings and all save slots

    Keep %APPDATA%/z2rs on Windows, or the existing XDG_DATA_HOME/z2rs override, including z2-native.json, battery saves, savestate*.z2snap and other user files. Preserve the original ROM’s separate path, optional HD packs, randomizer outputs and existing custom config paths. Do not assume save-state compatibility beyond upstream’s documented format, import another project’s saves or reset populated options to add the reference. The ROM is not copied into the default data directory. Online co-op, the signalling service, HD packs and Discord presence are upstream options; Portcove does not enable services, supply credentials or configure them. The launcher starts a separate game process: Portcove follows the selected program only, and its activity can finish while the game continues. Close the actual game and helpers before replacing the complete upstream release or recovering files. Review/select the executable after updates. Reference removal preserves external files; Portcove does not replace or back up this external copy.

  5. Select the prepared player

    Select z2rs.exe and use its containing folder as the working directory. Leave arguments empty. Keep the complete independently permitted runtime and finish the title-specific preparation before Play.

Setup notes
Registration ownership and removal
Portcove records the selected executable, working folder and literal arguments after review. Play is separate and only the selected process is supervised. You and upstream own replacement and updates; relink changed executable bytes after reviewing them. Removing this registration preserves every external file. Managed installation, backup, rollback, migration and deletion are not offered for this external copy.
Player-data ownership
You and upstream own the external copy's data: the active %APPDATA%/z2rs or XDG_DATA_HOME/z2rs profile, original ROM and any custom save or pack directories. Back up these locations separately; registration does not migrate or certify their compatibility.
Managed runtime ownership
Portcove installs and replaces its separate official runtime using the declared release rules. Existing external registrations retain their files and user/upstream ownership. Runtime rollback carries current declared data; it does not rewind saves or establish older-runtime compatibility. Gameplay and populated-save compatibility remain separate qualification. Portcove preserves only these declared local inputs during replacement and backup: .z2rs-data. Its backup does not include external profiles.

Limitations and evidence

  • Use your own exact USA ROM. If you attach the prepared launcher, select z2rs-launcher.exe from the complete external package. Preserve %APPDATA%/z2rs and the ROM’s original path; the selected launcher does not establish full-game lifetime.
  • Back up your external z2rs profile before changing versions. Use an absolute personal profile and the default data directory. Use a separately prepared copy for relative paths, a custom data_dir_override or launcher-only options. Windows and Linux can use the fixed .z2rs-data fallback when the upstream environment supplies no profile root. On Mac, use an absolute XDG_DATA_HOME or HOME outside the managed library. Runtime rollback does not establish save-state compatibility.
  • The inspected Linux packages require glibc 2.39, libudev.so.1, libasound.so.2 and libgcc_s.so.1.
