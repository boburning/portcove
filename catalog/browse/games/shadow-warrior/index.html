Setup

  1. Use your recognized original game files

    Use your own 1997 PC Shadow Warrior data folder, anchored by SW.GRP. Keep its accompanying files and any separately owned expansion data. The 2013 reboot is a different game. Raze searches installed Steam/GOG copies and configured game-data folders. Reuse a recognized copy; do not duplicate it unnecessarily. If it is not found, add its real location to GameSearch.Directories in raze.ini, or in raze_portable.ini for the Portcove-managed Windows player; do not copy game files into the managed player folder, because Portcove verifies that folder. Elsewhere, you may instead place a copy of its complete data folder beside Raze. Keep your own originals; no original game files are included.

  2. Choose Play in the upstream player

    On Windows, choose Install, then Play explicitly. Portcove downloads and verifies the official Windows ZIP, keeps the player folder together, and creates Raze’s portable configuration marker so its configuration, saves, screenshots and demos stay beside the managed player, where Portcove preserves them across updates. Raze may ask which detected game/edition to use, because the same player supports several games. For a fixed entry, Change launch details can use two argument lines: -gamegrp, then the local Windows drive-letter absolute path (for example C:/Games/...) to your SW.GRP archive. Use Raze’s game picker for UNC/network paths; this fixed-entry example does not establish a POSIX/macOS path rule. Keep that archive’s companion files together.

  3. Keep upstream update ownership and platform handoffs

    On Windows, Portcove replaces the managed runtime and preserves its declared data. A separate existing Windows copy stays yours: registering it preserves every external file and Portcove does not manage its Update, Backup or Rollback, and the normal-profile settings described below are not imported into a managed install. Elsewhere, you and upstream replace this external player. On macOS, use the official universal Raze.app through the normal OS application flow; do not register its private Contents/MacOS binary. Its normal settings are ~/Library/Preferences/raze.ini saves ~/Documents/raze/Savegames and screenshots ~/Documents/raze/Screenshots. A native Linux build outside Flatpak uses its own profile, usually ~/.config/raze. Preserve that profile and any older ~/.raze directory before launching a replacement.

  4. Use Raze from Flathub on Linux

    Install org.zdoom.Raze from Flathub for Linux x64 or ARM64. Make sure ~/.config exists in your home directory. Keep your original files and place a complete working copy of this game's data in its own subfolder under ~/.var/app/org.zdoom.Raze/.config/raze. Open Raze and choose this game if a picker appears. Close Raze and back up its actual configuration, saves and mods before updating through Flatpak.

Setup notes
Keep the shared profile this game uses
A Portcove-managed Windows install keeps raze_portable.ini, Save, Screenshots and Demos beside the managed player and does not share or import the normal-profile locations described next. Windows normally keeps raze.ini in Documents/My Games/raze, saves under the system Saved Games/Raze folder, and screenshots in the system Screenshots/Raze folder; redirected Windows known folders can change those absolute locations. A writable raze_portable.ini outside Program Files uses the player folder with Save and Screenshots instead. Custom -config/-savedir locations remain external. Normal save roots contain game/edition subfolders. A custom -savedir disables that partition, so keep a separate chosen directory for each game. Several entries can share Raze settings. Switching a portable marker redirects paths; it does not move normal-profile saves. Close all copies and back up the actual locations, original data and selected mods before changing versions. First Play in a newer copy may migrate an older configuration; preserve its old location too. Keep a working runtime until its saves work in the replacement.
