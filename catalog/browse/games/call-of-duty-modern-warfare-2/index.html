Setup

  1. Complete the supported Xbox 360 preparation

    Use your own Modern Warfare 2 (2009) Xbox 360 USA/Europe disc version 1.0.557, not the PC release, remaster or another Call of Duty. Complete upstream installation and its required title update 6 before attachment. The native player hashes game/default.xex or game/default_mp.xex against the exact SHA-256 compiled into that build; title/version text alone does not replace this check. The selected release’s literal build-time hashes are not independently reproduced here. Do not bypass a mismatch or register an incomplete install that redirects to setup.

  2. Retain the complete matching Windows release

    Keep the full official v0.8.3 Windows package, both native players, mw2-launcher.exe, game/, renderer resources, shader caches, libraries and notices. The documented host requires 64-bit Windows, SSE4.2 and Vulkan 1.2. Use an independently permitted prepared player; project GPL-3.0-only applies to its own runtime/tools/patches, not Activision originals or original-derived generated C++. Separate title-update, Steam/network, custom-map and shader/component rights remain separate.

  3. Choose the upstream frontend or retain a direct player

    For normal setup/profile/mode controls, select mw2-launcher.exe in the complete existing package directory, use that directory as working directory and leave arguments empty. Review the selected program, folder and arguments, then choose Play when ready and use the upstream frontend. It supplies its own settings, preparation and selected SP/MP context. The existing direct choices remain valid: mw2-sp.exe for campaign/Special Ops or mw2-mp.exe for multiplayer, same directory and empty arguments, after upstream preparation. Portcove observes whichever program you selected, not detached successors; its activity may finish while a game or switched mode continues. Use actual game/upstream controls to quit.

  4. Preserve the complete save and settings unit

    Retain saves/, game/, .env, profile/settings files, logs, shader caches and all original/backup copies together. Saves are beside the executables, not inside read-only game/: the runtime represents content packages as directories, including saves/savegame.svg/savegame.svg, and this is not an Xbox STFS container or a promised console-save conversion. Preserve separate profiles and upstream shared SP/MP progress. Keep existing environment overrides; copying only an EXE or replacing .env with defaults can change behavior or separate progress.

  5. Keep maintenance and remaining acceptance upstream

    Use the upstream frontend for preparation, title updates, shader compilation, profile/network configuration, custom maps and runtime replacement. Close actual SP/MP games and helpers before making changes, even after Portcove’s selected-program activity ends. Re-select/review changed player bytes as needed. No credentials, network/server participation, full-game/controller/real-save acceptance, managed install/update/backup/rollback/migration or external-file deletion is supplied.

Limitations and evidence

  • The native mw2-launcher.exe frontend preserves ordinary upstream setup and mode choices; existing direct mw2-sp.exe/mw2-mp.exe registrations remain available. Portcove tracks only the selected program. Preserve game/, saves/ and .env, close actual games/helpers before changes.
