Setup

  1. Finish the upstream build first

    The v0.1.12 release is a ROM-free setup pack, not the prepared game. Use upstream's Generate & Build flow separately with your own Japanese original: SHA-256 dd94308d822636c6ddf73c5e2644c84f2eb8fb4d9201150fc5f37d44d6f423f1, CRC32 c0aecdca. Upstream generates private C code and builds the game locally. Keep the original, generated code, source tree and build tools private and unchanged elsewhere. Portcove does not run that setup or authenticate your original.

  2. Choose the prepared game

    Select the completed build's GundamWingEndlessDuelSNESRecomp.exe, normally under build, with the folder containing that executable as its working folder. Do not select the downloaded setup host just because it has the same name. For the documented v0.1.12 game, enter --no-launcher on the first argument line and the actual absolute path to your Japanese .sfc file on the second. Each line is one argument; do not add shell quotes. This route opens the prepared game without the Generate & Build launcher. Keep existing working registrations on their own supported arguments.

  3. Add the game and choose Play separately

    Portcove records your selected native executable, working folder and literal arguments after review; Play is a separate action. You and upstream own the runtime, originals and player data. Removing the registration preserves those files. Portcove does not install, rebuild, update, back up, roll back, migrate or delete this external copy, and it does not adopt a replacement process launched by upstream. Older Portcove-built installations keep their retained installation, source, backup and recovery contracts.

Setup notes
Preserve the complete working copy
Keep the complete project and build tree, original, generated files, mods, settings, saves and save states with their creating runtime. The game uses config.ini in its working folder, falling back to ../config.ini; keybinds.ini is beside the executable. Preserve the parent project as well as the build folder, plus any separately configured upstream launcher/profile locations. Rebuilds, toolchain changes and updates belong upstream and must finish outside the selected Play session. Runtime replacement does not establish old-save, mod or save-state compatibility.
