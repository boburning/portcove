Setup

  1. Use a completed copy you already have

    Add only a complete copy you already have. Portcove downloads are paused because the package includes a shader cache built from the game’s own shaders.

  2. Prepare your own supported original upstream

    Use your own legitimate Xbox 360 Condemned 2: Bloodshot. Complete upstream’s ISO and required title-update preparation outside the attached session; the inspected player requires its own default.xex and default.xexp. Preserve the full original layout. Optional QuickBMS full-asset extraction remains upstream preparation, not a Portcove operation.

  3. Attach the completed native Windows player

    Select condemned2recomp.exe and its complete prepared package folder as working directory. Keep the established configuration and supported literal custom-root arguments; use no extra arguments for the normal already-prepared in-process player. Do not attach condemned2recomp_updater.exe or an extraction utility.

  4. Review launch details, then choose Play

    Review the selected game executable, working folder and launch arguments, then agree to use them. Choose Play separately when you are ready. Adding this copy does not prepare, update or replace its external files. Removing its registration leaves all external files in place. Before changing versions, close the game and its companion programs and keep the working copy and all data. Review and select the changed executable before playing again.

Setup notes
Keep upstream maintenance outside the attached session
The in-process start screen offers updates. Accepting one starts condemned2recomp_updater.exe and ends the old player. Perform deliberate updates and any successor launch as upstream maintenance outside the attached session; no successor is adopted automatically.
Preserve the creating copy and every effective data root
The inspected title defaults game data to Assets, user data to UserData and cache to Cache beside its configuration; explicit configured roots override defaults. Preserve the full creating folder, runtime configuration, originals, title update, profiles, saves, mods, logs, caches, backups, temporary files and all effective custom roots. An update can rewrite configuration; retain it with the creating runtime.
