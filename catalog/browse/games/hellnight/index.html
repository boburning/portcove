Setup

  1. Use the exact original and permitted complete kit

    Use source, components and a completed kit you are independently permitted to use, with your own Hellnight Europe SLES-01562 CUE/BIN, with its complete 633,786,384-byte data track. The selected config accepts Redump MD5 050d2848368af2ef945706bc73ef69ef / SHA-1 6154819380f41c921f5d37f757a9985de7803a8c, NTSC-converted MD5 01ce6367485ab848973be612df58b5b9 / SHA-1 b0c791ebe50e5e678cb36aed531f2ac553b37999, or Undub v1.1 MD5 cb6f8e5a863920bf33d8cfe78dd684df / SHA-1 e5bc992aba7491b3e134d8a366d3f85695138d16. These are distinct supported variants, not permission to acquire patched game data. Keep every original track unchanged and together with its CUE. Released ZIPs are setup kits, not already generated games. No retail BIOS dump is needed by the documented OpenBIOS route; retain its supplied image and applicable notices. The pinned psxrecomp code is noncommercial-use licensed; separate UI/component/original rights still apply. In the official 0.1.7 Windows kit, the root Hellnight_Recompiled.exe starts upstream setup. Complete Generate & rebuild with Python and the upstream build tools before selecting the build-release player below; the kit supplies the recompiler emitters and leaves game-code generation to your own disc.

  2. Complete all upstream generation and rebuilding first

    Use the documented upstream setup wizard or source-build recipe outside Portcove, including its required Python/toolchain setup and Generate & rebuild step. Wait for the completed native psx-runtime product, normally build-release/Hellnight_Recompiled.exe, with its matching bios, mods, configs, assets and other staged companions. Keep the complete kit/source and completed output together. Root/setup executables forward to another process and exit on Windows; do not register those setup hosts or codegen/helper scripts. A generated-source tree or incomplete build is not the finished player.

  3. Select the documented completed build product

    Select the finished build-release/Hellnight_Recompiled.exe and use that complete build-release directory as working directory; leave arguments empty. Upstream stages runtime configs for direct build launches. The completed player runs its normal launcher and game in the selected process, while the setup program starts another process and exits. Keep the same supported disc selected if the player asks. Saving launch details and Play are separate actions. Setup, Generate & rebuild, PGO optimize or optional relaunch/restart actions remain outside this tracked initial-player route; close any actual successors before another attachment or maintenance.

  4. Keep runtime and mod replacement with upstream

    Upstream/player owns generation, rebuilding, updates and recovery. This title’s CMake notes that the framework clears mods/packages during builds before copying title packages back; preserve custom packages and the old complete runtime outside all build/output paths before rebuilding. Close all actual player/setup/rebuild processes first, then review/relink changed executable bytes after preparation. Portcove does not adopt optional rebuild successors. Removing registration preserves external files; no managed update, rollback, backup, save migration or external deletion is offered.

Setup notes
Back up active settings, cards and all custom roots before startup
Preserve the complete creating runtime and upstream kit, executable-adjacent settings.toml, disc/BIOS .cfg sidecars, saves/ (including cards, game options and save states), mods/, reports/logs/caches/captures and original discs. The default game config uses saves/ and card1.mcd/card2.mcd; established explicit card files or --memcard-dir and PSX_OVERLAY_CAPTURE_ROOT overrides are separate roots. Do not merge profiles or infer save compatibility between disc variants. Startup can remove an older settings.toml.bad and rename malformed settings.toml there; back up both outside the runtime beforehand. Before startup, also preserve the loose legacy state_*.pst files, their openbios/ and scph1001/ destination subfolders and .pst_bios_isolated marker in a separate backup: upstream can move those legacy states into BIOS-scoped subfolders during its first migration. This does not establish cross-BIOS or cross-build save-state compatibility.
