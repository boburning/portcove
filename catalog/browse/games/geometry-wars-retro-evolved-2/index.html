Setup

  1. Keep the complete package together

    Follow the upstream guide. Preserve the complete package, runtime libraries, configuration and notices in a writable folder; do not register an updater or installer. Before the first upstream startup, make separate backups of any existing Documents/geometry_wars_retro_evolved_2 profile and portable user_data/ profile; a successful upstream migration removes the legacy folder.

  2. Install your own matching Xbox 360 original

    Deliberately finish upstream setup outside Portcove using your own Geometry Wars: Retro Evolved 2 XBLA LIVE package, title 584108FF and content type 000D0000. The extracted default.xex must be 704,512 bytes with SHA-256 6D5D9980A1D17DC74B9CCF540CEC16C2E144E7CEE3A74938E78C237B8ACEEB88. Individual container hashes can vary. The launcher installs the game into adjacent game/. A container or another Xbox title is not a substitute for this executable gate.

  3. Add the prepared native player

    Choose geometry_wars_retro_evolved_2.exe (on Linux, the GeometryWarsRetroEvolved2Recompiled AppImage) with its containing package folder as the working folder and no arguments for ordinary Play. Its built-in launcher starts the game in the same native process. Finish setup and any update or setting that requires Restart before adding or starting a tracked session; Restart and the separate updater may replace the process. Saving launch details and Play are separate actions. Use the actual selected copy, not a guessed path.

Setup notes
Preserve original and player data
Upstream/player remains the only runtime-replacement owner. Preserve game/, user_data/, logs/, the executable TOML and any chosen custom roots before changing versions. Portable user_data/ contains the 584108FF profile/local scores, achievements, cache and launcher settings. Before the first upstream startup, back up the legacy Documents/geometry_wars_retro_evolved_2 profile and any portable user_data/ profile separately. When upstream migrates legacy data, it moves the legacy folder by rename, or uses a staged verified copy and then removes the legacy folder after activation; successful migration does not leave the old profile in place. A failed migration falls back to the legacy root for that run and retries on the next startup. If only legacy cleanup fails after activation, portable user_data/ stays active and the legacy folder may remain. An unwritable portable root can also fall back to the system root. --user_data_root=<folder> selects that root without migration; --cache_root can select a separate cache. Preserve every active root and the separate backups. Portcove does not own these external files or promise backup, rollback, save compatibility or deletion.
