Setup

  1. Build an upstream player

    Use the tagged upstream build instructions to make your player. The Linux build needs the SDL2 libraries and TinyXML listed by upstream. On CMake 4, add -DCMAKE_POLICY_VERSION_MINIMUM=3.5 at configure time for this tag. On Windows the tag provides an upstream Visual Studio solution. Launch the actual OpenClaw player from its working folder, which is Build_Release for the Linux build. The optional Mono launcher edits the configuration.

  2. Use your own Captain Claw data

    Keep your original installation intact. Put a separate copy of its CLAW.REZ alongside the source-built player, the project ASSETS.ZIP and the tagged working-folder config.xml. Leave AssetsFolder empty when the files are together. Start the player with that folder as its working folder. Keep the original edition and asset package together.

  3. Keep the data from your working copy

    Close the player before copying config.xml and the save file selected by SavesFile, normally SAVES.XML. Keep any edited assets and settings with the working copy. A local config.xml selects that folder. Without it, the Linux player looks under ~/.config/openclaw. Use upstream tools when changing the player.

Setup notes
Check Mac and Android build availability
Upstream has Mac and Android build material. The reviewed release has neither an Intel or Apple Silicon Mac app nor an Android APK.

Limitations and evidence

  • The PortMaster launcher can replace CLAW.REZ with its bundled archive. Keep any original you supply outside that working folder.
