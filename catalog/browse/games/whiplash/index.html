Setup

  1. Prepare the complete native Windows copy

    Follow the upstream native release guide and keep the complete Windows x86-64 folder in a writable location. This guide follows the development release and selected source; stability is not confirmed. Keep its runtime dependencies, MIDI assets and notices with the player. Project GPLv3 and separate SDL, SDL_image, WildMIDI, libcdio and other component terms do not grant rights to original retail assets. Browser/demo packaging is a separate route.

  2. Import your own retail game assets with upstream

    Deliberately run upstream preparation outside Portcove when ready to supply a legally owned Whiplash/Fatal Racing retail CD image: keep each CUE with its referenced BIN track files, or use a supported ISO. The native program prompts when FATDATA/fatdata is missing and extracts the assets into the selected writable root. Preserve the original image. README FATAL.EXE hashes describe decompilation inputs, not a proven native-runtime asset acceptance hash. Exact retail content hashes and per-edition compatibility remain Unknown.

  3. Add the prepared native player

    After upstream preparation, choose roller.exe with its containing folder as working folder and no arguments for the ordinary portable layout. Its main function runs the native game loop in that process. The supported --whiplash-root <folder> override selects an existing alternate root and changes the game data/working directory; retain the exact override if you use it. --midi-root <folder> is a separate MIDI location. Do not substitute a DOS executable, matching-decomp build, browser bundle or setup tool. Saving launch details and Play are separate actions.

Setup notes
Preserve the whole active data root
Upstream/player owns runtime replacement. The native source enters FATDATA/fatdata under the executable or --whiplash-root root; original extracted data and mutable FATAL.INI, ROLLER.INI, records and save slots live there. REPLAYS/ and TRACKS/ are created under the root. Preserve that whole root, custom MIDI location and any logs/crash data before changing a daily build. Portcove does not own original assets, external saves, update compatibility, backups, rollback or deletion.
