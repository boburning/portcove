# Customer-copy follow-up: authored setup guides

Dated 2026-11-02. Read-only investigation against source head `b12c162a8109719800fa7ac1bde8236c20631b26`. This report proposes a bounded guide change; it does not claim a complete editorial review or authorize operational/catalog-support changes. Machine evidence: ignored `work/copy-followup/guide-inventory.json` retains every guide, source SHA-256, selection matches, and the reviewed per-step classifications.

## Recommendation

Keep numbered items for setup actions. Put essential prerequisites, permissions, shared-profile/migration risks and known launch blockers in visible warnings before the relevant decision. Add an optional authored reference-section collection to the existing guide for save locations, build facts, dated observations and maintenance details. Render it explicitly as an accessible disclosure after the action list. Use the same small title/text shape as existing authored steps if suitable; do not infer section purpose from titles or instruction keywords at runtime.

Existing fields are insufficient for both seeds. `manual_preparation` is only available on operational presentation, while Syphon Filter is listing-only. The renderer also hides that note when an external registration uses a managed definition. Moving text there would lose visible access for some consumers. `help_url` points upstream rather than retaining the exact reviewed content. See [Core presentation and strict guide types](../../crates/portcove-core/src/types.rs#L183), [strict listings](../../crates/portcove-core/src/types.rs#L751), [Desktop guidance](../../apps/desktop/src/components/ExternalRuntime.tsx#L82), and [listing-only projection](../../apps/desktop/src/features/browsing/catalog-entry.ts#L95).

Do not claim the optional nested field is backward compatible merely because `PortPresentation` accepts additive fields. `ManualSetupGuide` and `ManualSetupStep` deny unknown fields, as does `PortListing`; the maintained Playnite reader explicitly rejects unknown guide and step keys. The existing older-reader test only deserializes `id` and `adapter`, so it does not exercise a strict nested guide reader. See [Rust types](../../crates/portcove-core/src/types.rs#L235), [Playnite strict reader](../../integrations/playnite/GuidedSetup.cs#L18), [its rejection fixture](../../integrations/playnite/tests/ContractTests.cs#L1108), and [limited older-reader test](../../crates/portcove-core/src/catalog.rs#L3468).

The implementation needs an explicit versioned modern/legacy projection: current readers receive structured references; the legacy guide projection removes every new key and restores every reference title and paragraph into ordinary legacy-compatible steps. Preserve all existing fields, enum values, commands, operation behavior and old API supported-version membership. Select the containing document/API versions deliberately: listing formats currently stop at 5, catalog schemas at 2, and API is 84. New listing metadata cannot silently use an old strict format. Keep catalog/source authority unchanged unless a version change is actually needed; any retained schema-1/2 output must project strict nested guides into their old shape. Do not silently strip references from an old-shaped export. See [listing format admission](../../crates/portcove-core/src/catalog/listings.rs#L60), [catalog admission](../../crates/portcove-core/src/catalog.rs#L121), [API version](../../crates/portcove-core/src/lib.rs#L339), [generator output](../../scripts/generate-catalog.mts#L617), and [schema history](../reference/cli-schema-history.md#L612).

Legacy projection must remain within the existing 1–8 step and 4,096-byte listing instruction bounds. The proposed thirteen-guide set has room for a direct action-plus-reference step projection, but validate the final authored data rather than assuming that property survives edits. Do not truncate or omit a paragraph to fit; refuse an unrepresentable projection. Permission and save-safety warnings remain warnings in both forms. Keep old `manual_preparation` content intact as a fallback/compatibility contract. See [listing guide validation](../../crates/portcove-core/src/catalog/listings.rs#L460) and [operational guide validation](../../crates/portcove-core/src/catalog.rs#L598).

also receive explicit visible external-backup/update exclusions; Render96 keeps
the inspected migration consequence visible before setup. The initial proposal
warning counts above describe the research artifact, not the final warning count.

refuses source contracts that its existing rules cannot represent.

and help links use the retained setup contract, rather than substituting the
