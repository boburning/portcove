# Tomba Recompiled Linux and macOS route hold

Tomba Recompiled declared managed Linux x86-64 and Intel and Apple Silicon Mac routes (selectors `linux-x64`, `macos-x64` and `macos-arm64`). I listed all 52 releases of `mstan/TombaRecomp`. The current releases (v0.24.x, alpha, pre-release) publish only a Windows x64 ZIP and its checksum. No release has ever carried a macOS asset. A Linux asset exists only up to v0.20.2 as `TombaRecomp-vX-alpha-linux-x86_64.AppImage`, a different asset family from the declared ZIP route and named `linux-x86_64`, which the declared `linux-x64` selector does not match. A route whose selector matches no published package cannot select a release for the player.

The fresh definition therefore offers Windows only. Installed copies keep their retained definitions, and a player can still use the upstream project directly. No Linux or Mac package was inspected, because none matching exists to inspect. Reconsider when upstream publishes a current Linux or macOS package; the route then needs the selector and executable hints to match that package, and its archive shape checked with Core's extraction and declared-executable resolver before it is offered.
