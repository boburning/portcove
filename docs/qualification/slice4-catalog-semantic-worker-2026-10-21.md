# Catalog semantic worker connection, 2026-10-21

This source connects the existing fixed semantic worker to the neutral catalog
request in the existing coordinator journal. It does not install or run the
worker, appoint an issuer, accept a definition, sign a role or publish a site.

The worker selects one exact catalog or application request; simultaneous,
malformed or changed requests refuse. Catalog routing checks the current
publication baseline, imports only exact Git objects, acquires the fixed inert
catalog bundle, and freezes the original Core inspection and full prior catalog
bytes through the maintained input builder. The catalog path performs one whole
opportunity review and does not ask for an application version proposal.

Accepted and negative results both require the existing private settled runtime
capture before issuer authentication. Catalog negatives have a distinct kind,
full-catalog stage, Check title and external ID. They remain failure Checks and
cannot enter application classification or catalog acceptance. Fresh selected-App
GET readback binds the exact request, opportunity, issuer and report. The existing
complete Check inventory, original POST locator, ambiguous-response refusal,
exclusive technical attempts and positive cleanup requirements are retained.
The compact negative receipt is inert data; the protected coordinator owns its
fresh authenticated consumption and existing retry/repair counter transitions.

The same original 64 KiB Check wire bound applies, including the retained neutral
request/Core bytes. An oversized negative report refuses rather than truncating
its evidence or increasing a transport ceiling.
