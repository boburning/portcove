Each per-port authored record now supplies an actionable guide to the actual
upstream, original-file requirements, complete extraction, interactive preparation,
executable selection, Play and data preservation. Generation projects those same
guides into the strict catalog and descriptive directory. The managed definitions,
source contracts, persistence declarations, support tiers and qualification fields
are retained. An authored setup guide is not evidence that preparation happened.

The existing Desktop Files section exposes **Use an existing installation ·
Installation options**, followed by **Use an existing installation**, executable
selection and reviewed consent. Registration and Play remain separate actions.
Core binds the selected native program, working directory and literal arguments;
its listing route does not depend on a managed artifact's checksum authority.
A user selection and executable hash record execution intent, not publisher
identity, source validation or a certified prepared package.

For an external copy the player/upstream owns preparation, replacement and
recovery. Launch and registration removal are offered; managed updates, backups,
rollback, migration and file deletion are unavailable. Removal preserves originals,
external runtime and saves. Close the actual player and helpers before upstream
maintenance, preserve the whole working folder and prepare replacements separately.
An existing managed owner prevents attaching another route for that identity;
keep using its safe existing operations rather than remove it just for this guide.

## Evidence and validation boundary

The Starship [pinned upstream guide](https://github.com/HarbourMasters/Starship/blob/cb19785b51698185a688e17ba1a34c7889195bdb/README.md)
identifies US 1.0/1.1 Rev A `.z64` input, extraction and interactive Windows
preparation. Its [pinned extraction source](https://github.com/HarbourMasters/Starship/blob/cb19785b51698185a688e17ba1a34c7889195bdb/src/port/Engine.cpp)
and the retained package observation distinguish generated `sf64.o2r` from shipped
assets. The [Ghostship 3.0.0 guide](https://github.com/HarbourMasters/Ghostship/blob/deb091c29caff57dd986398087b058f16b11911e/README.md)
supplies the supported upstream setup; accepted Windows observations remain
US-scoped. Public source inspection does not establish source-to-binary provenance.

Two actual-ID Core tests exercise reviewed registration, restart, supervised
launch and registration removal using an owned inert native probe with empty
arguments. They preserve the managed definition and external save bytes; they
neither execute these games nor authenticate an upstream artifact. Existing
user-selected negative cases cover native-path safety, changed bytes, consent,
managed ownership overlap and unoffered operations. Two browser cases render each
actual catalog guide, visible warnings, upstream link and executable/working-folder
controls. Final execution results belong to the source-bound PR/CI receipt.

The first two local lifecycle cases retained 30-second harness cutoffs after
registration, relink and retained-contract restart progressed to about 19 seconds.
They now use the existing `prepared_guide_adoption_` family and its finite
90-second budget. All assertions, product deadlines, two local workers and zero
retries remain unchanged; a later pass proves completion under that existing
budget, not a product-speed repair. The first browser attempt was unexecuted
because this new worktree lacked its pinned Chromium runtime.

The first final-head Windows run (41934461132/1) retained seven passing
partitions and two existing-fixture timeouts in partition 5. Curated activation
recovery reached preservation at 29.042 seconds before the 30.059-second cutoff;
that exact Windows fixture now allows 90 seconds. The three-version Tails
backup/rollback/consented-restore/interruption fixture hit its existing
90.350-second cutoff; that exact Windows case now allows 180 seconds with phase
observations. Assertions, product/child deadlines, cleanup, worker settings and
zero retries remain. These are finite harness calibrations, not causal product
repairs; final-head results and all earlier failures stay separately attributed.

No original was acquired, no upstream game/helper was executed and no desktop
STOP was resumed. Ghostship's accepted native evidence is reused at its recorded
scope; new Starship game execution, gameplay and populated-save observations remain
unclaimed. There is no all-version or other-platform campaign. These guides and
mechanism tests implement the revised bounded route without claiming protected,
production or full lifecycle completion.
