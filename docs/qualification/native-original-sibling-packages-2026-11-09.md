# Native original-file sibling packages

The two BStone entries [#2555](https://github.com/boburning/portcove/issues/2555) and [#2556](https://github.com/boburning/portcove/issues/2556) use the official Linux x86-64 and Intel Mac ZIPs. The Diablo and Hellfire entries [#2563](https://github.com/boburning/portcove/issues/2563) and [#2564](https://github.com/boburning/portcove/issues/2564) use the official Linux x86-64 AppImage. All four keep their existing Windows player, fixed original-file mappings and private profile. Matching originals come from the player.

The local files matched publisher release sizes and SHA-256 values. The two BStone ZIPs passed archive member and CRC inspection. Linux BStone reported v1.3.4 in an isolated version diagnostic and wrote its log under the chosen profile. SDL reported that the dummy driver could not show the version message box. DevilutionX reported v1.5.5 and exited normally in an isolated FUSE version diagnostic. Both diagnostics used empty original folders. Intel Mac evidence is static package inspection. Retail gameplay, save compatibility and protected publication retain their separate acceptance.

Tagged BStone code selects the requested `--data_dir` and `--profile_dir`, and puts the log, settings, saves, scores and screenshots under that profile. Its error dialog can open the log on explicit player input. Tagged DevilutionX code binds `--data-dir`, `--save-dir` and `--config-dir` to the existing original and profile directories. The managed Linux entry selects the AppImage directly. The upstream TAR.XZ uses its own shell launcher and bundled loader path. DevilutionX DMG and mobile packages remain upstream setup routes. The inspected BStone Mac ZIP supplies Intel bytes.

The managed selectors follow the stable package family and publisher digest. The shared successor fixtures exercise later compatible metadata, and the source lifecycle fixture exercises staging, activation and rollback with the declared profile and original input retained. Existing Windows creating definitions and BStone’s older Native4 migration boundary remain separately interpreted.

Primary sources are the [BStone release](https://github.com/bibendovsky/bstone/releases/tag/v1.3.4), [BStone profile and launch implementation](https://github.com/bibendovsky/bstone/blob/v1.3.4/src/bstone/src/3d_main.cpp), [DevilutionX release](https://github.com/diasurgical/DevilutionX/releases/tag/1.5.5), and [DevilutionX path implementation](https://github.com/diasurgical/DevilutionX/blob/1.5.5/Source/utils/paths.cpp).
