## Shared capabilities supported by evidence

[PS2Recomp](https://github.com/ran-j/PS2Recomp) has repeated ELF/function-map/TOML-to-C++ preparation, a runtime, per-build address overrides, and original IRX/device handling. That supports shared source-identity/build-description authoring. It does **not** establish one game-independent build: source layouts, overlays, Ghidra maps, patches, renderers, VU/IOP execution and packaged launchers differ. Address bindings are explicitly not portable between builds. Respect upstream runtime-replacement ownership rather than creating bespoke Portcove engine forks.

PS2Recomp now documents optional [recomp.board metadata](https://github.com/ran-j/PS2Recomp#describing-your-game-project), explicitly third-party and not consumed by the recompiler. A project-authored .recomp.json is a useful provenance-bearing discovery input for identity/system/toolchain/source serial/status; it is optional and can be stale. Root should validate stable schema/repository identity and treat upstream status as a claim. The discovery pipeline must retain index timestamps and primary retrieval clocks separately.

The primary [sp00nznet PSP framework comparison](https://github.com/sp00nznet/psprecomp#other-psp-recompilers--which-one-are-you-looking-at) distinguishes four unrelated codebases: sal063's SDL3/Vulkan work, JessicaNatalia's C++20 profile framework, wizardengineer's Rust/C++17 pipeline, and sp00nznet's C11 toolkit. Matching the text PSPRecomp is not implementation identity. [PortableKit](https://github.com/TeamGDB/PortableKit) is extracted from Yakumo and has repeated profile/submodule/setup behavior, but warns its API is unstable. Its generic tests cover no retail game by themselves. Independent [psprism/Refract](https://github.com/anthonyhfm/psprism) and DrummingBird routes add further distinct contracts.

Repeated acquisition shapes are: downloadable native runtime with user data imported/read at runtime; downloadable launcher that generates and compiles locally; source-only local generation; and browser runtime/local browser compilation. A released launcher and a released game runtime are different payloads. Generated source/binaries are private-only in several upstream projects, while others distribute asset-free runtime/front-end packages. Preserve those stated provenance boundaries; neither a framework's license nor an index download badge authorizes distributing game-derived output. Recipe pinning and recorded hashes support reproducible inputs, but no deterministic binary-output build was executed in this pass.

Framework burst detection should group by exact framework repository ID plus source console, not just name. Track credible independently reviewed implementations and primary source changes. Count a transferred repository, helper and multi-source appearance once; don't count Tenkawa interpreter title as a new native-playable event. Incremental cursors should advance only on complete successful source scans, periodically overlap the previous audit, and preserve previous records on temporary404/timeout rather than interpreting disappearance as deletion.
