# Slice 4 unchanged-authority application Targets renewal

Owner: #534, approved simpler setup. This component prepares the application Rust signer/verifier. It does not activate a controller, provision keys or publish metadata. The catalog variant, trusted two-App configuration, job custody, Node descriptor/coordinator integration and recovery vault remain separate implementation work. Hosted same-client proof remains the first actual setup gate.

An explicit `online-unchanged-authority-v1` context selection requires the independently selected single-owner initial Root profile and an authenticated previous repository. Initial bootstrap is excluded. Omission retains the existing offline-pinned contract. Unknown modes refuse. The next Targets body is derived from the authenticated base: only a checked single version increment and strictly advancing expiry may change. Expiry is bounded by the frozen generation time plus90days and the unchanged Root expiry. Root, role keys, delegation paths/order/thresholds, terminating flags, payload registry and other signed content remain unchanged. Expired current metadata still requires separate recovery; historical expired envelopes do not grant freshness.

The isolated Targets invocation reads exactly its appointed private key after public context authentication. Snapshot/Timestamp jobs verify the required sixth signed envelope, including its actual Root-authorized signature and exact expected body, before reading their own key. The previous-generation Tough projection uses the base version/expiry/bytes; current assembly, Snapshot hashes and publication facts use the newly signed version. All retained versioned Targets and Snapshot bytes remain immutable. Historical signatures and Snapshot references are verified, followed by safe-expiry Tough authentication of the merged output and current targets.

Online renewal emits a schema2 descriptor with the explicit Targets mode. The existing schema1 parser refuses it; this prevents an old pinned-Targets coordinator from silently admitting the changed contract. The descriptor's `offline_targets_sha256` identifies the authenticated base; assembled publication facts identify the actual current Targets bytes. Node/coordinator integration must distinguish those identities, bind actual verifier output and update the durable baseline. No existing production caller opts in through this component.

New regression source exercises two real six-role renewal/assembly generations with safe Tough readback, original Targets/Snapshot byte preservation, a second readback of identical outputs, changed/implicit mode and profile refusals, skipped/rollback versions, invalid expiry, missing prior, and a genuinely signed changed delegation rejected before Snapshot key read. Existing legacy five-role cases remain. These new Rust assertions have not yet run; owned formatting and source checks alone do not establish behavior. Exact-head CI and independent review are required before delivery.

Existing spending, runner, concurrency, timeout, archive, cache and seven-day retention restrictions remain. The final controller must account for the additional signing job within the existing budget before activation.
