# Slice 4 automatic fixed-controller wake

Owner: [#534](https://github.com/boburning/portcove/issues/534). This is an inactive
implementation proposal under the selected unattended release direction. The
[canonical packet](slice4-production-authorization-packet-2026-10-18.md) remains
the authority/preparation record. Nothing here provisions or activates an App,
workflow, protected ref, key, signature or publication.

## Proposed routine path

Default-main pushes and a six-hour schedule wake only the separately ratified
immutable controller. The standard public Ubuntu job has a one-minute ceiling,
with the original provider-observed job start enforcing a 55-second operation
budget across preparation, immutable upload and dispatch. No npm installation,
candidate checkout, cache or larger runner is involved. The source graph is
builtin-only and is checked out at the fixed controller revision.

The default read token prepares the exact controller/source/run routing intent.
The maintained immutable Actions upload retains it for seven days before the
selected repository-scoped dispatch App token is acquired. The dispatch process
downloads and verifies that exact artifact ID/digest/source/run/ZIP/CRC/content,
brackets the main and controller refs and checks both workflow byte digests.
There is no copied review report, classification stamp, environment reviewer or
manual dispatch in this route.

Only the existing selected dispatch role receives Actions write for
`boburning/portcove`. It receives no journal, classification, semantic issuer,
native issuer, signing, Release or Pages credential. The controller independently
checks its actual actor, source, controls and candidate eligibility; an available
token or public repository establishes none of that authority.

Dispatch uses the provider's supported `return_run_details:true` on API version
`2026-03-10`, retaining the returned run ID before another read. The fixed neutral
`wake_run_id` input and run title correlate the actual exact source/ref/actor/run;
they carry no release policy. A successful dispatch means scheduling only.
See the [provider dispatch contract](https://docs.github.com/en/rest/actions/workflows#create-a-workflow-dispatch-event).

Before any later POST, bounded prior-wake readback must reach either a successful
fixed-workflow recovery boundary or the fresh setup activation preimage. A failed
response never means no effect. A provider-observed skipped exact dispatch step
can establish that the step did not run. Otherwise the original correlated
controller run must be observed exactly once with the appointed actor/source.
Zero matches, duplicates, missing/expired history, changed source, nonterminal
ownership, incomplete inventories and provider failures hold further dispatch.
No original POST is repeated. The
[workflow-run API](https://docs.github.com/en/rest/actions/workflow-runs?apiVersion=2026-03-10)
has a 1,000-result filtered-search ceiling; saturated results are explicitly
Unknown. The implementation bounds pages and preserves all available receipts.

## Setup and recovery boundary

The consolidated setup must bind the full controller revision/ref/workflow digest,
the exact active wake workflow digest, observed selected dispatch App/installation
and bot actor, fresh activation timestamp/preimage, repository-scoped credential,
fixed run-title/input contract and protected configuration. A controller or wake
source change must reconcile the prior routing history before a new activation
boundary; changing the timestamp cannot erase an unresolved dispatch.

The held review artifact is `application-update-wake.held.yml`. Final active bytes
and their digest must be reconciled with the complete reviewed controller before
the grant. The initial setup includes its conditional proof/readback and safe
recovery; this document does not request another mechanism selection.

correlation, source/ref/actor changes, malformed/altered intent, incomplete and
saturated inventories, imported policy/manual/rerun refusal, original lost
response retention, prior readback/skip and expired clocks. The actual builtin
source graph and held step ordering are checked. Typed lint and formatting pass.

workflow assertion overmatched both disabled package-manager cache and the App's

token permissions. Neither failure is production execution evidence.

complete controller DAG remain unobserved. The 99-job-minute total proposal is

eligibility, Unknown availability/headroom and no capacity reservation. No paid
