# Zombies Ate My Neighbors managed Linux route

The official `moshferatu/zombies-ate-my-neighbors-pc-port` release `20261028` publishes `zamn-linux-x86_64.tar.gz`. I downloaded it, compared its SHA-256 with the provider digest, and read its entry table without extracting or running it. It is one `zamn/` folder holding `zamn_launcher` and `zamn` (both ELF64 x86-64 with the executable bit set), a bundled `libSDL2-2.0.so.0` and two license files: no links, no case-insensitive path collisions and no nested archive. Both binaries carry `$ORIGIN` and `SDL_GetBasePath`, so the bundled library is found beside them. Their embedded help text and defaults place `zamn.ini`, `zamn.hiscore` and `zamn.quicksave` in the working directory or beside the executable, which is the same player-data contract the Windows route declares; Core's persistence root is the selected executable's folder.

The managed route therefore adds Linux x86-64 for this title with the selector `zamn-linux-x86_64.tar.gz` and the declared executable `zamn_launcher`, reusing the existing Windows persistent paths and no new capability. Upstream calls the Linux build experimental; the inspected package needs glibc 2.38 or later. Limits: this is a package inspection, not a run. No Linux player executed the launcher or the game, no original ROM was used, and the claim about where player data lands rests on the binaries' embedded text, not an observed session.
