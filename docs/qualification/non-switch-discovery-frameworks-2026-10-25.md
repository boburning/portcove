## Existing behavior to reuse

The [upstream-first contract](../CATALOG.md#integration-ownership) already separates three useful routes:

- A fitting official runtime archive can use `native-portable`, including an upstream first-run original-data picker. Portcove may replace the runtime only when that ownership is established.
- An upstream builder, installer or setup window can perform extraction, generation and local compilation. If its launcher updates/replaces the result, retain upstream ownership through non-owning registration rather than treating its mutable output as an immutable Portcove version.
- Source-only or immature projects can have honest discovery listings, primary links and precise preparation instructions. Existing-installation registration can serve a player-prepared runtime without adopting its files. An incomplete build route remains a concrete deferral, not an invented installer.

[Download hints](../CATALOG.md) can distinguish a player runtime from an upstream installer, source archive or SDK. They are advisory asset selection, not authority to run a recipe or proof of package authenticity. Keep required original data, persistent saves/settings and disposable generated/cache files distinct. A launcher release is not necessarily a runtime release; absence of a README or release observation does not prove that no release exists.

The later target advance [386419e3](https://github.com/boburning/portcove/commit/386419e3dc9a70e3db01f7ed2f9871c28d62cfff) adds pinned native-source acquisition before host dependency setup in the hosted Linux installation/qualification harness. Its source commit/tree, harness digest, original hosted-parent binding, custody rechecks and separate source/dependency phases are existing mechanics to assess for reuse where the exact source/provenance/route contract fits. They do not establish a generic console-game build engine or authorize arbitrary upstream host-setup commands. Source acquisition, host preparation and a game runtime remain separate boundaries; this discovery report does not claim those newer target capabilities are absent.

The subsequent [#3031 provider conversion](https://github.com/boburning/portcove/pull/3031), merged at [59c9afe4](https://github.com/boburning/portcove/commit/59c9afe4b386978b82d05ad2b0ec6cc98f6edda4), reuses ordinary GitHub release resolution for fifteen existing `psx-recomp-managed` integrations, with package/platform asset rules. Their original-data/BIOS profiles, setup contracts and historical release-specific qualification remain unchanged. Compatible later artifacts can be discovered without editing a pinned version; historical evidence does not qualify a new artifact. This existing update capability is relevant shared reuse, while a new game or differing preparation contract still needs its own source and acquisition evidence. It neither promotes discovery listings nor replaces upstream-owned/manual routes. See the [dated conversion evidence](psx-update-provider-rollout-2026-10-25.md).

## Evidence needed before another shared capability

No deterministic binary-output build or general distribution permission was established by this audit. Pinned dependencies, source hashes and checked manifests support input provenance; they do not prove byte-identical output, clean-machine reproducibility or permission to ship generated game code. Some upstreams publish asset-free compiled runtimes; others require locally generated code to remain private. Inspect the actual title's source/distribution terms and payload rather than extend a framework license to the game.

A proposed shared adapter needs at least two concrete consumers with matching, supported upstream operations: exact input fingerprints and formats; required BIOS/firmware/keys/TUs; pinned invocation and bounded tool provisioning; success/failure/cancellation signals; output identity and repeat behavior; network use; mutable-data paths; and one runtime-replacement owner. Establish update resolution and save/settings compatibility separately. Until then, shared descriptive authoring plus existing upstream preparation/registration is useful coverage without taking over compiler or engine maintenance.

## Discovery-source coverage and continuity

The maintained collector uses the published [recomp.board Atom feed](https://recomp.fyi/feed.xml), captured at `2026-10-25T03:47Z`, and optionally reads a project's pinned `.recomp.json` using the attributed [draft v1 specification](https://recomp.fyi/spec). The public spec is not a license to scrape the restricted board table. Project metadata is optional, can lag reality and remains a claim. The separately retained [open recompiled-games list](https://github.com/wangxiaoxiang5599/recompiled-games-list) publishes CC BY 4.0 data and supplied audit leads; this report does not claim that list has been added as a maintained collector.

Atom scope is the currently published stream, not complete historical coverage. Expired entries do not mean deletion. A lost overlap retains positive leads and the previous successful clock, requesting reconciliation of the missing interval before explicit checkpoint reset. Incremental GitHub family searches retain fixed windows/pages and overlap, include relevant forks/topics/organizations, and keep caps/failures visible. Repository IDs and aliases preserve transfers; framework names and search hits alone do not prove game identity. Burst summaries flag clusters for primary review; they neither admit projects nor certify playability. Manual periodic completeness sweeps remain necessary for old, unindexed or inaccessible projects.

[PlayPorted](https://playported.com/) remains an attributable per-console/manual lead source where accessible. Captured feed requests returned **403** access challenges at `2026-10-25T03:47Z`; [robots.txt](https://playported.com/robots.txt) explicitly disallows `/api/`. The pass did not use that private/disallowed route or interpret denial as an empty catalog. Quiver, Retro Catalog/RetComM, GHLAppList and newest-first community sources supplement discovery; social/index status, downloads and activity signals never replace primary repository/release/source evidence.

The frozen sweeps are bounded, not an Internet-completeness claim. Paginated framework inventories, exact source clocks, retained failures and all-lead dispositions are preserved in the [PS2/PSP](non-switch-ps2-psp-research-2026-10-25.md), [Xbox](non-switch-xbox-research-2026-10-25.md) and [other-console](non-switch-other-consoles-research-2026-10-25.md) reports. A broad GD's Melee lexical search retained only page 1; its direct primary project was separately reviewed. No receipt completion erases such coverage limits.
