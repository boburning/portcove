## Architecture and identity findings

PS3 seeds resolve to real PPU/SPU static-recompilation efforts, often with game-specific SPURS, RSX and firmware differences. [AC4-Port](https://github.com/SulphurS16/AC4-Port) and [ACFA-Port](https://github.com/SulphurS16/ACFA-Port) explicitly share a runtime, but own different games and source serials. The USA PSN Tekken 5 [release repository](https://github.com/TheWishin/T5DROnline) and [source companion](https://github.com/TheWishin/T5DROnline-Source) form one implementation; its player launcher compiles the exact owned NPUB30009 01.00 package locally. Four initial Ascension repositories plus the additional Linux gowa-pc attempt are distinct candidate retargets with different editions/updates and maturity; do not deduplicate by game title.

PS4 CPU architecture needs its own category. [HayatoG Gravity Rush 2](https://github.com/HayatoG/gr2_pc), [MaouAnimus Persona Dancing](https://github.com/MaouAnimus/p3d-pc), [Killzone Shadow Fall](https://github.com/lesca-191204/killzone-shadowfall-pc), the UFC and Order runtimes execute original x86-64 code with replacement Orbis APIs and translated GPU commands. That is native compatibility, not static CPU recompilation. A shadPS4-derived GPU renderer alone does not make these a general emulator bundle. Conversely, [Pink-shadPS4](https://github.com/luizgustavs/Pink-shadPS4) explicitly distributes an emulator plus launcher; its package is excluded as a native implementation.

Three PS3 arcade leads demonstrate why names are insufficient. [Simpsons Arcade PS3](https://github.com/sp00nznet/simpsonsarcade-ps3) explicitly says its EBOOT emulates the Konami 052001/Z80/YM2151/K053260 and interprets original game code from SIMPSONS.SR. [Rampage PS3](https://github.com/sp00nznet/rampage-ps3) recompiles Digital Eclipse's TMS34010 arcade emulator, and [Midway Origins](https://github.com/sp00nznet/midway-ps3) similarly retains emulated arcade ROMs. These are excluded even where their native front ends reach gameplay. Emulator-derived **hardware** code paired with ahead-of-time game CPU code, as in [RumbleRecomp](https://github.com/ToShredsYouSay/RumbleRecomp), is a different architecture and can remain a legitimate static-recomp candidate.

Multi-game and multi-repository identity are distinct. [OpenSpideyPS1](https://github.com/GTTeancum/SpideyPS1recomp) owns two game identities on one RecompOne implementation; the old OpenSpidey URL resolves to the same repository ID 1349832342. Prathewsh's [Gravity Rush runtime](https://github.com/Prathewsh/gravityrush_pc) also supports two independently catalogable games through one implementation. The two Disruptor repositories have different IDs (1323163112 and 1373710367) and should remain independent pending any contrary lineage proof. Alexbeav's former MGS URL redirects to alexbeavs-ps1-ports and reuses canonical [#466](https://github.com/boburning/portcove/issues/466).

[SwitchWakerHD](https://github.com/centollOS/SwitchWakerHD) targets Wii U source code, so it belongs in this lineage review despite Switch being a destination. It explicitly forks [ZeldaWWHDRecomp](https://github.com/ZeldaWWHDRecomp/ZeldaWWHDRecomp), whose existing canonical owner is [#1913](https://github.com/boburning/portcove/issues/1913); its Windows build helper contains no game runtime and should attach as a helper. Wii U [IshaanKalra BotWRecomp](https://github.com/IshaanKalra2103/BotWRecomp) and [vasist15-source BOTWRecomp](https://github.com/vasist15-source/BOTWRecomp) differ from Switch-source implementations. Their human update labels conflict (1.6.0 versus 1.5.0), but both cite v208 and the same exact U-King.rpx SHA-256. Retain the discrepancy and use verified executable identity. SheikahRecomp is only an Android bootstrap pinned to the former; it has no game loader, renderer or playable APK yet.

## Maturity, source and package boundaries

The individual JSON records preserve unknown source versions as exact unresolved questions, not guessed disc revisions. A README source-build recipe proves an upstream route exists, not that Portcove reproduced it. Upstream claims of entire-game completion remain attributed claims. Examples with bounded scope include Haze opening-scene gameplay; n0madic Soulcalibur Mac/Windows fights and Linux software-rasterizer window; inFAMOUS 2 first missions; GD's Melee public test build; Lufia II opening/gameplay/battles/saves; and Until Dawn's one-development-PC full playthrough with documented severe slowdowns.

Releases are sometimes ahead of README prose. The retained API confirms GD's Melee v0.3.0 (15 October), OpenSpidey sm1/sm2 v1.1 (29 September), ACFA v0.7.3 (24 October), RecompTeam Disruptor v0.8.0 (24 October), Killzone Shadow Fall v0.5.0 (24 October), Until Dawn v0.1.3-wip (24 October), and Lufia II v0.9.2 prerelease (17 September). The release list for ethannicholas F-Zero GX was empty: its documented source route remains legitimate. The recommendations retain both README and release evidence instead of claiming the latest tag's gameplay was tested.

Source/distribution concerns do not erase native identity. Some PSX projects explicitly commit generated game C or distribute precompiled game-derived code; their visibility can be honest while package/source review remains a separate hold. Until Dawn has documentation-only source archives; its [third-party notice](https://github.com/SuperCatElvis/UntilDawn_PC/blob/main/THIRD_PARTY_NOTICES.md) declares a proprietary native runtime, three game GPU programs totaling 228 bytes, and the game icon. No finding here grants redistribution, signing or trust approval.

Artwork has not been authored by this research worker. Existing listing art is reported when a canonical baseline match exists; proposed new listings use the normal project-specific/game/fallback preference. Artwork absence never changes canonical legitimacy.
