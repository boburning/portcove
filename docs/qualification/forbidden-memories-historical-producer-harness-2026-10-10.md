## Bounded stage caller — October 12, 2026

The qualification-only example additionally supports one independently admitted
stage per invocation:

```text
--supervise-stage <reviewed-binary-sha256> <stage> <retained-operation-or-dash> <isolated-library> <original-CHD>
```

Stages are exactly `generate`, `configure`, `compile-first`, `compile-next` and
`finalize`. Generation uses `-` and requires an exclusively fresh library. Each
other stage requires the exact canonical operation UUID returned by generation
and a positively closed, error-free `StagedPreparing` owner loaded from that
same library. No old failed monolithic producer, copied library, caller-supplied
preparation or deserialized witness acquires continuation authority.

The separate `generate-normalized` stage may reach Core's explicit schema-45
failed-attempt acknowledgement for a positively closed normalized predecessor.

exact parent/journal/history under the port lock and retain the failed journal
atomically with its owned start. Complete fresh input and toolchain verification
still precede dispatch. Other stages retain their error-free owner requirement.
This source contract is not native continuation or lifecycle acceptance.

Each invocation opens current service state, requires the full immutable catalog
and official historical release, rechecks publisher/acquisition authority and
uses the maintained Installer stage gateway. Reopening verifies the original
registered source without rewriting its registration timestamp. The worker keeps
the retained lifecycle identity; a fresh durable activity owns cancellation and
root event ancestry. Compile progress includes the store-loaded sealed total
batch count so a controller can select the next finite phase explicitly.

The existing private child environment, 150-second cooperative deadline,
180-second Core work bound, bounded process supervision and output/failure
preservation apply to each selected invocation. There is no internal orchestration
loop, automatic retry, cap enlargement or authorization to execute a game.
Frozen executable/controller identity, literal root/source/environment bindings,
fresh uncontended native admission and positive exit proof remain required.
These interfaces do not prove actual generation, Ninja format/resource fit,
usable installation, native lifecycle acceptance or beta readiness. Historical
failed producer evidence remains unchanged and Unknown.

The qualification sampler retains root informational phase messages of at most
512 UTF-8 bytes under the existing 32-event limit, alongside monotonic elapsed
milliseconds from reporter creation. Descendant information and chunk progress
remain omitted; root terminal events remain unconditional and omitted counts
remain visible. Existing asset-verification and generation-entry messages can
locate the preparation boundary reached before cancellation. They do not prove
extraction, toolkit inventory, generation completion or a resumable witness.
The stream/projection and controller bounds remain unchanged.

The qualification-only terminal diagnostic also retains source/BIOS verification,
preparation-contract and toolkit-inventory phases. Inventory retains fixed entry,
completed-file/byte and hashing-time counters, and marks entry to the final fence.
There are at most eight process-local records and eight phase marks per record; eviction
and lock contention are reported as omitted records. It publishes after scope
exit, including cancellation, without callbacks or serialization inside a fence.
An incomplete file hash is not counted as completed. These feature-gated counters
report elapsed successful stable-file calls, including I/O and identity rechecks;
they exclude an interrupted current call and do not measure SHA CPU time. They
preserve the original result and every source, object, name, content and deadline
check; they confer no generation, custody or continuation acceptance.

On Windows, identity-only comparisons request metadata access on no-reparse
handles; readable handles remain mandatory for complete byte hashing and metadata
content reads. The same ancestor, canonical path, object, type, size, time and
final name fences remain in place. This access correction does not establish
performance fit: an exact rebuilt executable needs separate review and a fresh
bounded native observation before any stage can acquire acceptance.
