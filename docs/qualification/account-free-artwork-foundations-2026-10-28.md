existing `prepare-port.mts` entry point. A new listing first tries an attributable,
unique exact-port match. A coverless, absent or ambiguous port can use a reliably
identified underlying game; if neither role has usable imagery, retain the
specific exception and generated/text fallback. Image integrity alone does not
establish semantic identity. Distinct ports can reuse accepted original-game art

## Health, retention and offline limits

[Machine-readable observations](account-free-artwork-foundations-2026-10-28.json)
record **two requests, 27,849 image bytes**, with HTTP 200/JPEG and matching accepted
digests for `2ship2harkinian` (port) and `2xtreme-recomp-catsandsoup-2xtreme`
(underlying game). Reads were capped at 16 MiB plus one overflow-detection byte
with a 15-second timeout. No image payload or credentials were retained. This is
a two-image HTTP/integrity sample, not a decoded/native/installed proof or a
catalog-wide health result. Repair latency, total live provider costs and
production throughput were not measured.

[Core's existing bounds](../ARCHITECTURE.md#local-artwork-ownership) remain the
client contract: two remote workers; 16 MiB encoded originals with bounded
dimensions/decode; a 64 MiB disposable disk cache; 8 MiB/256 converted previews;
256 request identities and 30-second transient negative caching. Warm conversion
reuse still hashes the original. Local imports preserve their copied originals,
explicit choices, revision checks and independent cache/reset/unused removal.
These are resource ceilings, not an indefinite retention or redistribution grant.

Preparation distinguishes uncertain outage/404 from an exact image HTTP410 Gone
observation. Gone invalidates every matching reference in the proposal; only
validated replacements or fallback can replace it. Actual withdrawal must reach
the client through accepted correction before the mapping is no longer selected.
Old unselected disposable bytes are not authority to display a withdrawn mapping;
cache clear removes disposable files without deleting personal originals.

Offline cached imagery is possible only when the permitted original was already
retrieved and still validates. First launch offline with an empty cache displays
the generated/text fallback. Failed fetch/render also displays fallback and
retains truthful source/unavailability information. Do not promise an uncached
image or convert an unavailable local choice into a new automatic preference.
