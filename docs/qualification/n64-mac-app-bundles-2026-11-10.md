# N64 recomp macOS app bundles

Managed Mac routes were already declared for Banjo-Recompiled, Snowboard Kids 2, SSSV, Mega Man 64, Harvest Moon 64, Zelda64 and Extreme-G but could not install: their upstream ZIPs carry four dylib version links, which Core refused, and the last three wrap the app in an inner ZIP. The shared extraction fix landed in [#4896](https://github.com/boburning/portcove/pull/4896) and [#4903](https://github.com/boburning/portcove/pull/4903). This change declares `release.archive_file_links` on those six routes, so definitions reach only readers with N64 capability 5, and adds Mac routes for Bomberman 64, Bomberman Hero and Goemon 64 (Intel and Apple Silicon) and Donkey Kong 64 (Apple Silicon only).

I inspected each latest upstream Mac ZIP. Every template-built package holds one `.app` with a unique executable name and a Mach-O containing both `x86_64` and `arm64` slices, except Donkey Kong 64, whose executable is `arm64` only, and Castlevania: Legacy of Darkness, which was already declared Apple Silicon only. Bomberman 64, Bomberman Hero, Goemon 64, Duke Nukem Zero Hour, Mega Man 64, Harvest Moon 64, Zelda64 and Donkey Kong 64 ship the app inside an inner ZIP. The shared upstream frontend honors a `portable.txt` in the directory that contains the app bundle on macOS, and Portcove's N64 launch places that marker in the install root beside the app, so player data stays in the Portcove profile rather than `~/Library/Application Support`. Asset selection uses version-independent name pieces, so ordinary compatible releases need no catalog edit. Duke Nukem Zero Hour is not added: its Linux package is a TAR.GZ inside a ZIP, and its Mac route is deferred with its Linux sibling.

These are static package observations. No Mac executed any of these packages here. Native launch, macOS first-launch behavior for a Portcove-downloaded copy, dylib loading from the copied library files, saves and gameplay remain separate acceptance.

Extreme-G (GitLab, v1.0.0) was added to this record after the first change: its Mac package is an outer ZIP holding one inner ZIP, the inner archive has four dylib links, and its executable is a universal x86_64 plus arm64 Mach-O. Its route now declares the same `release.archive_file_links` and requires N64 capability 5.
