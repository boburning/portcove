## Route, setup, maintenance and data

All selected runtimes use the delivered shared native-portable lifecycle.
Portcove owns compatible replacement of the new managed runtime; upstream owns
its first-Play original-file picker/setup behavior. Existing external copies
retain their files and replacement owner. Registration never silently adopts
those files. No package helper, installer, compiler or game is run by discovery.

Maintenance declaration for every selected managed route:
`managed-compatible-release`; the corresponding non-owning route remains
`user-managed-update`. Provider/project, stable discriminating asset hints,
executable rules and reviewed persistence contracts stay authored; exact changing
release, asset and digest identities are observed by the provider and retained
by Core. BattleTanx, Infinite Mario64 Ever and DKC1 use version-independent
package/platform fragments. Their N→N+1 regression now reads the actual embedded
adopted definitions. Explicit pins, channel policy, ambiguity, integrity holds
and qualification non-inheritance remain authoritative. No publication authority
from #534/#246 is absorbed.

The per-ID records linked below own exact executable-parent coordinates, launch
arguments, setup guide and persistent-path declarations. External originals,
user-profile saves/settings and registry preferences remain outside backup
where the record says so; an empty in-folder contract is not a save promise.
Julius writes its user-selected original-data folder outside Portcove ownership; DKC1's AppData
and registry state remain external. OpenLoco/OpenRCT2 and the other external-data
players disclose their limits. Linux package scope does not establish Linux
execution or minimum environment.

Source review separately checked writes and compatible update behavior. AC6's
shader/pipeline descriptions have upstream version checks and current-translator
regeneration; it does not preserve host PSO blobs. Chaotix's states reject other
program/ROM versions and its backdrop cache contains PNG data. Infinite Mario's
normal transparency setting writes `project.godot`, which is absent from the
packaged immutable files. Source, executable, immutable-tree, original-input and
retained-contract guards remain in the delivered lifecycle. Runtime rollback
carries current declared data; it does not rewind saves.

MDK retains its `mdk-sdl-nemo22` identity and original project origin. Explicit
release preparation refused the old provider spelling after its redirect to
`nautilusbits/mdk-sdl`. Both resolve to GitHub repository `1406153922`; the retained
guide and selected release already name the current location. Only its managed
release-provider fact changes. This is a reviewed alias correction, not a new
port identity or a second integration.
