# Native qualification Check consumer preparation

Owner: [#534](https://github.com/boburning/portcove/issues/534).

The read-only native consumer authenticates the exact configured native App's
completed Check and its suite in the Portcove repository. This issuer must differ
from the semantic, classification and GitHub Actions issuers. The fixed caller
must derive issuer IDs, host/account/profile, source/harness identities and
candidate expectations from the independently ratified setup and actual admitted
inputs. Candidate JSON cannot choose that authority. The producer must issue the
Check only from its genuine, broker-owned capture; persistence of an arbitrary
report by an App is not native execution evidence.

The contract separates the candidate's source/build run/attempt/artifact/package
from the local native producer's invocation, source and harness. It does not
invent a GitHub numeric job for that local invocation. Both stages require the
observed host/account, loaded-engine floor, compatibility and positive root/tree
teardown evidence. Pre-sign package qualification cannot be interpreted as the
post-sign compatible update, rollback and journal gate. Post-sign evidence binds
the exact predecessor and signed context/signature identities.

The collector uses seven bounded, fixed `GET` requests, a pinned `github.com`
transport, a fifteen-second subprocess bound and a 512 KiB prebuffer ceiling.
It verifies the Check/suite before and after source acquisition, both source
commit/tree identities and the actual harness content at the producer commit,
including its SHA-256 and Git blob identity. It retains eleven bounded public
files in an owned directory. Failure receipts contain phase/status and the
owned evidence location, without transport exception or bearer text.

Only the actual default provider path can create the module-private receipt.
Injected API and subprocess fixtures remain `injected-provider`; imported or
serialized receipts cannot use `verifiedNativeReleaseQualification`. That getter
rehashes all retained files, reads the exact Check/suite again and returns a
detached, deeply frozen report with the actual Check identity. Configuration and
transport references are captured before asynchronous effects. Native report
timestamps retain their full millisecond precision and digest; only the outer
Checks wire timestamps use documented whole UTC seconds.

Seven focused inert tests pass, including both stages, wrong/conflated issuers,
input and host mismatch, provider drift, partial source and harness-byte refusal,
documented timestamp normalization, scrubbed fixed-host transport
boundaries and imported/injected receipt refusal. No actual native App, account,
host, qualification capture or credential has been exercised here. The fixed
parent producer, genuine stage eligibility, private record/context join and
final protected execution remain separate obligations. This component activates
no permission, key, publication route or production authority.
