# Original publication-result custody and bounded report repair

This source preparation connects the existing coordinator journal to interrupted
immutable-result uploads. It makes no protected provider call in qualification,
and does not establish signing, native, release or #534 acceptance.

The fixed coordinator reauthenticates the original context and all five role
envelopes, performs the maintained keyless Tough verification, and brackets the
terminal original publisher, complete 4-page/400-artifact inventory, exact report
archive and current immutable Release bytes. Only positive exact custody can
settle the existing pending upload. Missing, expired, drifted or partial evidence
stays held; no absence permits another upload or Release mutation.

A successful original producer and attestation are consumed by the existing
strict result receiver. The fixed DAG can then pass those original locators to
the site consumer, which independently reauthenticates them. It does not repeat
aggregate, payload, TUF or immutable Release production.

When actual report custody exists but the original publisher failed or its
attestation is absent, an append-only candidate descriptor retains the original
operation, artifact, context, promoting proof and stable Release identity. The
existing transient-failure plan must consume one of its two retries before a
distinct descriptor-bound report-only dispatch. Original compiler and new
dispatch/custodian run identities remain separate. The release workflow's
read-only identity job checks the current durable dispatch intent, actual run,
actor, prepared tag and descriptor; inputs/title alone grant no eligibility.
An identity check may observe its exact pending intent before the coordinator
records the run receipt, avoiding a circular acknowledgement wait.

If a settled metadata effect has interleaved, the descriptor carries the exact
original result operation, hash-equal to its existing compact journal proof.
This keeps minimal sparse checkpoint recovery self-contained. The descriptor
is bounded to 4 KiB and the existing whole-state 64 KiB cap remains enforced.
An unrelated unresolved or partial current effect still blocks failure recording.

The dispatching wake holds subsequent jobs. The next wake reauthenticates the
original signing custody. Fresh existing admission and phase writers apply; the
aggregate can only read/re-attest its original upload, and the Release callable
must verify the original settled publication before advancing repair phases or
producing a new report. It cannot rebuild, re-sign payload/TUF or replay a Release
effect. Missing original evidence and exhausted counters remain held.

Focused checks exercise these restrictions and the actual routing functions with
disposable/inert fixtures. A separate admitted real-Git case covers journal and
counter persistence. The original case passed at source `5ab1073` (50.503 seconds;
253.565 seconds admission wait). The expanded settled-interleaving case requires
its own retained terminal result; the earlier result does not qualify later changes.
Actual protected execution and timing under provider latency remain unqualified.
The complete held workflow/proposal bytes and their capacity hashes change;
the ceiling stays 99 job-minutes and historical ratification does not cover the
new bytes. Initial consolidated source/configuration ratification is still needed.

The separate report-only candidate workflow identity job has a provider-enforced
2-minute bound from job start, including checkout/setup; its read-only code also
uses a 60-second acquisition cap. At most two consumed technical retries therefore
add a separate ceiling of 4 candidate-workflow job-minutes. The ordinary legacy
identity job keeps its 360-minute default. Hosted timing is not yet qualified.
