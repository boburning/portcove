# Initial one-key offline ceremony preparation

Owner: [#534](https://github.com/boburning/portcove/issues/534).
This checkpoint adds five maintained initial-only CLI commands to the existing
Tough 0.24 release-tools crate. Production key generation, signing, installation,
publication and custody activation were not performed.

The public Root builder computes key IDs from six digest-bound public keys,
keeping three Root keys with threshold two and distinct Targets/Snapshot/Timestamp
keys. Each Root signing child receives one private-key pathname. The next
custodian receives only the public partial and approved body digest. Individual
signatures and exact canonical body are checked before merge; the original
threshold-two Root is never weakened. Finalization reads no private key.
The independent offline Targets child receives only its one private key, the
completed Root, public payload registry and three public delegation keys.

Each disposable key is generated by a separate actual `create-offline-key` CLI
process using existing aws-lc Ed25519 and Tough public projection. The strict
config names one new output directory and accepts no existing key input.
Private PKCS#8 bytes never appear on stdout; existing/partial outputs refuse
replacement. Windows actual ACLs remain an independent setup obligation.

Actual local disposable qualification invokes the compiled CLI for public
proposal, two separate Root signatures, keyless finalization, offline Targets,
five separate one-key online workers and keyless assembly. Existing bootstrap
inspection refuses the first partial; complete assembly loads through Tough and
retains exact offline Targets bytes. Four focused cases passed with zero skips
on Windows. Negative cases include duplicate/foreign/wrong-role signatures,
valid-policy body changes, threshold weakening, invalid signatures, private
fields in public JSON, wrong public digests, overlapping delegation keys,
version/rotation attempts, bounded-input overflow and retained output reuse.
Unix-only symlink/hardlink checks remain subject to actual hosted Linux execution;
the Windows result is not credit for those assertions.

Retained local logs are `work/offline-ceremony/first-cli-tests.log` and
`work/offline-ceremony/final-cli-tests.log` in the dedicated compiler-producer
worktree. The first and expanded focused checks both passed; their disposable
keys live only under test temporary directories. Fixture processes scrub ambient
environment variables and provide only owned temporary paths and Windows loader
basics. This verifies the maintained CLI/crypto/bootstrap connection, not actual
custodian separation, production fingerprints, secure media, backup restoration,
provider enforcement or a protected execution grant.

The [operating contract](../RELEASING.md#one-key-initial-offline-ceremony)
records exact config fields and custody prerequisites. Existing Root lifetime is
365 days maximum and Targets 90; no expiry or trust policy was extended.
The complete pre-key-creator crate check passed 24 cases. After the final
one-key creator, strict Root envelope and Ed25519 repairs, the four connected
cases passed again; `cargo clippy --locked -p portcove-release-tools --all-targets
-- -D warnings` passed under the maintained resource guard. One earlier queued
full-crate request refused before payload because documentation changed; its
log remains retained and is not a test result. The formatter completed both docs;
its preceding automatic dependency reconciliation refused the existing linked
workspace hoist directory, so no successful dependency installation is claimed.
The canonical authorization packet remains owned by the consolidated setup work.
