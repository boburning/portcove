# Fixed controller tool bootstrap

This #534 implementation prepares public tools before role-key access. The held
fragment is outside `.github/workflows`; it activates no job, permission, signing
key, App credential or publication route. Final composition must allocate these
jobs within the existing 100-minute controller ceiling and rebind the reviewed
workflow/resource policy. No larger ceiling is introduced.

The unprivileged bootstrap checks the exact clean controller commit/tree, bundles
five fixed Node CLIs with repository-pinned Vite+ 1.3.0 Pack, and builds the
maintained `portcove-release-tools` once under the existing resource supervisor.
Cargo home/target and temporary storage are fresh. Compilation receives no role
credentials, Node/npm hooks, shared Cargo target or candidate checkout. Only the
fixed trusted source lockfile is installed, with hooks disabled, before this
stage. Node 24.22.0, the Rust executable, the pinned Tauri CLI 2.12.2 native addon,
five bundled CLI files, package policy, the fixed controller workflow and generated
`compiler-source-closure.json` form a schema-2 exact eleven-file manifest of
paths, bytes and SHA-256 values.

The unprivileged bootstrap generates the compiler closure from that exact clean
Git commit/tree. The fixed inventory includes explicit absent entries. The
receiver validates its bounded bytes and source identity before materializing
anything; its actual, same-process tool getter rehashes the whole inventory and
returns the closure's owned path. Raw imported JSON is not compiler acceptance.
The receiver imports only the pure closure validator, without the generator's
Git/API preparation dependencies. The earlier ten-file hosted fixture remains
evidence for that earlier inventory; the new eleven-file hosted build still
requires its own ordinary fixture result.

The first entries are `production-controller-admission`, `release-control-ready`
and `release-reviewed-inputs`, followed by `release-payload-preparation` and
`release-role-key-channel`. Imported modules retain their own module URLs via
the pinned parser's AST, so their direct-launch guards remain inactive and static
policy paths retain their meaning. Node built-ins and a possible own bundle
reference are the only remaining imports. Receiver-side tools need no npm install,
hook or cache. Additional controller entrypoints must be added explicitly when
their fixed wrappers are ready; this does not claim the whole final DAG is bundled.

The producer uploads one immutable run/attempt artifact with seven-day declared
retention and no overwrite. It downloads and checks those actual opaque ZIP bytes
before preparing a predicate. Fresh OIDC verifies the bootstrap's actual numeric
job and signed check-run identity while it is still active. The raw bearer is
never retained or exported. An isolated, held `actions/attest` job signs the exact
manifest subject and predicate using the existing GitHub custom-predicate path.
No payload or TUF private key enters either job.

The receiver shares the aggregate consumer's pinned `gh attestation verify`
invocation and verified certificate checks. It binds source commit/tree to the
provider, fixed workflow/ref, repository, controller run/attempt, immutable tool
artifact and bundle IDs/digests, the complete manifest and every opaque tool byte.
It checks the signed numeric producer against the completed successful fixed
bootstrap job and its exact check-run URL, with provider brackets. It neither
reaccepts an expired JWT nor assumes a job ID from a name-only inventory match.
Only after all checks does it materialize the fixed files. The same-process
`verifiedControllerToolPaths` boundary refuses imported or injected-provider
receipts and rehashes the whole inventory before returning fixed tool paths.
Serializing a receipt cannot establish that boundary in another process.

These facts establish fixed-source tool-artifact custody at their stated scope.
They do not establish compiler acceptance, semantic review, candidate provenance,
native qualification, protected settings/custody, a capacity reservation or
permission to use a role key or publish. Injected verification tests remain marked
`injected-provider` and cannot select executable tools through the production
boundary. Actual local bundle smoke tests run the bundled CLIs in a directory
without `node_modules`; they do not qualify a protected bootstrap execution or a
fresh Rust build. No such execution or build is claimed by this preparation.

The separate ordinary `Controller tool build fixture` workflow now runs on
relevant pull requests and main changes with only `contents: read`. It binds the
actual checked-out fixture commit/tree, invokes the same fresh Cargo-home/target
build, rechecks every tool byte and compiler closure, and smokes the copied Node runtime, all five
bundled CLI refusal paths without runtime dependencies, the Tauri version and
supported signer/build flags, and the actual Rust
binary's usage refusal. It retains only bounded public manifest/result JSON for
seven days. It has no OIDC, attestation, App, role-key, environment or production
tool-artifact route. The fifteen-minute ordinary job is separate from the held
controller's resource allocation. Adding this workflow is not a claim that its
hosted build has passed; that requires exact-head provider execution evidence.
The original three-entry fixture receipt remains evidence for that earlier
inventory. It does not qualify the expanded schema-2 inventory or the actual
Linux role-key channel; the ordinary fixture now also runs those channel tests.
