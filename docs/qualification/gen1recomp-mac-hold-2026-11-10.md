# Gen1Recomp macOS route hold

[Issue #98](https://github.com/boburning/portcove/issues/98) previously declared managed Intel and Apple Silicon Mac routes for Gen1Recomp. I inspected the latest upstream Mac package, `gen1recomp-0.4.2-macos.zip` from `bryanthaboi/gen1recomp`, and the declared routes could not complete: the app is a LÖVE runtime whose only launchable executable is `gen1recomp.app/Contents/MacOS/love`, so no file named `gen1recomp` exists for the declared executable hint, and the bundle links framework folders (for example `Versions/Current`) to directories, which managed extraction refuses. The package also carries 39 links in total plus a `__MACOSX` metadata folder. Extraction safety, not a mistaken download, decides this; no Portcove install of that package could have succeeded.

The fresh definition therefore stops offering Mac, while Windows and Linux are unchanged and installed copies keep their retained definitions. Reconsider when Core can extract bundle framework folder links safely and the record declares a verified executable path inside the app (for example `gen1recomp.app/Contents/MacOS/love` with its launch arguments), or when upstream publishes a Mac package without those shapes. A player can still run the upstream Mac app outside Portcove. No Mac execution was observed, and this record does not establish whether the upstream app works.
