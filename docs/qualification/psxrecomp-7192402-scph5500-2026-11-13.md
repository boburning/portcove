# PSXRecomp 7192402: King's Field and Ace Combat 3 (Japan) move to SCPH-5500

Dated evidence from November 13, 2026, under #2926. It adds the retail
SCPH-5500 (Japan) BIOS as a catalog profile and requalifies the two managed
PS1 routes whose newest kits now require it. The
[retail BIOS record](psxrecomp-7192402-retail-bios-2026-11-13.md) moved 24
other routes to SCPH-1001 or SCPH-5552 and held these two because no
SCPH-5500 profile existed. This change follows that record. The framework
review is in the
[builder downloads record](psxrecomp-7192402-builder-downloads-2026-11-13.md).
No upstream program was executed.

## The SCPH-5500 profile

In PSXRecomp `7192402c283880e318c97732c9b733c4d1b144d0`, `bios/SCPH5500.toml`
declares this image in `[program.image]`:

- **Image:** Sony SCPH-5500 BIOS (Japan, v3.0 09/09/96), 512 KiB, CRC32
  `FF3EEB8C`, SHA-256 `9c0421858e217805f4abe18698afea8d5aa36ff0727eb8484944e00eb5e7eadb`.
- **Staged path:** `bios/SCPH5500.BIN`, with output stem `SCPH5500`.
- **Identity gate:** `recompiler/src/main_bios.cpp` refuses to generate from
  any image whose SHA-256 differs from the declared one.

The new catalog identity `psx-scph-5500-bios` (variant `japan-v3-0`, product
code SCPH-5500, raw `bin` or `rom` file) has the same shape as
`psx-scph-5552-bios` and binds that normalized-content SHA-256. Its evidence
record cites the framework file at that commit.

Core and the authoring scripts now accept it wherever they list the reviewed
retail profiles:

- **Authoring form:** `psx_managed_windows_v1` `true` and `"split-mods"`
  accept SCPH-1001, SCPH-5552 or SCPH-5500.
- **Kit guard:** a kit whose `game.toml` names `SCPH5500.toml` maps to
  `psx-scph-5500-bios`. Core refuses to build it with another registered
  retail profile, and refuses to build a SCPH-1001 or SCPH-5552 kit with the
  SCPH-5500 profile.
- **BIOS staging:** this already reads the profile's `rom` path, so the
  player's BIOS is staged as `psxrecomp/bios/SCPH5500.BIN` with no further
  change. Raw-BIOS checks and the generation-marker check at launch don't
  depend on the profile.

## Kits

Both routes' newest kits are tag `v0.3.7` on framework `7192402c`. The
Windows and Linux x64 kits were downloaded and inspected statically. In each
one:

- the SHA-256 matched the kit's `SHA256SUMS.txt`;
- `game.toml` selected `psxrecomp/bios/SCPH5500.toml` with
  `[runtime] openbios = false`, and agreed on both platforms;
- `project-manifest.toml` and `README-SETUP.txt` required the player's own
  SCPH-5500 (Japan) BIOS, 524,288 bytes, SHA-256 `9c042185…`;
- the data-track SHA-1, track count and serials matched the route's source
  identity;
- the generated player matched the catalog;
- `mods/bundled` was present with empty texture-pack folders, and there was
  no flat `mods/packages`, no links and no case-colliding Linux paths.

| King's Field                        | `bbac8aa1` | 47,931,734, `f4e81074…` | 45,738,884, `27c4a3ff…` | authoring | off        |

King's Field's bound v0.3.6 kits ran with the bundled OpenBIOS. Ace Combat 3
(Japan)'s v0.3.6 kits selected no retail configuration, and the route bound
them to SCPH-1001.

### Ace Combat 3 (Japan) and `bios_hle`

Its kit sets `[runtime] bios_hle = true`. As for Mega Man Legends with
SCPH-5552, `runtime/include/bios_hle.h` and `runtime/src/bios_hle_plan.c` in
PSXRecomp `7192402` make this an optional tier on top of the recompiled real
BIOS:

- **Kernel calls:** it handles the calls it implements, but only when the
  profile declares a `deliver_event_ret` anchor. `SCPH5500.toml` declares
  `deliver_event_ret = "0x80001720"`.
- **Boot intro:** it skips the shell intro, which needs the
  `shell_entry_phys` anchor. `SCPH5500.toml` declares `0x00030000`.
- **Everything else:** kernel initialization and every unimplemented call
  still run in the recompiled retail BIOS.

The profile notes that the SCPH-5500 kernel (ROM `0x80` to `0x18000`) is
byte-identical to SCPH-1001 v2.2. The retail image is still recompiled and
executed, so it remains a required build and launch input. The route is
included.

### Ace Combat 3 (Japan) disc roster

The new `game.toml` renames the roster from `disc/disc1.cue` and
`disc/disc2.cue` to the Redump file names, and adds Disc 2's data-track SHA-1
`a23e046b…` to `known_sha1`. Both SHA-1 values are already in the
`ace-combat-3-japan-psx` profile, so the source identity doesn't change.

The renaming doesn't affect Core:

- **Preparation:** `materialize_runtime_raw_set` writes the verified set as
  `runtime-discs/disc-01.cue` and `disc-02.cue` in catalog order.
  `rewrite_game_discs` then replaces the whole `discs` value with those
  paths. The kit's own names are never used.
- **Launch disc choice:** `[disc] selected = N` indexes that rewritten
  roster, so Disc 1 and Disc 2 keep their numbers.

## What changes in the catalog

- **Persistence:** King's Field moves from `"bundled-openbios"` to
  `"split-mods"` with `bios_source_profile: psx-scph-5500-bios`, which drops
  the `--bios bios/openbios.bin` argument. Ace Combat 3 (Japan) replaces
  `mods` with the six split paths, including `mods/texture-packs`, and
  changes its BIOS profile.
- **Launch:** Core passes the registered SCPH-5500 BIOS with `--bios` after
  checking it against the generation marker.
- **Source contracts:** each game contract also applies to the new Windows
  and Linux kits and cites the new evidence. King's Field gets a new BIOS
  contract. Core allows one BIOS contract per port, so the existing Ace
  Combat 3 (Japan) SCPH-1001 contract changes, as Dino Crisis did:
  - it now names `psx-scph-5500-bios`, variant `japan-v3-0`;
  - its review authority moves to the new kit commit;
  - it binds only the v0.3.7 kits. The v0.3.6 kits stay bound in the game
    contract.
- **Evidence:** one framework record for the profile, and one upstream
  evidence record per route. The provider release digests were not read.
- **Player copy:** summaries, setup steps, BIOS requirements and manual
  preparation now ask for the player's own SCPH-5500 (Japan) BIOS. The Ace
  Combat 3 (Japan) Mac step now points to the kit's `README-SETUP.txt` for
  the BIOS. The Mac kits were not inspected.
- **Release corpus:** King's Field expects `psx-scph-5500-bios` and the split
  paths. Its observed v0.3.6 release ran with OpenBIOS, so the corpus marks
  `retail_bios_from_later_release`. Ace Combat 3 (Japan) has no corpus
  entry. No provider release data was added.

The game contracts keep the v0.3.6 kits, but release selection takes the
newest release. Neither v0.3.6 kit names a BIOS configuration, so the kit
guard can't refuse it. If one were built under the new definition anyway,
two things could happen:

- **Wrong BIOS staged:** Core would stage the SCPH-5500 BIOS at the default
  `SCPH1001.BIN` path. Framework `08ec704a` declares no image identity, so
  nothing would refuse it.
- **Flat packages:** a kit that stages defaults in `mods/packages` is refused
  by the split-scope check before anything is installed.

## Existing installations

As in the retail BIOS record, `bios_source_profile`, launch arguments and
persistent paths are part of an installation's retained contract. Existing
copies keep their retained definition:

- **Launch:** a King's Field copy keeps launching with `--bios
  bios/openbios.bin`. An Ace Combat 3 (Japan) copy keeps its SCPH-1001 BIOS.
  Both keep their whole-`mods` scope.
- **Update:** before downloading anything, the update requires a registered
  SCPH-5500 BIOS. Without one it fails with a source error that names the
  profile, and the active copy stays unchanged.
- **New BIOS input:** once the BIOS is supplied, the update restores the
  split paths into the new copy, which builds and launches with SCPH-5500.
- **Rollback:** it restores the earlier copy with its retained contract.

## Not observed

Nothing was built or run. No retail BIOS was used, and no update, rollback,
disc switch or backup with real player data was observed. Like SCPH-5552,
the SCPH-5500 profile has no shell seeds and relies on the framework's
dirty-RAM interpreter for the shell. Whether the kit builds enable it, and
the effect on King's Field, which doesn't skip the intro, weren't checked.
