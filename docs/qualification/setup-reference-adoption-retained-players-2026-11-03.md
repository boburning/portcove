# Setup reference adoption for retained players — 2026-11-03

This finite guide-adoption component belongs to [#2926](https://github.com/boburning/portcove/issues/2926). It applies the existing [setup action/reference contract](../CATALOG.md#setup-actions-and-reference-notes) to **40 additional existing ports**, selected from 58 plausible records in the retained inventory. This is maintenance of existing routes, not a new port census or admission campaign. The batch is disjoint from the 40-port batches in [PR #4294](https://github.com/boburning/portcove/pull/4294) and [PR #4296](https://github.com/boburning/portcove/pull/4296).

## Shared change and evidence

Forty-four complete original paragraphs move from numbered setup steps to optional references. Seventy-five literal existing consequence passages are also copied into visible warnings. Original/edition selection, preparation, executable/working directory/arguments, consent and separate Play remain actions. Data loss, shared-profile, compatibility and runtime-owner consequences remain visible before the relevant choices. No new upstream claim is introduced. Guides containing mandatory cache/save-path choices, stock-runtime preparation or mixed preparation/Play paragraphs were excluded from the ready membership.

The authored records retain every original paragraph object exactly once across actions and references; warnings retain all prior entries followed only by literal passages already present in that guide. All other authored fields, help links and integrations are identical to [the source base](https://github.com/boburning/portcove/tree/b9180382682bcbffcd7f7c2bf3347cff945234c0/crates/portcove-core/catalog/ports). This preserves each title’s source, permission, executable, persistence, update-owner, original-identity and qualification boundaries, including differences between games using one engine. The six native-portable definitions keep their operational and manual-preparation contracts; the other 34 retain their staged-source-portable routes. Existing external registrations retain all external files and their user/upstream owner.

Every changed authored record passed maintained `checkedAuthoredPort` validation and exact action/reference/literal-warning/non-guide comparisons. All three generated outputs (`catalog-current-authoring.json`, `catalog.json`, `listings.json`) exactly project the 40 authored guides; all remaining record and document fields are unchanged. `node scripts/generate-catalog.mts --check` verifies reproduction. These are record/projection checks, not game execution, installed-client delivery, save compatibility, protected publication or unchanged signed-definition hashes. Required complete-diff CI and independent review are reported on the delivery PR at the exact source and target.
