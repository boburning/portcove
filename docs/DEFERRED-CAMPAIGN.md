## Phase-aware cancellation

Core now records preparation/finishing state and cancellation requests on the durable activity UUID, protected by a per-activity OS lock. An atomic SQLite transition closes cancellation before recoverable publication or retained/staged activation. Searches, update checks, installs, updates, and reconciliation support cooperative checkpoints. Downloads, network waits, and source/download hashing can stop promptly; blocking extraction, conversion, and build steps are joined before stopping. Restore, migration, transfers, publication, and game/save supervision keep their existing recovery boundaries. Accepted cancellation has a distinct durable terminal status and error code; request acknowledgement is never presented as completion.

CLI API schema 6 and operation event schema 2 expose cancellation. `cancel <activity-uuid>` works across processes. Ctrl-C and Unix SIGTERM target only the CLI service's own active and queued work and continue waiting through finishing phases. Tauri forwards the same core request.
