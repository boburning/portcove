# Packaged public CLI agent exercise — October 11, 2026

This dated evidence map belongs to [#1499](https://github.com/boburning/portcove/issues/1499).
An agent used argument arrays, public CLI responses and schemas with explicitly
selected disposable libraries. It used existing first-party fixtures with
test-derived assistance; it was not blind community adoption. Core remained the
only lifecycle, plan, locking, activity and recovery authority. No consumer
imported private Core APIs, read SQLite, added per-port lifecycle rules, or used
production credentials, a daemon or a paid model requirement.

## Costs, interventions and recovery material

The Linux release build took 268.357s, packaging 1.759s and maintained smoke 1.002s.
The lost-output apply took 0.799s within its 60s budget. Public reads had 15s/1MiB
bounds; each packet retained exact child identities, argv, exits, logs/hashes and
scoped process-group absence. These are observations, not speedup claims or an
exhaustive descendant-lifetime guarantee. Retained fixtures and packages avoided
rebuilding accepted components.

One discovery preflight failed before library creation or CLI execution because
loopback was down. A separately reviewed correction enabled only loopback inside
the already isolated namespace and used a fresh coordinate. Earlier offline
admission failures, cancelled recovery-required material and original Windows
failures remain retained. No successful rerun retroactively fixes their evidence.

The owning issue remains open until public-guide delivery and its whole-issue
evidence audit pass. This finite exercise does not
complete the full frozen cohort, Windows/Linux beta platform security or release
qualification. The Linux GLib hold and production signing/publication authority
are unchanged.
