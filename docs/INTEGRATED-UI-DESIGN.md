# Integrated Portcove experience

This contract supersedes the earlier staged UI delivery proposal. The owner requested one integrated product candidate. Base reconciliation: `d7f1b50` (21 October 2026); historical references and earlier evidence retain their original identities. Internal implementation commits are not separate product deliveries.

## Product decisions

- Keep four destinations: Library, Find games, Activity and Settings. Add games is a contextual task. Keep Commands and its shortcut discoverable with quiet secondary treatment; place installation copy with Add games and About/help with Settings rather than competing permanent sidebar actions. Preserve shortcuts, navigation regions and valid return focus.
- Identity and the current next action lead. Separate games, stable port IDs and variants. Keep red Play, green readiness, blue selection and gold keyboard focus. Keep graphite/warm-light tokens, bundled Geist, Lucide controls and the approved crab assets.
- Keep whole-image 2:3 collection frames, metadata outside artwork, compact wrapping rows and bounded detail/task artwork. Do not infer ownership, readiness, image crops or eligibility from appearance. Unclassified artwork retains its complete source image.
- Use the existing workspace scroll owner and native sizing preference. Constrain reading/forms within the available workspace; never constrain its scrollbar to a stale width. Reflow navigation and task actions with no lost functionality at enlargement.
- Add games offers intentions: choose a game/port, find games in a folder, or use an existing installation. Requirements determine the route; there is no universal six-step wizard. Preserve checked inputs and drafts across navigation.
- Reviews group inputs, changes and running-work consequences. Focused decisions stay in dialogs; complex inventories and task accounts use workspace/disclosure surfaces. Keep full locations and native approval/plan binding. Keep Move materially distinct from keeping a location or copying files.
- Running work can be left where the existing invocation owner survives navigation. Continue browsing closes observation, not the task. Activity keeps the authoritative target and outcome; completion never steals focus from another workspace. Cancellation-requested is not cancellation-settled.
- Game updates use one explicit immediate choice across detail, notices and Activity. Compact presentation and future policy do not choose a different action. A changed disposition needs a new plan. A staged update is distinct from the current playable version; game, app and catalog updates remain separate.
- Activity is target-first, with attention/current/recent groupings derived from actual records. A read-only retained-work account exposes facts before a separate cleanup decision. Join only by authoritative operation identity. Do not invent universal retry/resume/rollback actions.
- Saved-data backup, metadata export, manual recovery copy, checked restore and library copy-and-switch have distinct names, included/excluded content and consequences. Keep credential/external-file guidance complete. No new whole-library backup engine is promised.

## Acceptance and evidence

### Reconciled surfaces retained deliberately

- The current Library action/identity projections, profile-local view preference, exact detail-return hooks, visibility-gated artwork cache and whole-image fitting remain. They preserve duplicate ports, current/staged versions, user artwork and browsing context; the redesign changes composition rather than duplicating their logic.
- Source intake, saved-location removal, installation-copy detection and external-folder controls retain their existing requirement-specific inputs and fresh-plan/native-consent boundaries. They already distinguish keeping, copying, moving, forgetting and unsupported registration. The common shell, quieter review surfaces and intention-led Add route connect them without a universal wizard.
- Backup inventories, restore/removal reviews, retained-version actions and storage controls retain their specialized consequences and eligibility. A generic maintenance dialog would hide material differences. Their shared row/control presentation is tightened, while the recovery guide now distinguishes saves, metadata, manual copy, checked restore and copy-and-switch explicitly.
- Application and catalog updates retain their separate trust, pending/restart and provenance owners. Application preferences now name the saved future default separately from the one-time check. Game-update choices and execution feedback are corrected independently.
- Existing account/device/token, Steam, tool-path, language, diagnostics/manual-copy and help functions remain in their task categories. Mounted panels preserve validation and unsaved drafts; common hierarchy, selection, focus and disclosure changes apply to them without a new settings store.
- Startup recovery remains independent of the normal Library because that Library may be unreadable. Its copied-file recovery choices remain capability-bound, and its own viewport scroll region keeps final actions reachable when enlarged.
- A caught display failure also has its own viewport scroll region. Reload precedes an optional diagnostic disclosure; full selectable diagnostic text stays in a bounded read-only field. This recovery surface does not claim that a task stopped or that reloading undoes its effects.

These are retained production workflows, not placeholders or future redesign slices. Their available acceptance evidence is recorded separately from implementation decisions.

### Layout and task state refinements

The compact Library readiness choice uses the query-area container, so it appears
when that area's effective reading width is at most 46em. The wide choices and
compact choice never compete in the keyboard order. Narrow navigation uses
wrapping labeled destinations, with two columns when 320 CSS pixels permits it.
Narrow collection art is capped at 160 CSS pixels; scrolling remains intentional.
Activity rows keep one keyed parent across attention/running/recent grouping so
settlement preserves focus and open diagnostics.

Game-update entries keep identity, versions and independent actions inside one
bounded panel. Their facts reflow against the entry's effective width. Activation
reviews show the returned saves/settings location, preserve specific external
notices, and say that keeping an old game version is separate from a save backup;
this review has no save-compatibility assessment. Saved candidates use keeping
language instead of inventing another download.
