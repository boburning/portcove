# Quality operation reference

Read only the operation needed. [QUALITY](../QUALITY.md#required-hosted-baseline) owns
current selection. In retained details, platform-wide, browser, analyzer and installed
requirements refer to explicit exhaustive qualification or named acceptance; they do
not expand ordinary PR CI. The completed #1682 cutover is historical evidence.

## Staged audit receipts

Upstream health's protected accounting policy is
`.github/upstream-health-accounting.json`. Its reviewed original-location
conditions and exact provider-reported pin assessments retain degraded/unknown
availability and unverified bytes. They are monitoring dispositions, never
catalog maintenance, successor, installation or artifact authority. Changes to
this policy or its metadata helpers select full monitoring and applicable review
and hosted checks under QUALITY; the candidate cannot authorize its own accounting
or waive a failed run. New, changed or insufficient facts fail closed under
[UPSTREAM-OBSERVATIONS.md](../UPSTREAM-OBSERVATIONS.md).

Local validation selects resource preflight from its actual command plan before
execution: tooling/frontend scopes do not resolve Cargo or native outputs,
Rust resolves actual Cargo storage, and mixed/unknown commands keep the complete
scope. Capacity, physical-path and machine-policy checks run independently of
successful test receipts. See [development storage](../DEVELOPMENT-STORAGE.md#bootstrap-and-preflight)
for portable defaults and the private strict Windows profile.

`just audit` executes the canonical frontend static group, Rust, the frontend runtime group, script-lint, repository-tooling, Roadmap,
development-tool, dependency-policy, rscheck, release-unit, and applicable
Windows-qualification stages. It continues independent stages after a failure
and returns one aggregate failure so a late problem does not hide remaining
results. `just audit --plan` reports each run/reuse decision without executing a
stage or creating receipt storage. `just audit --fresh` ignores prior success and
runs every applicable stage; release preflight uses this mode; ordinary validation-policy changes follow QUALITY.

Successful deterministic-stage receipts live under ignored
`work/validation-receipts`. Their fingerprints cover the complete conservative
repository-owned domain inventory, tracked/index/worktree content identities,
untracked inputs, recipes and pins, host/tool versions, and whitelisted
behavior-affecting environment. Unknown files affect every reusable domain. A
content-identical unrelated rebase can therefore retain a stage, while a relevant
edit, tool/environment drift, missing input, or receipt-integrity failure forces a
rerun. Unresolved or partially staged paths are refused because one execution
cannot validate two different candidate contents. Failed, interrupted, or incomplete stages never create a reusable receipt.
Frontend static/runtime tasks always execute; Vite Task alone decides production
bundle execution/restoration. Dependency/advisory policy and packaged Windows qualification always rerun because
their external or machine state can change.

`just local-check` stores compatible command-stage receipts below the same root.
It may preserve a proven Rust or other non-frontend obligation after an unrelated tooling repair
while rerunning the changed tooling obligation. It cannot compose incomplete,
failed, interrupted, policy-stale, or stateful evidence into a pass, and it never
replaces current-head required CI.
Repository-wide Oxlint always executes when selected: its scan crosses several
receipt domains, and a content-identical extension or path change can alter the
applicable lint environment even when file bytes are unchanged.

Representative hosted selection after explicit ownership routing:

| Candidate                                                          | Selected hosted behavior                                                        |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| Informational docs or issue template                               | formatting, links and relevant cheap contracts                                  |
| Frontend presentation                                              | frontend and Rust-quality fast groups                                           |
| Focused core Rust                                                  | Rust and Rust-quality fast groups                                               |
| Ordinary tooling repair                                            | explicit groups, or all-fast primary-host fallback when safely unknown          |
| Selector, workflow, updater-trust, signing or authorization policy | ordinary affected contracts; explicit qualification when acceptance requires it |

Renames and deletions classify both identities, mixed changes union their owners,
and incomplete discovery authorizes no plan. Words such as `design`, `channel`, or
`release` in an otherwise inert filename do not assign trust authority.

The maintained native artwork-correction harness, its preparation/main consumers,
two synthetic JPEG fixtures, and scenario catalog/test have explicit frontend
ownership. Both frontend lanes run their Node contracts and context preflight;
ordinary native acceptance still runs separately on the changed scenario. These
qualification consumers do not change Rust, signed catalog inputs, or publisher
authority. The exact inventory lives in the protected hosted selector. New or
renamed unknown harness paths retain all-fast fallback; mixed product, native,
signing, and policy changes retain their additional owners and qualification.

The maintained `apps/desktop/scripts/desktop-source-dialog-test.mts` consumer
also has explicit frontend ownership and selects its Node scenario contracts
locally. It observes source intake, discovery and scan presentation through the
existing application and CLI; it does not implement durable scanning or source
authority. Its changed native interactions still require the ordinary isolated
native scenario. This exact entry grants no ownership to another harness, its
Core/Tauri implementation, or a renamed or mixed authority input.

The pure `apps/desktop/scripts/desktop-install-fixture.test.mts` assertions
belong to frontend Node validation. Compiler-backed probe and shell roundtrips
live in `*.native.test.mjs` and run through Node directly. The canonical
`native:tools` task retains their explicit local route. Existing affected Windows
helper and full Windows qualification lanes provision pinned Rust and run these
cases without installing frontend dependencies. Both rename/delete sides and
the actual probe, quoting and launch inputs select Windows proof; a Linux skip
does not supply it. This exact test ownership does not narrow fixture, scenario
or Playnite lifecycle implementations.
Fallow runs in explicit exhaustive UI checks and qualification. Ordinary local
and hosted checks select integrated lint/type checks, build and runtime tests;
analyzer invocation does not create a merge prerequisite.

Every completed audit writes a current-head run receipt listing the fingerprint,
originating head, duration, rationale, and fresh/reused/failed result for every
applicable stage. These files are disposable local execution evidence. They do not
replace exact-head required CI, issue acceptance, final review, release preflight,
or any protected authority.

## Formatting contract

`just fmt` is the canonical write command and `just fmt-check` is its no-write
counterpart. Cargo formats Rust; Vite+'s bundled Oxfmt formats active JavaScript,
TypeScript, CSS, HTML, hand-maintained JSON and YAML, active Markdown and maintained
TOML, including root manifests, hidden configuration, app and crate files.
Oxfmt uses a configured 100-column width, sorts package manifests, and
deliberately leaves import order unchanged. Import order can carry side effects,
and normalizing the existing tree would add unrelated churn without a product or
quality benefit. The formatter version follows the exact coordinated Vite+ bundle.
Recommended VS Code formatting uses Oxc for these supported formats; the TOML
extension remains useful for schema completion and validation. The workspace
`fmt` block owns discovery/exclusions for local, staged and hosted checks.
Diff selection chooses candidate extensions and lets Oxfmt apply that policy;
it does not maintain a competing generated/history exclusion list.

Generated files, catalogs, fixtures, dependency lockfiles, archived documents,
and dated release evidence are outside the bulk-format boundary so a formatter
cannot rewrite their content or invalidate historical evidence. This includes
the Playnite integration and contract tests' `bin` and `obj` directories, which
MSBuild and NuGet own. Secondary languages and scripts remain outside the
bulk-format boundary; their lint contracts are specified below. Mechanical
repository-wide format commits are listed in `.git-blame-ignore-revs`.

Deterministic failures block: rustfmt, Cargo compilation, Clippy, tests,
type-aware Oxlint, Oxfmt, Stylelint, Ruff, ShellCheck, actionlint,
PSScriptAnalyzer, cargo-shear, cargo-deny security/license/source policy, the
Cargo-metadata architecture checker, the retained whole-Desktop Fallow policy
when selected, and rscheck's absolute-path rule outside reviewed exceptions.

Oxlint uses one root configuration for the desktop TypeScript/TSX and the
repository's maintained TypeScript tooling, tests and configuration files. Its explicit plugin list includes ESLint,
TypeScript, React, JSX accessibility, Oxc, import, and Vitest coverage; an
explicit list replaces Oxlint's defaults. The standard pass applies the
correctness category plus explicit JavaScript correctness, React Hooks, modern
React `refs`/`set-state-in-effect`, and the complete supported
`jsx-a11y/recommended` policy inherited from the former ESLint configuration.
Broad suspicious, pedantic, performance, style, restriction, and nursery
categories remain opt-in so an Oxc update cannot silently expand the blocking
policy. Rules that assume the legacy JSX transform remain disabled.

The correctness category also keeps Oxc's stable compiler-backed React checks
for error boundaries, immutability, incompatible libraries, preserved manual
memoization, purity, render-time state changes, static components, and memo use.
The overlapping nursery dependency/derivation variants are not promoted to a
second blocking policy. `react/todo` is also excluded because it reports React
Compiler lowering limitations such as `try`/`finally`, not application defects.

`jsx-a11y/prefer-tag-over-role` remains disabled as one rule-specific tool
exception. It was not part of `jsx-a11y/recommended`, has no role-specific
configuration, and currently proposes behavior-changing or invalid substitutes
for Portcove's managed dialogs, button-based listbox options, and labelled ARIA
groups. The blocking ARIA role, property, interaction, focus, labelling, and
semantic-content rules remain enabled. Reassess the exception when the rule can
distinguish these patterns instead of suppressing accessibility diagnostics by
file or across the plugin.

The pinned Vite+ check integrates standard lint, type-aware rules and TypeScript
compiler diagnostics through its bundled Oxlint/tsgolint toolchain. The strict
policy reaches application code, tooling, associated tests and configuration;
the Node and browser environments use separate scoped projects. The shared
policy preserves strict checking, exact optional properties and unchecked-index
handling. Unsafe argument, assignment, call, member-access and return rules are
enforced across maintained TypeScript. Unbound-method handling remains the
existing test-only rule exception.

The linter accepts no warnings and rejects unused suppression comments.
`pnpm --dir apps/desktop typecheck` runs the same admitted root Vite+ check with
formatting and lint diagnostics omitted; it does not select another compiler or
checking scope. The normal `pnpm check` workflow runs the complete static route.
Project membership follows the nearest scoped `tsconfig.json` for each file;
no-emit projects do not require declaration output or build references. The
[TypeScript execution contract](../DEVELOPMENT-TOOLS.md#typescript-execution-and-compatibility-files)
owns environments and the exact JavaScript compatibility inventory.

Vitest correctness rules reject focused or disabled tests, conditional or
standalone expectations, invalid callbacks and titles, missing awaited promise
expectations, and message-less throw assertions. `vitest/valid-expect` permits
Vitest's supported optional assertion-message argument. The
`vitest/require-mock-type-parameters` rule remains disabled because applying it
to contextually typed component doubles would repeat their prop and module
contracts across hundreds of ordinary test mocks; contract-sensitive mocks may
still declare explicit types. This is a rule-specific policy decision, not a
file exclusion or diagnostic suppression.

Vite+ pins its TypeScript 7 checker backend with the rest of the frontend
toolchain. Native Node tools execute erasable TypeScript directly; checking does
not emit JavaScript or add a runtime loader. Transport compiler refusal fixtures
continue to exercise their installed compiler boundary independently.

Stylelint applies its recommended correctness rules to the existing stylesheet.
The documented descending-specificity exception preserves the stylesheet's
intentional later-override structure; it does not disable formatting coverage.
Ruff checks the tracked Python asset scripts; ShellCheck checks the tracked shell
bootstrap; actionlint checks every GitHub Actions workflow and receives the exact
ShellCheck executable selected by aqua; PSScriptAnalyzer checks all tracked PowerShell scripts.
The PowerShell profile omits only cmdlet naming rules that do not apply to private
script helpers.

The Playnite C# projects intentionally rely on the SDK compiler analyzers and set
`TreatWarningsAsErrors` in both the extension and contract-test projects.
`just playnite-check` is therefore the C# warning gate. Portcove does not add a
separate Roslyn analyzer package or repository-wide `.editorconfig`; any compiler
warning exposed by that required build must be fixed rather than suppressed.

The bundled Oxlint `portcove/player-copy` rule checks production static copy, including accessible attributes and cooked strings. Its bundled RuleTester cases cover encoded text and the narrowly named technical disclosures; Oxlint owns parsing, diagnostics and source discovery.

The check deliberately excludes non-runtime declarations/tests, imports, property
names, machine-value comparisons and non-copy JSX attributes. A lexical `details`
disclosure named “Technical details”, “View technical details” or “Full identity
and evidence” permits technical terms within that disclosure; it does not exempt
the rest of the component. These boundaries distinguish technical syntax and
evidence from ordinary copy. Runtime catalog/IPC text and raw-enum data flow still
need their owner-layer presentation tests and review; this static check is not a
proof of all rendered wording or of translation quality.

Structural heuristics advise: dependency duplication, unmaintained transitive dependencies, complexity, responsibility splits, god objects, duplicate logic, dead public APIs, semantic duplication, and mutation survivors. Do not refactor simply to make an advisory number green.

## Focused Rust properties and mutation experiments

Core's `path::property_tests` exercises reserved metadata components in synthetic
path strings. Each of its three properties runs 64 cases with ChaCha seed `242046`, at
most 4096 shrink iterations and at most eleven short components. The cases mix
both separators, component placement, ASCII case and ordinary Unicode neighbors.
They distinguish reserved metadata from similar player filenames without reading
the filesystem or constructing the production catalog. Existing example tests
and other property suites retain their own coverage and settings.

Run the selected properties through the existing Rust admission/supervision route:

```powershell
node scripts/run-rust-tests.mts --guard-command cargo test --locked -p portcove-core --lib path::property_tests -- --test-threads=1 --nocapture
if ($LASTEXITCODE) { throw 'Selected properties failed' }
```

Proptest retains failing seeds in its source-relative `proptest-regressions`
file and prints the shrunk input. Preserve both before repairing the failure;
replaying the same test consumes those seeds before new cases. Keep a minimized
regression with the owning boundary when it exposes a real defect. The fixed
configuration above bounds this family regardless of ambient case-count or
shrink-count settings. A passing seed is sampled coverage, not an exhaustive proof.

For an optional mutation experiment, first verify the repository's pinned tool
and inspect the selected inventory. No tool installation is added to ordinary CI.
The following selection targets only `is_portcove_metadata` in one file; inspect
the inventory again after source/tool changes rather than assuming a mutant count.

```powershell
node scripts/quality-tools.mts --verify cargo-mutants
if ($LASTEXITCODE) { throw 'Pinned mutation tool unavailable' }
cargo mutants --file crates/portcove-core/src/path.rs --re is_portcove_metadata --list --json
if ($LASTEXITCODE) { throw 'Mutation inventory failed' }
```

The copy explicitly respects repository ignore rules and excludes build/VCS trees;
this string-only selection needs no ignored frontend dependencies or symlinks.
Run the reviewed finite selection in a copied tree, retaining its output in a new
owned evidence directory. This example allows a 15-minute admission wait and a
25-minute payload including copy, baseline, one guard mutation and cleanup. Every
build has a 600-second limit and every test invocation a 30-second limit. Set
`PORTCOVE_MUTATION_EVIDENCE` to a new absolute evidence directory and
`PORTCOVE_MUTATION_TARGET` to a separate new Cargo target directory. Both must be
outside the resolved checkout with existing parents; keep the target path short
on Windows. The recipe refuses internal or existing destinations before launching
Cargo. It overrides an inherited `CARGO_TARGET_DIR` so deliberate mutations cannot
replace executables in the ordinary test cache. Keep that ordinary target when
checking the original source afterward. The retained regression seed came from a
deliberately broken guard, not a production defect.

```powershell
@'
import path from "node:path";
import { existsSync, mkdirSync, realpathSync } from "node:fs";
import { runResourceCommand } from "./scripts/resource-command.mts";
const workspace = realpathSync(".");
function externalDirectory(requested, label) {
  if (!requested || !path.isAbsolute(requested)) throw Error(`Expected absolute ${label} directory`);
  const result = path.join(realpathSync(path.dirname(requested)), path.basename(requested));
  const relative = path.relative(workspace, result);
  if (!relative || (relative !== ".." && !relative.startsWith(`..${path.sep}`) && !path.isAbsolute(relative))) {
    throw Error(`${label} must be outside the resolved workspace`);
  }
  return result;
}
const output = externalDirectory(process.env.PORTCOVE_MUTATION_EVIDENCE, "Mutation evidence");
const target = externalDirectory(process.env.PORTCOVE_MUTATION_TARGET, "Mutation target");
if (!path.relative(output, target)) throw Error("Evidence and mutation target must be separate directories");
if (existsSync(output) || existsSync(target)) throw Error("Refuse existing evidence or mutation target directory");
mkdirSync(output); // Refuse reuse: earlier failures remain intact.
mkdirSync(target);
const scratch = path.join(output, "scratch");
mkdirSync(scratch);
process.exitCode = await runResourceCommand("rust", "cargo", [
  "mutants", "-p", "portcove-core", "--file", "crates/portcove-core/src/path.rs",
  "--re", "replace is_portcove_metadata -> bool with false$",
  "--baseline=run", "--test-tool=cargo", "--jobs=1",
  "--build-timeout=600", "--timeout=30", "--gitignore=true",
  "--copy-vcs=false", "--leak-dirs", "--output", output,
  "--", "--locked", "--lib", "path::property_tests", "--", "--test-threads=1", "--nocapture",
], {
  executionTimeoutMilliseconds: 1_500_000,
  queueDeadline: performance.now() + 900_000,
  environment: { ...process.env, CARGO_TARGET_DIR: target, TMP: scratch, TEMP: scratch, TMPDIR: scratch },
});
'@ | node --input-type=module
if ($LASTEXITCODE) { throw 'Mutation experiment failed; inspect retained results' }
```

Retain the exact source and file hashes, pin verification, selected inventory,
arguments, platform/compiler, budgets, unmutated baseline, every mutant diff and
outcome, and generated failure seeds/minimal inputs. Count caught, survived,
unviable and timed-out mutants separately; a build failure or timeout is not a
killed behavioral invariant. Review surviving mutants individually and record
equivalence only with a concrete reason. Do not suppress them or substitute a
global mutation score for behavior coverage. A broken selected guard must fail
the expected property, and the original source must still pass afterward. These
experiments establish no installed, native, signing or release acceptance.

## Bounded raw TAR parser campaign

`archive::fuzz_tests::bounded_raw_tar_mutation_campaign` is an opt-in,
memory-only investigation of `preflight_raw_tar` through its real bounded reader.
Its ordinary-test ignore reason identifies this route. It uses the existing
pinned Rust/proptest/TAR dependencies and installs no fuzzer or mandatory tool.

Eight synthetic, redistributable seeds cover an ordinary member, empty stream,
truncated header, checksum corruption, the exact 64 KiB raw extension limit,
oversized extension/file declarations and an unsupported long link. Refusal
controls require the specific size-limit refusal and zero body-read attempts,
including failed or zero-byte attempts after the first 512-byte header. EOF or
truncation cannot substitute for the intended bound. Raw preflight acceptance
does not establish semantic TAR acceptance.

The campaign uses ChaCha seed `242047`, 256 generated cases, at most sixteen byte
edits per case, truncation, optional checksum repair and four short-read shapes.
Inputs and decoded work are capped at 128 KiB; retained seed bytes together also
fit 128 KiB. It permits 1024 successful checkpoint calls plus the two refusal
rechecks. The raw iterator returns fixed headers before the pinned TAR parser's
long-name/PAX `read_all` preprocessing; declared sizes do not allocate payloads.
Memory contains the bounded corpus, one bounded input and fixed reader/header
state, plus bounded generator/shrinker state. This is not a resident-memory cap.
There is no gzip expansion, semantic-entry extraction or filesystem publication
in this boundary; those retain their separate tests and protections.

Run from a clean, committed checkout. Set `PORTCOVE_FUZZ_EVIDENCE` and
`PORTCOVE_FUZZ_TARGET` to new, separate absolute directories outside it, with
existing parents. Keep the target short on Windows. Preserve the source while
the commands run; earlier evidence/targets are refused. This recipe admits each
stage through the existing resource supervisor, allows twenty minutes to compile
and sixty seconds for the actual campaign, and preserves both logs on failure.

```powershell
@'
import path from "node:path";
import { createHash } from "node:crypto";
import { execFileSync } from "node:child_process";
import { existsSync, mkdirSync, realpathSync, readFileSync, writeFileSync, openSync, closeSync } from "node:fs";
import { runResourceCommand } from "./scripts/resource-command.mts";
const workspace = realpathSync(".");
if (execFileSync("git", ["status", "--porcelain"], { encoding: "utf8" }).trim()) throw Error("Clean committed campaign source required");
function externalDirectory(requested) {
  if (!requested || !path.isAbsolute(requested)) throw Error("Expected absolute output directory");
  const result = path.join(realpathSync(path.dirname(requested)), path.basename(requested));
  const relative = path.relative(workspace, result);
  if (!relative || (relative !== ".." && !relative.startsWith(`..${path.sep}`) && !path.isAbsolute(relative))) {
    throw Error("Output must be outside the resolved workspace");
  }
  return result;
}
const output = externalDirectory(process.env.PORTCOVE_FUZZ_EVIDENCE);
const target = externalDirectory(process.env.PORTCOVE_FUZZ_TARGET);
if (!path.relative(output, target) || existsSync(output) || existsSync(target)) throw Error("New separate outputs required");
const hash = (bytes) => createHash("sha256").update(bytes).digest("hex");
const files = ["Cargo.toml", "Cargo.lock", "rust-toolchain.toml", "crates/portcove-core/Cargo.toml", "crates/portcove-core/src/archive.rs", "crates/portcove-core/src/archive_fuzz_tests.rs"];
const snapshot = () => Object.fromEntries(files.map(file => [file, hash(readFileSync(file))]));
const source = snapshot();
mkdirSync(output);
mkdirSync(target);
const receipt = { source, revision: execFileSync("git", ["rev-parse", "HEAD"], { encoding: "utf8" }).trim(), node: process.version, platform: process.platform, arch: process.arch, status: "running", stages: [] };
const selection = ["test", "--locked", "-p", "portcove-core", "--lib", "archive::fuzz_tests::bounded_raw_tar_mutation_campaign"];
try {
  writeFileSync(path.join(output, "compiler.txt"), execFileSync("rustc", ["--version", "--verbose"], { env: { ...process.env, RUSTUP_AUTO_INSTALL: "0" } }));
  for (const [name, args, budget] of [
    ["build", [...selection, "--no-run"], 1_200_000],
    ["campaign", [...selection, "--", "--ignored", "--exact", "--test-threads=1", "--nocapture"], 60_000],
  ]) {
    const log = path.join(output, `${name}.log`), fd = openSync(log, "wx");
    let status = null;
    try {
      status = await runResourceCommand("rust", "cargo", args, {
        executionTimeoutMilliseconds: budget, queueDeadline: performance.now() + 900_000,
        output: { stdout: fd, stderr: fd }, environment: { ...process.env, CARGO_TARGET_DIR: target, RUSTUP_AUTO_INSTALL: "0" },
      });
    } finally {
      closeSync(fd);
      receipt.stages.push({ name, args, budget, status, log, sha256: hash(readFileSync(log)) });
    }
    if (JSON.stringify(snapshot()) !== JSON.stringify(source)) throw Error("Campaign inputs changed");
    if (status !== 0) throw Error(`Retain failed ${name} evidence`);
    if (name === "campaign" && !/1 passed; 0 failed; 0 ignored/u.test(readFileSync(log, "utf8"))) throw Error("Campaign did not execute exactly once");
  }
  if (execFileSync("git", ["status", "--porcelain"], { encoding: "utf8" }).trim()) throw Error("Campaign changed the source checkout");
  receipt.status = "passed";
} catch (error) {
  receipt.status = "failed";
  receipt.error = String(error);
  throw error;
} finally { writeFileSync(path.join(output, "receipt.json"), JSON.stringify(receipt, null, 2) + "\n", { flag: "wx" }); }
'@ | node --input-type=module
if ($LASTEXITCODE) { throw 'Parser campaign failed; retain its packet before repair' }
```

The existing shrinker allows at most 512 iterations. Failure persistence is
disabled so it cannot change the input checkout; the retained failure prints the
small seed index/edit/truncation tuple. Promote a minimized real failure into a
named deterministic seed or regression and retain its original source, tuple and
log before repair. Ordinary runs continue reporting the campaign as explicitly
ignored. Passing this bounded campaign is investigative evidence, not broad
format, extraction, native or release coverage.

## Fallow scopes and policy

Use the repository-pinned Fallow through the maintained wrappers so reports retain
their source identity and Portcove's enforcement mapping. Ordinary fast PR CI
and default focused local checks do not run an exhaustive Fallow scan.

Each native analysis has a finite 20-minute payload budget; saved-report formatting
has one minute. Admission, compiler preparation and source identity collection are
separate phases. The owned-tree executor proves termination before releasing its
reservation. Raw stdout/stderr are retained live, bounded to 32 MiB per analysis
stream and 1 MiB per formatting stream, with initial and final execution records.
Timeouts, missing exit proof and incomplete evidence remain failed or incomplete;
they cannot establish reusable success. A native exit code of 124 remains distinct
from a supervisor deadline. Formatter or retention failure cannot replace an
earlier analyzer failure. Existing refusal to release on an escaped or unproven
descendant remains in force.

Windows and Linux inherited invocations establish their own inner containment.
On other Unix platforms, a bounded invocation inside an inherited reservation is
refused before launch because a second detached group lacks registration in that
outer receipt. Standalone execution retains the existing registered group and
watchdog route. The CLI acquires resources at each actual native phase; source
validation and unique evidence writes need no redundant enclosing reservation.
Hosted analyzer routes explicitly install the repository-pinned custody compiler.

The [October 19 audit and dispositions](fallow-audit-2026-10-19.md) retain original
finding identities, corrections and source-review limits.

| Command                   | Use and scope                                                                                   | Enforcement                                                                                                     |
| ------------------------- | ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `just fallow`             | Whole Desktop JS/TS graph; also selected by explicit full frontend qualification and deep audit | Validated `check.total_issues` must be zero, including warning findings; critical-complexity count must be zero |
| `just fallow-tooling`     | Investigate maintained repository JS/TS, especially root scripts and their consumers            | Advisory; historical tooling findings do not block Desktop qualification                                        |
| `just fallow-review BASE` | Review a meaningful JS/TS branch change against its real comparison base                        | Advisory changed-code audit and review brief, with inherited context                                            |
| `just fallow-css`         | Substantial styling changes or design-system maintenance                                        | Advisory dedicated CSS analysis                                                                                 |

The full gate retains dead-code, dependency, circular-dependency and configured
architecture checks. Its zero total includes warning findings; replacing that
decision with a native error-only verdict would weaken existing protection.
Critical complexity remains the complexity blocker. Aggregate duplication above
the former 2% ceiling does not fail: use group identities, locations and shared
responsibility to decide whether a refactor helps. Do not impose a substitute
percentage or treat a new advisory category as a blocking check.

Whole-Desktop qualification also requires the native `--fail-on-parse-error`
gate to be enforced. A successful process with zero findings cannot qualify
source the parser could not analyze. Qualification also rejects required-source
read failures or an unexpectedly empty source scope. The summary displays
diagnostics at their native report locations; intentional exclusions and unavailable optional
history, ownership or rankings qualify the corresponding conclusions without
blocking unrelated static checks.

[PR #1097](https://github.com/boburning/portcove/pull/1097) records a candidate
crossing the old duplication threshold and a repair before delivery. That is
evidence of workflow friction; it does not establish that the repaired code was
harmful or that every duplicate should remain. Judge the actual responsibilities.

The Desktop configuration retains the shared-to-feature prohibition, including
type-only imports, re-exports and literal dynamic imports. Its causal fixtures
exercise allowed shared/shared and feature/shared imports too. Unclassified
legacy/root modules remain explicit coverage limits; feature-to-feature imports
are not generally prohibited. The tooling graph models maintained executable
entry points and follows helper imports; generated inputs, fixtures and dynamic
consumers still require checking before accepting an unused-code candidate.
Fallow does not analyze Rust, PowerShell or native application behavior.

The root graph explicitly includes catalog generators, discovery and semantic
qualification commands, Docker's copied entry script, and Desktop script tests.
Native harnesses and development scenarios have test roles; their dependencies
do not become production requirements. Narrow export credits identify symbols
consumed by repository tests outside the Desktop graph, including the maintainer
configuration helper imported by an isolated child process. Other exports in
those modules remain checked. The scope fixtures retain orphan detection and
shared-to-feature enforcement, and distinguish test-only from production imports.

Two unresolved-import exceptions represent resources rather than module edges.
Vite serves `apps/desktop/public/theme-bootstrap.js` at `/theme-bootstrap.js`,
which repository-root resolution cannot model. The reviewed-input reader reads
`../.github/workflows/release-reviewed-inputs.yml` as workflow bytes. Preserve
the actual files and their consumers when maintaining either exception.

Every wrapper invocation retains original analyzer output, stderr and source,
scope, version and comparison metadata below ignored `work/fallow-reports`.
Local source identity includes dirty content; a commit SHA alone does not identify
an uncommitted candidate. The bounded summary lists concrete findings and
refactoring targets from the report already produced. The review summary also
shows bounded changed-export test reach and guardrail-change evidence. Test reach
describes the static import graph, not executed coverage; missing tests, capped
mock detection and end-to-end coverage limits remain explicit. Unknown reach

## Consumed Intel test transfers

The `intel-rust-tests-<attempt>` archive transfers compiled tests from the Apple
Silicon producer to both Intel test partitions. It is not a release artifact.
`Cleanup consumed Intel transfers` runs trusted default-branch code after CI,
qualification or release completion and hourly. Completion events inspect the
triggering run's artifacts only; hourly cleanup and manual dispatch without a run
ID sweep exact names `intel-rust-tests-1` through `intel-rust-tests-4`. That is
bounded recovery, not an exhaustive repository artifact inventory. A later
attempt missed by the sweep can be retried with `--run-id <id>` or the manual
workflow input; completion events handle arbitrary attempt numbers. Its only
write authority is a job-scoped Actions token. It deletes a transfer only after
a complete job inventory proves that its exact producer and both Intel consumers
succeeded in the same completed run attempt. Active runs, failed Intel attempts, ambiguous inventories, all other
artifacts, and release assets are preserved. The one-day upload retention remains
as the fallback. After successful transfer cleanup, rerun Intel tests together
with their producer rather than rerunning only an already-successful consumer.

Use `node scripts/cleanup-intel-artifacts.mts` for the read-only bounded sweep,
or `node scripts/cleanup-intel-artifacts.mts --run-id <id>` for one exact run;
add `--apply` only for authorized cleanup. A restarted attempt or changed

## Bounded dependency delivery

[QUALITY](../QUALITY.md#bounded-dependency-delivery) owns when review and validation are required.
The deployed helper owns eligibility; these commands describe its use.

Start one authorized maintenance cycle with
`just renovate-check --queue [--json]`. It reads the complete current proposal
inventory, exact source heads, target interactions, required checks and run
identities. The selected row is a recommendation: confirm existing ownership and
actual writer activity and source-owner release before overlapping work. No
coordinator grant or acknowledgment is required for independent delivery.
The queue's `release_age_diagnosis` separates a passed status, explicitly missing
timestamps, unexplained pending, and missing/conflicting/failed observations.
A generic pending status does not establish a young release or a running timer.
The optional bot version comes from the PR debug marker, not proof of the current
hosted deployment. These fields are diagnostic only; raw statuses and all existing
eligibility and delivery gates remain authoritative.

For unexplained age blocks, bind every affected member's official datasource
timestamp to the exact proposed version/digest, then inspect the hosted job's
lookup and branch inputs and deployed engine version. Missing job access remains
UNKNOWN. Never calculate an age expiry from PR creation, rebases or status-posting
time. Docker Hub uses the tag's `tag_last_pushed`, so a mutable tag repush can restart
the upstream delay. Digest and lock-maintenance symptoms may match
[Renovate #45236](https://github.com/renovatebot/renovate/issues/45236); a matching
symptom is not a confirmed hosted cause or permission to clear the status.

Retain the one-day, timestamp-required, strict policy. Adopt a supported upstream
correction when it is actually deployed, then request one supported retry after
checking how authored work survives, and read back the actual source/status.
An unmerged upstream fix cannot be installed into the hosted service by changing
repository metadata. Keep unresolved service defects on the existing maintenance
owner with exact heads, evidence and a concrete resume condition. Revisit on a
changed source/status/input or supported scheduled wake; do not poll unchanged
blocks tightly, write a custom age checker, manufacture green status, or silently
relax policy. Any proposed policy exception requires explicit owner authority.

The command does not retry, approve, rebase or merge proposals, assign ownership
or maintain another queue. Refresh
after every delivered outcome. No unattended execution is implied.

A final npm package rule retains the PR table's Package, Type, Update and Change
columns after inherited confidence presentation rules. A top-level column setting
alone does not override those inherited package rules. Missing update-type metadata still requires controlled maintenance;
neither a title nor a confidence badge supplies it. Column configuration is not
proof of hosted uptake or a completed operational fast-lane canary.

Use four delivery paths:

- **Routine fast lane:** run `just renovate-check --pr <number> --head <sha>`.
  Only `merge-ready` permits the existing #878 exception: exact-head hosted
  compilation/lint/tests plus locked metadata and dependency-policy validation,
  followed by concise delivering-agent upstream/diff review and guarded merge.
  This does not require a duplicate broad local aggregate or separate review.
- **Controlled maintenance:** compatibility groups, pre-1.0 inputs, tools,
  Actions, lockfile maintenance, sensitive boundaries and repaired proposals use
  the ordinary diff-selected hosted plan (local feedback stays optional) and independent non-writing
  review. Signing/trust, credential storage/transport, extraction and persistent
  database inputs require behavior-specific evidence regardless of labels or
  a small version increment. Inspect enabled features, transitive changes,
  install/build behavior and relevant compiler/runtime requirements. Browser
  provider updates include the real browser stage; native/updater changes retain
  their distinct acceptance. Pure formatter updates do not imply installed-updater
  qualification.
- **Planned migrations:** major proposals require selective Dependency Dashboard

  existing authority. Ordinary proposals do not need that approval. Priority
  orders eligible intake; it cannot evict occupied slots. Preserve finite owners,
  blocker/resume conditions and failed evidence rather than closing failures to
  free the queue.
- **Urgent remediation:** security-intent metadata selects prompt advisory

  advisory, locked graph and exposed function. Necessary fixes proceed separately
  from elective upgrades, without the ordinary release-age or intake delay; review,
  signatures, required checks and affected native/installed behavior remain.

Blocked proposals pause that update, not independent maintenance. Record a
durable maintainer comment on the PR with its exact source head, failure evidence,

description alone is not the hold record. The classifier remains a recommendation;
reconcile its output with these current ownership and hold records before pickup.
Use the existing owning issue for a larger repair rather than another backlog.

Repair a bounded defect through controlled maintenance. Otherwise retain the
upstream hold and continue independent candidates. Revisit only when the source,
checks, upstream remedy, eligibility or another recorded resume condition changes;
a newer version must pass the original reproducer and affected-consumer assessment.
Do not repeatedly rebase unchanged blockers, disable a whole dependency or close
a genuine failure to free capacity. Verify a linked replacement's delivery before
closing its superseded original; an explicit owner decision may reject an update.
The six-proposal limit does not increase automatically when all slots are occupied.
