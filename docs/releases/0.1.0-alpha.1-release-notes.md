# Portcove 0.1.0-alpha.1

> **Technical preview for maintainers and technically comfortable testers.**
> Use a disposable or fully backed-up Portcove library. Windows has isolated
> installer and replacement-lifecycle evidence. Linux and macOS have hosted
> build/test evidence, but not equivalent hands-on desktop package qualification.
> Desktop packages do not yet carry operating-system publisher signing.

This is the reviewed release-note source for Alpha 1. Its presence in the
repository does not mean the release is published. Packaged previews appear on
[GitHub Releases](https://github.com/boburning/portcove/releases).

## What this alpha improves

Portcove provides a local desktop app and a separate CLI over the same core
installation, library, and launch behavior. Alpha 1 hardens controlled technical
testing with:

- hosted release cache revalidation, bounded provider responses and pagination,
  explicit failure for tied runnable assets, and filename-bound aggregate checksums;
- install-tree and executable verification before launch, safe Unix executable
  permissions, and refusal to fall back to an unmanifested executable;
- current-byte source-health checks and content-bound preparation that reject
  changed source files, including changes during preparation;
- durable, observable, cancellable launch requests, restart recovery, and save
  collection tied to the selected installation;
- interrupted backup-deletion recovery and inventory that exposes damaged or
  unavailable backups without hiding healthy entries.

The implementation and integration record is [issue #13](https://github.com/boburning/portcove/issues/13).
Portcove does not distribute or download original ROMs, disc images, BIOS files,
or other copyrighted game data. Catalog membership and upstream release channels
do not establish hands-on support on every platform.

## Choose a download

Download from the versioned prerelease entry, not GitHub's generated **Source
code** archives. Those require a development build. The desktop and CLI are
separate downloads; a CLI archive is not a desktop installer.

| System | Desktop | CLI |
|---|---|---|
| Windows x64 | `Portcove_0.1.0-alpha.1_x64-setup.exe` | `portcove-windows-x86_64.zip` |
| Linux x64, experimental | `Portcove_0.1.0-alpha.1_amd64.AppImage`, `Portcove_0.1.0-alpha.1_amd64.deb`, or `Portcove-0.1.0-alpha.1-1.x86_64.rpm` | `portcove-linux-x86_64.tar.gz` |
| macOS Intel, experimental | `Portcove_0.1.0-alpha.1_x64.dmg` | `portcove-macos-x86_64.tar.gz` |
| macOS Apple silicon, experimental | `Portcove_0.1.0-alpha.1_aarch64.dmg` | `portcove-macos-aarch64.tar.gz` |

Names above follow the current workflow and the historical Alpha 1 package run;
the actual tag-generated draft must be checked before publication. Each platform
has `SHA256SUMS-<platform>.txt`, using the CLI's platform label. The aggregate
`SHA256SUMS.txt` covers the runnable packages across all platforms.

Windows has no Authenticode publisher signature and can display unknown-publisher
or reputation warnings. macOS has no Developer ID signature or notarization and
can prevent the app from opening. This alpha does not provide a qualified
workaround for those restrictions. Keep operating-system security protections
enabled. Linux and macOS desktop installation, runtime, and upgrades remain
experimental even when hosted compilation and native tests pass.

## Verify the downloaded bytes

Download the checksum manifest from the same release as the package. Compare
the entire SHA-256 against the line whose filename exactly matches your download.
Stop on a missing or conflicting entry or a hash mismatch. The examples below
use one actual package per platform; substitute your exact filename when using
another package. Keep the package and manifest in the same directory.

PowerShell, Windows installer:

```powershell
$asset = 'Portcove_0.1.0-alpha.1_x64-setup.exe'
(Get-FileHash -Algorithm SHA256 -LiteralPath $asset).Hash.ToLowerInvariant()
Get-Content -LiteralPath 'SHA256SUMS-windows-x86_64.txt' |
  Where-Object { $_.EndsWith('  ' + $asset) }
```

Compare the first output with the 64-character hash on the matching manifest
line. Exactly one matching line is expected.

Linux, AppImage (check this package only, without requiring other downloads):

```bash
awk '$2 == "Portcove_0.1.0-alpha.1_amd64.AppImage"' SHA256SUMS-linux-x86_64.txt | sha256sum --check --strict -
```

macOS, Apple silicon disk image (use `x64` and `macos-x86_64` for Intel):

```bash
awk '$2 == "Portcove_0.1.0-alpha.1_aarch64.dmg"' SHA256SUMS-macos-aarch64.txt | shasum -a 256 --check -
```

Expect the exact filename followed by `OK`; no match or any other result is not
a successful verification. These commands require the normal host checksum
tools. SHA-256 establishes agreement with the published manifest, not an
independent publisher identity, full security assurance, or gameplay qualification.

## First setup, manual upgrades, and recovery

After verifying the package, use the Windows installer, or the package appropriate
to your experimental Linux/macOS host. Extract the CLI archive if you want the
command-line interface; start with `portcove about` and `portcove doctor`.
Use `--library <path>` or `PORTCOVE_LIBRARY` to select an isolated test library.
Register only the original files required by your chosen port, review its source
and setup requirements, and use the install plan before installation. See the
[CLI guide](https://github.com/boburning/portcove/blob/main/docs/CLI.md).

Application upgrades are manual in this alpha. Close Portcove and all managed
games before copying a backup of the complete library to a separate location.
Retain the previous application package and record the version and checksum.
Verify the new package before replacing the application. A game update in
Portcove is separate from an upgrade of Portcove itself; no desktop in-app updater
or updater feed ships here.

The recorded Windows test covers one isolated predecessor-to-candidate installer
replacement with a preserved database and test-data marker, followed by uninstall.
It does not qualify arbitrary application downgrades, every future schema
migration, or Linux/macOS upgrades. If an application upgrade fails, stop using
the affected library, preserve it for diagnosis, and recover only from a complete
pre-upgrade copy with its matching earlier application. Test that recovery on a
copy first; do not open a migrated library with an older app based on this alpha's
installer evidence alone.

For managed games, retained-version rollback and persistent-data backup/restore
are separate operations. Review the selected version and any backup/restore
preview. A game rollback is not a rollback of the Portcove application or its
database. Do not manually delete damaged recovery state to make an operation pass.

## Known limitations

- The Linux Tauri GTK3 dependency graph contains `glib 0.18.5`, affected by
  [GHSA-wrw7-89jp-8q8g](https://github.com/advisories/GHSA-wrw7-89jp-8q8g).
  The first patched version is `0.20.0`; the current graph cannot directly accept
  that upgrade. [Issue #49](https://github.com/boburning/portcove/issues/49)
  tracks the upstream blocker. The alert remains open, without a suppression or
  fork. Lack of direct Portcove API use is not proof of non-exploitability.
- Windows publisher signing, macOS signing/notarization, and hands-on Linux/macOS
  package qualification remain outstanding. Hosted tests cannot replace them.
- Port qualification is specific to the platform and recorded scenario in the
  catalog. No universal gameplay, audio, controller, or save/load claim is made.
- Later onboarding, storage, integrations, and updater work remain on the
  [live roadmap](https://github.com/users/boburning/projects/1).

## Report a problem safely

Search [existing issues](https://github.com/boburning/portcove/issues), then report
the Portcove version, operating system and architecture, exact package filename,
steps to reproduce, expected result, and actual result. Review diagnostic text
before sharing: redact usernames, local paths, private logs, account identifiers,
tokens, and other credentials. Never attach ROMs, game data, BIOS files, or a
complete library. Share only the minimum redacted excerpt needed to explain the
failure. Report vulnerabilities through
[private vulnerability reporting](https://github.com/boburning/portcove/security/advisories/new),
following [SECURITY.md](https://github.com/boburning/portcove/blob/main/SECURITY.md).
