## Phase evidence log

### Phase 0A — child-process and credential boundary

- Baseline search found direct production process creation in CLI game launch, Tauri game launch and folder integration, upstream setup, managed PS1 building, `chdman`, and DolphinTool.
- `ChildProcessPolicy` now owns environment construction for all of them. `LaunchKind` makes native and Windows batch launches explicit.
- `scripts/check-child-process-policy.mjs` is part of `just check-rust` and rejects future direct production `Command::new` bypasses.
- Proof: `cargo test -p portcove-core process::tests -- --nocapture`, `cargo check --workspace --all-targets`, `just check-rust`, `just check`, and `just audit` passed. The final audit ran 143 Rust tests and 64 frontend tests, reported zero blocking cargo-deny or rscheck findings, and retained only the documented cargo-modules advisory cycle and dependency/shape advisories.

### Phase 0B — durable operations and database foundation

- `database.rs` is the single migration authority. `locks/migration.lock` supplies cross-process serialization; each of seven ordered steps is transactional and records its version only after structural verification.
- `OperationCoordinator` reuses durable activity IDs and emits a versioned, sequence-aware envelope. Nested PSX setup carries its parent ID. The desktop reducer retains independent operation state and ignores stale events.
- Durable lifecycle rows record install, adoption, removal, restore, and staged-activation intent and phase. `recovery.rs` resumes only path/identity states whose outcome is unambiguous; errors remain journaled and become repair-plan items.
- Installation and adoption validate a private same-volume tree before rename. Removal renames registered managed versions into `recovery/` before deleting metadata. Restore preserves the prior live tree until the replacement is published. Startup cleanup is retryable and never treats an untracked final directory as disposable.
- Focused database and service suites pass, including fresh and historical migration, four simultaneous migrators, future/partial schemas, every injected publication boundary, half-published path matrices, retained/staged reuse, and read-only repair reporting.
- `just check` passed with 157 Rust and 66 frontend tests before the final mutation additions; `just audit` passed with zero blocking cargo-deny or rscheck findings and only the recorded dependency/shape/cargo-modules advisories. Final `just check-rust` passed with 162 Rust tests.
- Targeted cargo-mutants coverage selected 41 state-transition mutations. The first run caught 28, exposed 12 meaningful coverage gaps, and produced one compiler-rejected mutation. After adding exact corruption and recovery-matrix tests, all 13 prior survivors/rejected cases were caught. Windows symlink privilege prevented isolated-copy mode, so the runs used cargo-mutants' transactional in-place mode followed by `git diff --check`; its generated reports were removed after evidence was recorded.
- Host-specific antivirus/open-handle and read-only/full-disk failures are represented by deterministic boundary injection and retryable persisted states. Portable CI cannot force those OS conditions reliably; no destructive repair behavior is enabled on that basis.

### Phase 0C — immutable artifact and archive trust

- Schema 8 adds an asset name, verified artifact SHA-256 and size, manifest SHA-256, and catalog-selected executable to every new install. Existing rows receive no invented identity and therefore fail current-integrity gates until replaced or re-adopted.
- Full artifact digests own version-directory keys. Display tags remain unchanged across stable, beta, rolling, and direct-manifest releases; update checks, install plans, active/staged matching, and retained reuse compare artifact identity.
- Schema-2 manifests bind port/install/display/artifact/executable identity and every immutable file. The hot critical set contains the selected executable and same-directory libraries, launchers, and bootstrap configuration; declared saves and mutable configuration remain outside it.
- Active/staged/retained reuse, activation, rollback, lifecycle recovery, and launch revalidate the manifest and current critical bytes before pointer, persistence, marker, or process side effects. The PS1 toolchain cache applies the same principle to Python, CMake, Ninja, and toolchain metadata.
- One shared archive engine preflights release and toolchain ZIP/TAR packages with compressed, expanded, per-entry, count, ratio, path length/depth, entry-type, portable collision, and free-space policy before extraction. Downloads enforce declared and global compressed sizes while streaming.
- Focused proof covers same-tag republishing, active executable/library/manifest and database-identity tamper, staged/retained/rollback tamper, no executable fallback, mutable-file exclusion, toolchain tamper, and hostile ZIP/TAR cases. Final `just check` and `just audit` passed with 153 core tests, 22 CLI tests, 66 frontend tests, architecture/process/release gates, zero blocking cargo-deny findings, and zero blocking rscheck findings. The recorded cargo-modules inherent-item cycle, dependency advisories, and shape findings remain advisory.
